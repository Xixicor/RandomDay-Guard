# Admin.ini การบังคับใช้

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


RandomDayGuard จะไม่เปลี่ยนรายการแบนเซิร์ฟเวอร์ในการตั้งค่าเริ่มต้น โดยจะสร้างรายงานให้ผู้ดูแลระบบตรวจสอบเท่านั้น หน้านี้อธิบายตัวเลือกการอัปเดตรายการแบนอัตโนมัติสำหรับผู้ดูแลระบบที่จงใจเปิดใช้งาน

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## สิ่งที่ Guard ตรวจสอบก่อนที่จะเปลี่ยนรายการแบน

Guard จะเพิ่มการแบนเฉพาะเมื่อทุกคำตอบด้านล่างคือ **ใช่**:

1. หลักฐานปัจจุบันระบุบัญชีใดบัญชีหนึ่งด้วยความมั่นใจเพียงพอหรือไม่
2. บัญชีไม่ใช่ทั้ง ผู้ดูแลหรือบัญชีที่ผู้ดูแลระบบทำเครื่องหมายว่าเชื่อถือได้?
3. บัญชีไม่อยู่ในรายการแบนหรือไม่
4. บัญชีถึงคะแนนการดำเนินการอัตโนมัติที่กำหนดค่าไว้หรือไม่
5. Guard สามารถอ่านปัจจุบัน `Admin.ini` และบันทึกข้อมูลสำรองที่เหมือนกันหรือไม่
6.  `Admin.ini` ยังคงไม่เปลี่ยนแปลงในขณะที่ Guard เตรียมการอัปเดตหรือไม่
7. หลังจากบันทึก ไฟล์ที่สมบูรณ์ตรงกับผลลัพธ์ที่ต้องการทุกประการหรือไม่

หากคำตอบคือ **no** หรือไม่สามารถตรวจสอบได้ Guard จะออกไป `Admin.ini` ไม่เปลี่ยนแปลงและบันทึก เหตุผลในรายงาน หากการบันทึกเริ่มต้นขึ้นแต่การตรวจสอบขั้นสุดท้ายล้มเหลว Guard จะคืนค่าข้อมูลสำรองที่ได้รับการยืนยัน

<a id="file-format"></a>
## รูปแบบไฟล์

`Admin.ini` ต้องได้รับบรรทัดแบนที่ชัดเจนเท่านั้น:

```ini
BannedPlayer=<ID>
```

- ไม่มีชื่อ
- ไม่มีความคิดเห็น
- ไม่มีเหตุผล
- ไม่มีส่วนต่อท้าย

<a id="safe-defaults"></a>
## ค่าเริ่มต้นที่ปลอดภัย

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## แหล่งที่มาของ ID การแบน

แหล่งที่มาที่ดีที่สุด:

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

รันไทม์ยอมรับ ID ที่เป็นตัวเลขแบบเต็มหรือแบบฟอร์มการเชื่อมต่อ `<digits>_+_|<non-space token>` ที่มีเอกสารครบถ้วน และได้รับรหัสการแบนที่เป็นตัวเลขจากมัน คำนำหน้าตัวเลขตามอำเภอใจที่มีส่วนต่อท้ายที่ไม่รู้จักจะถูกปฏิเสธ จะไม่ถูกตัดทอนเป็นรหัสแบน

ถูกต้อง:

```ini
BannedPlayer=2535422284688820
```

ผิด:

```ini
BannedPlayer=ExamplePlayer
```

ผิดด้วย:

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## การตั้งค่าที่แน่นอน การตรวจสอบความปลอดภัย

การตั้งค่าเหล่านี้ใช้การตรวจสอบที่อธิบายไว้ข้างต้น ทุกเงื่อนไขที่ระบุไว้จะต้องเป็นจริง:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

หากเงื่อนไขใด ๆ เป็นเท็จหรือไม่สามารถตรวจสอบได้ Guard จะไม่เปลี่ยนแปลงรายการแบนและบันทึกสิ่งที่หยุดไว้

<a id="transaction-safety"></a>
## ความปลอดภัยของธุรกรรม

พาธการกลายพันธุ์ `Admin.ini` เพียงอย่างเดียวดำเนินการตามขั้นตอนเหล่านี้ตามลำดับ:

1. อ่านและตรวจสอบโครงสร้างไบต์ที่เชื่อถือได้
2. รับผู้ตรวจสอบ เชื่อถือได้ และสถานะการแบนที่มีอยู่จากสแน็ปช็อตเดียวกันนั้น
3. เขียนการสำรองข้อมูลที่ไม่ซ้ำกันภายใต้ `runtime/backups/` และตรวจสอบ เป็นไบต์ต่อไบต์
4. อ่านซ้ำ `Admin.ini` ทันทีก่อนที่จะแทนที่และปฏิเสธการเปลี่ยนแปลงภายนอกใดๆ
5. เขียนตัวเลือกผ่านพาธการแทนที่ที่มีการควบคุมที่กำหนดค่าไว้
6. ต้องการไบต์การอ่านกลับที่สมบูรณ์เพื่อให้เท่ากับไบต์ของตัวเลือกที่สมบูรณ์
7. เมื่อการอ่านกลับล้มเหลว ให้คืนค่าการสำรองข้อมูลที่ตรวจสอบแล้วในขณะที่ไฟล์ปัจจุบันเท่านั้น ยังคงเป็นผู้สมัครที่แน่นอนที่เขียนโดย Guard หากผู้เขียนคนอื่นเปลี่ยนแปลง Guard จะปฏิเสธการย้อนกลับแทนที่จะเขียนทับไบต์ภายนอกที่ไม่รู้จัก

รหัสที่ซ้ำกันถือเป็นค่าเดิม: ไม่มีบรรทัดที่สองและไม่มีการเขียนข้อมูลสำรองที่สอง ชื่อการสำรองข้อมูลประกอบด้วยการประทับเวลา ลายนิ้วมือของไบต์ต้นทาง และ ID ที่สะอาด ดังนั้นความพยายามที่แยกจากกันจึงไม่สามารถแชร์ชื่อไฟล์เก่าหนึ่งวินาทีได้

<a id="local-regression-proof"></a>
## หลักฐานการถดถอยในเครื่อง

`tests/lua/enforcement_runtime_test.lua` บู๊ตตัวโหลดที่จัดส่งหนึ่งครั้ง จากนั้นดำเนินการปิด `append_ban()` จริงในเครื่องกับไฟล์สังเคราะห์ที่แยกออกมาด้านล่างไดเร็กทอรี `.tmp/` โดยครอบคลุมถึงการแทรก, การระบุตัวตนที่ซ้ำกัน, การปฏิเสธ moderator/trusted, การปฏิเสธข้อมูลประจำตัวที่อ่อนแอและผิดรูปแบบ, การตรวจสอบการสำรองข้อมูลแบบไบต์ตรง, การปฏิเสธการแก้ไขพร้อมกัน, การย้อนกลับได้สำเร็จหลังจากอ่านกลับล้มเหลว และการปฏิเสธที่จะเขียนทับการเปลี่ยนแปลงภายนอกหลังการเขียน wrappers ระบบไฟล์ของมันปฏิเสธการกลายพันธุ์ใด ๆ ภายนอกรูทฟิกซ์เจอร์ ไม่มีการใช้เส้นทางเซิร์ฟเวอร์จริงหรือ `Admin.ini` จริง

เรียกใช้ผ่าน `python tools/test_public_pipeline.py` บัตรผ่านประจำจะพิสูจน์พฤติกรรมการทำธุรกรรมในท้องถิ่นเท่านั้น มันไม่ได้เปิดใช้งานการบังคับใช้ อนุญาตการเขียนการผลิต หรือพิสูจน์สิทธิ์เฉพาะโฮสต์

<a id="rollback"></a>
## ย้อนกลับ

1. หยุดเซิร์ฟเวอร์
2. กู้คืนข้อมูลสำรอง Admin.ini ล่าสุดจาก `runtime/backups/`.
3. ลบข้อมูลที่ไม่ถูกต้อง `BannedPlayer=<ID>` บรรทัดหากจำเป็น
4. เริ่มการทำงานของเซิร์ฟเวอร์
5. เปิดใหม่ Admin.ini และยืนยันว่าบรรทัดยังคงอยู่หรือถูกลบออก
6. เก็บรักษา `enforced_bans.jsonl` สำหรับการตรวจสอบ
