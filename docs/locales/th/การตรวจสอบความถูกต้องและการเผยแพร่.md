# การตรวจสอบและการเผยแพร่

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [VALIDATION_AND_RELEASE.md](../../VALIDATION_AND_RELEASE.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


หน้านี้มีไว้สำหรับผู้มีส่วนร่วมและผู้ดูแลรุ่น ผู้ดำเนินการเซิร์ฟเวอร์ไม่จำเป็นต้องเรียกใช้คำสั่งเหล่านี้เพื่อติดตั้ง RandomDayGuard.

<a id="user-visible-proof"></a>
## หลักฐานที่ผู้ใช้มองเห็นได้

การเผยแพร่จะเข้าใจได้เมื่อผู้ดำเนินการรายใหม่สามารถติดตั้งได้ ค้นหารายงานสถานะเซิร์ฟเวอร์รายการแรก แยกเส้นทางรายงานทั้งห้าเส้นทาง และปฏิบัติตามการดำเนินการที่ชัดเจนหนึ่งรายการจากตัวอย่างที่ใช้งานได้ งานของผู้อ่านจะต้องไม่จำเป็นต้องมีความรู้ Git, PowerShell, Python หรือเช็คซัม

<a id="contributor-checks"></a>
## การตรวจสอบผู้ร่วมให้ข้อมูล

```powershell
python -B tools/validate_repo.py
python -B tools/test_public_pipeline.py
python -B -m unittest discover tests
```

เมื่อ `luac` พร้อมใช้งาน:

```powershell
luac -p RandomDayGuard/Scripts/main.lua
luac -p RandomDayGuard/Scripts/public_pipeline.lua
```

การทดสอบฟิกซ์เจอร์ Lua ครอบคลุมตัวโหลด ตัวกำหนดเวลา เส้นทางรายงาน และธุรกรรมการเขียน Admin.ini ที่เป็นทางเลือก ฟิกซ์เจอร์การบังคับใช้จะใช้ไฟล์ชั่วคราวเท่านั้นและตรวจสอบข้อมูลระบุตัวตน การปฏิเสธบัญชีที่เชื่อถือได้ เกณฑ์ การสำรองข้อมูล การปฏิเสธการเปลี่ยนแปลงที่เกิดขึ้นพร้อมกัน การอ่านกลับ และการย้อนกลับ

<a id="package-proof"></a>
## หลักฐานแพ็คเกจ

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

- เครื่องหมายเวอร์ชันทั้งหมดตรงกัน `VERSION`.
- เฉพาะเวอร์ชันปัจจุบันเท่านั้นที่มีอยู่ภายใต้ `releases/`.
- ไฟล์ ZIP มีไบต์ `RandomDayGuard/Scripts/main.lua` ตามรูปแบบบัญญัติ และไม่มีตัวโหลดตัวแปรตัวพิมพ์เล็ก
- ไม่รวมเอาต์พุตรันไทม์ การกำหนดค่าส่วนตัว ข้อมูลรับรอง เส้นทางในเครื่อง แคช และส่วนทดสอบ
- การกำหนดค่าสาธารณะยังคงตรวจสอบเท่านั้นโดยปิดใช้งานการบังคับใช้
- ตัวอย่างรายงานที่ทำงานทั้งห้ารายการยังคงสอดคล้องกับความเป็นเจ้าของเส้นทางและโปรแกรมทดสอบการเปิดตัว
- ZIP ตามรูปแบบบัญญัติที่กำหนดไว้และตรงกัน `CHECKSUMS.sha256`.
- ตรวจสอบลิงก์เอกสารในเครื่องทั้งหมดและหน้ารายการสถานที่ 27 หน้า

<a id="avoid-validation-environment-pitfalls"></a>
## หลีกเลี่ยงข้อผิดพลาดเกี่ยวกับสภาพแวดล้อมในการตรวจสอบ

- เรียกใช้การตรวจสอบการเขียนที่เก็บข้อมูลตามลำดับเพื่อหลีกเลี่ยงการโต้แย้งไฟล์ชั่วคราว
- บน Windows ให้ตรวจสอบชื่อสมาชิกที่เก็บถาวรหรือการสะกดเส้นทางที่แจกแจง แทนที่จะค้นหาไฟล์ที่ไม่คำนึงถึงตัวพิมพ์เล็กและตัวพิมพ์ใหญ่เมื่อตรวจสอบรายการที่ซ้ำกัน ตัวโหลด
- คำสั่ง `luac` หายไปหรือรันไทม์ Lua เป็นความสามารถที่ไม่พร้อมใช้งาน ไม่ใช่ผ่านไวยากรณ์หรือการทดสอบรันไทม์
- ฟิกซ์เจอร์จะพิสูจน์เฉพาะอินพุตตามแบบจำลองเท่านั้น ไม่ได้พิสูจน์ว่าเซิร์ฟเวอร์ที่ใช้งานจริงสร้างรายงานปัจจุบัน
- บันทึกการหมดเวลาของคำสั่งและเอาต์พุตบางส่วนแทนที่จะถือว่าเสร็จสมบูรณ์

<a id="repair-failed-repository-validation"></a>
## การซ่อมแซมการตรวจสอบความถูกต้องของพื้นที่เก็บข้อมูลที่ล้มเหลว

เริ่มต้นด้วยเส้นทางหรือสัญญาที่รายงานครั้งแรก แก้ไขรายการนั้น รันการทดสอบแบบแคบอีกครั้ง จากนั้นรันเมทริกซ์ที่สมบูรณ์อีกครั้ง อย่าซ่อนความสามารถที่ขาดหายไปโดยการลบการทดสอบที่จำเป็นต้องใช้ออก

<a id="known-limits-and-release-decision"></a>
## ขีดจำกัดที่ทราบและการตัดสินใจปล่อย

การตรวจสอบในท้องถิ่นพิสูจน์แหล่งที่มา การติดตั้ง แพ็คเกจ และสัญญาเอกสารประกอบ การติดตั้งเซิร์ฟเวอร์เฉพาะ หน้าต่างความเสถียรที่ทำงานเป็นเวลานาน หรือจอแสดงผลไคลเอนต์จำเป็นต้องมีผลการรวมที่แยกต่างหาก บันทึกผลลัพธ์นั้นด้วยการสร้าง การกำหนดค่า ระยะเวลา และเอาต์พุตที่สังเกตได้ก่อนที่จะทำการอ้างสิทธิ์ที่ตรงกัน
