# ขั้นตอนการตรวจสอบผู้เล่น

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [PLAYER_REVIEW_WORKFLOW.md](../../PLAYER_REVIEW_WORKFLOW.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


ใช้หน้านี้สำหรับผู้เล่น บัญชี หรือเคสเดียว จุดประสงค์คือการตัดสินใจทบทวนซ้ำ ไม่ใช่การกล่าวหาโดยอัตโนมัติ

<a id="quick-path"></a>
## เส้นทางด่วน

1. เปิด `runtime/final_logs/player_activity_latest.json`.
2. ยืนยันสถานะเส้นทางใน `runtime/final_logs/route_proof.json`.
3. ระบุว่าการสังเกตใดเป็นปัจจุบันและรายการใดเป็นประวัติ
4. ตรวจสอบข้อมูลประจำตัวที่อ้างถึงและการอ้างอิงแหล่งที่มาของเซสชัน
5. ตรวจสอบ `case_review_latest.json` เมื่อมีกรณีที่สัมพันธ์กัน
6. บันทึกสิ่งที่ไม่รู้จักและ `does_not_prove` ก่อนที่จะเลือกการดำเนินการ
7. ปล่อยให้การบังคับใช้ถูกปิดใช้งาน เว้นแต่จะมีการบังคับใช้แยกต่างหาก ประตูได้รับการพิสูจน์แล้ว

<a id="1-confirm-route-proof"></a>
## 1. ยืนยันการพิสูจน์เส้นทาง

ตีความเส้นทางของผู้เล่นเป็น:

| สถานะ | การดำเนินการ |
|---|---|
| `full` | ดำเนินการต่อโดยยังคงตรวจสอบขีดจำกัดของแหล่งที่มา |
| `limited_expected_empty` | ดำเนินการต่อเฉพาะกับหัวข้อที่มีอยู่จริงเท่านั้น อย่าสร้างผู้เล่นหรือเคสที่หายไป |
| `missing` | หยุดการตัดสินใจของผู้เล่นและแก้ไขปัญหาเส้นทาง |

ตัวกำหนดเวลาที่ดีไม่ได้แทนที่การพิสูจน์เส้นทาง

<a id="2-establish-identity"></a>
## 2. สร้างข้อมูลประจำตัว

ต้องการตัวระบุบัญชีที่ปลอดภัยซึ่งยืนยันโดยหลักฐานระบุตัวตนที่เปิดเผยโดยเซิร์ฟเวอร์ และหากมี PlayerData ชื่อไฟล์ เก็บการอ้างอิงแหล่งที่มาดิบ

อย่าบังคับใช้จาก:

- ชื่อที่แสดงเพียงอย่างเดียว
- ชื่อที่เห็นในการแจ้งเตือนหรือการโฮสต์แผง
- ความคล้ายคลึงกันของเวลา;
- ข้อมูลระบุตัวตนที่ไม่ได้แมปหรือมีความมั่นใจต่ำ
- รายงานเชิงประวัติที่ไม่มีการยืนยันในปัจจุบัน

<a id="3-separate-current-from-historical"></a>
## 3. แยกปัจจุบันออกจากประวัติ

หลักฐานปัจจุบันอธิบายหน้าต่างการรายงานที่ใช้งานอยู่หรือยุคของเซิร์ฟเวอร์ หลักฐานทางประวัติศาสตร์อาจอธิบายรูปแบบได้ แต่ไม่สามารถเติมเต็มช่องว่างในหน้าต่างปัจจุบันได้

บันทึกทั้งสองขอบเขตอย่างอิสระ:

```text
Current observations:
Current source references:
Historical context:
Historical source references:
```

<a id="4-review-observations-and-interpretation"></a>
## 4. ทบทวนข้อสังเกตและการตีความ

อ่านส่วนรายงานเหล่านี้อย่างชัดเจน:

```text
observed
interpretation
unknown
does_not_prove
next_action
source_references
```

เปิดหลักฐานที่มีโครงสร้างที่อ้างถึงอีกครั้งสำหรับการตัดสินใจที่มีสาระสำคัญ การแปลเป็นเพียงการนำทางและการอธิบาย ไม่ใช่หลักฐานใหม่

<a id="5-calibrate-the-decision"></a>
## 5. ปรับเทียบการตัดสินใจ

| การตัดสินใจ | ใช้เมื่อ |
|---|---|
| `INFO` | การสังเกตแบบปกติหรือแบบมีบริบทต่ำ |
| `WATCH` | การตรวจสอบสัญญาณอ่อนหรือไม่สมบูรณ์ |
| `REVIEW` | หลักฐานที่เกี่ยวข้องกันจำเป็นต้องได้รับการตัดสินจากผู้ดูแลระบบ |
| `BAN-ELIGIBLE` | ตรงตามเกณฑ์การระบุตัวตนที่สะอาดและหลักฐานที่กำหนดค่าไว้ เกตการเขียนยังคงมีผลอยู่ |
| `AUTO-BANNED` | เปิดใช้งานการบังคับใช้อย่างชัดเจน และสำรองข้อมูล เขียน อ่านกลับ และตรวจสอบได้สำเร็จทั้งหมด |

ไม่มีป้ายกำกับการตัดสินใจใดที่พิสูจน์ได้ว่ามีความผิดหรือเจตนา

<a id="6-apply-the-evidence-boundary"></a>
## 6. ใช้ขอบเขตหลักฐาน

ขัดข้อง เชื่อมต่อใหม่ คำเตือน object/class และการจัดกลุ่มกรณีและปัญหาสามารถรองรับการตรวจสอบได้ เพียงอย่างเดียว พวกเขาไม่ได้พิสูจน์ว่ามีการโกง การโจรกรรม การทำซ้ำ การเป็นเจ้าของ ความเสียหายโดยตรง หรือสาเหตุของเหตุการณ์

หากข้อมูลประจำตัว การแยกวิเคราะห์ การสำรองข้อมูล การเขียน การอ่านกลับ หรือการย้อนกลับอ่อนหรือล้มเหลว การบังคับใช้จะต้องล้มเหลวในการปิด
