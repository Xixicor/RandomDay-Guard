# สถาปัตยกรรมและวงจรชีวิต

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [ARCHITECTURE.md](../../ARCHITECTURE.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


RandomDayGuard เป็นหนึ่งรายการ UE4SS บวกกับโมดูลการรายงานที่แยกออกมาหนึ่งรายการ ไม่มีผู้ให้บริการ แผงควบคุม บริการแจ้งเตือน RandomDay หรือการพึ่งพาเครือข่าย

<a id="end-to-end-data-flow"></a>
## กระแสข้อมูลจากต้นทางถึงปลายทาง

1. UE4SS โหลดจุดเข้ามาตรฐานเดียว `RandomDayGuard/Scripts/main.lua`. แพ็คเกจปัจจุบันไม่จัดส่งตัวพิมพ์เล็ก-ตัวแปรที่ซ้ำกัน
2. ตัวโหลดอ่าน `config.lua` พจนานุกรมข้อมูลสามรายการ และตัวเลือก `SavedRoot.txt`. ข้อมูลระบุเวอร์ชันต้องสอดคล้องกับ `VERSION`, `MANIFEST.json` และ `BUILD_MARKER.txt`.
3. การตรวจสอบการค้นพบที่บันทึกไว้จะตรวจสอบขอบเขตผู้สมัครที่รู้จักและไฟล์ที่รู้จักโดยตรง มันบันทึกสิ่งที่อ่านได้ใน `runtime/saved_path_probe.json`; การค้นหาไดเร็กทอรีเพียงอย่างเดียวไม่ใช่หลักฐานที่ครอบคลุม
4. เลเยอร์ในทันทีจะติดตามบันทึกเซิร์ฟเวอร์ที่ใช้งานอยู่จากออฟเซ็ตที่ปลอดภัย โดยทำให้วงจรการใช้งาน เซสชัน บัญชี คำเตือน การเชื่อมต่อใหม่ และเหตุการณ์อื่นๆ ที่สังเกตได้เป็นปกติให้เป็นหลักฐานแบบผนวกเท่านั้นพร้อมสแนปช็อตปัจจุบัน
5. สินค้าคงเหลือในเลเยอร์ที่ช้า ไฟล์ที่บันทึกไว้ในชิ้นที่มีขอบเขต มันเขียนความคืบหน้าและจุดตรวจสอบ ทำงานที่ไม่สมบูรณ์ต่อ เปรียบเทียบไฟล์ Manifest ที่เปลี่ยนแปลง และสร้างบางส่วนจากนั้นเป็นขั้นสุดท้าย object/world บริบท
6. ตรรกะการตรวจสอบจะสัมพันธ์กับหลักฐานที่มีอยู่เท่านั้น ชื่อไฟล์ เวลา จำนวนคลาส พิกัดสัมพันธ์ การเลิกใช้งาน การขัดข้องครั้งเดียว หรือ ping ที่ไม่ชัดเจนจะยังคงอยู่ในบริบทและไม่สามารถอนุญาตการบังคับใช้เพียงอย่างเดียวได้
7. เจ้าหน้าที่รายงานแยกต่างหากเรียก `Scripts/public_pipeline.lua`. โดยจะจัดทำคลาสของแหล่งที่มา บันทึกขอบเขตปัจจุบันเทียบกับขอบเขตในอดีต ผูกวงจรไว้ที่ version/boot/epoch/poll/source ความใหม่ เขียนห้าเส้นทางเฉพาะ JSON/TXT จับคู่แล้วเขียน `route_proof.json`.
8. เมื่อเปิดใช้งานอย่างชัดเจน กล่องขาออกในเครื่องจะคัดลอกการอ้างอิงจากรายงานที่เสร็จสมบูรณ์หลังจากที่มีการพิสูจน์เส้นทางแล้ว มันบันทึก `delivery_backend="none"` และ `delivery_attempted=false`; การขนส่งอยู่นอกผลิตภัณฑ์นี้

<a id="ownership-and-asynchronous-boundaries"></a>
## ความเป็นเจ้าของและขอบเขตอะซิงโครนัส

| เจ้าของ | งานมีขอบเขต | ต้องไม่บล็อกหรือบอกเป็นนัย |
|---|---|---|
| เริ่มต้น | กำหนดค่า, Saved-root, active-log, ยุค, ดัชนี, สถานะเริ่มต้น | เครื่องหมายตัวโหลดที่ประสบความสำเร็จไม่ได้พิสูจน์หลักฐานหรือเส้นทาง |
| โทรกลับแบบสำรวจ | ไบต์บันทึกใหม่ อัปเดตสถานะ event/session/account เอาต์พุต การกำหนดเวลา | การค้นพบแบบเรียกซ้ำช้าหรือการระบายรายงาน |
| ผู้ปฏิบัติงานสแกน | การค้นพบอย่างชัดแจ้ง, การแยกวิเคราะห์ไฟล์, จุดตรวจสอบ partial/final พื้นฐาน | ความคืบหน้าของบันทึกปัจจุบัน; บางส่วนไม่ใช่ความล้มเหลว |
| รายงานผู้ปฏิบัติงาน | การบัญชีแหล่งที่มา การแปล คู่รายงาน การพิสูจน์เส้นทาง กล่องขาออกในเครื่อง | การบังคับใช้หรือการส่งมอบภายนอก |
| การบังคับใช้แบบเลือกได้ | ยืนยันบัญชีและคะแนน ปกป้องบัญชีที่เชื่อถือได้และรายการที่ซ้ำกัน ตรวจสอบการสำรองข้อมูล ปฏิเสธการเปลี่ยนแปลงไฟล์ภายนอก จากนั้นตรวจสอบผลลัพธ์ที่บันทึกไว้ | คะแนนรายงาน สถานะเส้นทาง หรือความเป็นสมาชิกของกรณีที่ข้ามการตรวจสอบความปลอดภัยที่จำเป็น |

ลูปการสำรวจความคิดเห็นจะยังคงมีสุขภาพที่ดีในขณะที่ `poll_id` ก้าวหน้าเท่านั้น `poll_in_flight` ส่งกลับค่า false และการตั้งเวลายังคงทำงานอยู่ นั่นพิสูจน์องค์ประกอบโพล ไม่ใช่ไปป์ไลน์รายงาน การสแกนช้าอาจเป็น `partial` หรือ `deferred`; ค่าเริ่มต้น `slow_world_scan_blocks_current_reports=false` ช่วยให้เส้นทางปัจจุบันใหม่ดำเนินต่อไปในขณะที่ตั้งชื่อข้อจำกัดในอดีต

<a id="state-and-lifecycle"></a>
## สถานะและวงจรชีวิต

| สถานะ | รายการ | เทอร์มินัลหรือสถานะถัดไป | ข้อผิดพลาดและการกู้คืน |
|---|---|---|---|
| เริ่มต้น | UE4SS เรียกใช้ตัวโหลด | การรัน poll/scan/report ผู้ปฏิบัติงานด้วย ID บูตและยุค | `startup_error` เป็นหลักฐานสำคัญในการบูตในปัจจุบัน ซ่อมแซม config/path/source และรีสตาร์ท |
| การสำรวจความคิดเห็นปัจจุบัน | การโทรกลับที่มีขอบเขตตามกำหนดเวลาจะเริ่มต้นขึ้น | การประทับเวลาบันทึกการสำรวจความคิดเห็นที่เสร็จสมบูรณ์และกำหนดเวลาใหม่ | `poll_error` เป็นหลักฐานสำคัญในการบูตในปัจจุบัน เรียกคืนการทำงานที่มีขอบเขตและยืนยันการสำรวจความคิดเห็นที่ใหม่กว่า |
| การสแกนที่รอดำเนินการ | พบจุดตรวจสอบพื้นฐานที่จำเป็นหรือไม่สมบูรณ์ | `partial`/`deferred` จากนั้น `scan_complete`. | ดำเนินการจุดตรวจสอบต่อ สร้างใหม่เฉพาะเมื่อมีการบันทึก stale/incompatible หลักฐาน |
| การบัญชีต้นทาง | ผู้ปฏิบัติงานรายงานสินค้าคงคลังแปดคลาสต้นทาง | `complete`, `complete_with_gaps`, `partial` หรือ `unavailable`. | Disabled/failed การบัญชีบังคับทุกเส้นทางไปยัง `missing`. |
| การสร้างเส้นทาง | วงจรปัจจุบัน มีบัญชีสายเลือดและแหล่งที่มา | `full`, `limited_expected_empty` หรือ `missing`. | จับคู่ JSON/TXT หรือความล้มเหลวในการเขียนพิสูจน์เส้นทางบรรจบกันเส้นทางไปยัง `missing`. |
| กล่องขาออกในเครื่อง | เส้นทางถูกเปิดใช้งาน เสร็จสมบูรณ์ และมีสิทธิ์ | รอดำเนินการเอนเวโลปในเครื่องและผลลัพธ์สถานะการแจ้งเตือน | การไม่มีการเขียนหรือการพิสูจน์ที่ไม่สมบูรณ์หมายความว่าไม่มีซองจดหมาย ไม่มีการส่งมอบที่อนุมาน |
| การตรวจสอบการบังคับใช้ | หลักฐานเฉพาะบัญชีถึงคะแนนที่กำหนดไว้สำหรับการดำเนินการอัตโนมัติ | คำแนะนำสำหรับการตรวจสอบเท่านั้นหรือการเปิดใช้งานอย่างชัดเจน `Admin.ini` การอัปเดต | การตรวจสอบความปลอดภัยที่ล้มเหลวหรือไม่พร้อมใช้งานจะหยุดการอัปเดต การเปรียบเทียบขั้นสุดท้ายที่ล้มเหลวจะคืนค่าการสำรองข้อมูลที่ตรวจสอบแล้วเมื่อเปิดใช้งานการกู้คืน |

<a id="current-and-historical-evidence"></a>
## หลักฐานปัจจุบันและในอดีต

หลักฐานปัจจุบันเป็นของ boot/poll ที่ใช้งานอยู่ และไม่เคยสร้างขึ้นใหม่จากชื่อไฟล์ที่เก็บไว้เพียงอย่างเดียว หลักฐานทางประวัติศาสตร์ประกอบด้วยบันทึกที่หมุนเวียน คงทน account/session ประวัติ เก็บรักษา cases/reports/evidence และการสแกนแบบมีขอบเขต รายงานเปิดเผยอาร์เรย์และการนับปัจจุบันและในอดีตแยกกัน การรีสตาร์ทแบบเงียบต้องไม่ลบบริบทที่คงทน และบันทึกประวัติจะต้องไม่แสดงเป็นสถานะปัจจุบัน

<a id="completion-and-recovery-boundary"></a>
## ขอบเขตการเสร็จสมบูรณ์และการกู้คืน

การเสร็จสิ้นสำหรับหนึ่งเส้นทางต้องใช้เวอร์ชันของวงจรปัจจุบันที่ตรงกัน, ID การบูต, ID ยุค, ID โพลเชิงบวก, สถานะบันทึกที่ใช้งานอยู่ใหม่, ทั้งเอาต์พุตเส้นทาง และรายการใน `route_proof.json` การอ้างสิทธิ์การแจ้งเตือนจำเป็นต้องมีซองจดหมายในเครื่องรอบเดียวกันเพิ่มเติม การจัดส่งภายนอกไม่เคยเป็นส่วนหนึ่งของการพิสูจน์สาธารณะ

หากรายงานขั้นสุดท้ายหายไปหรือเก่ากว่าสถานะ poll/source สถานะ ดำเนินการต่อจากเชื้อสายแรกที่ไม่ตรงกันหรือเขียนล้มเหลว อย่าเปลี่ยนเส้นทาง ข้อความ หรือการบังคับใช้ที่ไม่เกี่ยวข้อง ดู [`OUTPUT_SCHEMA_REFERENCE.md`](%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%AD%E0%B9%89%E0%B8%B2%E0%B8%87%E0%B8%AD%E0%B8%B4%E0%B8%87%E0%B8%AA%E0%B8%84%E0%B8%B5%E0%B8%A1%E0%B8%B2%E0%B9%80%E0%B8%AD%E0%B8%B2%E0%B8%97%E0%B9%8C%E0%B8%9E%E0%B8%B8%E0%B8%95.md), [`TROUBLESHOOTING.md`](%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B9%81%E0%B8%81%E0%B9%89%E0%B9%84%E0%B8%82%E0%B8%9B%E0%B8%B1%E0%B8%8D%E0%B8%AB%E0%B8%B2.md) และ [`SOURCE_MODULE_REFERENCE.md`](%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%AD%E0%B9%89%E0%B8%B2%E0%B8%87%E0%B8%AD%E0%B8%B4%E0%B8%87%E0%B9%82%E0%B8%A1%E0%B8%94%E0%B8%B9%E0%B8%A5%E0%B9%81%E0%B8%AB%E0%B8%A5%E0%B9%88%E0%B8%87%E0%B8%97%E0%B8%B5%E0%B9%88%E0%B8%A1%E0%B8%B2.md).
