# เริ่มต้นที่นี่: อ่านรายงาน Guard ฉบับแรก

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [START_HERE.md](../../START_HERE.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


คำแนะนำนี้เริ่มต้นหลังจาก RandomDayGuard ได้รับการติดตั้งและเปิดใช้งาน มันพิสูจน์ผลลัพธ์ที่เป็นประโยชน์อย่างหนึ่งโดยไม่ต้องขอให้ผู้ปฏิบัติงานรายใหม่ตรวจสอบซอร์สโค้ด ภายในแพ็คเกจ หรือไฟล์สถานะเฉพาะเครื่อง

<a id="what-happens-after-the-server-starts"></a>
## จะเกิดอะไรขึ้นหลังจากเซิร์ฟเวอร์เริ่มทำงาน

Guard จะรอเซิร์ฟเวอร์เกมและ UE4SS โหลด ค้นหาบันทึกที่มีอยู่ของเซิร์ฟเวอร์ และเริ่มการสแกนพื้นหลังแบบมีขอบเขต สามารถรายงานสภาพเซิร์ฟเวอร์ปัจจุบันในขณะที่ประวัติเก่ายังคงถูกจัดทำดัชนี

รายงานแรกควรเป็น **สถานะเซิร์ฟเวอร์** โดยจะตอบว่า Guard กำลังดำเนินการรอบการตรวจสอบให้เสร็จสิ้นในขณะนี้หรือไม่ เมื่อเซิร์ฟเวอร์ปัจจุบันเริ่มต้นขึ้นหากมีการประทับเวลานั้น active/rotated ครอบคลุมบันทึกและการสแกน จำนวนผู้เล่นที่เชื่อมต่อ กลุ่มแหล่งที่มาใดขาดหายไป และจำเป็นต้องดำเนินการกับผู้ปฏิบัติงานหรือไม่

การสแกนพื้นหลังที่ยังดำเนินอยู่ถือเป็นข้อจำกัดของความครอบคลุมในอดีต ไม่ใช่ความล้มเหลวในการเริ่มต้นโดยอัตโนมัติ Guard จะบันทึกเคอร์เซอร์การสแกน ไฟล์ที่เสร็จสมบูรณ์ ไฟล์ที่ค้นพบ และเวลาความคืบหน้าล่าสุด หากค่าเหล่านั้นหยุดการเปลี่ยนแปลงในรอบการตรวจสอบซ้ำ ให้ถือว่าเส้นทางประวัตินั้นหยุดนิ่งและปฏิบัติตามสาขาการสแกนในการแก้ไขปัญหา อย่าละทิ้งบันทึกและผลลัพธ์เซสชันปัจจุบันเพียงเพราะประวัติเก่าไม่สมบูรณ์

<a id="read-the-first-server-status-report"></a>
## อ่านรายงานสถานะเซิร์ฟเวอร์ฉบับแรก

1. เริ่มเซิร์ฟเวอร์เฉพาะตามปกติ
2. รอเซิร์ฟเวอร์เกมและ UE4SS เพื่อเริ่มต้นให้เสร็จสิ้น
3. เปิด RandomDayGuard's โฟลเดอร์รายงานขั้นสุดท้าย และเลือกรายงานสถานะเซิร์ฟเวอร์ใหม่ล่าสุดที่สามารถอ่านได้
4. ยืนยันรายงานที่มี:
   - **สรุป**
   - **สิ่งที่เจ้าหน้าที่เฝ้าสังเกต**
   - **มันหมายถึงอะไร**
   - **สิ่งที่ยังไม่ทราบ**
   - **แนะนำขั้นตอนต่อไป**
   - **บันทึกทางเทคนิค**
5. ใน **สิ่งที่เจ้าหน้าที่เฝ้าสังเกต** เท่าใด ยืนยันความก้าวหน้าของรอบการตรวจสอบล่าสุด และชื่อรายงานที่มี บันทึก การสแกน โปรแกรมเล่น และความครอบคลุมของแหล่งที่มา
6. หากขั้นตอนถัดไปบอกว่าไม่จำเป็นต้องมีการแทรกแซง ให้เก็บรายงานไว้เป็นผลลัพธ์แรกที่ประสบความสำเร็จ หากตั้งชื่อแหล่งที่มาที่ขาดหายไปหรือกระบวนการที่หยุดทำงาน ให้ปฏิบัติตามอาการดังกล่าวใน [การแก้ไขปัญหา](%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B9%81%E0%B8%81%E0%B9%89%E0%B9%84%E0%B8%82%E0%B8%9B%E0%B8%B1%E0%B8%8D%E0%B8%AB%E0%B8%B2.md).

รายงานอาจเชื่อมโยงกับหลักฐานทางเทคนิคเพื่อการตรวจสอบในเชิงลึก ผู้ปฏิบัติงานปกติสามารถอ่านรายงานก่อน และเปิดข้อมูลอ้างอิงเหล่านั้นเฉพาะเมื่อจำเป็นต้องตรวจสอบผลลัพธ์ธรรมดาเท่านั้น

<a id="understand-quiet-reports"></a>
## ทำความเข้าใจรายงานที่เงียบ

กิจกรรมของผู้เล่น การตรวจสอบกรณี และ Critical Guard เป็นไปตามเหตุการณ์ เซิร์ฟเวอร์แบบเงียบไม่ควรสร้างผู้เล่น กรณี หรือความล้มเหลวเพียงเพื่อเติมเต็มช่องเท่านั้น ผลลัพธ์ที่อ่านได้อาจบอกว่ามีการตรวจสอบแหล่งที่มาแล้วและไม่มีสิ่งใดอยู่ในรายงานนั้น

ภาพรวมรายวันแตกต่างออกไป โดยจะให้การตรวจสอบหนึ่งครั้งต่อวันของรายงานโดยใช้เซสชันวันเดียวกัน หัวข้อการตรวจสอบปัจจุบัน บริบท identity/case ที่เก็บไว้ ความคืบหน้าในการสแกน และช่องว่างของแหล่งที่มาที่ Guard สามารถอ่านได้จริง ข้อเท็จจริงที่ขาดหายไปจากบันทึกเซิร์ฟเวอร์ที่มีอยู่ยังคงไม่ทราบแน่ชัดแทนที่จะประมาณการ

<a id="test-one-ordinary-player-session"></a>
## ทดสอบเซสชันของผู้เล่นทั่วไปหนึ่งเซสชัน

หลังจากรายงานสถานะเซิร์ฟเวอร์แรกเป็นปัจจุบัน:

1. ให้ผู้เล่นที่รู้จักหนึ่งรายเข้าร่วมและออกจากตามปกติ
2. รอรอบการรายงานถัดไป
3. กิจกรรมเปิดผู้เล่น
4. ยืนยันว่าระบุบัญชีหรือชื่อที่แสดงที่ Guard ใช้งานได้ เวลาเข้าร่วมและออก ผลเซสชันที่สะอาดหรือไม่สมบูรณ์ ประวัติก่อนหน้าเมื่อพร้อมใช้งาน และการดำเนินการถัดไป

รายงานเซสชันควรมีข้อมูลที่สังเกตได้ ไม่ควรถูกแทนที่ด้วยรายการชื่อไฟล์หรือคำสั่งทั่วไปที่มีการบันทึกอยู่
