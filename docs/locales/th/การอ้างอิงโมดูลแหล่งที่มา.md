# การอ้างอิงโมดูลแหล่งที่มา

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [SOURCE_MODULE_REFERENCE.md](../../SOURCE_MODULE_REFERENCE.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


หน้านี้แมปทุกแหล่งที่มา การกำหนดค่า ข้อมูล ตัวโหลดความเข้ากันได้ และคลาสตัวยึดตำแหน่งรันไทม์ที่ยอมรับโดยรายการที่อนุญาตสำหรับการเผยแพร่ ดัชนีเครื่องคือ [`TRACEABILITY_INDEX.json`](../../TRACEABILITY_INDEX.json); หน้านี้เป็นคำอธิบายตามรูปแบบบัญญัติที่อ่านได้ แต่ละแถวของเครื่องที่สร้างขึ้นมีชื่อที่แตกต่างกันpath/class วัตถุประสงค์ การเป็นเจ้าของบล็อกต้นทาง การตั้งค่าสาธารณะ ผลข้างเคียง สถานะที่ผู้ปฏิบัติงานมองเห็นได้ ความล้มเหลว การกู้คืน และเอกสาร Canonical

<a id="ue4ss-loader-and-watchdog"></a>
## UE4SS ตัวโหลดและสุนัขเฝ้าบ้าน

`Scripts/main.lua` เป็นเจ้าของการเริ่มต้นของโปรแกรมเฝ้าระวังอิสระ, การค้นพบรูทที่บันทึกไว้, ส่วนท้ายของบันทึกปัจจุบัน, ยุคและเซสชันของเซิร์ฟเวอร์, การโพลและการสแกนแบบมีขอบเขต, object/world บริบท, การให้คะแนนการรีวิว `Admin.ini` ประตูนิรภัย, ผลลัพธ์การปฏิบัติงานแบบเดิม และแฮนด์ออฟของผู้ปฏิบัติงานรายงานที่แยกต่างหาก จะต้องรักษาขอบเขตการสำรวจสดในขณะที่งานประวัติศาสตร์ที่ช้าดำเนินการต่ออย่างอิสระ การเต้นของหัวใจ เครื่องหมายเริ่มต้น หรือการเพิ่มขึ้น `poll_id` พิสูจน์เฉพาะองค์ประกอบนั้นเท่านั้น การเสร็จสิ้นเส้นทางต้องใช้การบูตปัจจุบัน ยุค การหยั่งเสียง ความใหม่ของแหล่งที่มา คู่รายงาน และการพิสูจน์เส้นทางเดียวกัน

แหล่งที่มาและแพ็คเกจมีสิทธิ์เดียว: `RandomDayGuard/Scripts/main.lua` สำเนาตัวพิมพ์เล็ก `scripts/` ไม่ได้เป็นส่วนหนึ่งของแผนผังต้นทางหรือรีลีส การรักษาการสะกดแบบ Canonical ไว้หนึ่งแบบจะป้องกันการชนกันของตัวพิมพ์เล็กและตัวพิมพ์ใหญ่เมื่อแพ็กเกจถูกแยกบน Windows หรือ Linux

<a id="public-reporting-module"></a>
## โมดูลการรายงานสาธารณะ

`Scripts/public_pipeline.lua` ได้รับการติดต่อกลับแทนข้อมูลประจำตัวของโฮสต์หรืออะแดปเตอร์ของผู้ให้บริการ โดยจะจัดเก็บคลาสต้นทางแปดคลาส เทอร์มินัลบันทึกและสถานะที่ไม่สมบูรณ์ แยกผู้เล่นปัจจุบันออกจากประวัติที่เก็บไว้ แปลแต่ละเส้นทางตามลำดับ `Observed`, `Interpretation`, `Unknown`, `Does not prove`, `Next action` และ `Source references` จากนั้นเขียนการพิสูจน์เส้นทาง โหมดการแจ้งเตือนเสริมจะเขียน JSON ซองจดหมายเท่านั้น; ไม่เคยอ้างสิทธิ์ในการจัดส่งหรือรวมการจัดส่ง endpoint/bridge.

ฟิกซ์เจอร์ปฏิบัติการใน `tests/lua/public_pipeline_runtime_test.lua` โหลดโมดูลที่จัดส่งนี้ด้วย Lua พิสูจน์เส้นทางที่สมบูรณ์และว่างเปล่าที่คาดหวัง พิสูจน์ว่าวงจรแหล่งที่มาปัจจุบันที่ขาดหายไปล้มเหลวในการปิด และพิสูจน์ว่าเส้นทางที่ไม่สมบูรณ์ไม่ได้เข้าสู่กล่องขาออก

## เค้าโครงแพ็คเกจ

ตัวสร้างยอมรับเฉพาะไฟล์ทางกฎหมายหลักสามไฟล์เท่านั้น `RandomDayGuard/` เส้นทางด้านบน และตัวยึดตำแหน่งรันไทม์ว่างเปล่า มันสั่งสมาชิกตามไบต์ แก้ไข ZIP ทำแพ็กเกจ Canonical Loader หนึ่งครั้ง สแกนสมาชิกทุกคนเพื่อหาเนื้อหาส่วนตัว บันทึก SHA-256 สำหรับสมาชิกทุกคน ผูกชื่อและไบต์เป็นเนื้อหาย่อยเดียว และสร้างสองครั้ง การทดสอบปฏิเสธการชนกันของ case-fold ทุกกรณี และพิสูจน์ว่าการแยกแบบปกติจะสร้างไฟล์จริงหนึ่งไฟล์ต่อรายการเก็บถาวร

พื้นที่เก็บข้อมูลสาธารณะจะเก็บเฉพาะโฟลเดอร์ที่เผยแพร่ในปัจจุบันเท่านั้น ตัวสร้างตรวจสอบว่า ZIP, เช็คซัม, บันทึก, เครื่องหมายเวอร์ชัน และแผนผังแหล่งที่มาสอดคล้องกัน

## สัญญาความคิดเห็นเกี่ยวกับโค้ด

ความคิดเห็นรันไทม์เป็นสัญญาผู้ดูแลที่กระชับ ไม่ใช่คู่มือฉบับที่สอง โมดูลรันไทม์ที่จัดส่งแต่ละโมดูลจะต้องวางลิงก์ Canonical หนึ่งลิงก์ในบล็อกความคิดเห็นที่กำลังเปิด:

```lua
-- Documentation: docs/SOURCE_MODULE_REFERENCE.md#ue4ss-loader-and-watchdog
```

สถานะที่ไม่ชัดเจน, การกำหนดเวลา, write/readback/rollback, การค้นพบแหล่งที่มา, การแปล, หลักฐาน, สคีมาเอาต์พุต, จังหวะเส้นทาง และบล็อกการแก้ไข ใช้ความคิดเห็นที่เน้นด้วยป้ายกำกับเหล่านี้ตามความเหมาะสม:

```lua
-- Public contract: <invariant or consequence>
-- Evidence boundary: <what the input cannot prove>
-- Failure behavior: <how the block fails closed or recovers>
-- Documentation: docs/<canonical-file>.md#<existing-anchor>
```

ตัวโหลดหลักยังมีความคิดเห็นของเจ้าของที่เน้นหนึ่งรายการสำหรับการโหลดการกำหนดค่า การค้นพบที่บันทึกไว้ การทดแทนอะตอม การบังคับใช้ และกำหนดเวลา ความคิดเห็นเหล่านี้ระบุขอบเขตการควบคุมและความล้มเหลว โดยจะไม่เปลี่ยนพฤติกรรมรันไทม์

เครื่องมือตรวจสอบความถูกต้องต้องการลิงก์ระดับโมดูล `Documentation:` สำหรับแต่ละโมดูลรันไทม์ แก้ไขทุกเส้นทางความคิดเห็นและจุดยึด ต้องการสัญญาที่มุ่งเน้นและความคิดเห็นที่ล้มเหลวในทั้งสองโมดูลรันไทม์ และเปรียบเทียบลิงก์ Canonical เดียวกันกับ `TRACEABILITY_INDEX.json` ความคิดเห็นคือความสามารถในการตรวจสอบย้อนกลับ ไม่ใช่การพิสูจน์รันไทม์

## รายการตรวจสอบการเปลี่ยนแปลงผู้ร่วมให้ข้อมูล

1. อัปเดตโมดูลที่เป็นเจ้าของหนึ่งโมดูลและฟิกซ์เจอร์ที่มุ่งเน้น
2. อัปเดตการกำหนดค่า Canonical สคีมา เอาต์พุต หลักฐาน หรือส่วนวงจรการใช้งาน
3. เรียกใช้ `python -B tools/generate_documentation_audit.py --write` หลังจากการกำหนดค่าที่จัดทำแพ็กเกจแล้ว เส้นทาง คลาสเอาต์พุตที่สร้างขึ้น เจ้าของ หรือการเปลี่ยนแปลงสัญญาการกู้คืน
4. เรียกใช้ `python -B tools/generate_documentation_audit.py --check`, การทดสอบหน่วยที่เน้น, โปรแกรมติดตั้ง Lua จริงที่ Lua พร้อมใช้งาน, เครื่องมือตรวจสอบความถูกต้องเต็มรูปแบบ, บิลด์ที่กำหนดขึ้นอย่างอิสระสองรายการ และ `git diff --check`.
5. ตรวจสอบรายชื่อสมาชิก ZIP ที่สร้างขึ้น เช็คซัม และการสแกนเนื้อหาส่วนตัวก่อนสร้างรีลีส
