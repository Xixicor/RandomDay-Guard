<a id="evidence-boundary"></a>
# ขอบเขตหลักฐาน

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [EVIDENCE_BOUNDARY.md](../../EVIDENCE_BOUNDARY.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


ใช้หน้านี้เพื่อตัดสินใจว่าอะไร RandomDayGuard สามารถรายงานและสิ่งที่ยังต้องมีการตรวจสอบโดยเจ้าหน้าที่

<a id="core-rule"></a>
## กฎหลัก

RandomDayGuard บันทึกการสังเกตที่มีขอบเขตจากไฟล์ที่เซิร์ฟเวอร์เป็นเจ้าของ โดยจะต้องระบุแหล่งที่มา ขอบเขต สถานะการรวบรวม และขีดจำกัดสำหรับข้อสรุปของเนื้อหาทั้งหมด

หลักฐานที่มีโครงสร้างเชื่อถือได้ รายงานที่แปลจะอธิบายหลักฐาน ไม่สามารถเพิ่มข้อเท็จจริงที่ขาดหายไปจากบันทึกที่มีโครงสร้างได้

<a id="evidence-source-classes"></a>
## คลาสแหล่งที่มาของหลักฐาน

| คลาสแหล่งที่มา | การใช้งานทั่วไป | ไม่ได้พิสูจน์ด้วยตัวเอง |
|---|---|---|
| `admin_ini` | สถานะการดูแลระบบที่มีอยู่และตรวจสอบแล้ว write/readback บริบท | ใครเป็นสาเหตุของ เหตุการณ์ |
| `active_log` | เหตุการณ์ server/session ปัจจุบันที่มองเห็นได้ในบันทึกที่ใช้งานอยู่ | เจตนา ความเป็นเจ้าของ หรือความเสียหายโดยตรง |
| `recent_backup_logs` | บริบทบันทึกประวัติ | เหตุการณ์ปัจจุบันเกิดขึ้น |
| `playerdata_filenames` | การยืนยันว่ามีตัวระบุบัญชีที่สะอาดอยู่ | พฤติกรรม ความรู้สึกผิด หรือการเป็นเจ้าของข้อมูลประจำตัวที่อยู่นอกเหนือตัวระบุที่ถูกเปิดเผย |
| `existing_cases` | บริบทการตรวจสอบก่อนหน้า | การตีความก่อนหน้านี้ยังคงถูกต้อง |
| `existing_reports` | บทสรุปและการตัดสินใจก่อนหน้านี้ | ความจริงปัจจุบันที่ไม่มีการยืนยันในปัจจุบัน |
| `existing_evidence` | มีโครงสร้างทางประวัติศาสตร์ หลักฐาน | กิจกรรมปัจจุบัน |
| การสแกนบันทึกโลกแบบมีขอบเขต | ช้า world/class บริบท | การกระทำของผู้เล่น ความเป็นเจ้าของ การโจรกรรม การทำซ้ำ หรือความเสียหาย |

แต่ละแหล่งข้อมูลบันทึก availability/readability จำนวนไฟล์ การอ้างอิงแหล่งที่มา ขอบเขตปัจจุบันหรือประวัติ และคำสั่ง `does_not_prove` ที่ชัดเจน

<a id="source-states"></a>
## สถานะแหล่งที่มา

| สถานะ | ความหมายของตัวดำเนินการ |
|---|---|
| `available` | แหล่งที่มาสามารถอ่านได้และมีการรวบรวมหลักฐาน |
| `expected_empty` | แหล่งที่มาสามารถอ่านได้และถูกต้องตามกฎหมายไม่มีบันทึกที่ตรงกัน |
| `partial` | หลักฐานบางส่วนได้รับการรวบรวม; ความครอบคลุมไม่สมบูรณ์ |
| `deferred` | งานที่ถูกผูกไว้ถูกเลื่อนออกไปโดยเจตนา |
| `unavailable` | แหล่งที่มาไม่มีอยู่ในสภาพแวดล้อมนี้ |
| `malformed` | มีแหล่งที่มาอยู่แต่ไม่สามารถแยกวิเคราะห์ได้อย่างปลอดภัย |
| `permission_denied` | โปรแกรมเฝ้าระวังขาดสิทธิ์ในการอ่าน |
| `error` | การรวบรวมล้มเหลวด้วยเหตุผลอื่นที่บันทึกไว้ |

คาดว่าจะว่างเปล่าเป็นการสังเกตที่ถูกต้อง จะต้องไม่ถูกแปลงเป็นผู้เล่น กรณี เหตุการณ์ หรือการกล่าวหา

<a id="current-versus-historical-evidence"></a>
## หลักฐานปัจจุบันเทียบกับหลักฐานทางประวัติศาสตร์

หลักฐานปัจจุบันเป็นของหน้าต่างการรวบรวมหรือยุคเซิร์ฟเวอร์ที่ใช้งานอยู่ หลักฐานทางประวัติศาสตร์มาจากบันทึก กรณี รายงาน บันทึกหลักฐาน ข้อมูลสำรอง หรือข้อมูลพื้นฐานก่อนหน้านี้

หลักฐานทางประวัติศาสตร์สามารถให้บริบทได้ ไม่สามารถเติมเต็มช่องว่างหลักฐานในปัจจุบันได้อย่างเงียบๆ รายงานจะต้องติดป้ายกำกับทั้งสองขอบเขตและอ้างอิงแหล่งที่มาแยกกัน

<a id="corroboration-rule"></a>
## กฎการยืนยัน

สิ่งเหล่านี้เป็นบริบทที่มีประโยชน์ แต่ไม่สามารถพิสูจน์ได้โดยตรง:

- แสดงชื่อหรือความคล้ายคลึงกันของชื่อ
- ความบังเอิญตามเวลา
- ยกเลิกการเชื่อมต่อหรือเชื่อมต่อใหม่ การเลิกใช้งาน
- ข้อขัดข้องหนึ่งครั้งหรือคำเตือนระเบิด
- คลาส เส้นทาง นักแสดง แผนที่ หรือโทเค็นการนับวัตถุ
- การเป็นสมาชิกในกรณีที่จัดกลุ่มโดยอัตโนมัติ
- รายงานก่อนหน้าโดยไม่มีการยืนยันแหล่งที่มาในปัจจุบัน

อย่าอ้างสิทธิ์ ความรู้สึกผิด เจตนา การโกง ความเป็นเจ้าของ การโจรกรรม การทำซ้ำ ความเสียหายโดยตรง การใช้คอนเทนเนอร์โดยตรง การดำเนินการสินค้าคงคลังโดยตรง พิกัดปัจจุบันที่แน่นอน การปิงแบบเรียลไทม์ หรือพฤติกรรมระดับหน่วยความจำโดยไม่มีหลักฐานที่เปิดเผยข้อเท็จจริงโดยตรง

<a id="truthful-report-language"></a>
## ภาษารายงานที่เป็นจริง

ใช้:

```text
Observed: the account was active in the recorded crash window.
Interpretation: repeated overlap warrants operator review.
Unknown: the cause of the crash.
Does not prove: that the account caused the crash.
Next action: compare the cited current session and lifecycle records.
```

หลีกเลี่ยง:

```text
The player crashed the server.
The player stole or duplicated items.
The world token proves who used the object.
```

<a id="report-reading-order"></a>
## รายงานลำดับการอ่าน

รายงานที่เปิดเผยต่อสาธารณะทุกฉบับควรอธิบาย:

1. ความหมายธรรมดา
2. เหตุใดจึงสำคัญ
3. หลักฐานทางเทคนิคและการอ้างอิงแหล่งที่มา
4. การดำเนินการถัดไป
5. ขีดจำกัด สิ่งที่ไม่รู้จัก และการอ้างสิทธิ์ไม่ได้รับการพิสูจน์
