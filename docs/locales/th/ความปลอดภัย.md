# นโยบายความปลอดภัย

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [SECURITY.md](../../../SECURITY.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


<a id="report-a-vulnerability-privately"></a>
## รายงานช่องโหว่แบบส่วนตัว

ใช้ [GitHub การรายงานช่องโหว่ส่วนตัว](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) เพื่อส่งรายงานที่เป็นความลับไปยังเจ้าของพื้นที่เก็บข้อมูล หากไม่มีแบบฟอร์มนั้น ให้ใช้โปรไฟล์ [สาธารณะของเจ้าของ GitHub](https://github.com/Xixicor) เพื่อขอช่องทางการติดต่อส่วนตัวโดยไม่รวมถึงรายละเอียดช่องโหว่

อย่าเปิดปัญหาสาธารณะที่มีขั้นตอนการใช้ประโยชน์ ข้อมูลประจำตัว เส้นทางเซิร์ฟเวอร์ส่วนตัว ตัวระบุผู้เล่น `Admin.ini` ข้อมูลที่บันทึกไว้ URL ของ webhook หรือไฟล์หลักฐานที่ใช้งานอยู่

<a id="include-useful-evidence"></a>
## รวมหลักฐานที่เป็นประโยชน์

จัดเตรียม:

- เวอร์ชันหรือคอมมิต RandomDayGuard ที่ได้รับผลกระทบ
- ส่วนประกอบที่ได้รับผลกระทบและพฤติกรรมที่ปลอดภัยที่คาดหวัง
- ขั้นตอนการทำซ้ำขั้นต่ำโดยใช้อุปกรณ์ติดตั้งที่ผ่านการฆ่าเชื้อ
- ผลกระทบที่สังเกตได้และไม่ว่าจะสามารถทำซ้ำได้หรือไม่ และ
- การบรรเทาผลกระทบใด ๆ ที่เสนอซึ่งไม่เปิดเผยข้อมูลส่วนตัว

อย่าส่งความลับที่แท้จริง แทนที่เส้นทางส่วนตัว ตัวระบุบัญชี ชื่อโฮสต์ และโทเค็นด้วยตัวยึดตำแหน่งที่ชัดเจน ขณะเดียวกันก็รักษาโครงสร้างที่จำเป็นในการเกิดปัญหา

<a id="expect-review-first-handling"></a>
## คาดว่าจะได้รับการจัดการก่อนการตรวจสอบ

รายงานเป็นหลักฐานสำหรับการตรวจสอบของผู้ดูแล ไม่ใช่การอนุญาตให้เข้าถึงเซิร์ฟเวอร์ ทดสอบเป้าหมายที่ใช้งานจริง เผยแพร่รายละเอียดการหาประโยชน์ หรือลดค่าเริ่มต้นที่ปิดเมื่อล้มเหลว เจ้าของจะตรวจสอบขอบเขตและประสานงานการเปิดเผยใด ๆ ผ่านทางรายงานส่วนตัว
