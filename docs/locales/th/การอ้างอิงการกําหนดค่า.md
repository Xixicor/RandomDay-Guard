<a id="configuration-concepts"></a>
# แนวคิดการกำหนดค่า

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [CONFIG_REFERENCE.md](../../CONFIG_REFERENCE.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


คำอธิบายนี้อธิบายถึงสิ่งที่แต่ละพื้นที่การกำหนดค่าหลักควบคุม เวลาที่เรียกใช้ และวิธีที่พื้นที่โต้ตอบกับหลักฐานและประตูนิรภัย ไม่ได้เป็นเจ้าของแค็ตตาล็อกฟิลด์หรือขั้นตอนโปรไฟล์ที่แน่นอน

สำหรับการตั้งค่าล่วงหน้าตามงานและขั้นตอนการเปลี่ยนแปลงที่ปลอดภัย ให้ใช้ [`CONFIG_PROFILES.md`](%E0%B9%82%E0%B8%9B%E0%B8%A3%E0%B9%84%E0%B8%9F%E0%B8%A5%E0%B9%8C%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%81%E0%B9%8D%E0%B8%B2%E0%B8%AB%E0%B8%99%E0%B8%94%E0%B8%84%E0%B9%88%E0%B8%B2.md). สำหรับทุกฟิลด์แหล่งที่มา ค่าเริ่มต้น ประเภท ค่าคงที่ เอฟเฟกต์เอาต์พุต และกฎการกู้คืน ให้ใช้ [`CONFIG_FIELD_CATALOG.md`](%E0%B9%81%E0%B8%84%E0%B9%87%E0%B8%95%E0%B8%95%E0%B8%B2%E0%B8%A5%E0%B9%87%E0%B8%AD%E0%B8%81%E0%B8%9F%E0%B8%B4%E0%B8%A5%E0%B8%94%E0%B9%8C%E0%B8%81%E0%B9%8D%E0%B8%B2%E0%B8%AB%E0%B8%99%E0%B8%94%E0%B8%84%E0%B9%88%E0%B8%B2.md); เครื่องมือตรวจสอบต้องมีหนึ่งแถวสำหรับการจัดส่งทุกครั้ง`config.lua` ฟิลด์ใบไม้ที่จัดส่ง

<a id="top-level-safety"></a>
## ความปลอดภัยระดับสูงสุด

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
|---|---:|---|
| `enabled` | `true` | สวิตช์หลักสำหรับการ์ด |
| `enforcement.review_only_mode` | `true` | Record/recommend เท่านั้น |
| `enforcement.auto_ban` | `false` | อย่าแบนโดยอัตโนมัติตามค่าเริ่มต้น |
| `enforcement.write_admin_ini` | `false` | อย่าเขียน Admin.ini ตามค่าเริ่มต้น |

เก็บสิ่งเหล่านี้ไว้อย่างปลอดภัยจนกว่าเจ้าของเซิร์ฟเวอร์จะตรวจสอบเอาต์พุตแล้ว

<a id="saved"></a>
## `saved`

ควบคุมวิธีที่ยามค้นหาโฟลเดอร์เซิร์ฟเวอร์ `Saved/` และตระกูลไฟล์ที่สามารถสแกนได้

ใช้เมื่อ:

```text
Saved root auto-detection fails.
World folder changed.
Provider or container path is unusual.
```

ตรวจสอบ:

```text
runtime/saved_path_probe.json
RandomDayGuard/SavedRoot.txt
```

กฎ:

```text
SavedRoot.txt -> AbioticFactor/Saved
not -> Worlds/<WorldName>
```

<a id="log_tail"></a>
## `log_tail`

ควบคุมการอ่านบันทึกแบบเรียลไทม์

ตัวเลือกที่มีประโยชน์:

| ตัวเลือก | ค่าที่ปลอดภัย | เหตุใด |
|---|---|---|
| `enabled` | `true` | จำเป็นสำหรับการป้องกันแบบเรียลไทม์ |
| `start_at_end_on_first_run` | `true` | หลีกเลี่ยงบันทึกเก่าเนื่องจาก กิจกรรมสด |
| `tail_backup_logs` | `false` | บันทึกการสำรองข้อมูลเป็นประวัติ ไม่ใช่ |
| `max_lines_per_poll` | มีขอบเขต | ช่วยให้การสำรวจความคิดเห็นวนซ้ำตอบสนอง |

ตรวจสอบ:

```text
runtime/log_offsets.tsv
runtime/evidence/session_events.jsonl
runtime/current/poll_status.json
```

<a id="runtime"></a>
## `runtime`

ควบคุมการสำรวจและงบประมาณ

กฎสุขภาพหลัก:

```text
poll_id increases
poll_in_flight returns false
poll_scheduled is true
```

ตรวจสอบ:

```text
runtime/current/poll_status.json
```

หาก `poll_id` หยุด มีบางอย่างกำลังขัดขวางการวนซ้ำ

<a id="source_accounting"></a>
## `source_accounting`

ควบคุมความครอบคลุมและขอบเขตของแหล่งที่มาของหลักฐานที่ชัดเจน

| คีย์ | ค่าเริ่มต้น | ความหมาย |
|---|---:|---|
| `enabled` | `true` | เขียนการบัญชีแหล่งที่มาสำหรับรายงานเส้นทางสาธารณะ |
| `require_terminal_status` | `true` | กำหนดให้แต่ละแหล่งต้องเปิดเผยเทอร์มินัลที่ชัดเจนหรือสถานะที่ไม่สมบูรณ์ |
| `distinguish_current_from_historical` | `true` | แยกหลักฐานปัจจุบันและหลักฐานทางประวัติศาสตร์ออกจากกัน |
| `slow_world_scan_blocks_current_reports` | `false` | อนุญาตให้รายงานปัจจุบันระบุว่าการสแกนโลกที่มีขอบเขตถูกเลื่อนออกไปหรือบางส่วน |
| `changed_file_manifest` | เส้นทางรายการพื้นฐาน | ข้อมูลอ้างอิงที่ใช้สำหรับการบัญชี historical/world ที่มีขอบเขต |

สถานะแหล่งที่มาคือ `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied` หรือ `error`.

การตั้งค่า `source_accounting.enabled = false` จะไม่ลบสถานะเอาต์พุตอย่างเงียบ ๆ ไปป์ไลน์ยังคงเขียน `runtime/final_logs/source_accounting_latest.json` ด้วย `enabled=false`, `status="unavailable"` และ `disabled_reason="source_accounting_disabled"`. นอกจากนี้ยังเขียนบันทึกสถานะในอดีตโดยไม่มีการบัญชีที่ไม่พร้อมใช้งาน เนื่องจากการบัญชีต้นทางเป็นส่วนหนึ่งของสัญญารายงาน ทุกเส้นทางจึงไม่สามารถปิดไปยัง `missing`; ไม่มีเส้นทางใดที่จะถือว่าเสร็จสมบูรณ์ในขณะที่การบัญชีถูกปิดใช้งาน

<a id="reports"></a>
## `reports`

ควบคุมไปป์ไลน์การรายงานในพื้นที่ทั่วไป

ค่าเริ่มต้นเปิดใช้งานทั้งห้าเส้นทางและเขียนภายใต้ `runtime/final_logs`:

```text
server_status
daily_rollup
player_activity
case_review
critical_guard
```

แต่ละเส้นทางจะต้องเขียนเอาต์พุตที่มีโครงสร้างและแปลแล้ว พร้อมการพิสูจน์ใน `route_proof.json`. การปิดใช้งานเส้นทางจะสร้าง `missing` พิสูจน์แทนที่จะแสร้งทำเป็นว่ามันเสร็จสมบูรณ์

<a id="notification"></a>
## `notification`

กล่องขาออกไฟล์ภายในเครื่องทั่วไปที่เป็นตัวเลือก มันถูกปิดใช้งานโดยค่าเริ่มต้นและไม่ส่งอะไรเลยไปยังผู้ให้บริการภายนอก

ค่าเริ่มต้น:

```lua
notification = {
    enabled = false,
    mode = "local_file_outbox",
    include_expected_empty = false,
},
```

ทุกเส้นทางการแจ้งเตือนจะถูกปิดใช้งานตามค่าเริ่มต้น เมื่อเปิดใช้งานโดยเจตนา กล่องขาออกอาจใช้เฉพาะรายงานที่แปลเสร็จแล้วหลังจาก `route_proof.json` ถูกเขียน หลักฐานและรายงานในท้องถิ่นยังคงเชื่อถือได้ การจัดส่งเฉพาะผู้ให้บริการ ปลายทางการจัดส่ง ข้อมูลรับรอง และบริดจ์ไม่ได้เป็นส่วนหนึ่งของสัญญาเฝ้าระวังอิสระสาธารณะ

<a id="scanning"></a>
## `scanning`

ควบคุมการสแกนพื้นฐาน จุดตรวจสอบ และการรีเฟรชไฟล์ที่เปลี่ยนแปลง

ใช้เมื่อ:

```text
building first world baseline
resuming after crash
refreshing changed files later
```

ตรวจสอบ:

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/baselines/file_manifest.tsv
```

การตั้งค่าที่สำคัญ:

```lua
scanning = {
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
    changed_file_detection = true,
},
```

<a id="forensic_rollup"></a>
## `forensic_rollup`

ควบคุมแพ็คเกจการอัปโหลดรายวันอย่างรวดเร็วและบันทึกภาษาธรรมดาขั้นสุดท้าย

ผลลัพธ์:

```text
runtime/current/forensic_today.json
runtime/current/forensic_today.md
runtime/current/forensic_today.txt
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

ใช้เมื่อ:

```text
You want one daily folder that summarizes what happened.
You want a plain-language TXT to upload for quick analysis.
```

ตรวจสอบ:

```text
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

กฎ:

```text
Daily summaries are rebuildable indexes.
Source evidence remains authoritative.
```

<a id="logging"></a>
## `logging`

ควบคุมปริมาณเหตุการณ์และการรวมกลุ่มที่มีความสำคัญต่ำ

ใช้เมื่อ:

```text
actor-touch events are noisy
raw event files grow too quickly
```

รูปแบบที่ปลอดภัย:

```lua
logging = {
    low_importance_mode = "aggregate",
    write_low_importance_raw_events = false,
},
```

<a id="retention"></a>
## `retention`

ควบคุมระยะเวลาที่จะเก็บไฟล์และเมื่อใด JSONL หมุนเวียนบันทึก

ใช้เมื่อ:

```text
disk usage grows too fast
you need more audit history
you need shorter live-history windows
```

ตัวเลือกที่สำคัญ:

```text
detailed_retention_days
rotate_jsonl_when_bytes_exceed
max_raw_events_lines
keep_enforced_forever
keep_evidence_forever
```

<a id="warning_bursts"></a>
## `warning_bursts`

ควบคุมการตรวจจับหน้าต่างคำเตือน

ตัวอย่าง:

```text
ActorChannelFailure
DeployableSaveWarning
UpdateActorToWorldSave
ServerMove warnings
```

กฎ:

```text
Warnings are context until correlated with mapped sessions and thresholds.
```

<a id="crash_correlation"></a>
## `crash_correlation`

การควบคุมซ้ำ crash/reconnect ทบทวน

ค่าเริ่มต้นที่ปลอดภัย:

```lua
crash_correlation = {
    single_crash_never_bans = true,
    require_same_account = true,
},
```

ตัวนับที่มีประโยชน์:

```text
server_crash_overlap_count
post_crash_reconnect_count
unclean_disconnect_count
```

<a id="join_leave"></a>
## `join_leave`

ควบคุมการติดตามการปั่นป่วนและการรวมคลื่น

ค่าเริ่มต้นที่ปลอดภัย:

```lua
join_leave = {
    churn_alone_never_bans = true,
},
```

ใช้สำหรับ:

```text
rapid reconnect loops
join waves
short-session patterns
```

<a id="raid_detection"></a>
## `raid_detection`

บัญชีกลุ่มที่ใช้งานอยู่ในหน้าต่างที่เกี่ยวข้อง

กฎ:

```text
A raid case groups accounts for review.
It does not make every account guilty.
```

บัญชีที่บังคับใช้แต่ละบัญชียังคงต้องการหลักฐานเฉพาะบัญชี

<a id="object_registry"></a>
## `object_registry`

ควบคุม object/class การแยกโทเค็นจากหลักฐานที่บันทึกไว้ที่อ่านได้

ผลลัพธ์:

```text
runtime/object_registry_partial.json
runtime/object_registry.json
runtime/object_registry_counts.tsv
```

กฎ:

```text
Object/class context is not a ban reason by itself.
```

<a id="world_state"></a>
## `world_state`

ควบคุม boot/current/session สแนปชอตสถานะโลก

ผลลัพธ์:

```text
runtime/world_state/current/world_state_latest.json
runtime/world_state/sessions/<date>/<session_id>_<account_id>/
```

ใช้สำหรับการตรวจสอบเซสชันและบริบทโลก

<a id="enforcement"></a>
## `enforcement`

ควบคุมคำแนะนำและการเขียน Admin.ini จริง

ก่อนที่ Guard จะเพิ่มการแบน ทุกข้อความด้านล่างจะต้องเป็นจริง:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
account identity is mapped
not trusted
not moderator
threshold is met
```

หากข้อความใดข้อความหนึ่งเป็นเท็จหรือไม่สามารถตรวจสอบได้ Guard จะปล่อย `Admin.ini` ไม่เปลี่ยนแปลงและบันทึกเหตุผล

<a id="admin_ini"></a>
## `admin_ini`

ควบคุมอย่างปลอดภัย เขียนไฟล์

กฎ:

```text
Back up before writing.
Preserve existing bans.
Preserve moderators.
Write clean BannedPlayer=<ID> only.
```

<a id="restart_request"></a>
## `restart_request`

ควบคุมไฟล์มาร์กเกอร์โลคัลเสริมที่กระบวนการอื่นที่เป็นเจ้าของอาจตรวจสอบ ไม่รีสตาร์ทหรือปิดเซิร์ฟเวอร์

ค่าเริ่มต้น:

```lua
restart_request = {
    enabled = false,
    restart_marker_file = "runtime/request_restart.flag",
    restart_reason_file = "runtime/restart_reason.json",
},
```

ผลลัพธ์:

```text
runtime/request_restart.flag
runtime/restart_reason.json
```

ไม่มีแผงการโฮสต์ บริดจ์ของผู้ให้บริการ หรือการรีสตาร์ทอัตโนมัติรวมอยู่ด้วย การเปิดใช้งานการสร้างมาร์กเกอร์ไม่ได้พิสูจน์ว่ากระบวนการภายนอกใช้คำขอหรือรีสตาร์ทเซิร์ฟเวอร์
