# รูปแบบและความยืดหยุ่นของผู้ดำเนินการที่ไม่ดี

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [BAD_ACTOR_PATTERNS_AND_RESILIENCE.md](../../BAD_ACTOR_PATTERNS_AND_RESILIENCE.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


ใช้หน้านี้เพื่อทำความเข้าใจวิธีที่เจ้าหน้าที่รักษาความปลอดภัยช่วยตรวจสอบการละเมิดการขัดข้อง พฤติกรรมที่อยู่ติดกัน และการวางแผนการกู้คืน

<a id="what-the-guard-can-help-with"></a>
## สิ่งที่เจ้าหน้าที่รักษาความปลอดภัยสามารถช่วยได้

| รูปแบบ | สิ่งที่ต้องตรวจสอบ |
|---|---|
| การส่งคืนที่สัมพันธ์กับข้อขัดข้อง | บัญชีเดียวกันที่ใช้งานก่อนข้อขัดข้องและการกลับมาหลังจากรีสตาร์ท |
| การตรวจสอบการเชื่อมต่อใหม่อย่างรวดเร็ว | ซ้ำ join/leave หรือ timeout/reconnect วนซ้ำ |
| หลายบัญชี คลัสเตอร์ | เข้าร่วม wave, หน้าต่างคำเตือนที่ใช้ร่วมกัน, หน้าต่างความล้มเหลวที่ใช้ร่วมกัน |
| คำเตือนความเครียดที่ระเบิด | ซ้ำ ActorChannelFailure หรือหน้าต่างคำเตือนการบันทึก |
| บริบทนอกขอบเขต | PlayerData/map/world บริบทเมื่อสามารถอ่านได้ |
| Save-touch overlap | World-save context ซ้อนทับเซสชันที่แมป |
| ความสับสนของข้อมูลประจำตัว | ชื่อที่ต้องการการแมป ConnectID |

<a id="why-it-avoids-memory-access"></a>
## เหตุใดจึงหลีกเลี่ยงการเข้าถึงหน่วยความจำ

RandomDayGuard ทำงานจากไฟล์ที่เซิร์ฟเวอร์เป็นเจ้าของ:

```text
Saved/Logs/*.log
Admin.ini
World saves
PlayerData
Backups
runtime evidence
```

นั่นทำให้ขึ้นอยู่กับสถานะหน่วยความจำฝั่งไคลเอ็นต์น้อยลงและเปราะบางน้อยลงในการอัปเดตเกม

การแลกเปลี่ยน:

```text
It cannot prove hidden live actions unless the server writes evidence.
```

<a id="crash-correlated-returners"></a>
## ตัวส่งคืนที่สัมพันธ์กับข้อขัดข้อง

รูปแบบ:

```text
Account joins.
Server crashes or restarts.
Same account reconnects quickly.
Pattern repeats.
```

ไฟล์ที่มีประโยชน์:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="rapid-reconnect-probers"></a>
## เครื่องมือตรวจสอบการเชื่อมต่อใหม่อย่างรวดเร็ว

รูปแบบ:

```text
join -> leave -> join -> leave -> join
```

ไฟล์ที่มีประโยชน์:

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
```

<a id="multi-account-clusters"></a>
## หลายบัญชี คลัสเตอร์

รูปแบบ:

```text
Several accounts join in the same window.
Warnings or crashes follow.
Some accounts rotate or reconnect after restart.
```

ไฟล์ที่มีประโยชน์:

```text
runtime/raid_cases/
runtime/forensic_days/YYYY-MM-DD/raid_cases.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

กฎ:

```text
A cluster is not a mass-ban list.
Each account still needs its own evidence.
```

<a id="sticky-backup-recommendation"></a>
## คำแนะนำในการสำรองข้อมูลที่ติดหนึบ

สร้างการสำรองข้อมูลที่ติดหนึบหลังจาก:

```text
first full baseline completes
object_registry.json exists
file_manifest.tsv exists
world_state_latest.json has scan_complete=true
Admin.ini is verified
trusted IDs are configured
```

สำรองข้อมูล:

```text
RandomDayGuard/config.lua
RandomDayGuard/SavedRoot.txt
RandomDayGuard/runtime/baselines/
RandomDayGuard/runtime/object_registry.json
RandomDayGuard/runtime/world_state/current/world_state_latest.json
Saved/SaveGames/Server/Admin.ini
```

<a id="recovery-model"></a>
## รูปแบบการกู้คืน

```text
Clean install
-> verify live defense
-> complete first baseline
-> create sticky backup
-> run server normally
-> use daily rollups for review
-> restore sticky backup if needed
```
