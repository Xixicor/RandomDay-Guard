# การมีส่วนร่วม

> **แหล่งที่มาของภาษาอังกฤษตามรูปแบบบัญญัติ:** [CONTRIBUTING.md](../../../CONTRIBUTING.md). เอกสารที่แปลเป็นภาษาท้องถิ่นนี้จะรักษาคำสั่ง เส้นทาง คีย์ ค่าสถานะ แฮช และชื่อไฟล์ที่แน่นอน หากถ้อยคำทางเทคนิคแตกต่างออกไป ให้ใช้ต้นฉบับภาษาอังกฤษ


RandomDayGuard ยอมรับการปรับปรุงที่มุ่งเน้นและทำซ้ำได้สำหรับตัวแยกวิเคราะห์ เอกสาร การทดสอบ และการตรวจสอบความปลอดภัยสาธารณะ เก็บทุกการเปลี่ยนแปลงที่ผูกมัดกับสัญญาโครงการสาธารณะและรักษาพฤติกรรมที่เน้นการตรวจสอบเป็นอันดับแรก: Guard ต้องปล่อยให้ `Admin.ini` ไว้ไม่เปลี่ยนแปลงเมื่อไม่สามารถยืนยันการตรวจสอบความปลอดภัยที่จำเป็นได้

<a id="prepare-a-safe-workspace"></a>
## เตรียมพื้นที่ทำงานที่ปลอดภัย

1. แยกหรือโคลนพื้นที่เก็บข้อมูลและสร้างสาขาที่มุ่งเน้น
2. ติดตั้งล่าม Python 3 ที่รองรับ ติดตั้งคอมไพเลอร์ Lua เมื่อคุณเปลี่ยน Lua เพื่อให้ `luac -p` สามารถตรวจสอบไวยากรณ์ได้
3. อ่าน [หน้าแรกของเอกสาร](%E0%B9%80%E0%B8%AD%E0%B8%81%E0%B8%AA%E0%B8%B2%E0%B8%A3%E0%B8%9B%E0%B8%A3%E0%B8%B0%E0%B8%81%E0%B8%AD%E0%B8%9A.md), [สถาปัตยกรรม](%E0%B8%AA%E0%B8%96%E0%B8%B2%E0%B8%9B%E0%B8%B1%E0%B8%95%E0%B8%A2%E0%B8%81%E0%B8%A3%E0%B8%A3%E0%B8%A1.md) และ [ขอบเขตหลักฐาน](%E0%B8%82%E0%B8%AD%E0%B8%9A%E0%B9%80%E0%B8%82%E0%B8%95%E0%B8%AB%E0%B8%A5%E0%B8%B1%E0%B8%81%E0%B8%90%E0%B8%B2%E0%B8%99.md) สำหรับพื้นที่ที่คุณจะเปลี่ยนแปลง
4. ตรวจสอบ `git status` ก่อนที่จะแก้ไขและรักษางานที่ไม่เกี่ยวข้อง
5. ใช้อุปกรณ์จับยึดสังเคราะห์หรือที่ผ่านการฆ่าเชื้อแล้วเท่านั้น

อย่าส่งบันทึกเซิร์ฟเวอร์ส่วนตัว, โฟลเดอร์ที่บันทึกไว้, ตัวระบุผู้เล่น, `Admin.ini`, จุดสิ้นสุดการแจ้งเตือนส่วนตัว, ข้อมูลประจำตัว, เส้นทางส่วนตัว, เอาต์พุตรันไทม์ หรือหลักฐานที่คัดลอกไว้

<a id="make-a-focused-change"></a>
## ทำการเปลี่ยนแปลงที่มุ่งเน้น

- ปฏิบัติตามการตั้งชื่อ การจัดรูปแบบ การตรวจสอบความปลอดภัย และเจ้าของโมดูลที่มีอยู่
- เก็บเจ้าของเอกสารมาตรฐานไว้หนึ่งรายสำหรับแต่ละขั้นตอนหรือข้อเท็จจริงที่แน่นอน
- อัปเดตเอกสารของผู้ใช้และตัวอย่างเมื่อพฤติกรรมหรือผลลัพธ์สาธารณะเปลี่ยนแปลง
- เพิ่มการทดสอบการถดถอยสำหรับการแก้ไขข้อบกพร่องเมื่อใช้งานได้จริง
- อย่าทำให้การยืนยันบัญชีอ่อนแอลง การป้องกันบัญชีที่เชื่อถือได้ การตรวจสอบการสำรองข้อมูล การตรวจจับการเปลี่ยนแปลงภายนอก การเปรียบเทียบไฟล์ที่บันทึกไว้ การกู้คืน หรือค่าเริ่มต้นเฉพาะการตรวจทานเพื่อทำการทดสอบ ผ่าน

<a id="run-the-relevant-checks"></a>
## เรียกใช้การตรวจสอบที่เกี่ยวข้อง

สำหรับการเปลี่ยนแปลงเฉพาะเอกสาร ให้เรียกใช้:

```powershell
python -B tools\generate_documentation_audit.py --check
python -B -m unittest discover tests -p "test_documentation*.py"
git diff --check
```

สำหรับแหล่งที่มา การกำหนดค่า บรรจุภัณฑ์ หรือการเปลี่ยนแปลงการทดสอบ ให้เรียกใช้การตรวจสอบที่เกี่ยวข้องจาก [การตรวจสอบความถูกต้องและการทบทวนการเปิดตัว](%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B8%95%E0%B8%A3%E0%B8%A7%E0%B8%88%E0%B8%AA%E0%B8%AD%E0%B8%9A%E0%B8%84%E0%B8%A7%E0%B8%B2%E0%B8%A1%E0%B8%96%E0%B8%B9%E0%B8%81%E0%B8%95%E0%B9%89%E0%B8%AD%E0%B8%87%E0%B9%81%E0%B8%A5%E0%B8%B0%E0%B8%81%E0%B8%B2%E0%B8%A3%E0%B9%80%E0%B8%9C%E0%B8%A2%E0%B9%81%E0%B8%9E%E0%B8%A3%E0%B9%88.md) รวมถึงการตรวจสอบไวยากรณ์ Lua การตรวจสอบความถูกต้องของพื้นที่เก็บข้อมูล การทดสอบไปป์ไลน์สาธารณะ และชุดการทดสอบหน่วยแบบเต็ม รายงานทุกเช็คที่ข้ามหรือไม่พร้อมใช้งาน อย่าอธิบายว่าผ่านแล้ว

<a id="submit-the-change-for-review"></a>
## ส่งการเปลี่ยนแปลงเพื่อตรวจสอบ

เปิดคำขอดึงที่เน้นเฉพาะหลังจากตรวจสอบความแตกต่างที่สมบูรณ์แล้วเท่านั้น รวมถึง:

- ปัญหาและพฤติกรรมที่ต้องการ;
- ไฟล์ที่แน่นอนและสัญญาสาธารณะมีการเปลี่ยนแปลง
- คำสั่งที่ทำงานและผลลัพธ์
- ผลกระทบด้านความเป็นส่วนตัว ความเข้ากันได้ และการบังคับใช้; และ
- ข้อจำกัดที่เหลืออยู่หรืองานติดตามผล

อย่ารวมหลักฐานรันไทม์ที่สร้างขึ้นหรือไฟล์เก็บถาวรที่เผยแพร่ เว้นแต่การเปลี่ยนแปลงจะกำหนดและตรวจสอบอย่างชัดเจน การสนับสนุนไม่อนุญาตให้เผยแพร่ การปรับใช้ การทดสอบเซิร์ฟเวอร์สด การดำเนินการบังคับใช้ หรือการเผยแพร่บนไซต์บุคคลที่สาม

รายงานช่องโหว่ผ่าน [เส้นทางความปลอดภัยส่วนตัว](%E0%B8%84%E0%B8%A7%E0%B8%B2%E0%B8%A1%E0%B8%9B%E0%B8%A5%E0%B8%AD%E0%B8%94%E0%B8%A0%E0%B8%B1%E0%B8%A2.md) ไม่ใช่ปัญหาสาธารณะหรือคำขอดึงข้อมูลทั่วไป
