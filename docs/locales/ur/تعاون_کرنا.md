# تعاون کرنا

> **کیننیکل انگریزی ماخذ:** [CONTRIBUTING.md](../../../CONTRIBUTING.md). یہ مقامی دستاویزات درست کمانڈز، پاتھز، کیز، اسٹیٹس ویلیوز، ہیشز اور فائل کے ناموں کو محفوظ رکھتی ہیں۔ اگر تکنیکی الفاظ میں فرق ہے تو انگریزی ماخذ استعمال کریں۔


RandomDayGuard تجزیہ کاروں، دستاویزات، ٹیسٹس، اور عوامی محفوظ توثیق میں توجہ مرکوز، دوبارہ پیدا کرنے کے قابل بہتری کو قبول کرتا ہے۔ ہر تبدیلی کو پبلک پروجیکٹ کنٹریکٹ کے پابند رکھیں اور نظرثانی کے پہلے رویے کو محفوظ رکھیں: گارڈ کو چھوڑنا چاہیے `Admin.ini` غیر تبدیل شدہ جب ایک مطلوبہ حفاظتی جانچ کی تصدیق نہیں کی جاسکتی ہے۔

<a id="prepare-a-safe-workspace"></a>
## ایک محفوظ ورک اسپیس تیار کریں

1. ریپوزٹری کو فورک یا کلون کریں اور ایک فوکسڈ برانچ بنائیں۔
2. ایک تعاون یافتہ Python 3 انٹرپریٹر انسٹال کریں۔ Lua کو تبدیل کرتے وقت Lua کمپائلر انسٹال کریں `luac -p` نحو کی جانچ کر سکتا ہے۔
3. پڑھیں [دستاویزی گھر](%D8%AF%D8%B3%D8%AA%D8%A7%D9%88%DB%8C%D8%B2%D8%A7%D8%AA.md), [آرکیٹیکچر](%D8%A2%D8%B1%DA%A9%DB%8C%D9%B9%DB%8C%DA%A9%DA%86%D8%B1.md)، اور [ثبوت کی حد](%D8%AB%D8%A8%D9%88%D8%AA_%DA%A9%DB%8C_%D8%AD%D8%AF.md) اس علاقے کے لیے جسے آپ تبدیل کریں گے۔
4. معائنہ کریں `git status` ترمیم کرنے سے پہلے اور غیر متعلقہ کام کو محفوظ کریں۔
5. صرف مصنوعی یا سینیٹائزڈ فکسچر استعمال کریں۔

کبھی بھی نجی سرور لاگز، محفوظ کردہ فولڈرز، پلیئر شناخت کنندگان، `Admin.ini`، نجی اطلاع کے اختتامی نقطہ، اسناد، نجی راستے، رن ٹائم آؤٹ پٹ، یا کاپی شدہ لائیو ثبوت۔

<a id="make-a-focused-change"></a>
## ایک توجہ مرکوز تبدیلی کریں

- موجودہ نام سازی، فارمیٹنگ، حفاظتی چیکس، اور ماڈیول کی ملکیت کی پیروی کریں۔
- ہر طریقہ کار یا قطعی حقیقت کے لیے ایک کیننیکل دستاویزات کا مالک رکھیں۔
- جب برتاؤ یا عوامی آؤٹ پٹ میں تبدیلی آتی ہے تو صارف کی دستاویزات اور مثالوں کو اپ ڈیٹ کریں۔
- جب عملی ہو تو بگ فکس کے لیے ریگریشن ٹیسٹ شامل کریں۔
- ٹیسٹ پاس کرنے کے لیے اکاؤنٹ کی تصدیق، معتبر اکاؤنٹ کے تحفظ، بیک اپ کی توثیق، باہر کی تبدیلی کا پتہ لگانے، محفوظ کردہ فائل کا موازنہ، ریکوری، یا صرف ریویو ڈیفالٹس کو کمزور نہ کریں۔

<a id="run-the-relevant-checks"></a>
## متعلقہ چیکس چلائیں

صرف دستاویزی تبدیلیوں کے لیے، چلائیں:

```powershell
python -B tools\generate_documentation_audit.py --check
python -B -m unittest discover tests -p "test_documentation*.py"
git diff --check
```

ذریعہ، ترتیب، پیکیجنگ، یا ٹیسٹ تبدیلیوں کے لیے، [توثیق اور رہائی کا جائزہ](%D8%AA%D9%88%D8%AB%DB%8C%D9%82_%D8%A7%D9%88%D8%B1_%D8%B1%DB%81%D8%A7%D8%A6%DB%8C.md)، بشمول Lua سنٹیکس چیک، ریپوزٹری کی توثیق، پبلک پائپ لائن ٹیسٹ، اور مکمل یونٹ ٹیسٹ سوٹ۔ ہر نظر انداز یا غیر دستیاب چیک کی اطلاع دیں؛ اسے گزرے ہوئے کے طور پر بیان نہ کریں۔

<a id="submit-the-change-for-review"></a>
## تبدیلی کو جائزہ کے لیے جمع کروائیں

مکمل فرق کا جائزہ لینے کے بعد ہی توجہ مرکوز کرنے کی درخواست کھولیں۔ شامل کریں:

- مسئلہ اور مطلوبہ سلوک؛
- بالکل فائلیں اور عوامی معاہدوں کو تبدیل کر دیا گیا؛
- کمانڈز چلتی ہیں اور ان کے نتائج؛
- رازداری، مطابقت، اور نفاذ کا اثر؛ اور
- باقی حدود یا فالو اپ کام۔

جنریٹڈ رن ٹائم ثبوت یا ریلیز آرکائیوز کو شامل نہ کریں جب تک کہ تبدیلی واضح طور پر ان کی ضرورت اور توثیق نہ کرے۔ شراکت کسی تیسرے فریق کی سائٹ پر ریلیز، تعیناتی، لائیو سرور ٹیسٹ، نفاذ کی کارروائی، یا اشاعت کی اجازت نہیں دیتی ہے۔

کے ذریعے کمزوریوں کی اطلاع دیں [نجی حفاظتی راستہ](%D8%B3%DB%8C%DA%A9%DB%8C%D9%88%D8%B1%D9%B9%DB%8C.md)، کوئی عوامی مسئلہ یا عام پل کی درخواست نہیں۔
