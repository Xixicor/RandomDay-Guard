# توثیق اور رہائی

> **کیننیکل انگریزی ماخذ:** [VALIDATION_AND_RELEASE.md](../../VALIDATION_AND_RELEASE.md). یہ مقامی دستاویزات درست کمانڈز، پاتھز، کیز، اسٹیٹس ویلیوز، ہیشز اور فائل کے ناموں کو محفوظ رکھتی ہیں۔ اگر تکنیکی الفاظ میں فرق ہے تو انگریزی ماخذ استعمال کریں۔


یہ صفحہ شراکت داروں اور ریلیز مینٹینرز کے لیے ہے۔ سرور آپریٹرز کو انسٹال کرنے کے لیے ان کمانڈز کو چلانے کی ضرورت نہیں ہے RandomDayGuard.

<a id="user-visible-proof"></a>
## صارف کو دکھائی دینے والا ثبوت

ایک ریلیز اس وقت سمجھ میں آتی ہے جب کوئی نیا آپریٹر اسے انسٹال کر سکتا ہے، پہلی سرور اسٹیٹس رپورٹ تلاش کر سکتا ہے، رپورٹ کے پانچ راستوں میں فرق کر سکتا ہے، اور کام کی گئی مثال سے ایک واضح عمل کی پیروی کر سکتا ہے۔ قارئین کے کاموں کو Git، PowerShell، Python، یا checksum علم کی ضرورت نہیں ہونی چاہیے۔

<a id="contributor-checks"></a>
## Contributor کے چیک

```powershell
python -B tools/validate_repo.py
python -B tools/test_public_pipeline.py
python -B -m unittest discover tests
```

کب `luac` دستیاب ہے:

```powershell
luac -p RandomDayGuard/Scripts/main.lua
luac -p RandomDayGuard/Scripts/public_pipeline.lua
```

لوا فکسچر ٹیسٹ لوڈر، شیڈولر، رپورٹ کے راستوں اور اختیاری Admin.ini لین دین لکھیں۔ انفورسمنٹ فکسچر صرف عارضی فائلوں کا استعمال کرتے ہیں اور شناخت، ٹرسٹڈ اکاؤنٹ کو مسترد کرنے، تھریشولڈز، بیک اپ، کنکرنٹ چینج انکار، ریڈ بیک اور رول بیک کی تصدیق کرتے ہیں۔

<a id="package-proof"></a>
## پیکیج کا ثبوت

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

- تمام ورژن مارکر مماثل ہیں `VERSION`.
- صرف موجودہ ورژن `releases/`.
- The ZIP کینونیکل پر مشتمل ہے `RandomDayGuard/Scripts/main.lua` پاتھ اور کوئی لوئر کیس کیس ویرینٹ لوڈر نہیں۔
- رن ٹائم آؤٹ پٹ، پرائیویٹ کنفیگریشن، اسناد، لوکل پاتھ، کیچز، اور ٹیسٹ آرٹفیکٹس کو خارج کر دیا گیا ہے۔
- عوامی کنفیگریشن صرف انفورسمنٹ کے غیر فعال ہونے کے ساتھ جائزہ کے لیے رہتی ہے۔
- پانچ کام شدہ رپورٹ کی مثالیں روٹ کی ملکیت اور ریلیز ٹیسٹ فکسچر کے ساتھ مطابقت رکھتی ہیں۔
- ZIP بائٹس تعییناتی ہیں اور مماثل ہیں `CHECKSUMS.sha256`.
- تمام مقامی دستاویزات کے لنکس اور 27 مقامی اندراج کے صفحات کی توثیق ہوتی ہے۔

<a id="avoid-validation-environment-pitfalls"></a>
## توثیق کے ماحول کے نقصانات سے بچیں

- عارضی فائل کے تنازعہ سے بچنے کے لیے ریپوزٹری رائٹنگ چیکس کو سلسلہ وار چلائیں۔
- Windows پر، ڈپلیکیٹ لوڈرز کی جانچ کرتے وقت آرکائیو شدہ ممبر کے ناموں یا گنتی والے راستے کے ہجے کا معائنہ کریں نہ کہ کیس غیر حساس فائل تلاش کریں۔
- ایک غائب `luac` کمانڈ یا Lua رن ٹائم ایک غیر دستیاب صلاحیت ہے، نہ کہ ایک پاسنگ سنٹیکس یا رن ٹائم ٹیسٹ۔
- ایک فکسچر صرف اس کے ماڈلڈ ان پٹس کو ثابت کرتا ہے۔ یہ ثابت نہیں کرتا کہ لائیو سرور نے موجودہ رپورٹ تیار کی ہے۔
- کمانڈ ٹائم آؤٹ اور جزوی آؤٹ پٹ کو مکمل ہونے کو ماننے کے بجائے ریکارڈ کریں۔

<a id="repair-failed-repository-validation"></a>
## ریپوزٹری کی توثیق میں ناکامی کی مرمت

پہلے اطلاع شدہ راستے یا معاہدے سے شروع کریں۔ اس آئٹم کو درست کریں، تنگ ٹیسٹ کو دوبارہ چلائیں، پھر مکمل میٹرکس کو دوبارہ چلائیں۔ جس ٹیسٹ کی ضرورت ہے اسے ہٹا کر گمشدہ صلاحیت کو نہ چھپائیں۔

<a id="known-limits-and-release-decision"></a>
## معلوم حدود اور رہائی کا فیصلہ

مقامی چیک ماخذ، فکسچر، پیکیج، اور دستاویزات کے معاہدوں کو ثابت کرتے ہیں۔ ایک مخصوص سرور کی تنصیب، طویل عرصے سے چلنے والی استحکام ونڈو، یا کلائنٹ ڈسپلے کے لیے الگ انضمام کے نتیجے کی ضرورت ہوتی ہے۔ مماثل دعویٰ کرنے سے پہلے اس نتیجے کو اس کی تعمیر، ترتیب، مدت، اور مشاہدہ شدہ آؤٹ پٹ کے ساتھ ریکارڈ کریں۔
