# Admin.ini نفاذ

> **کیننیکل انگریزی ماخذ:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). یہ مقامی دستاویزات درست کمانڈز، پاتھز، کیز، اسٹیٹس ویلیوز، ہیشز اور فائل کے ناموں کو محفوظ رکھتی ہیں۔ اگر تکنیکی الفاظ میں فرق ہے تو انگریزی ماخذ استعمال کریں۔


RandomDayGuard اپنے ڈیفالٹ سیٹ اپ میں سرور کی پابندی کی فہرست کو تبدیل نہیں کرتا ہے۔ یہ صرف منتظم کے لیے جائزہ لینے کے لیے رپورٹیں بناتا ہے۔ یہ صفحہ ان منتظمین کے لیے اختیاری خودکار پابندی کی فہرست کی تازہ کاری کی وضاحت کرتا ہے جو جان بوجھ کر اسے فعال کرتے ہیں۔

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## پابندی کی فہرست کو تبدیل کرنے سے پہلے گارڈ چیک کرتا ہے

گارڈ صرف اس وقت پابندی لگاتا ہے جب نیچے ہر جواب **ہاں**:

1. کیا موجودہ شواہد نے کافی اعتماد کے ساتھ ایک مخصوص اکاؤنٹ کی شناخت کی ہے؟
2. کیا اکاؤنٹ نہ تو ماڈریٹر ہے اور نہ ہی اکاؤنٹ کو منتظم نے بطور قابل اعتماد نشان زد کیا ہے؟
3. کیا اکاؤنٹ پہلے سے پابندی کی فہرست میں نہیں ہے؟
4. کیا اکاؤنٹ خودکار کارروائی کے ترتیب شدہ اسکور تک پہنچ گیا؟
5. کیا گارڈ موجودہ کو پڑھ سکتا ہے `Admin.ini` اور ایک جیسا بیک اپ محفوظ کریں؟
6. کیا `Admin.ini` جب تک گارڈ نے اپ ڈیٹ تیار کیا تھا اس میں کوئی تبدیلی نہیں ہوگی؟
7. محفوظ کرنے کے بعد، کیا مکمل فائل مطلوبہ نتیجہ سے بالکل مماثل ہے؟

اگر کوئی جواب ہے **نہیں**، یا چیک نہیں کیا جا سکتا، گارڈ چھوڑ دیتا ہے `Admin.ini` کوئی تبدیلی نہیں کی گئی اور اس کی وجہ کو اپنی رپورٹس میں درج کرتا ہے۔ اگر بچت شروع ہو جاتی ہے لیکن آخری چیک ناکام ہو جاتا ہے، تو گارڈ تصدیق شدہ بیک اپ کو بحال کر دیتا ہے۔

<a id="file-format"></a>
## فائل فارمیٹ

`Admin.ini` صرف صاف پابندی والی لائنیں موصول ہونی چاہئیں:

```ini
BannedPlayer=<ID>
```

- کوئی نام نہیں۔
- کوئی تبصرے نہیں۔
- کوئی وجہ نہیں۔
- کوئی لاحقہ نہیں۔

<a id="safe-defaults"></a>
## محفوظ ڈیفالٹس

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## ID ماخذ پر پابندی لگائیں

بہترین ذریعہ:

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

رن ٹائم یا تو مکمل عددی ID یا مکمل دستاویزی کو قبول کرتا ہے `<digits>_+_|<non-space token>` کنکشن فارم اور اس سے عددی پابندی ID اخذ کرتا ہے۔ ایک نامعلوم لاحقہ کے ساتھ صوابدیدی عددی سابقے مسترد کر دیے جاتے ہیں۔ وہ پابندی کی شناخت میں نہیں کٹے ہیں۔

درست:

```ini
BannedPlayer=2535422284688820
```

غلط:

```ini
BannedPlayer=ExamplePlayer
```

بھی غلط:

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## بالکل سیٹنگز گارڈ چیکس

یہ ترتیبات اوپر بیان کردہ چیکس کو نافذ کرتی ہیں۔ ہر درج شرط درست ہونی چاہیے:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

اگر کوئی شرط غلط ہے یا اسے چیک نہیں کیا جا سکتا ہے، تو گارڈ پابندی کی فہرست کو بغیر کسی تبدیلی کے چھوڑ دیتا ہے اور ریکارڈ کرتا ہے کہ اسے کس چیز نے روکا ہے۔

<a id="transaction-safety"></a>
## لین دین کی حفاظت

واحد `Admin.ini` میوٹیشن پاتھ ان مراحل کو ترتیب سے انجام دیتا ہے:

1. مستند بائٹس کو پڑھیں اور ساختی طور پر توثیق کریں۔
2. اسی سنیپ شاٹ سے ماڈریٹر، قابل اعتماد، اور موجودہ پابندی والی حالت حاصل کریں۔
3. کے تحت ایک منفرد بیک اپ لکھیں `runtime/backups/` اور بائٹ کے لیے بائٹ کی تصدیق کریں۔
4. دوبارہ پڑھیں `Admin.ini` تبدیل کرنے سے فوراً پہلے اور کسی بھی بیرونی تبدیلی کو مسترد کریں۔
5. کنفیگرڈ کنٹرول شدہ متبادل راستے کے ذریعے امیدوار لکھیں۔
6. مکمل امیدوار بائٹس کے برابر کرنے کے لیے مکمل ریڈ بیک بائٹس کی ضرورت ہے۔
7. ریڈ بیک کی ناکامی پر، تصدیق شدہ بیک اپ کو صرف اس وقت بحال کریں جب کہ موجودہ فائل ابھی بھی گارڈ کے ذریعہ لکھی گئی عین مطابق امیدوار ہے۔ اگر کسی اور مصنف نے اسے تبدیل کیا تو گارڈ نامعلوم بیرونی بائٹس کو اوور رائٹ کرنے کے بجائے رول بیک سے انکار کرتا ہے۔

ڈپلیکیٹ IDs idempotent ہیں: کوئی دوسری لائن اور کوئی دوسرا بیک اپ نہیں لکھا جاتا ہے۔ بیک اپ کے ناموں میں ٹائم اسٹیمپ، سورس بائٹ فنگر پرنٹ، اور کلین آئی ڈی شامل ہوتی ہے اس لیے الگ الگ کوششیں پرانے ایک سیکنڈ کے فائل نام کا اشتراک نہیں کر سکتیں۔

<a id="local-regression-proof"></a>
## مقامی رجعت کا ثبوت

`tests/lua/enforcement_runtime_test.lua` بھیجے گئے لوڈر کو ایک بار بوٹ کرتا ہے اور پھر اس کے اصلی مقامی کو انجام دیتا ہے `append_ban()` مخزن کے نیچے الگ تھلگ مصنوعی فائلوں کے خلاف بندش `.tmp/` ڈائریکٹری۔ یہ اندراج، ڈپلیکیٹ آئیڈیمپوٹینسی، moderator/trusted مسترد کرنا، کمزور اور غلط شناخت کا مسترد کرنا، بائٹ کے عین مطابق بیک اپ کی توثیق، کنکرنٹ ترمیم کو مسترد کرنا، ریڈ بیک کے ناکام ہونے کے بعد کامیاب رول بیک، اور پوسٹ رائٹ بیرونی تبدیلی کو اوور رائٹ کرنے سے انکار۔ اس کے فائل سسٹم ریپرز فکسچر روٹ سے باہر کسی بھی تبدیلی کو مسترد کرتے ہیں۔ کوئی حقیقی سرور پاتھ یا حقیقی `Admin.ini` استعمال کیا جاتا ہے۔

اسے چلائیں `python tools/test_public_pipeline.py`۔ فکسچر پاس صرف مقامی لین دین کے رویے کو ثابت کرتا ہے۔ یہ نفاذ کو فعال نہیں کرتا، پروڈکشن رائٹ کی اجازت نہیں دیتا، یا میزبان کے لیے مخصوص اجازتوں کو ثابت نہیں کرتا۔

<a id="rollback"></a>
## رول بیک

1. سرور کو روکیں۔
2. تازہ ترین بحال کریں Admin.ini `runtime/backups/`.
3. غلط کو ہٹا دیں `BannedPlayer=<ID>` لائن۔
4. سرور شروع کریں۔
5. دوبارہ کھولیں Admin.ini اور تصدیق کریں کہ لائن برقرار ہے یا ہٹا دی گئی ہے۔
6. محفوظ کریں `enforced_bans.jsonl` آڈٹ کے لیے۔
