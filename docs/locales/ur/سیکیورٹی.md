# سیکیورٹی پالیسی

> **کیننیکل انگریزی ماخذ:** [SECURITY.md](../../../SECURITY.md). یہ مقامی دستاویزات درست کمانڈز، پاتھز، کیز، اسٹیٹس ویلیوز، ہیشز اور فائل کے ناموں کو محفوظ رکھتی ہیں۔ اگر تکنیکی الفاظ میں فرق ہے تو انگریزی ماخذ استعمال کریں۔


<a id="report-a-vulnerability-privately"></a>
## نجی طور پر خطرے کی اطلاع دیں

استعمال کریں [GitHub نجی خطرے کی رپورٹنگ](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) مخزن کے مالک کو ایک خفیہ رپورٹ بھیجنے کے لیے۔ اگر وہ فارم دستیاب نہیں ہے تو [مالک کا عوامی GitHub پروفائل](https://github.com/Xixicor) خطرے کی تفصیلات شامل کیے بغیر نجی رابطہ چینل کی درخواست کرنا۔

ایسا عوامی مسئلہ نہ کھولیں جس میں استحصال کے مراحل، اسناد، نجی سرور کے راستے، پلیئر شناخت کنندگان، `Admin.ini`، محفوظ کردہ ڈیٹا، ویب ہک URLs، یا لائیو ثبوت فائلز۔

<a id="include-useful-evidence"></a>
## مفید ثبوت شامل کریں

فراہم کریں:

- متاثرہ RandomDayGuard ورژن یا کمٹ؛
- متاثرہ جزو اور متوقع محفوظ رویہ؛
- سینیٹائزڈ فکسچر کا استعمال کرتے ہوئے تولیدی کم سے کم اقدامات؛
- مشاہدہ اثر اور آیا یہ دہرایا جا سکتا ہے؛ اور
- کوئی بھی مجوزہ تخفیف جو نجی ڈیٹا کو بے نقاب نہ کرے۔

حقیقی راز مت بھیجیں۔ مسئلے کو دوبارہ پیش کرنے کے لیے درکار ڈھانچے کو محفوظ رکھتے ہوئے پرائیویٹ پاتھ، اکاؤنٹ کے شناخت کنندگان، میزبان ناموں، اور ٹوکنز کو واضح پلیس ہولڈرز سے تبدیل کریں۔

<a id="expect-review-first-handling"></a>
## جائزہ کے پہلے ہینڈلنگ کی توقع کریں

ایک رپورٹ مینٹینر کے جائزے کا ثبوت ہے، نہ کہ سرور تک رسائی کی اجازت، لائیو ٹارگٹ کی جانچ، استحصال کی تفصیلات شائع کرنا، یا فیل بند ڈیفالٹس کو کمزور کرنا۔ مالک دائرہ کار کی توثیق کرے گا اور نجی رپورٹ کے ذریعے کسی بھی انکشاف کو مربوط کرے گا۔
