<a id="configuration-concepts"></a>
# کنفیگریشن کے تصورات

> **کیننیکل انگریزی ماخذ:** [CONFIG_REFERENCE.md](../../CONFIG_REFERENCE.md). یہ مقامی دستاویزات درست کمانڈز، پاتھز، کیز، اسٹیٹس ویلیوز، ہیشز اور فائل کے ناموں کو محفوظ رکھتی ہیں۔ اگر تکنیکی الفاظ میں فرق ہے تو انگریزی ماخذ استعمال کریں۔


یہ وضاحت اس بات کی وضاحت کرتی ہے کہ ہر بڑا کنفیگریشن ایریا کس چیز کو کنٹرول کرتا ہے، یہ کب چلتا ہے، اور یہ ثبوت اور حفاظتی دروازوں کے ساتھ کیسے تعامل کرتا ہے۔ یہ قطعی فیلڈ کیٹلاگ یا پروفائل طریقہ کار کا مالک نہیں ہے۔

کام پر مبنی پیش سیٹ اور محفوظ تبدیلی کے مراحل کے لیے، استعمال کریں [`CONFIG_PROFILES.md`](%D9%BE%D8%B1%D9%88%D9%81%D8%A7%D8%A6%D9%84%D8%B2_%DA%A9%D9%88_%D8%AA%D8%B1%D8%AA%DB%8C%D8%A8_%D8%AF%DB%8C%DA%BA.md)۔ ہر عین ماخذ فیلڈ، ڈیفالٹ، ٹائپ، انویرینٹ، آؤٹ پٹ اثر، اور ریکوری کے اصول کے لیے، تیار کردہ استعمال کریں [`CONFIG_FIELD_CATALOG.md`](%DA%A9%D9%86%D9%81%DB%8C%DA%AF_%D9%81%DB%8C%D9%84%DA%88_%DA%A9%DB%8C%D9%B9%D9%84%D8%A7%DA%AF.md)؛ تصدیق کنندہ کو ہر بھیجے گئے `config.lua` لیف فیلڈ۔

```text
What it controls

```

<a id="top-level-safety"></a>
## اعلی سطح کی حفاظت

| آپشن | ڈیفالٹ | مطلب |
|---|---:|---|
| `enabled` | `true` | گارڈ کے لیے ماسٹر سوئچ |
| `enforcement.review_only_mode` | `true` | Record/recommend صرف |
| `enforcement.auto_ban` | `false` | بذریعہ ڈیفالٹ خود بخود پابندی نہ لگائیں |
| `enforcement.write_admin_ini` | `false` | نہ لکھیں Admin.ini بذریعہ ڈیفالٹ |

ان کو اس وقت تک محفوظ رکھیں جب تک کہ سرور کا مالک آؤٹ پٹ کا جائزہ نہ لے لے۔

<a id="saved"></a>
## `saved`

کنٹرول کرتا ہے کہ گارڈ سرور کو کیسے تلاش کرتا ہے `Saved/` فولڈر اور کون سی فائل فیملیز اسکین کرسکتے ہیں۔

استعمال کریں جب:

```text
Saved root auto-detection fails.
World folder changed.
Provider or container path is unusual.
```

چیک کریں:

```text
runtime/saved_path_probe.json
RandomDayGuard/SavedRoot.txt
```

قاعدہ:

```text
SavedRoot.txt -> AbioticFactor/Saved
not -> Worlds/<WorldName>
```

<a id="log_tail"></a>
## `log_tail`

لائیو لاگ ریڈنگ کو کنٹرول کرتا ہے۔

مفید اختیارات:

| آپشن | محفوظ قدر | کیوں |
|---|---|---|
| `enabled` | `true` | لائیو ڈیفنس کے لیے درکار ہے |
| `start_at_end_on_first_run` | `true` | لائیو ایونٹس کے بطور پرانے لاگز سے اجتناب کرتا ہے |
| `tail_backup_logs` | `false` | بیک اپ لاگز تاریخ ہیں، لائیو نہیں |
| `max_lines_per_poll` | باؤنڈڈ | پول لوپ کو ریسپانسیو رکھتا ہے |

چیک کریں:

```text
runtime/log_offsets.tsv
runtime/evidence/session_events.jsonl
runtime/current/poll_status.json
```

<a id="runtime"></a>
## `runtime`

پولنگ اور بجٹ کو کنٹرول کرتا ہے۔

صحت کا بنیادی اصول:

```text
poll_id increases
poll_in_flight returns false
poll_scheduled is true
```

چیک کریں:

```text
runtime/current/poll_status.json
```

اگر `poll_id` رک جاتا ہے، کچھ لوپ کو روک رہا ہے۔

<a id="source_accounting"></a>
## `source_accounting`

واضح ثبوت کے ماخذ کی کوریج اور دائرہ کار کو کنٹرول کرتا ہے۔

| کلید | ڈیفالٹ | مطلب |
|---|---:|---|
| `enabled` | `true` | عوامی روٹ رپورٹس کے لیے ماخذ اکاؤنٹنگ لکھتا ہے۔ |
| `require_terminal_status` | `true` | ہر ماخذ کو ایک واضح ٹرمینل یا نامکمل حالت کو ظاہر کرنے کی ضرورت ہوتی ہے۔ |
| `distinguish_current_from_historical` | `true` | موجودہ اور تاریخی شواہد کو الگ الگ رکھتا ہے۔ |
| `slow_world_scan_blocks_current_reports` | `false` | موجودہ رپورٹس کو یہ بتانے کی اجازت دیتا ہے کہ باؤنڈڈ ورلڈ اسکیننگ موخر یا جزوی ہے۔ |
| `changed_file_manifest` | بیس لائن مینی فیسٹ پاتھ | حد کے لیے استعمال شدہ حوالہ historical/world اکاؤنٹنگ۔ |

ماخذ کی حالتیں ہیں `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied`، یا `error`.

ترتیب `source_accounting.enabled = false` خاموشی سے اسٹیٹس آؤٹ پٹ کو نہیں ہٹاتا ہے۔ پائپ لائن اب بھی `runtime/final_logs/source_accounting_latest.json` کے ساتھ `enabled=false`, `status="unavailable"`، اور `disabled_reason="source_accounting_disabled"`۔ یہ غیر دستیاب اکاؤنٹنگ کے ساتھ تاریخی حیثیت کا ریکارڈ بھی لکھتا ہے۔ چونکہ ماخذ اکاؤنٹنگ رپورٹ کے معاہدے کا حصہ ہے، اس لیے ہر راستہ `missing`؛ اکاؤنٹنگ غیر فعال ہونے کے دوران کسی بھی راستے کو مکمل نہیں سمجھا جاتا۔

<a id="reports"></a>
## `reports`

عام مقامی رپورٹنگ پائپ لائن کو کنٹرول کرتا ہے۔

ڈیفالٹ پانچوں راستوں کو فعال کرتے ہیں اور `runtime/final_logs`:

```text
server_status
daily_rollup
player_activity
case_review
critical_guard
```

ہر روٹ کو `route_proof.json`۔ راستے کو غیر فعال کرنے سے پیدا ہوتا ہے `missing` ثبوت یہ دکھاوا کرنے کے بجائے کہ یہ مکمل ہو گیا ہے۔

<a id="notification"></a>
## `notification`

اختیاری عام لوکل فائل آؤٹ باکس۔ یہ بطور ڈیفالٹ غیر فعال ہے اور کسی بیرونی فراہم کنندہ کو کچھ نہیں بھیجتا ہے۔

ڈیفالٹس:

```lua
notification = {
    enabled = false,
    mode = "local_file_outbox",
    include_expected_empty = false,
},
```

اطلاع کا ہر راستہ بطور ڈیفالٹ غیر فعال ہے۔ جان بوجھ کر فعال ہونے پر، آؤٹ باکس `route_proof.json` لکھا ہوا ہے۔ مقامی شواہد اور رپورٹیں مستند رہیں۔ فراہم کنندہ کے لیے مخصوص ڈیلیوری، ڈیلیوری اینڈ پوائنٹس، اسناد، اور پل عوامی آزاد نگران معاہدے کا حصہ نہیں ہیں۔

<a id="scanning"></a>
## `scanning`

بیس لائن اسکین، چیک پوائنٹ، اور تبدیل شدہ فائل ریفریش کو کنٹرول کرتا ہے۔

استعمال کریں جب:

```text
building first world baseline
resuming after crash
refreshing changed files later
```

چیک کریں:

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/baselines/file_manifest.tsv
```

اہم ترتیبات:

```lua
scanning = {
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
    changed_file_detection = true,
},
```

<a id="forensic_rollup"></a>
## `forensic_rollup`

تیز روزانہ اپ لوڈ پیکج اور حتمی سادہ زبان کے لاگز کو کنٹرول کرتا ہے۔

آؤٹ پٹس:

```text
runtime/current/forensic_today.json
runtime/current/forensic_today.md
runtime/current/forensic_today.txt
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

استعمال کریں جب:

```text
You want one daily folder that summarizes what happened.
You want a plain-language TXT to upload for quick analysis.
```

چیک کریں:

```text
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

قاعدہ:

```text
Daily summaries are rebuildable indexes.
Source evidence remains authoritative.
```

<a id="logging"></a>
## `logging`

ایونٹ کے حجم اور کم اہمیت کے مجموعے کو کنٹرول کرتا ہے۔

استعمال کریں جب:

```text
actor-touch events are noisy
raw event files grow too quickly
```

محفوظ پیٹرن:

```lua
logging = {
    low_importance_mode = "aggregate",
    write_low_importance_raw_events = false,
},
```

<a id="retention"></a>
## `retention`

کنٹرول کرتا ہے کہ فائلیں کتنی دیر تک رکھی جائیں اور کب JSONL لاگز گھومتے ہیں۔

استعمال کریں جب:

```text
disk usage grows too fast
you need more audit history
you need shorter live-history windows
```

اہم اختیارات:

```text
detailed_retention_days
rotate_jsonl_when_bytes_exceed
max_raw_events_lines
keep_enforced_forever
keep_evidence_forever
```

<a id="warning_bursts"></a>
## `warning_bursts`

انتباہی ونڈو کا پتہ لگانے کو کنٹرول کرتا ہے۔

مثالیں:

```text
ActorChannelFailure
DeployableSaveWarning
UpdateActorToWorldSave
ServerMove warnings
```

قاعدہ:

```text
Warnings are context until correlated with mapped sessions and thresholds.
```

<a id="crash_correlation"></a>
## `crash_correlation`

دوہرائے جانے والے کنٹرولز crash/reconnect جائزہ۔

محفوظ ڈیفالٹس:

```lua
crash_correlation = {
    single_crash_never_bans = true,
    require_same_account = true,
},
```

مفید کاؤنٹرز:

```text
server_crash_overlap_count
post_crash_reconnect_count
unclean_disconnect_count
```

<a id="join_leave"></a>
## `join_leave`

منتھن اور جوائن ویو ٹریکنگ کو کنٹرول کرتا ہے۔

محفوظ ڈیفالٹ:

```lua
join_leave = {
    churn_alone_never_bans = true,
},
```

استعمال برائے:

```text
rapid reconnect loops
join waves
short-session patterns
```

<a id="raid_detection"></a>
## `raid_detection`

متعلقہ ونڈوز میں فعال گروپس اکاؤنٹس۔

قاعدہ:

```text
A raid case groups accounts for review.
It does not make every account guilty.
```

ہر نافذ شدہ اکاؤنٹ کو اب بھی اکاؤنٹ کے مخصوص ثبوت کی ضرورت ہے۔

<a id="object_registry"></a>
## `object_registry`

کنٹرولز object/class پڑھنے کے قابل محفوظ شدہ ثبوت سے ٹوکن نکالنا۔

آؤٹ پٹس:

```text
runtime/object_registry_partial.json
runtime/object_registry.json
runtime/object_registry_counts.tsv
```

قاعدہ:

```text
Object/class context is not a ban reason by itself.
```

<a id="world_state"></a>
## `world_state`

کنٹرولز boot/current/session عالمی ریاست کے اسنیپ شاٹس۔

آؤٹ پٹس:

```text
runtime/world_state/current/world_state_latest.json
runtime/world_state/sessions/<date>/<session_id>_<account_id>/
```

سیشن کے جائزے اور عالمی سیاق و سباق کے لیے استعمال کریں۔

<a id="enforcement"></a>
## `enforcement`

سفارشات اور حقیقی Admin.ini لکھتا ہے۔

اس سے پہلے کہ گارڈ پابندی لگا سکے، نیچے دیا گیا ہر بیان درست ہونا چاہیے:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
account identity is mapped
not trusted
not moderator
threshold is met
```

اگر ایک بیان غلط ہے یا اسے چیک نہیں کیا جا سکتا ہے تو گارڈ چھوڑ دیتا ہے `Admin.ini` غیر تبدیل شدہ اور وجہ ریکارڈ کرتا ہے۔

<a id="admin_ini"></a>
## `admin_ini`

محفوظ فائل تحریروں کو کنٹرول کرتا ہے۔

قواعد:

```text
Back up before writing.
Preserve existing bans.
Preserve moderators.
Write clean BannedPlayer=<ID> only.
```

<a id="restart_request"></a>
## `restart_request`

اختیاری مقامی مارکر فائلوں کو کنٹرول کرتا ہے جن کا آپریٹر کی ملکیت والا دوسرا عمل معائنہ کرسکتا ہے۔ یہ سرور کو دوبارہ شروع یا ختم نہیں کرتا ہے۔

ڈیفالٹس:

```lua
restart_request = {
    enabled = false,
    restart_marker_file = "runtime/request_restart.flag",
    restart_reason_file = "runtime/restart_reason.json",
},
```

آؤٹ پٹس:

```text
runtime/request_restart.flag
runtime/restart_reason.json
```

کوئی ہوسٹنگ پینل، پرووائیڈر برج، یا ری اسٹارٹ آٹومیشن بنڈل نہیں ہے۔ مارکر تخلیق کو فعال کرنے سے یہ ثابت نہیں ہوتا ہے کہ کسی بیرونی عمل نے درخواست کو استعمال کیا یا سرور کو دوبارہ شروع کیا۔
