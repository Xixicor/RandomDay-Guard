# خراب اداکار کے نمونے اور لچک

> **کیننیکل انگریزی ماخذ:** [BAD_ACTOR_PATTERNS_AND_RESILIENCE.md](../../BAD_ACTOR_PATTERNS_AND_RESILIENCE.md). یہ مقامی دستاویزات درست کمانڈز، پاتھز، کیز، اسٹیٹس ویلیوز، ہیشز اور فائل کے ناموں کو محفوظ رکھتی ہیں۔ اگر تکنیکی الفاظ میں فرق ہے تو انگریزی ماخذ استعمال کریں۔


یہ سمجھنے کے لیے اس صفحہ کا استعمال کریں کہ گارڈ کس طرح حادثے کے غلط استعمال، استحصال سے ملحقہ رویے، اور بحالی کی منصوبہ بندی کا جائزہ لینے میں مدد کرتا ہے۔

<a id="what-the-guard-can-help-with"></a>
## گارڈ کس چیز میں مدد کرسکتا ہے

| پیٹرن | کیا چیک کرنا ہے |
|---|---|
| کریش سے متعلقہ واپسی | کریش ہونے سے پہلے ایک ہی اکاؤنٹ فعال ہوتا ہے اور دوبارہ شروع ہونے کے بعد واپس آتا ہے |
| ریپڈ ری کنیکٹ پروبنگ | دہرایا گیا join/leave یا timeout/reconnect لوپس |
| ملٹی اکاؤنٹ کلسٹرز | جوائن ویوز، مشترکہ وارننگ ونڈوز، مشترکہ ناکامی ونڈوز |
| انتباہی برسٹ تناؤ | دہرایا گیا ActorChannelFailure یا محفوظ کرنے کی وارننگ ونڈوز |
| حد سے باہر سیاق و سباق | PlayerData/map/world پڑھنے کے قابل ہونے پر سیاق و سباق |
| محفوظ ٹچ اوورلیپ | ورلڈ سیو سیاق و سباق کو اوورلیپ کرنے والے میپڈ سیشنز |
| شناختی الجھن | وہ نام جنہیں ConnectID میپنگ کی ضرورت ہے |

<a id="why-it-avoids-memory-access"></a>
## یہ میموری تک رسائی سے کیوں گریز کرتا ہے

RandomDayGuard سرور کی ملکیت والی فائلوں سے کام کرتا ہے:

```text
Saved/Logs/*.log
Admin.ini
World saves
PlayerData
Backups
runtime evidence
```

یہ اسے کلائنٹ سائیڈ میموری کی حالت پر کم انحصار کرتا ہے اور گیم اپ ڈیٹس میں کم نازک بناتا ہے۔

Tradeoff:

```text
It cannot prove hidden live actions unless the server writes evidence.
```

<a id="crash-correlated-returners"></a>
## کریش سے متعلقہ واپس کرنے والے

پیٹرن:

```text
Account joins.
Server crashes or restarts.
Same account reconnects quickly.
Pattern repeats.
```

مفید فائلیں:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="rapid-reconnect-probers"></a>
## تیز رفتار سے دوبارہ جڑنے والے پروبرز

پیٹرن:

```text
join -> leave -> join -> leave -> join
```

مفید فائلیں:

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
```

<a id="multi-account-clusters"></a>
## ملٹی اکاؤنٹ کلسٹرز

پیٹرن:

```text
Several accounts join in the same window.
Warnings or crashes follow.
Some accounts rotate or reconnect after restart.
```

مفید فائلیں:

```text
runtime/raid_cases/
runtime/forensic_days/YYYY-MM-DD/raid_cases.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

قاعدہ:

```text
A cluster is not a mass-ban list.
Each account still needs its own evidence.
```

<a id="sticky-backup-recommendation"></a>
## چسپاں بیک اپ کی تجویز

اس کے بعد ایک چسپاں بیک اپ بنائیں:

```text
first full baseline completes
object_registry.json exists
file_manifest.tsv exists
world_state_latest.json has scan_complete=true
Admin.ini is verified
trusted IDs are configured
```

بیک اپ:

```text
RandomDayGuard/config.lua
RandomDayGuard/SavedRoot.txt
RandomDayGuard/runtime/baselines/
RandomDayGuard/runtime/object_registry.json
RandomDayGuard/runtime/world_state/current/world_state_latest.json
Saved/SaveGames/Server/Admin.ini
```

<a id="recovery-model"></a>
## بازیابی ماڈل

```text
Clean install
-> verify live defense
-> complete first baseline
-> create sticky backup
-> run server normally
-> use daily rollups for review
-> restore sticky backup if needed
```
