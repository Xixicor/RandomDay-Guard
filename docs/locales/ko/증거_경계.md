<a id="evidence-boundary"></a>
# 증거 경계

> **표준 영어 소스:** [EVIDENCE_BOUNDARY.md](../../EVIDENCE_BOUNDARY.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


이 페이지를 사용하여 무엇을 결정할지 RandomDayGuard 사람의 검토가 필요한 내용을 보고할 수 있습니다.

<a id="core-rule"></a>
## 핵심 규칙

RandomDayGuard 서버 소유 파일에서 제한된 관찰 결과를 기록합니다. 모든 중요한 결론에 대한 소스, 범위, 컬렉션 상태 및 제한을 식별해야 합니다.

구조화된 증거는 권위가 있습니다. 번역된 보고서는 증거를 설명합니다. 구조화된 기록에 없는 사실은 추가할 수 없습니다.

<a id="evidence-source-classes"></a>
## 증거 소스 클래스

| 소스 클래스 | 일반적인 사용 | 자체적으로 증명하지 않음 |
|---|---|---|
| `admin_ini` | 기존 관리 상태 및 감사 write/readback컨텍스트 | 사고를 일으킨 사람 사건 |
| `active_log` | 현재 server/session 활성 로그에 표시되는 이벤트 | 의도, 소유권 또는 직접적인 피해 |
| `recent_backup_logs` | 기록 로그 컨텍스트 | 현재 이벤트 발생 |
| `playerdata_filenames` | 깨끗한 계정 식별자임을 확증 존재 | 노출된 식별자를 넘어서는 행동, 죄책감 또는 신원 소유권 |
| `existing_cases` | 사전 검토 맥락 | 이전 해석이 정확함 |
| `existing_reports` | 이전 요약 및 결정 | 현재 확증 없는 현재 진실 |
| `existing_evidence` | 역사적으로 구조화된 증거 | 현재 활동 |
| 제한된 세계 저장 스캔 | 느림 world/class컨텍스트 | 플레이어 행동, 소유권, 도난, 복제 또는 손상 |

각 소스는 availability/readability, 파일 수, 소스 참조, 현재 또는 과거 범위 및 명시적인 `does_not_prove`를 기록합니다. 진술.

<a id="source-states"></a>
## 소스 상태

| 상태 | 연산자 의미 |
|---|---|
| `available` | 소스를 읽을 수 있었고 증거가 수집되었습니다. |
| `expected_empty` | 소스를 읽을 수 있었고 합법적으로 일치하는 기록이 없었습니다. |
| `partial` | 일부 증거가 수집되었습니다. 적용 범위가 불완전합니다. |
| `deferred` | 제한된 작업이 의도적으로 연기되었습니다. |
| `unavailable` | 소스가 이 환경에 없습니다. |
| `malformed` | 소스가 존재하지만 안전하게 구문 분석할 수 없습니다. |
| `permission_denied` | 워치독에 읽기 권한이 없습니다. |
| `error` | 기록된 다른 항목에 대한 수집이 실패했습니다. 이유. |

비어 있을 것으로 예상되는 것은 유효한 관찰입니다. 이는 조작된 플레이어, 사건, 사건 또는 고발로 변환되어서는 안 됩니다.

<a id="current-versus-historical-evidence"></a>
## 현재 증거와 과거 증거 비교

현재 증거는 활성 수집 기간 또는 서버 시대에 속합니다. 역사적 증거는 이전 로그, 사례, 보고서, 증거 기록, 백업 또는 기준에서 나옵니다.

역사적 증거는 맥락을 제공할 수 있습니다. 현재 증거의 격차를 조용히 채울 수는 없습니다. 보고서는 두 범위 모두에 라벨을 지정하고 소스를 별도로 인용해야 합니다.

<a id="corroboration-rule"></a>
## 확증 규칙

다음은 유용한 맥락이지만 그 자체로 직접적인 증거는 아닙니다.

- 표시 이름 또는 이름 유사성,
- 시간 일치;
- 탈퇴 연결 끊기 또는 다시 연결,
- 한 번의 충돌 또는 경고 버스트,
- 클래스, 경로, 행위자, 지도 또는 개체 수 토큰,
- 자동으로 그룹화된 사례의 멤버십,
- 현재 소스 확인이 없는 이전 보고서.

실행 사실을 직접적으로 드러내는 증거 없이 죄책감, 의도, 부정 행위, 소유권, 절도, 복제, 직접적인 손상, 직접적인 컨테이너 사용, 직접적인 재고 조치, 정확한 실시간 좌표, 실시간 핑 또는 메모리 수준 동작을 주장하지 마십시오.

<a id="truthful-report-language"></a>
## 진실한 보고 언어

사용:

```text
Observed: the account was active in the recorded crash window.
Interpretation: repeated overlap warrants operator review.
Unknown: the cause of the crash.
Does not prove: that the account caused the crash.
Next action: compare the cited current session and lifecycle records.
```

피해야 할 사항:

```text
The player crashed the server.
The player stole or duplicated items.
The world token proves who used the object.
```

<a id="report-reading-order"></a>
## 보고서 읽기 순서

모든 대중에게 공개되는 보고서는 다음을 설명해야 합니다.

1. 명확한 의미.
2. 중요한 이유.
3. 기술적 증거 및 소스 참조.
4. 다음 조치.
5. 한계, 알 수 없는 사항, 주장 입증되었습니다.
