<a id="ue4ss-loader-and-watchdog"></a>
## UE4SS 로더 및 워치독

`Scripts/main.lua` 독립적인 감시의 시작, 저장된 루트 검색, 현재 로그 테일, 서버 에포크 및 세션, 제한된 폴링 및 스캐닝, object/world 컨텍스트, 검토 채점, `Admin.ini` 안전 게이트, 레거시 운영 출력 및 별도의 보고 작업자 핸드오프. 느린 기록 작업이 독립적으로 재개되는 동안 실시간 폴링을 제한적으로 유지해야 합니다. 하트비트, 시작 표시 또는 증가하는 `poll_id`는 해당 구성 요소만을 증명합니다. 경로 완료에는 동일한 현재 부팅, 에포크, 폴링, 소스 신선도, 보고서 쌍 및 경로 증명이 필요합니다.

소스와 패키지에는 하나의 권한이 있습니다: `RandomDayGuard/Scripts/main.lua`. 소문자 `scripts/` 사본은 소스 트리 또는 릴리스의 일부가 아닙니다. 하나의 표준 철자를 유지하면 Windows 또는 Linux에서 패키지를 추출할 때 대/소문자 충돌 오류를 방지할 수 있습니다.

## 공개 보고 모듈

`Scripts/public_pipeline.lua`은 호스트 자격 증명이나 공급자 어댑터 대신 콜백을 수신합니다. 8개의 소스 클래스를 목록화하고, 최종 상태와 불완전 상태를 기록하고, 현재 플레이어를 보유 기록과 분리하고, 각 경로를 `Observed`, `Interpretation`, `Unknown`, `Does not prove`, `Next action` 및 `Source references`, 그런 다음 경로 증명을 작성합니다. 선택적 알림 모드는 로컬 JSON 봉투에만 씁니다. 배달을 주장하거나 배달 endpoint/bridge.

`tests/lua/public_pipeline_runtime_test.lua`의 실행 가능한 픽스처는 Lua와 함께 이 배송된 모듈을 로드하고, 전체 및 예상되는 비어 있는 경로를 증명하고, 누락된 전류 소스 주기가 실패 처리되었음을 증명하고, 불완전한 경로가 발신 편지함에 들어가지 않음을 증명합니다.

<a id="package-layout"></a>
## 패키지 레이아웃

빌더는 3개의 루트 법적 파일인 `RandomDayGuard/` 위 경로 및 빈 런타임 자리 표시자. 회원을 바이트 단위로 정렬하고 수정합니다 ZIP 메타데이터는 정식 로더를 한 번 패키징하고, 모든 멤버에서 비공개 자료를 검색하고, 모든 멤버에 대해 SHA-256을 기록하고, 이름과 바이트를 하나의 콘텐츠 다이제스트에 바인딩하고, 두 번 빌드합니다. 테스트는 모든 경우 충돌을 거부하고 정상적인 추출이 아카이브 항목당 정확히 하나의 실제 파일을 생성한다는 것을 증명합니다.

공개 저장소는 현재 릴리스 폴더만 유지합니다. 빌더는 ZIP, 체크섬, 메모, 버전 표시 및 소스 트리가 일치하는지 확인합니다.

<a id="code-comment-contract"></a>
## 코드 주석 계약

런타임 주석은 간결한 관리자 계약이며 보조 매뉴얼이 아닙니다. 배송된 각 런타임 모듈은 시작 주석 블록에 하나의 정식 링크를 배치해야 합니다.

```lua
-- Documentation: docs/SOURCE_MODULE_REFERENCE.md#ue4ss-loader-and-watchdog
```

불분명한 상태, 예약, write/readback/rollback, 소스 검색, 번역, 증거, 출력 스키마, 경로 케이던스 및 수정 블록은 해당되는 경우 이러한 레이블과 함께 집중된 주석을 사용합니다.

```lua
-- Public contract: <invariant or consequence>
-- Evidence boundary: <what the input cannot prove>
-- Failure behavior: <how the block fails closed or recovers>
-- Documentation: docs/<canonical-file>.md#<existing-anchor>
```

메인 로더에는 구성 로딩, 저장된 검색, 원자성에 대한 하나의 집중된 소유자 주석도 있습니다. 교체, 시행 및 예약. 이러한 주석은 제어 흐름 및 실패 경계를 나타냅니다. 런타임 동작은 변경되지 않습니다.

유효성 검사기는 각 런타임 모듈에 대한 모듈 수준 `Documentation:` 링크가 필요하고 모든 주석 경로와 앵커를 확인하며 두 런타임 모듈 모두에서 집중된 계약 및 실패 주석이 필요하며 동일한 표준 링크를 `TRACEABILITY_INDEX.json`와 비교합니다. 주석은 추적 가능성이지 런타임 증명이 아닙니다.

<a id="contributor-change-checklist"></a>
## 기여자 변경 체크리스트

1. 하나의 소유 모듈과 해당 집중 설비를 업데이트하세요.
2. 표준 구성, 스키마, 출력, 증거 또는 수명 주기 섹션을 업데이트하세요.
3. 구성 후 `python -B tools/generate_documentation_audit.py --write`실행하세요. 패키지 경로, 생성된 출력 클래스, 소유자 또는 복구 계약 변경.
4. 구성 후 `python -B tools/generate_documentation_audit.py --check`, 집중 단위 테스트, Lua를 사용할 수 있는 실제 Lua 설비, 전체 유효성 검사기, 두 개의 독립적인 결정론적 빌드 및 `git diff --check`.
5. 릴리스를 생성하기 전에 생성된 ZIP 멤버 목록, 체크섬 및 비공개 자료 스캔을 검토하세요.
