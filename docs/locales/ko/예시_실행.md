<a id="worked-operation-examples"></a>
# 실제 작업 예

> **표준 영어 소스:** [EXAMPLE_RUNS.md](../../EXAMPLE_RUNS.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


이 예에서는 발명된 값을 사용하여 예상되는 상태 전환을 설명합니다. 라이브 호환성이나 플레이어 증거가 아닙니다.

<a id="successful-current-cycle"></a>
## 성공적인 현재 주기

입력: 읽기 가능한 활성 로그, version/boot/epoch, `poll_id=41`, 현재 폴링 완료, 쓰기 가능 accounting/history/report 루트, 차단 느린 스캔 정책 없음

예상:

```text
server_status = full
player_activity = full or limited_expected_empty
case_review = full or limited_expected_empty
daily_rollup = full or limited_expected_empty
critical_guard = full or limited_expected_empty
```

활성화된 모든 경로에는 JSON/TXT 출력 및 `route_proof.json`의 동일한 계보. 경로 상태는 일반적인 성공 메시지가 아닌 자체 주제에 따라 다릅니다.

<a id="expected-empty-player-and-case-routes"></a>
## 예상 비어 있는 플레이어 및 케이스 경로

입력: 현재 주기 증명이 완료되었습니다. 현재 또는 유지된 플레이어 행이 없습니다. 보관된 사례도 없고 현재 REVIEW/BAN-ELIGIBLE 계정도 없습니다.

예상:

```text
player_activity.route_proof_status = limited_expected_empty
player_activity.expected_empty = true
player_activity.players = []

case_review.route_proof_status = limited_expected_empty
case_review.expected_empty = true
case_review.cases = []
```

번역된 보고서에 따르면 적격한 제한된 주제가 관찰되지 않았습니다. 그들은 또한 이것이 아무도 연결되지 않았거나 맥락이 누락되지 않았다는 것을 증명하지 못한다고 말합니다. 자리 표시자 player/case가 생성되지 않습니다.

<a id="partial-bounded-scan"></a>
## 부분 경계 스캔

입력: 최신 전류 log/poll; `scan_checkpoint.json` 또는 `scan_progress.json`가 존재합니다. 스캔이 불완전합니다. 기본값 `slow_world_scan_blocks_current_reports=false`.

예상:

```text
world_save_scan.status = partial
source accounting = partial
server_status may still be full for fresh current state
historical routes name the scan limitation
```

운영자가 현재 보고서를 차단하기 위해 선택적 느린 소스를 원하는 경우에만 `slow_world_scan_blocks_current_reports=true`를 설정합니다. 복구는 체크포인트를 삭제하는 것이 아니라 스캔 작업자가 재개되도록 허용하는 것입니다.

<a id="missing-current-cycle-proof"></a>
## 현재 주기 증명 누락

입력: 활성 로그를 사용할 수 없음, `poll_id=0` 또는 boot/epoch/last-poll 계보가 누락되었습니다.

예상:

```text
current_cycle_proof_complete = false
all route proof statuses = missing
each configured route envelope status = suppressed_current_cycle
delivery_eligible = false
delivery_attempted = false
```

숨겨진 봉투는 대기 중인 전달이 아닌 감사 기록입니다. 이전 최종 로그는 기록으로만 남아 있습니다. 첫 번째 누락된 lineage/source 필드를 복구하고 새로운 주기를 생성하세요.

<a id="malformed-optional-adminini-source"></a>
## 잘못된 선택 사항 Admin.ini 소스

입력: `Admin.ini` 존재하지만 완전한 구조 검증에 실패합니다.

예상:

```text
admin_ini.status = malformed
source reference preserved
write/enforcement path closed
```

파일을 보존하고 복원하세요. 검토된 깨끗한 형식입니다. 런타임 증거에 설명 텍스트를 유지합니다. 각 `Admin.ini` 금지 항목만 남습니다 `BannedPlayer=<ID>`.

<a id="required-active-log-probe-error"></a>
## 필수 활성 로그 프로브 오류

입력: 제한된 필수 활성 로그 프로브가 삭제된 읽기 오류로 인해 실패합니다.

예상:

```text
source_accounting.sources[active_log].status = error
source_accounting.sources[active_log].detail = "bounded active-log probe failed: <sanitized reason>"
coverage_status = unavailable
all route proof statuses = missing
```

`error` 제한된 세부 정보가 있는 소스 행에 남아 있습니다. 최상위 보고서는 `unavailable`를 사용하며 새로운 현재 주기가 필요한 소스를 증명할 때까지 경로 증명은 `missing` 유지됩니다.

<a id="incompatible-or-stale-baseline"></a>
## 호환되지 않거나 오래된 기준선

입력: 변경된 package/source ID 또는 stale/incompatible 기준선 매니페스트.

예상: 유효성 검사 또는 런타임 상태가 비호환성을 기록합니다. 스캔 상태는 완료된 재사용을 주장하지 않습니다. 이전 증거를 보존하고, 명시적인 기준 재구축을 시작하고, 새로운 터미널 증명을 기다립니다. 기록된 이유 없이 강제 재구축은 기본 복구가 아닙니다.

<a id="paired-report-write-failure"></a>
## 페어링된 보고서 쓰기 실패

입력: JSON 쓰기는 성공하지만 TXT 쓰기는 실패하거나 그 반대입니다.

예상:

```text
route_proof_status = missing
completed = false
coverage_status = unavailable
output_write_detail = "paired JSON/TXT write failed: <sanitized reason>"
next_action = repair both route output writes
```

작성기는 실패 시 수렴하기 위해 최선을 다해 두 형제를 다시 작성합니다. 성공한 형제자매 중 한 명이 성공 주장으로 남을 수는 없습니다. 제한된 쓰기 세부정보는 다섯 번째 최상위 적용 범위 값을 생성하지 않습니다.

<a id="route-proof-write-failure"></a>
## 경로 방지 쓰기 실패

입력: 경로 쌍이 작성되었지만 `route_proof.json` 대체할 수 없습니다.

예상: 모든 보고서가 다시 작성되고 `missing`, 모든 알림 결과는 `route_proof_write_failed`, 봉투는 허용되지 않습니다. 구성된 경로에는 배달 플래그가 false인 `suppressed_current_cycle` 감사 봉투가 있을 수 있습니다. 출력 루트를 복구하고 동일한 현재 주기를 재생성합니다.

<a id="review-only-enforcement-example"></a>
## 검토 전용 시행 예

구성:

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

예상: 점수, 사례 및 권장 사항이 기록될 수 있습니다. `Admin.ini`는 변경되지 않습니다. 이는 공개 기본값입니다.

<a id="approved-write-success-example"></a>
## 승인된 쓰기 성공 예시

별도로 승인된 테스트만 세 개의 쓰기 스위치를 모두 설정할 수 있습니다. 또한 명확한 숫자 ID, trust/moderator 제외, 임계값 적격성, 유효한 Admin.ini path/parse, 백업 성공, 쓰기 성공, 다시 읽기 동일성 및 계정별 증거를 증명해야 합니다.

예상:

```text
runtime/backups/Admin_<timestamp>_<source-fingerprint>_<clean-ID>.ini
Admin.ini contains one clean BannedPlayer=<ID>
runtime/enforced_bans.jsonl and evidence mirror record success
```

성공적인 예에서는 다른 계정에 대한 자동 시행을 활성화하지 않습니다.

<a id="writereadback-failure-with-rollback"></a>
## Write/readback 롤백 실패

입력: 모든 사전 쓰기 게이트가 통과되었습니다. 대체 쓰기 또는 다시 읽기가 실패합니다. `rollback_on_readback_failure=true` 검증된 백업이 가능합니다.

예상: 실패 증거가 단계를 기록하고 `rollback_success`; 원래 Admin.ini 바이트가 복원되고 계정이 성공적으로 시행된 것으로 보고되지 않습니다. 롤백도 실패하면 쓰기를 중지하고 files/evidence을 모두 보존하고 백업에서 수동으로 복구합니다.

<a id="local-outbox-example"></a>
## 로컬 보낼 편지함 예

입력: `local_file_outbox` 모드에서 알림 활성화, 경로 활성화, 경로 증명 완료, `full` 또는 명시적으로 허용됨 예상-비어 있음.

예상 봉투:

```text
schema = randomdayguard.notification/v1
completed_output = true
status = ready_for_local_consumer
delivery_eligible = true
delivery_backend = none
delivery_attempted = false
```

missing/ineligible 출력, 동일한 경로에 대신 `status=suppressed_current_cycle`, `completed_output=false` 및 `delivery_eligible=false`이 포함될 수 있습니다. 두 파일 모두 로컬 쓰기 전용임을 증명합니다. 제공업체, 전송, 배달 또는 읽음 확인은 번들로 제공되거나 유추되지 않습니다.
