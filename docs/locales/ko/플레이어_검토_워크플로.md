# 플레이어 검토 워크플로

> **표준 영어 소스:** [PLAYER_REVIEW_WORKFLOW.md](../../PLAYER_REVIEW_WORKFLOW.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


이 페이지는 하나의 플레이어, 계정 또는 케이스에 사용하세요. 목적은 자동 고발이 아닌 재현 가능한 검토 결정입니다.

<a id="quick-path"></a>
## 빠른 경로

1. 열기`runtime/final_logs/player_activity_latest.json`.
2. 경로 상태를 확인하세요`runtime/final_logs/route_proof.json`.
3. 현재 관찰 내용과 과거 관찰 내용을 식별합니다.
4. 인용된 ID와 세션 소스 참조를 확인합니다.
5. 추론 전 `case_review_latest.json`상관된 사례가 있는 경우.
6. 작업을 선택하기 전에 알 수 없는 내용과 `does_not_prove`를 기록합니다.
7. 별도의 시행이 아닌 이상 시행을 비활성화된 상태로 둡니다. 게이트가 입증되었습니다.

<a id="1-confirm-route-proof"></a>
## 1. 경로 증명 확인

플레이어 경로를 다음과 같이 해석하세요.

| 상태 | Action |
|---|---|
| `full` | 계속하면서 소스 제한을 검토하세요. |
| `limited_expected_empty` | 실제로 존재하는 주제로만 계속하세요. 누락된 플레이어나 케이스를 만들어내지 마세요. |
| `missing` | 플레이어 결정을 멈추고 경로 문제를 해결하세요. |

건강한 스케줄러는 경로 증명을 대체하지 않습니다.

<a id="2-establish-identity"></a>
## 2. 신원 확립

서버에 노출된 신원 증거와 가능한 경우 PlayerData 파일 이름으로 확증된 깨끗한 계정 식별자를 선호하세요. 원시 소스 참조를 유지합니다.

다음에서 시행하지 마세요:

- 표시 이름만,
- 알림 또는 호스팅 패널에 표시된 이름,
- 타이밍 유사성,
- 매핑되지 않거나 신뢰도가 낮은 ID
- 현재 확증이 없는 과거 보고서.

<a id="3-separate-current-from-historical"></a>
## 3. 과거와 현재를 분리

현재 증거는 활성 보고 기간 또는 서버 시대를 설명합니다. 역사적 증거는 패턴을 설명할 수 있지만 현재 기간의 공백을 자동으로 채울 수는 없습니다.

두 범위를 독립적으로 기록하세요.

```text
Current observations:
Current source references:
Historical context:
Historical source references:
```

<a id="4-review-observations-and-interpretation"></a>
## 4. 관찰 및 해석을 검토하세요

이 보고서 섹션을 명확하게 읽으세요.

```text
observed
interpretation
unknown
does_not_prove
next_action
source_references
```

중요한 결정에 대해 인용된 구조화된 증거를 다시 엽니다. 번역은 탐색과 설명이지 새로운 증거가 아닙니다.

<a id="5-calibrate-the-decision"></a>
## 5. 결정을 보정하세요

| 결정 |  |
|---|---|
| `INFO` | 정상적이거나 낮은 상황의 관찰. |
| `WATCH` | 모니터링할 가치가 있는 약하거나 불완전한 신호. |
| `REVIEW` | 상관 증거에는 관리자 판단이 필요합니다. |
| `BAN-ELIGIBLE` | 깨끗한 신원 및 구성된 증거 임계값은 다음과 같습니다. 만났다; 쓰기 게이트는 여전히 적용됩니다. |
| `AUTO-BANNED` | 시행이 명시적으로 활성화되었으며 백업, 쓰기, 다시 읽기 및 감사가 모두 성공했습니다. |

어떤 결정 레이블도 유죄 또는 의도를 입증하지 못합니다.

<a id="6-apply-the-evidence-boundary"></a>
## 6. 증거 경계 적용

충돌, 재연결, 경고, object/class 토큰 및 사례 그룹화를 통해 검토를 지원할 수 있습니다. 그것만으로는 부정행위, 도난, 복제, 소유권, 직접적인 피해 또는 사건 인과관계를 입증할 수 없습니다.

신원 확인, 구문 분석, 백업, 쓰기, 다시 읽기 또는 롤백이 약하거나 실패하는 경우 강제 종료해야 합니다.
