# 여기에서 시작: 첫 번째 Guard 보고서 읽기

> **표준 영어 소스:** [START_HERE.md](../../START_HERE.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


이 가이드는 RandomDayGuard가 설치되고 활성화된 후에 시작됩니다. 이는 새로운 운영자에게 소스 코드, 패키지 내부 또는 시스템 전용 상태 파일을 검사하도록 요청하지 않고도 유용한 결과를 입증합니다.

<a id="what-happens-after-the-server-starts"></a>
## 서버가 시작된 후 발생하는 일

Guard는 게임 서버와 UE4SS 로드를 기다린 후 서버의 사용 가능한 기록을 찾고 제한된 백그라운드 스캔을 시작합니다. 이전 기록이 계속 색인화되는 동안 현재 서버 상태를 보고할 수 있습니다.

에 의해 생성됩니다. 첫 번째 보고서는 **서버 상태**입니다. Guard가 지금 모니터링 주기를 완료하는지 여부, 현재 서버 실행이 시작된 시기(해당 타임스탬프를 사용할 수 있는 경우), active/rotated 로그 및 스캔 적용 범위, 연결된 플레이어 수, 누락된 소스 그룹, 운영자 작업이 필요한지 여부에 대해 답변합니다.

아직 진행 중인 백그라운드 스캔은 자동 시작 실패가 아니라 기록 적용 범위에 대한 제한 사항입니다. Guard는 검사 커서, 완료된 파일, 검색된 파일 및 마지막 진행 시간을 기록합니다. 반복되는 모니터링 주기에서 해당 값이 더 이상 변경되지 않으면 기록 경로를 정지된 것으로 간주하고 문제 해결의 검색 분기를 따르십시오. 이전 기록이 불완전하다는 이유만으로 현재 로그 및 세션 결과를 삭제하지 마십시오.

<a id="read-the-first-server-status-report"></a>
## 첫 번째 서버 상태 보고서를 읽습니다.

1. 전용 서버를 정상적으로 시작합니다.
2. 게임 서버 및 UE4SS 시작이 완료될 때까지 기다립니다.
3. 열기RandomDayGuard's 최종 보고서 폴더를 선택하고 읽을 수 있는 최신 서버 상태 보고서를 선택하세요.
4. 보고서에 다음 내용이 포함되어 있는지 확인하세요:
   - **요약**
   - **Guard가 관찰한 내용**
   - **의미**
   - **알려지지 않은 사항**
   - **권장되는 다음 단계**
   - **기술 기록**
5. **Guard가 관찰한 내용**의 양, 최신 모니터링 주기 진행을 확인하고 사용 가능한 로그, 스캔, 플레이어 및 소스 적용 범위에 대한 보고서 이름을 확인합니다.
6. 다음 단계에서 개입이 필요하지 않다고 나오면 보고서를 첫 번째 성공적인 결과로 유지하세요. 소스가 누락되었거나 프로세스가 중지된 경우 [문제 해결](%EB%AC%B8%EC%A0%9C_%ED%95%B4%EA%B2%B0.md).

보고서는 심층적인 검토를 위해 기술적 증거로 연결될 수 있습니다. 일반 운영자는 보고서를 먼저 읽고 일반 결과를 확인해야 하는 경우에만 해당 참조를 열 수 있습니다.

<a id="understand-quiet-reports"></a>
## 소리 없는 보고서 이해하기

플레이어 활동, 사례 검토, Critical Guard는 이벤트 중심입니다. 조용한 서버는 단지 채널을 채우기 위해 가상의 플레이어, 케이스 또는 실패를 생성해서는 안 됩니다. 읽을 수 있는 결과에는 출처가 확인되었으며 해당 보고서에는 아무것도 포함되지 않은 것으로 나타날 수 있습니다.

일일 롤업은 다릅니다. 당일 세션, 현재 리뷰 주제, 보관된 내용을 사용하여 보고 날짜당 하나의 리뷰를 제공합니다. identity/case Guard가 실제로 읽을 수 있는 컨텍스트, 스캔 진행률 및 소스 간격입니다. 사용 가능한 서버 기록에 없는 사실은 추정되지 않고 알 수 없는 상태로 남아 있습니다.

<a id="test-one-ordinary-player-session"></a>
## 일반 플레이어 세션 하나를 테스트하세요

첫 번째 서버 상태 보고서가 현재 상태인 후:

1. 알려진 플레이어 한 명을 정상적으로 참가하고 나가게 합니다.
2. 다음 보고 주기를 기다리세요.
3. 플레이어 활동을 엽니다.
4. Guard가 사용할 수 있는 계정 또는 표시 이름, 참여 및 종료 시간, 정상 또는 불완전한 세션 결과, 사용 가능한 경우 이전 기록, 다음 작업 하나를 식별하는지 확인하세요.

세션 보고서에는 관찰된 데이터가 포함되어야 합니다. 파일 이름 목록이나 기록이 존재한다는 일반적인 설명으로 대체해서는 안 됩니다.
