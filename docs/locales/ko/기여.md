# 기여

> **표준 영어 소스:** [CONTRIBUTING.md](../../../CONTRIBUTING.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


RandomDayGuard 파서, 문서, 테스트 및 공개 안전 검증에 대한 집중적이고 재현 가능한 개선 사항을 수용합니다. 모든 변경 사항은 공개 프로젝트 계약에 국한되고 검토 우선 동작을 유지해야 합니다. Guard는 이미 `Admin.ini` 변경하지 않고 그대로 두어야 합니다.

<a id="prepare-a-safe-workspace"></a>
## 안전한 작업 공간을 준비하세요

1. 저장소를 포크하거나 복제하고 집중 브랜치를 생성하세요.
2. 지원되는 Python 3 인터프리터를 설치하세요. Lua를 변경할 때 Lua 컴파일러를 설치하여 `luac -p` 구문을 확인할 수 있도록 하세요.
3. 읽기 [문서 홈](%EB%AC%B8%EC%84%9C%ED%99%94.md), [아키텍처](%EC%95%84%ED%82%A4%ED%85%8D%EC%B2%98.md) 및 [증거 경계](%EC%A6%9D%EA%B1%B0_%EA%B2%BD%EA%B3%84.md)변경할 영역에 대한 정보입니다.
4. 편집하기 전에 `git status`검사하고 관련 없는 작업을 보존하세요.
5. 합성 또는 위생 처리된 설비만 사용하세요.

개인 서버 로그, 저장된 폴더, 플레이어 식별자, `Admin.ini`, 개인 알림 엔드포인트, 자격 증명, 개인 경로, 런타임 출력 또는 복사된 실시간 증거를 절대 제출하지 마세요.

<a id="make-a-focused-change"></a>
## 중점적으로 변경하세요

- 기존 이름 지정, 형식, 안전 확인 및 모듈 소유권을 따르세요.
- 각 절차 또는 정확한 사실에 대해 한 명의 표준 문서 소유자를 유지하세요.
- 동작이나 공개 출력이 변경되면 사용자 문서와 예시를 업데이트하세요.
- 실현 가능한 경우 버그 수정을 위한 회귀 테스트를 추가하세요.
- 계정 확인, 신뢰할 수 있는 계정 보호, 백업 확인, 외부 변경 감지, 저장된 파일 비교, 복구 또는 검토 전용 기본값을 약화시키지 마세요. 테스트 통과.

<a id="run-the-relevant-checks"></a>
## 관련 검사 실행

문서 전용 변경의 경우 다음을 실행하세요.

```powershell
python -B tools\generate_documentation_audit.py --check
python -B -m unittest discover tests -p "test_documentation*.py"
git diff --check
```

소스, 구성, 패키징 또는 테스트 변경의 경우 [검증 및 출시 검토](%EA%B2%80%EC%A6%9D_%EB%B0%8F_%EB%A6%B4%EB%A6%AC%EC%8A%A4.md)(Lua 구문 검사, 저장소 유효성 검사, 공개 파이프라인 테스트 및 전체 단위 테스트 모음 포함) 건너뛰었거나 사용할 수 없는 모든 검사를 보고합니다. 통과했다고 설명하지 마세요.

<a id="submit-the-change-for-review"></a>
## 검토를 위해 변경 사항 제출

전체 차이점을 검토한 후에만 집중된 끌어오기 요청을 엽니다. 포함:

- 문제 및 의도된 동작,
- 변경된 정확한 파일 및 공개 계약,
- 명령 실행 및 결과,
- 개인 정보 보호, 호환성 및 시행 영향 및
- 나머지 제한 사항 또는 후속 작업.

변경 사항에서 명시적으로 요구하고 검증하지 않는 한 생성된 런타임 증거 또는 릴리스 아카이브를 포함하지 마세요. 기여는 릴리스, 배포, 라이브 서버 테스트, 강제 조치 또는 제3자 사이트에 대한 게시를 승인하지 않습니다.

다음을 통해 취약점을 신고하세요[개인 보안 경로](%EB%B3%B4%EC%95%88.md), 공개 문제나 일반적인 풀 요청이 아닙니다.
