# 작업 플레이북

> **표준 영어 소스:** [OPERATIONS_PLAYBOOK.md](../../OPERATIONS_PLAYBOOK.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


이것은 RandomDayGuard. 알 필요는 없습니다 JSON, Git, 체크섬 또는 명령줄 도구를 사용하여 정상적인 서버를 검토하세요.

<a id="daily-operator-flow"></a>
## 일일 운영자 흐름

1. 열기`runtime/final_logs/server_status_latest.txt`. Guard가 현재 서버 실행을 모니터링하는지 여부, 마지막 주기가 언제 완료되는지, 연결된 플레이어 수, 소스 또는 스캔이 완료되지 않았는지 여부를 알려줍니다.
2. 열기`runtime/final_logs/daily_rollup_latest.txt` 하루에 한 번. 모든 개별 기록을 반복하지 않고 당일 세션, 종료, 명명된 사례 작업, 신원 목록 및 소스 적용 범위를 요약합니다.
3. 열기`runtime/final_logs/player_activity_latest.txt` 하루 동안 서버에 참여, 종료 또는 활성 세션이 있었던 경우에만.
4. 열기`runtime/final_logs/case_review_latest.txt` 현재 주제의 이름이 지정된 경우에만. 보고서는 다음에 열 계정, 검토 상태, 점수, ID 소스 및 기록을 제공합니다.
5. 열기`runtime/final_logs/critical_guard_latest.txt` Guard가 자체 시작, 모니터링 주기 또는 보고서 쓰기 오류를 보고하는 경우에만 해당됩니다.

경로에 보고할 내용이 없으면 Guard는 예상되는 비어 있는 결과를 기록합니다. 이는 누락된 보고서가 아니라 완료된 확인입니다.

<a id="what-to-read-inside-a-report"></a>
## 보고서 내에서 읽을 내용

다음 섹션을 순서대로 읽으십시오:

1. **요약** - 이 보고서에서 다루는 내용.
2. **Guard가 관찰한 내용** - 이 경로에 대해 수집된 실제 타임스탬프, 개수, 계정, 세션 또는 상태 값.
3. **의미** - 해당 기록에 대한 일반 언어 해석.
4. **알려지지 않은 사항** - 결과에 영향을 미치는 소스 또는 스캔 제한.
5. **권장되는 다음 단계** - 명명된 주제를 모니터링하거나 검토할지 또는 Guard를 수리할지 여부.
6. **증거 경계** - 보고서의 제한 범위.

정확하게 구조화된 증거를 검사해야 하는 독자를 위해 기술 기록 및 소스 참조가 끝에 표시됩니다.

<a id="when-a-report-is-missing"></a>
## 보고서가 누락된 경우

열기`runtime/final_logs/route_proof.json` 읽을 수 있는 보고서가 없거나 현재 증거가 누락되었다고 표시되는 경우에만 해당됩니다. 각 경로에는 다음 결과 중 하나가 있습니다.

| 결과 | 의미 |
|---|---|
| `full` | Guard가 현재 경로 소유 증거로 경로를 완료했습니다. |
| `limited_expected_empty` | Guard가 경로를 완료했지만 적격 이벤트를 발견하지 못했거나 명명된 성숙도 제한을 기록했습니다. |
| `missing` | 필수 소스, 계보 확인 또는 쌍을 이루는 보고서 작성이 완료되지 않았습니다. |

경로가 누락된 경우 명명된 소스를 따르거나 보고서에 오류를 기록하세요. 관련 없는 경로 또는 알림 설정을 먼저 변경하지 마십시오.

<a id="after-a-crash-or-restart"></a>
## 충돌 또는 다시 시작 후

1. 새 서버 실행 타임스탬프 및 최근 완료된 모니터링 주기에 대한 서버 상태를 읽습니다.
2. 현재 시작 또는 폴링 실패에 대해 Critical Guard를 읽습니다.
3. 라이프사이클 이후 당일 세션이 참여하거나, 나가거나, 반환된 경우에만 플레이어 활동을 읽습니다. 변경하세요.
4. 구성을 변경하기 전에 인용된 소스 기록을 보존하세요.

<a id="before-enabling-optional-adminini-writes"></a>
## 선택적 Admin.ini 쓰기를 활성화하기 전에

기본 패키지는 `Admin.ini`. 고급 운영자는 파일 복사본에 대해 테스트한 후 선택적 적용 경로를 활성화할 수 있습니다. 그런 다음 Guard는 깨끗한 숫자 계정 ID를 요구하고, 신뢰할 수 있는 계정을 보호하고, 백업을 생성 및 확인하고, 동시 변경 사항을 거부하고, 저장된 파일을 다시 읽고, 확인이 실패할 경우 백업을 복원합니다. 전체 설정 및 테스트 절차는 [`ADMIN_INI_ENFORCEMENT.md`](%EA%B4%80%EB%A6%AC%EC%9E%90_INI_%EC%8B%9C%ED%96%89.md)를 참조하세요.
