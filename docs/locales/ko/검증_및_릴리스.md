# 검증 및 릴리스

> **표준 영어 소스:** [VALIDATION_AND_RELEASE.md](../../VALIDATION_AND_RELEASE.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


이 페이지는 기여자와 릴리스 관리자를 위한 것입니다. 서버 운영자는 설치를 위해 이러한 명령을 실행할 필요가 없습니다. RandomDayGuard.

<a id="user-visible-proof"></a>
## 사용자에게 표시되는 증거

새로운 운영자가 릴리스를 설치할 수 있고, 첫 번째 서버 상태 보고서를 찾고, 5개의 보고서 경로를 구별하고, 실제 사례에서 하나의 명확한 조치를 따를 수 있으면 릴리스를 이해할 수 있습니다. 리더 작업에는 Git, PowerShell, Python 또는 체크섬 지식이 필요하지 않습니다.

<a id="contributor-checks"></a>
## 기여자 확인

```powershell
python -B tools/validate_repo.py
python -B tools/test_public_pipeline.py
python -B -m unittest discover tests
```

`luac`을 사용할 수 있는 경우:

```powershell
luac -p RandomDayGuard/Scripts/main.lua
luac -p RandomDayGuard/Scripts/public_pipeline.lua
```

Lua 픽스처 테스트는 로더, 스케줄러, 보고서 경로 및 선택적 Admin.ini 쓰기 트랜잭션을 다룹니다. 시행 픽스처는 임시 파일만 사용하고 신원, 신뢰할 수 있는 계정 거부, 임계값, 백업, 동시 변경 거부, 다시 읽기 및 롤백을 확인합니다.

<a id="package-proof"></a>
## 패키지 증명

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

- 모든 버전 표시가 일치합니다. `VERSION`.
- `releases/`.
- ZIP 표준 `RandomDayGuard/Scripts/main.lua` 경로가 포함되어 있으며 소문자 변형 로더는 포함되어 있지 않습니다.
- 런타임 출력, 비공개 구성, 자격 증명, 로컬 경로, 캐시 및 테스트 아티팩트는 제외됩니다.
- 공개 구성은 시행이 비활성화된 검토 전용으로 유지됩니다.
- 작업된 5개의 보고서 예는 경로 소유권 및 릴리스 테스트 픽스처와 일관성을 유지합니다.
- ZIP 바이트가 결정적이고 일치합니다 `CHECKSUMS.sha256`.
- 모든 로컬 문서 링크와 27개의 로케일 항목 페이지가 검증됩니다.

<a id="avoid-validation-environment-pitfalls"></a>
## 검증 환경의 함정을 피하세요

- 저장소 쓰기 검사를 순차적으로 실행하여 임시 파일 경합을 방지하세요.
- Windows에서는 중복 로더를 확인할 때 대소문자를 구분하지 않는 파일 조회보다는 보관된 멤버 이름이나 열거된 경로 철자를 검사하세요.
- 누락된 `luac` 명령 또는 Lua 런타임은 사용할 수 없는 기능이지 구문이나 런타임 테스트를 통과한 것이 아닙니다.
- 픽스처는 모델링된 입력만 증명합니다. 라이브 서버가 현재 보고서를 생성했음을 증명하지는 않습니다.
- 완료를 가정하는 대신 명령 시간 초과 및 부분 출력을 기록합니다.

<a id="repair-failed-repository-validation"></a>
## 실패한 저장소 검증 복구

처음 보고된 경로 또는 계약으로 시작하세요. 해당 항목을 수정하고 좁은 테스트를 다시 실행한 다음 전체 매트릭스를 다시 실행하세요. 필요한 테스트를 제거하여 누락된 기능을 숨기지 마십시오.

<a id="known-limits-and-release-decision"></a>
## 알려진 제한 및 릴리스 결정

로컬 검사를 통해 소스, 픽스쳐, 패키지 및 문서 계약을 입증합니다. 특정 서버 설치, 장기 실행 안정성 창 또는 클라이언트 표시에는 별도의 통합 결과가 필요합니다. 일치하는 주장을 하기 전에 해당 결과를 빌드, 구성, 기간 및 관찰된 출력과 함께 기록하십시오.
