# RandomDayGuard 한국어 안내

> [!IMPORTANT]
> ## 프로젝트 상태 — RandomDay 테스트 종료
>
> RandomDay 테스트 운영이 완료되었으며 공개 테스트 서버는 곧 종료됩니다.
>
> 이번 운영에서 RandomDay와 RandomDayGuard는 반복적인 프로필 순환, 정상 및 중단된 서버 재시작, 복구와 롤백 점검, 확장 모드 통합, 서버 증거 수집, 운영자 보고서 검토를 함께 거쳤습니다.
>
> 이를 통해 목표했던 지식을 얻었습니다. 실제 전용 서버 수명 주기 전체에서 순환 sandbox 프로필이 어떻게 작동하는지, RandomDay가 지원되는 확장 모드와 어떻게 상호작용하는지, 그리고 RandomDayGuard가 누락이나 추측을 사실로 제시하지 않으면서 서버가 기록한 증거를 어느 정도까지 유용하고 신중한 모니터링으로 바꿀 수 있는지 확인했습니다.
>
> **테스트 서버에서 사용한 구성:**
>
> - RandomDay 비공개 개발 빌드 `v0.41.76`
> - RandomDayGuard 비공개 개발 빌드 `v0.46.130`
> - Chaotic Spawn Engine / DynamicSpawns `0.8.5 Hotfix 1`
> - Lethal Lasers `1.0 UE4SS`
> - ANTE Up `0.26`
> - Encounter Director integration — RandomDay가 소유한 DynamicSpawns 확장이며 별도로 배포되는 모드가 아님
> - UE4SS `v3.0.1 Beta #0` (Git `01e0a584`; Nexus `v3.0.1-940-g01e0a584`)
> - Abiotic Factor 전용 서버 `1.4.0.27939`
>
> 현재 공개된 패키지는 계속해서 RandomDay `v0.3.16-alpha`와 RandomDayGuard `v0.4.12-alpha`입니다.
>
> 두 프로젝트의 개발은 현재 일시 중지되었습니다. 기존 릴리스와 문서는 계속 제공되며, 다시 이 작업을 이어가고 싶을 때 돌아올 수 있습니다.
>
> 이 구성은 운영 중 사용된 항목을 기록한 것입니다. 최소 버전 요구 사항이나 이후 게임, loader 또는 모드 버전과의 호환성 보장이 아닙니다. 마지막으로 공식 기록된 주기에서는 Abiotic Factor `1.4.0.27939`를 사용했습니다.

**v0.4.12-alpha**

RandomDayGuard는 Abiotic Factor 전용 서버에서 범위가 제한된 증거를 수집하여
운영자가 읽기 쉬운 보고서로 정리합니다. 서버 상태, 일일 요약, 플레이어 활동,
사례 검토, 심각한 오류는 서로 다른 경로로 출력됩니다.

## 설치

[설치 안내](%EC%84%A4%EC%B9%98.md)를 따르십시오. 모드 위치는
`ue4ss/Mods/RandomDayGuard`이며 `mods.txt`에는 `RandomDayGuard : 1`이 있어야
합니다. 중첩 설치와 중복 `Scripts` 폴더를 제거하십시오.

## 첫 보고서 확인

`runtime/current/startup_status.json`,
`runtime/final_logs/latest_dossier.json`,
`runtime/final_logs/route_proof.json` 순서로 확인하십시오. 각 경로는 `full`,
`limited_expected_empty`, `missing` 중 하나를 표시합니다. 읽기용 요약과 인용된
원본은 같은 처리 주기에 속해야 합니다.

## 설정과 운영

공개 기본값은 `review_only_mode = true`, `auto_ban = false`,
`write_admin_ini = false`입니다. [시작](%EC%97%AC%EA%B8%B0%EC%84%9C_%EC%8B%9C%EC%9E%91.md),
[운영](%EC%9E%91%EC%97%85_%ED%94%8C%EB%A0%88%EC%9D%B4%EB%B6%81.md), [설정](%EA%B5%AC%EC%84%B1_%ED%94%84%EB%A1%9C%ED%95%84.md),
[문제 해결](%EB%AC%B8%EC%A0%9C_%ED%95%B4%EA%B2%B0.md)을 참고하십시오. 구조화된 증거가 기술 기록이며
번역 계층은 이를 읽기 쉽게 보여 줍니다.

명령, 경로, 키, 상태 값은 실제 파일과 맞도록 영어를 유지합니다.

## 알파 릴리스와 두 증거 경로

이 버전은 알파입니다. 문서화된 수집, 보고, 복구 경로는 테스트했으며 호환성, 과거 범위, 보고서 품질은 계속 개선 중입니다.

현재 경로는 활성 로그, 현재 시작 및 스케줄러 상태, 현재 세션을 사용하므로 현재 보고서를 바로 작성할 수 있습니다. 과거 경로는 보관 로그, PlayerData 파일명, 기존 증거와 사례를 제한된 단계로 확인합니다.

`runtime/current/report_worker_status.json`

여러 주기 동안 `runtime/current/report_worker_status.json`의 `scan_cursor`와 `last_progress_ts`를 비교하세요. 진행되면 스캔 중입니다. 현재 보고서는 진행되는데 두 값이 그대로라면 과거 스캔이 멈춘 것입니다. 현재 사실은 사용할 수 있지만 과거 기록이 필요한 결론은 제한됩니다.
