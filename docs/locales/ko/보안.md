<a id="security-policy"></a>
# 보안 정책

> **표준 영어 소스:** [SECURITY.md](../../../SECURITY.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


<a id="report-a-vulnerability-privately"></a>
## 비공개로 취약성을 보고하세요.

사용[GitHub 비공개 취약점 보고](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) to send a confidential report to the repository owner. 해당 양식을 사용할 수 없는 경우 [소유자 공개 GitHub 프로필](https://github.com/Xixicor) 취약점 세부정보를 포함하지 않고 비공개 연락 채널을 요청하세요.

악용 단계, 자격 증명, 개인 서버 경로, 플레이어 식별자, `Admin.ini`, 저장된 데이터, 웹훅 URL 또는 실시간 증거 파일이 포함된 공개 문제를 공개하지 마세요.

<a id="include-useful-evidence"></a>
## 유용한 증거를 포함하세요

제공:

- 영향을 받은 RandomDayGuard 버전 또는 커밋;
- 영향을 받은 구성 요소 및 예상되는 안전한 동작,
- 삭제된 장치를 사용한 최소 재생 단계,
- 관찰된 영향 및 반복 가능 여부 그리고
- 개인 데이터를 노출하지 않는 완화 제안.

실제 비밀을 보내지 마세요. 문제를 재현하는 데 필요한 구조를 유지하면서 개인 경로, 계정 식별자, 호스트 이름 및 토큰을 명확한 자리 표시자로 바꾸세요.

<a id="expect-review-first-handling"></a>
## 검토 우선 처리를 기대하세요

보고서는 서버 액세스 권한 부여, 라이브 대상 테스트, 익스플로잇 세부 정보 게시 또는 실패 시 닫힘 기본값 약화에 대한 증거가 아니라 유지 관리 담당자 검토를 위한 증거입니다. 소유자는 범위를 확인하고 비공개 보고서를 통해 모든 공개를 조정합니다.
