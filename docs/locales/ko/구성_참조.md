# 구성 개념

> **표준 영어 소스:** [CONFIG_REFERENCE.md](../../CONFIG_REFERENCE.md). 이 현지화된 문서는 정확한 명령, 경로, 키, 상태 값, 해시 및 파일 이름을 보존합니다. 기술적인 표현이 다를 경우 영어 소스를 사용하세요.


이 설명에서는 각 주요 구성 영역이 제어하는 내용, 실행 시기, 증거 및 안전 게이트와 상호 작용하는 방식을 설명합니다. 정확한 현장 카탈로그 또는 프로필 절차를 소유하지 않습니다.

작업 중심 사전 설정 및 안전한 변경 단계를 보려면 [`CONFIG_PROFILES.md`](%EA%B5%AC%EC%84%B1_%ED%94%84%EB%A1%9C%ED%95%84.md)을 사용하세요. 모든 정확한 소스 필드, 기본값, 유형, 불변, 출력 효과 및 복구 규칙에 대해 생성된 [`CONFIG_FIELD_CATALOG.md`](%EA%B5%AC%EC%84%B1_%ED%95%84%EB%93%9C_%EC%B9%B4%ED%83%88%EB%A1%9C%EA%B7%B8.md)를 사용하세요. 유효성 검사기는 배송된 모든 항목에 대해 하나의 행이 필요합니다. `config.lua` 리프 필드에 대해 하나의 행이 필요합니다.

<a id="top-level-safety"></a>
## 최상위 안전

| 옵션 | 기본값 | 의미 |
|---|---:|---|
| `enabled` | `true` | 마스터 스위치 Guard |
| `enforcement.review_only_mode` | `true` | Record/recommend 전용 |
| `enforcement.auto_ban` | `false` | 기본적으로 자동 차단 안 함 |
| `enforcement.write_admin_ini` | `false` | 기본적으로 Admin.ini 쓰지 않음 |

서버 소유자가 출력을 검토할 때까지 이를 안전하게 보관하십시오.

<a id="saved"></a>
## `saved`

경비원이 서버를 찾는 방법 `Saved/` 폴더 및 파일 계열을 제어합니다. 스캔할 수 있습니다.

사용할 경우:

```text
Saved root auto-detection fails.
World folder changed.
Provider or container path is unusual.
```

확인:

```text
runtime/saved_path_probe.json
RandomDayGuard/SavedRoot.txt
```

규칙:

```text
SavedRoot.txt -> AbioticFactor/Saved
not -> Worlds/<WorldName>
```

<a id="log_tail"></a>
## `log_tail`

실시간 로그 읽기를 제어합니다.

유용한 옵션:

| 옵션 | 안전한 값 | 이유 |
|---|---|---|
| `enabled` | `true` | 실시간 방어에 필요 |
| `start_at_end_on_first_run` | `true` | 오래된 로그를 라이브 이벤트로 방지 |
| `tail_backup_logs` | `false` | 백업 로그는 라이브가 아닌 기록입니다 |
| `max_lines_per_poll` | 제한적 | 폴링 루프의 응답성을 유지합니다. |

확인:

```text
runtime/log_offsets.tsv
runtime/evidence/session_events.jsonl
runtime/current/poll_status.json
```

<a id="runtime"></a>
## `runtime`

폴링 및 예산을 제어합니다.

기본 상태 규칙:

```text
poll_id increases
poll_in_flight returns false
poll_scheduled is true
```

확인:

```text
runtime/current/poll_status.json
```

`poll_id`중지되면 무엇인가가 루프를 차단하고 있는 것입니다.

<a id="source_accounting"></a>
## `source_accounting`

명시적인 증거 소스 적용 범위 및 범위를 제어합니다.

| 키 | 기본값 | 의미 |
|---|---:|---|
| `enabled` | `true` | 공개 경로 보고서에 대한 소스 계정을 작성합니다. |
| `require_terminal_status` | `true` | 각 소스가 명시적 터미널을 노출하거나 불완전해야 합니다. 상태. |
| `distinguish_current_from_historical` | `true` | 현재 증거와 과거 증거를 별도로 유지합니다. |
| `slow_world_scan_blocks_current_reports` | `false` | 현재 보고서에서 제한된 세계 스캔이 연기되었거나 부분적이라고 명시할 수 있습니다. |
| `changed_file_manifest` | 기준 매니페스트 경로 | 제한된 historical/world 회계에 사용되는 참조입니다. |

소스 상태는 `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied` 또는 `error`.

설정 `source_accounting.enabled = false` 상태 출력을 자동으로 제거하지 않습니다. 파이프라인은 여전히 ​​`runtime/final_logs/source_accounting_latest.json`를 씁니다. 또한 사용할 수 없는 회계로 과거 상태 레코드를 기록합니다. 소스 계정은 보고서 계약의 일부이므로 모든 경로는 `enabled=false`, `status="unavailable"` 및 `disabled_reason="source_accounting_disabled"`를 사용하여 `missing`로 닫히지 않습니다. 계정이 비활성화된 동안에는 어떤 경로도 완료된 것으로 간주되지 않습니다.

<a id="reports"></a>
## `reports`

일반 로컬 보고 파이프라인을 제어합니다.

기본값은 5개 경로를 모두 활성화하고 `runtime/final_logs`:

```text
server_status
daily_rollup
player_activity
case_review
critical_guard
```

에 쓰기입니다. 각 경로는 `route_proof.json`에 구조화되고 번역된 출력과 증거를 작성해야 합니다. 경로를 비활성화하면 경로가 완료된 척하는 대신 `missing` 증거가 생성됩니다.

<a id="notification"></a>
## `notification`

선택적인 일반 로컬 파일 발신함. 기본적으로 비활성화되어 있으며 외부 공급자에게 아무것도 전송하지 않습니다.

기본값:

```lua
notification = {
    enabled = false,
    mode = "local_file_outbox",
    include_expected_empty = false,
},
```

모든 알림 경로는 기본적으로 비활성화되어 있습니다. 의도적으로 활성화하면 보낼 편지함은 `route_proof.json`가 작성된 후 완성된 번역된 보고서만 사용할 수 있습니다. 현지 증거와 보고서는 여전히 권위가 있습니다. 제공업체별 전송, 전송 엔드포인트, 자격 증명 및 브리지는 공개 독립 감시 계약의 일부가 아닙니다.

<a id="scanning"></a>
## `scanning`

기준 검사, 체크포인트 및 변경된 파일 새로 고침을 제어합니다.

사용할 경우:

```text
building first world baseline
resuming after crash
refreshing changed files later
```

확인:

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/baselines/file_manifest.tsv
```

중요 설정:

```lua
scanning = {
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
    changed_file_detection = true,
},
```

<a id="forensic_rollup"></a>
## `forensic_rollup`

빠른 일일 업로드 패키지와 최종 일반 언어 로그를 제어합니다.

출력:

```text
runtime/current/forensic_today.json
runtime/current/forensic_today.md
runtime/current/forensic_today.txt
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

사용할 경우:

```text
You want one daily folder that summarizes what happened.
You want a plain-language TXT to upload for quick analysis.
```

확인:

```text
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

규칙:

```text
Daily summaries are rebuildable indexes.
Source evidence remains authoritative.
```

<a id="logging"></a>
## `logging`

이벤트 볼륨 및 중요도가 낮은 집계를 제어합니다.

사용할 경우:

```text
actor-touch events are noisy
raw event files grow too quickly
```

안전 패턴:

```lua
logging = {
    low_importance_mode = "aggregate",
    write_low_importance_raw_events = false,
},
```

<a id="retention"></a>
## `retention`

파일이 보관되는 기간과 JSONL 로그 회전 시기를 제어합니다.

사용할 경우:

```text
disk usage grows too fast
you need more audit history
you need shorter live-history windows
```

중요 옵션:

```text
detailed_retention_days
rotate_jsonl_when_bytes_exceed
max_raw_events_lines
keep_enforced_forever
keep_evidence_forever
```

## `crash_correlation`

반복되는 검토를 제어합니다. crash/reconnect검토.

안전한 기본값:

```lua
crash_correlation = {
    single_crash_never_bans = true,
    require_same_account = true,
```

```text
server_crash_overlap_count
post_crash_reconnect_count
unclean_disconnect_count
```

```lua
join_leave = {
    churn_alone_never_bans = true,
```

## `raid_detection`

```text
A raid case groups accounts for review.
```

```text
runtime/object_registry_partial.json
runtime/object_registry.json
```

```text
Object/class context is not a ban reason by itself.
```

<a id="world_state"></a>
## `world_state`

제어 boot/current/session 세계 상태 스냅샷.

출력:

```text
runtime/world_state/current/world_state_latest.json
runtime/world_state/sessions/<date>/<session_id>_<account_id>/
```

<a id="enforcement"></a>
## `enforcement`

권장 사항 및 실제 Admin.ini 쓰기를 제어합니다.

Guard가 차단을 추가하기 전에 아래의 모든 설명이 true여야 합니다.

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
account identity is mapped
not trusted
not moderator
threshold is met
```

한 가지 설명이 거짓이거나 확인할 수 없는 경우 Guard는 `Admin.ini` 변경하지 않고 이유를 기록합니다.

<a id="admin_ini"></a>
## `admin_ini`

안전한 파일 쓰기를 제어합니다.

규칙:

```text
Back up before writing.
Preserve existing bans.
Preserve moderators.
Write clean BannedPlayer=<ID> only.
```

<a id="restart_request"></a>
## `restart_request`

다른 운영자 소유 프로세스가 검사할 수 있는 선택적 로컬 마커 파일을 제어합니다. 서버를 다시 시작하거나 종료하지 않습니다.

기본값:

```lua
restart_request = {
    enabled = false,
    restart_marker_file = "runtime/request_restart.flag",
    restart_reason_file = "runtime/restart_reason.json",
},
```

출력:

```text
runtime/request_restart.flag
runtime/restart_reason.json
```

호스팅 패널, 공급자 브리지 또는 다시 시작 자동화가 번들로 제공되지 않습니다. 마커 생성을 활성화해도 외부 프로세스가 요청을 소비했거나 서버를 다시 시작했다는 사실이 입증되지는 않습니다.
