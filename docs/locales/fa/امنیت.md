# خط مشی امنیتی

> **منبع انگلیسی متعارف:** [SECURITY.md](../../../SECURITY.md). این اسناد بومی سازی شده دستورات، مسیرها، کلیدها، مقادیر وضعیت، هش ها و نام فایل ها را دقیق حفظ می کند. اگر عبارت فنی متفاوت است، از منبع انگلیسی استفاده کنید.


<a id="report-a-vulnerability-privately"></a>
## یک آسیب پذیری را به صورت خصوصی گزارش کنید

از [GitHub گزارش آسیب‌پذیری خصوصی](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) برای ارسال گزارش محرمانه به صاحب مخزن. اگر آن فرم در دسترس نیست، از [عمومی مالک GitHub نمایه](https://github.com/Xixicor) برای درخواست یک کانال تماس خصوصی بدون درج جزئیات آسیب‌پذیری.

موضوع عمومی حاوی مراحل بهره برداری، اعتبارنامه ها، مسیرهای سرور خصوصی، شناسه های پخش کننده، `Admin.ini`، داده‌های ذخیره‌شده، نشانی‌های وب هوک یا فایل‌های شواهد زنده.

<a id="include-useful-evidence"></a>
## شواهد مفید را لحاظ کنید

ارائه کنید:

- متأثر RandomDayGuard نسخه یا commit؛
- مولفه آسیب دیده و رفتار ایمن مورد انتظار؛
- مراحل تولید مثل حداقل با استفاده از وسایل ضدعفونی شده؛
- تأثیر مشاهده شده و تکرارپذیر بودن آن. و
- هر گونه کاهش پیشنهادی که داده های خصوصی را در معرض نمایش قرار نمی دهد.

اسرار واقعی ارسال نکنید. مسیرهای خصوصی، شناسه‌های حساب، نام میزبان و نشانه‌ها را با مکان‌نماهای واضح جایگزین کنید، در حالی که ساختار مورد نیاز برای بازتولید مشکل را حفظ کنید.

<a id="expect-review-first-handling"></a>
## انتظار اولین بررسی را داشته باشید

گزارش مدرکی برای بررسی نگهدارنده است، نه مجوز دسترسی به سرور، آزمایش یک هدف زنده، انتشار جزئیات سوء استفاده یا تضعیف پیش‌فرض‌های بسته شده با شکست. مالک دامنه را تأیید می کند و هرگونه افشاگری را از طریق گزارش خصوصی هماهنگ می کند.
