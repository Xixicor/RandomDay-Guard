#  اعتبار سنجی و انتشار

> **منبع انگلیسی متعارف:** [VALIDATION_AND_RELEASE.md](../../VALIDATION_AND_RELEASE.md). این اسناد بومی سازی شده دستورات، مسیرها، کلیدها، مقادیر وضعیت، هش ها و نام فایل ها را دقیق حفظ می کند. اگر عبارت فنی متفاوت است، از منبع انگلیسی استفاده کنید.


این صفحه برای مشارکت کنندگان و نگهبانان انتشار است. اپراتورهای سرور برای نصب نیازی به اجرای این دستورات ندارند RandomDayGuard.

<a id="user-visible-proof"></a>
## اثبات قابل مشاهده توسط کاربر

یک نسخه زمانی قابل درک است که یک اپراتور جدید بتواند آن را نصب کند، اولین گزارش وضعیت سرور را بیابد، پنج مسیر گزارش را متمایز کند و یک عمل واضح را از یک مثال کار شده دنبال کند. وظایف Reader نباید به دانش Git، PowerShell، Python یا checksum نیاز داشته باشند.

<a id="contributor-checks"></a>
## بررسی های مشارکت کننده

```powershell
python -B tools/validate_repo.py
python -B tools/test_public_pipeline.py
python -B -m unittest discover tests
```

وقتی `luac` موجود است:

```powershell
luac -p RandomDayGuard/Scripts/main.lua
luac -p RandomDayGuard/Scripts/public_pipeline.lua
```

تست‌های فیکسچر Lua لودر، زمان‌بندی، مسیرهای گزارش و اختیاری را پوشش می‌دهد Admin.ini تراکنش را بنویسید. برنامه‌های اجرایی فقط از فایل‌های موقت استفاده می‌کنند و هویت، رد کردن حساب مورد اعتماد، آستانه‌ها، پشتیبان‌گیری، رد تغییرات همزمان، بازخوانی و بازگرداندن را تأیید می‌کنند.

<a id="package-proof"></a>
## ضد بسته

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

- همه نشانگرهای نسخه مطابقت دارند `VERSION`.
- فقط نسخه فعلی در `releases/`.
- ZIP حاوی بایت های متعارف `RandomDayGuard/Scripts/main.lua` و بدون بارگیری با حروف کوچک.
- خروجی زمان اجرا، پیکربندی خصوصی، اعتبارنامه ها، مسیرهای محلی، حافظه پنهان، و مصنوعات آزمایشی مستثنی هستند.
- پیکربندی عمومی فقط برای بازبینی با غیرفعال بودن اجرا باقی می ماند.
- پنج مثال گزارش کار شده با مالکیت مسیر و ثابت آزمایش انتشار مطابقت دارند.
- ZIP قطعی هستند و با `CHECKSUMS.sha256`.
- همه پیوندهای اسناد محلی و 27 صفحه ورودی محلی تأیید می شوند.

<a id="avoid-validation-environment-pitfalls"></a>
## از دام های محیط اعتبارسنجی پرهیز کنید

- بررسی‌های مخزن‌نویسی را به‌صورت سریالی اجرا کنید تا از کشمکش فایل‌های موقت جلوگیری کنید.
- در Windows، به‌جای جستجوی فایل‌های حساس به حروف بزرگ، هنگام بررسی بارگیری‌های تکراری، نام‌های اعضای بایگانی شده یا املای مسیرهای شمارش شده را بررسی کنید.
- فقط `luac` یا Lua Runtime یک قابلیت غیرقابل دسترس است، نه یک آزمون دستوری یا زمان اجرا.
- یک فیکسچر فقط ورودی های مدل شده خود را اثبات می کند. این ثابت نمی کند که یک سرور زنده گزارش فعلی تولید کرده است.
- به‌جای فرض تکمیل، وقفه‌های زمانی فرمان و خروجی جزئی را ضبط کنید.

<a id="repair-failed-repository-validation"></a>
## تعمیر اعتبار ناموفق مخزن

با اولین مسیر یا قرارداد گزارش شده شروع کنید. آن مورد را تصحیح کنید، تست باریک را دوباره اجرا کنید، سپس ماتریس کامل را دوباره اجرا کنید. با حذف آزمایشی که به آن نیاز دارد، قابلیت از دست رفته را پنهان نکنید.

<a id="known-limits-and-release-decision"></a>
## محدودیت های شناخته شده و تصمیم انتشار

بررسی‌های محلی قراردادهای منبع، تجهیزات، بسته و اسناد را ثابت می‌کنند. نصب سرور خاص، پنجره پایداری طولانی مدت، یا نمایش مشتری نیاز به یک نتیجه یکپارچه سازی جداگانه دارد. قبل از ادعای تطبیق، آن نتیجه را با ساخت، پیکربندی، مدت زمان و خروجی مشاهده شده آن ثبت کنید.
