<a id="worked-operation-examples"></a>
# نمونه‌های عملیات کارکرده

> **منبع انگلیسی متعارف:** [EXAMPLE_RUNS.md](../../EXAMPLE_RUNS.md). این اسناد بومی سازی شده دستورات، مسیرها، کلیدها، مقادیر وضعیت، هش ها و نام فایل ها را دقیق حفظ می کند. اگر عبارت فنی متفاوت است، از منبع انگلیسی استفاده کنید.


این مثال‌ها از مقادیر ابداع شده برای توضیح انتقال حالت مورد انتظار استفاده می‌کنند. آنها سازگاری زنده یا شواهد پخش کننده نیستند.

<a id="successful-current-cycle"></a>
## چرخه فعلی موفق

ورودی ها: گزارش فعال قابل خواندن، version/boot/epoch, `poll_id=41`، نظرسنجی فعلی تکمیل شده، قابل نوشتن accounting/history/report ریشه، بدون خط مشی اسکن آهسته مسدود کردن.

مورد انتظار:

```text
server_status = full
player_activity = full or limited_expected_empty
case_review = full or limited_expected_empty
daily_rollup = full or limited_expected_empty
critical_guard = full or limited_expected_empty
```

هر مسیر فعال دارای JSON/TXT و همان اصل و نسب در `route_proof.json`. وضعیت مسیر به موضوعات خود بستگی دارد، نه به پیام موفقیت عمومی.

<a id="expected-empty-player-and-case-routes"></a>
## مسیرهای پخش کننده و کیس خالی مورد انتظار

ورودی ها: اثبات چرخه جریان کامل است. بدون ردیف بازیکن فعلی یا حفظ شده. بدون مورد حفظ شده و بدون جریان REVIEW/BAN-ELIGIBLE.

مورد انتظار:

```text
player_activity.route_proof_status = limited_expected_empty
player_activity.expected_empty = true
player_activity.players = []

case_review.route_proof_status = limited_expected_empty
case_review.expected_empty = true
case_review.cases = []
```

گزارش های ترجمه شده می گوید که هیچ موضوع محدود واجد شرایطی مشاهده نشده است. آنها همچنین می گویند این ثابت نمی کند که هیچ کس هرگز به هم متصل نشده است یا اینکه هیچ زمینه ای گم نشده است. جای جای player/case ایجاد شد.

<a id="partial-bounded-scan"></a>
## اسکن محدود جزئی

ورودی ها: جریان تازه log/poll; `scan_checkpoint.json` یا `scan_progress.json` وجود دارد. اسکن ناقص است. پیش فرض `slow_world_scan_blocks_current_reports=false`.

مورد انتظار:

```text
world_save_scan.status = partial
source accounting = partial
server_status may still be full for fresh current state
historical routes name the scan limitation
```

تنظیم `slow_world_scan_blocks_current_reports=true` فقط زمانی که اپراتور می‌خواهد آن منبع آهسته اختیاری گزارش‌های فعلی را مسدود کند. بازیابی به این معنی است که به کارمند اسکن اجازه از سرگیری مجدد داده می‌شود، نه اینکه پست بازرسی را حذف کند.

<a id="missing-current-cycle-proof"></a>
## غیر ثابت چرخه فعلی

ورودی ها: گزارش فعال در دسترس نیست، `poll_id=0` یا boot/epoch/last-poll نسب وجود ندارد.

مورد انتظار:

```text
current_cycle_proof_complete = false
all route proof statuses = missing
each configured route envelope status = suppressed_current_cycle
delivery_eligible = false
delivery_attempted = false
```

 پاکت سرکوب شده یک رکورد ممیزی است، نه یک تحویل در صف. سیاهههای مربوط نهایی قدیمی فقط تاریخی باقی می مانند. اولین lineage/source و یک چرخه جدیدتر ایجاد کنید.

<a id="malformed-optional-adminini-source"></a>
## اختیاری نادرست Admin.ini منبع

ورودی ها: `Admin.ini` وجود دارد اما اعتبار سنجی ساختاری پاکی ندارد.

مورد انتظار:

```text
admin_ini.status = malformed
source reference preserved
write/enforcement path closed
```

فایل را حفظ کنید و قالب تمیز بررسی شده را بازیابی کنید. متن توضیحی را در شواهد زمان اجرا نگه دارید. هر `Admin.ini` ورود ممنوع فقط `BannedPlayer=<ID>`.

<a id="required-active-log-probe-error"></a>
## خطای کاوشگر فعال ثبت نام ضروری

ورودی ها: کاوشگر اکتیو لاگ مورد نیاز محدود شده با خطای خواندن پاکسازی شده از کار می افتد.

مورد انتظار:

```text
source_accounting.sources[active_log].status = error
source_accounting.sources[active_log].detail = "bounded active-log probe failed: <sanitized reason>"
coverage_status = unavailable
all route proof statuses = missing
```

`error` در ردیف منبع با جزئیات محدود آن باقی می ماند. گزارش سطح بالا از `unavailable`، و اثبات مسیر باقی می ماند `missing` تا زمانی که یک چرخه فعلی جدیدتر منبع مورد نیاز را ثابت کند.

<a id="incompatible-or-stale-baseline"></a>
## پایه ناسازگار یا قدیمی

ورودی ها: تغییر کرد package/source هویت یا stale/incompatible مانیفست خط پایه.

مورد انتظار: وضعیت اعتبارسنجی یا زمان اجرا ناسازگاری را ثبت می کند. وضعیت اسکن ادعای استفاده مجدد کامل را ندارد. شواهد قبلی را حفظ کنید، یک بازسازی صریح پایه را شروع کنید و منتظر اثبات ترمینال جدید باشید. بازسازی اجباری بدون دلیل ثبت شده، بازیابی پیش فرض نیست.

<a id="paired-report-write-failure"></a>
## نوشتن گزارش جفت شده

ورودی ها: JSON نوشتن موفق است اما TXT نوشتن ناموفق است، یا برعکس.

مورد انتظار:

```text
route_proof_status = missing
completed = false
coverage_status = unavailable
output_write_detail = "paired JSON/TXT write failed: <sanitized reason>"
next_action = repair both route output writes
```

نویسنده best-effort هر دو خواهر و برادر را بازنویسی می کند تا در شکست همگرا شوند. یک خواهر یا برادر موفق نمی تواند به عنوان ادعای موفقیت باقی بماند. جزئیات نوشتن محدود شده پنجمین مقدار پوشش سطح بالایی ایجاد نمی کند.

<a id="route-proof-write-failure"></a>
## نوشتن مقاوم در مسیر

ورودی‌ها: جفت‌های مسیر نوشته شده‌اند اما `route_proof.json` قابل جایگزینی نیست.

مورد انتظار: همه گزارش‌ها بازنویسی می‌شوند `missing`، همه نتایج اعلان `route_proof_write_failed`، و هیچ پاکت نامه ای پذیرفته نمی شود. یک مسیر پیکربندی شده ممکن است دارای `suppressed_current_cycle` پاکت حسابرسی با پرچم های تحویل نادرست است. ریشه خروجی را تعمیر کنید و همان چرخه فعلی را بازسازی کنید.

<a id="review-only-enforcement-example"></a>
## نمونه اجرای فقط بازبینی

پیکربندی:

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

مورد انتظار: امتیازها، موارد و توصیه‌ها ممکن است نوشته شوند. `Admin.ini` بدون تغییر باقی می ماند. این پیش‌فرض عمومی است.

<a id="approved-write-success-example"></a>
## مثال موفقیت در نوشتن تایید شده

فقط یک آزمایش تایید شده جداگانه می‌تواند هر سه سوئیچ نوشتن را تنظیم کند. همچنین باید هویت عددی تمیز، trust/moderator حذف، واجد شرایط بودن آستانه، معتبر Admin.ini path/parse، موفقیت در پشتیبان گیری، موفقیت در نوشتن، برابری بازخوانی، و شواهد خاص حساب.

مورد انتظار:

```text
runtime/backups/Admin_<timestamp>_<source-fingerprint>_<clean-ID>.ini
Admin.ini contains one clean BannedPlayer=<ID>
runtime/enforced_bans.jsonl and evidence mirror record success
```

مثال موفق، اجرای خودکار سایر حساب‌ها را فعال نمی‌کند.

<a id="writereadback-failure-with-rollback"></a>
## Write/readback شکست با برگشت

ورودی‌ها: هر دروازه پیش‌نویسی عبور کرد. جایگزینی نوشتن یا بازخوانی ناموفق است. `rollback_on_readback_failure=true` و نسخه پشتیبان تأیید شده موجود است.

مورد انتظار: شواهد شکست مرحله را ثبت می کند و `rollback_success`; اصلی Admin.ini بایت‌ها بازیابی می‌شوند و حساب به‌عنوان اجرای موفقیت‌آمیز گزارش نمی‌شود. اگر بازگشت مجدد نیز انجام نشد، نوشتن را متوقف کنید، هر دو files/evidence، و به صورت دستی از نسخه پشتیبان بازیابی کنید.

<a id="local-outbox-example"></a>
## نمونه صندوق خروجی محلی

ورودی ها: اعلان در `local_file_outbox`، مسیر فعال است، اثبات مسیر کامل شده، و `full` یا صریحاً مجاز به انتظار خالی بودن است.

پاکت مورد انتظار:

```text
schema = randomdayguard.notification/v1
completed_output = true
status = ready_for_local_consumer
delivery_eligible = true
delivery_backend = none
delivery_attempted = false
```

برای missing/ineligible، همان مسیر ممکن است حاوی `status=suppressed_current_cycle`, `completed_output=false` و `delivery_eligible=false`. هر یک از فایل ها فقط نوشتن محلی را ثابت می کند. هیچ ارائه‌دهنده، حمل‌ونقل، تحویل یا رسید خواندنی همراه یا استنباط نشده است.
