# Admin.ini اجرا

> **منبع انگلیسی متعارف:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). این اسناد بومی سازی شده دستورات، مسیرها، کلیدها، مقادیر وضعیت، هش ها و نام فایل ها را دقیق حفظ می کند. اگر عبارت فنی متفاوت است، از منبع انگلیسی استفاده کنید.


RandomDayGuard لیست ممنوعیت سرور را در تنظیمات پیش فرض خود تغییر نمی دهد. این فقط گزارش هایی را برای یک مدیر ایجاد می کند تا آنها را بررسی کند. این صفحه به‌روزرسانی خودکار فهرست ممنوعیت اختیاری را برای مدیرانی که عمداً آن را فعال می‌کنند توضیح می‌دهد.

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## آنچه گارد قبل از تغییر لیست ممنوعیت بررسی می کند

Guard فقط زمانی ممنوعیت اضافه می کند که هر پاسخ زیر **بله**:

1. آیا شواهد فعلی یک حساب خاص را با اطمینان کافی شناسایی کردند؟
2. آیا این حساب نه ناظر است و نه یک حساب توسط سرپرست به‌عنوان مورد اعتماد علامت‌گذاری شده است؟
3. آیا حساب از قبل در لیست ممنوعیت نیست؟
4. آیا حساب به امتیاز اقدام خودکار پیکربندی شده رسیده است؟
5. آیا نگهبان می تواند `Admin.ini` و یک نسخه پشتیبان مشابه ذخیره کنید؟
6.  انجام داد `Admin.ini` تا زمانی که گارد به‌روزرسانی را آماده می‌کرد، بدون تغییر باقی بماند؟
7. پس از ذخیره، آیا فایل کامل دقیقاً با نتیجه مورد نظر مطابقت دارد؟

اگر پاسخی دارید **نه**، یا قابل بررسی نیست، گارد `Admin.ini` بدون تغییر است و دلیل را در گزارش های خود ثبت می کند. اگر ذخیره شروع شود اما بررسی نهایی ناموفق باشد، گارد پشتیبان تأیید شده را بازیابی می‌کند.

<a id="file-format"></a>
## قالب فایل

`Admin.ini` فقط باید خطوط ممنوعه تمیز را دریافت کند:

```ini
BannedPlayer=<ID>
```

- بدون نام.
- بدون نظر.
- بدون دلیل.
- بدون پسوند.

<a id="safe-defaults"></a>
## پیش‌فرض‌های ایمن

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## منبع شناسه ممنوع

بهترین منبع:

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

زمان اجرا یک شناسه کاملاً عددی یا مستند کامل را می پذیرد `<digits>_+_|<non-space token>` فرم اتصال را تشکیل می دهد و شناسه ممنوعیت عددی را از آن استخراج می کند. پیشوندهای عددی دلخواه با پسوند مجهول رد می شوند. آنها به یک شناسه ممنوعیت کوتاه نشده اند.

درست:

```ini
BannedPlayer=2535422284688820
```

اشتباه:

```ini
BannedPlayer=ExamplePlayer
```

همچنین اشتباه است:

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## تنظیمات دقیق گارد چک

این تنظیمات بررسی هایی را که در بالا توضیح داده شد اجرا می کنند. هر شرط فهرست شده باید درست باشد:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

اگر هر شرطی نادرست باشد یا قابل بررسی نباشد، گارد لیست ممنوعیت را بدون تغییر می‌گذارد و آنچه را که مانع آن شده است، ثبت می‌کند.

<a id="transaction-safety"></a>
## ایمنی تراکنش

تنه `Admin.ini` این مراحل را به ترتیب انجام می دهد:

1. بایت های معتبر را بخوانید و از نظر ساختاری اعتبار سنجی کنید.
2.  وضعیت ناظر، مورد اعتماد و ممنوعیت موجود را از همان عکس فوری بدست آورید.
3. یک نسخه پشتیبان منحصربفرد در زیر `runtime/backups/` و بایت آن را برای بایت تأیید کنید.
4. خواندن مجدد `Admin.ini` بلافاصله قبل از تعویض و هرگونه تغییر خارجی را رد کنید.
5. نامزد را از طریق مسیر جایگزینی کنترل شده پیکربندی شده بنویسید.
6. بایت های بازخوانی کامل را برای برابری با بایت های نامزد کامل نیاز دارید.
7. در صورت عدم موفقیت بازخوانی، نسخه پشتیبان تأیید شده را فقط در حالی بازیابی کنید که فایل فعلی هنوز دقیقاً کاندیدای نوشته شده توسط گارد است. اگر نویسنده دیگری آن را تغییر دهد، Guard به جای بازنویسی بایت‌های خارجی ناشناخته، از بازگشت مجدد امتناع می‌کند.

شناسه‌های تکراری فاقد قدرت هستند: هیچ خط دوم و پشتیبان دوم نوشته نمی‌شود. نام‌های پشتیبان شامل یک مهر زمان، اثر انگشت منبع بایت و شناسه تمیز است، بنابراین تلاش‌های جداگانه نمی‌توانند نام فایل قدیمی یک ثانیه‌ای را به اشتراک بگذارند.

<a id="local-regression-proof"></a>
## اثبات رگرسیون محلی

`tests/lua/enforcement_runtime_test.lua` یک بار لودر ارسال شده را بوت می کند و سپس محلی واقعی آن را اجرا می کند `append_ban()` بسته شدن در برابر فایل های مصنوعی جدا شده در زیر مخزن `.tmp/`. این درج، عدم توانایی تکراری، moderator/trusted رد، رد هویت ضعیف و نادرست، تأیید دقیق پشتیبان گیری بایت، رد تغییرات همزمان، بازگشت موفقیت آمیز پس از بازخوانی ناموفق، و امتناع از بازنویسی تغییر خارجی پس از نوشتن. فایل‌های سیستم فایل آن هرگونه جهش خارج از ریشه فیکسچر را رد می‌کنند. بدون مسیر سرور واقعی یا واقعی `Admin.ini` استفاده شده است.

آن را از طریق `python tools/test_public_pipeline.py`. یک مجوز ثابت فقط رفتار تراکنش محلی را ثابت می کند. اجرا را فعال نمی کند، اجازه نوشتن تولید را نمی دهد، یا مجوزهای خاص میزبان را اثبات نمی کند.

<a id="rollback"></a>
## بازگشت

1. سرور را متوقف کنید.
2. آخرین Admin.ini پشتیبان گیری از `runtime/backups/`.
3. `BannedPlayer=<ID>`.
4. سرور را راه اندازی کنید.
5. باز کردن مجدد Admin.ini و تأیید کنید که خط ادامه دارد یا حذف شده است.
6. حفظ `enforced_bans.jsonl` برای بازرسی.
