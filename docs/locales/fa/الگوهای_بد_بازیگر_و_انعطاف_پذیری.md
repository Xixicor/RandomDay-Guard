# الگوهای بازیگر بد و انعطاف پذیری

> **منبع انگلیسی متعارف:** [BAD_ACTOR_PATTERNS_AND_RESILIENCE.md](../../BAD_ACTOR_PATTERNS_AND_RESILIENCE.md). این اسناد بومی سازی شده دستورات، مسیرها، کلیدها، مقادیر وضعیت، هش ها و نام فایل ها را دقیق حفظ می کند. اگر عبارت فنی متفاوت است، از منبع انگلیسی استفاده کنید.


از این صفحه برای درک اینکه چگونه نگهبان به بررسی سوء استفاده از خرابی، رفتار سوء استفاده از مجاورت، و برنامه ریزی بازیابی کمک می کند، استفاده کنید.

<a id="what-the-guard-can-help-with"></a>
## چیزی که نگهبان می تواند در مورد آنها کمک کند

| الگو | چه چیزی را بررسی کنیم |
|---|---|
| بازده مرتبط با خرابی | همان حساب فعال قبل از خرابی و بازگشت پس از راه اندازی مجدد |
| کاوشگر اتصال مجدد سریع | تکرار شده join/leave یا timeout/reconnect حلقه‌ها |
| خوشه‌های چند حساب | پیوستن به امواج، پنجره‌های هشدار مشترک، پنجره‌های خرابی مشترک |
| هشدار استرس انفجاری | تکرار شده ActorChannelFailure یا پنجره های هشدار ذخیره |
| زمینه خارج از محدوده | PlayerData/map/world زمینه زمانی که قابل خواندن باشد |
| ذخیره همپوشانی لمسی | جلسات نقشه‌برداری شده با زمینه ذخیره‌سازی جهانی |
| آشفتگی هویت | نام هایی که نیاز به نقشه برداری ConnectID دارند |

<a id="why-it-avoids-memory-access"></a>
## چرا از دسترسی به حافظه جلوگیری می کند

RandomDayGuard از فایل های متعلق به سرور کار می کند:

```text
Saved/Logs/*.log
Admin.ini
World saves
PlayerData
Backups
runtime evidence
```

این باعث می‌شود کمتر به وضعیت حافظه سمت سرویس گیرنده وابسته باشد و در به‌روزرسانی‌های بازی کمتر شکننده باشد.

تجارت:

```text
It cannot prove hidden live actions unless the server writes evidence.
```

<a id="crash-correlated-returners"></a>
## بازگردانندگان مرتبط با خرابی

الگو:

```text
Account joins.
Server crashes or restarts.
Same account reconnects quickly.
Pattern repeats.
```

فایل های مفید:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="rapid-reconnect-probers"></a>
## کاوشگرهای اتصال مجدد سریع

الگو:

```text
join -> leave -> join -> leave -> join
```

فایل های مفید:

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
```

<a id="multi-account-clusters"></a>
## خوشه‌های چند حساب

الگو:

```text
Several accounts join in the same window.
Warnings or crashes follow.
Some accounts rotate or reconnect after restart.
```

فایل های مفید:

```text
runtime/raid_cases/
runtime/forensic_days/YYYY-MM-DD/raid_cases.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

قانون:

```text
A cluster is not a mass-ban list.
Each account still needs its own evidence.
```

<a id="sticky-backup-recommendation"></a>
## توصیه پشتیبان گیری چسبنده

یک پشتیبان چسبنده بعد از:

```text
first full baseline completes
object_registry.json exists
file_manifest.tsv exists
world_state_latest.json has scan_complete=true
Admin.ini is verified
trusted IDs are configured
```

پشتیبان گیری:

```text
RandomDayGuard/config.lua
RandomDayGuard/SavedRoot.txt
RandomDayGuard/runtime/baselines/
RandomDayGuard/runtime/object_registry.json
RandomDayGuard/runtime/world_state/current/world_state_latest.json
Saved/SaveGames/Server/Admin.ini
```

<a id="recovery-model"></a>
## مدل بازیابی

```text
Clean install
-> verify live defense
-> complete first baseline
-> create sticky backup
-> run server normally
-> use daily rollups for review
-> restore sticky backup if needed
```
