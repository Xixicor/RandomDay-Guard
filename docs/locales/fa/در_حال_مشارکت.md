# در حال مشارکت

> **منبع انگلیسی متعارف:** [CONTRIBUTING.md](../../../CONTRIBUTING.md). این اسناد بومی سازی شده دستورات، مسیرها، کلیدها، مقادیر وضعیت، هش ها و نام فایل ها را دقیق حفظ می کند. اگر عبارت فنی متفاوت است، از منبع انگلیسی استفاده کنید.


RandomDayGuard بهبودهای متمرکز و قابل تکرار در تجزیه کننده ها، اسناد، آزمایش ها و اعتبارسنجی ایمن عمومی را می پذیرد. هر تغییری را به قرارداد پروژه عمومی محدود کنید و رفتار اول بازبینی را حفظ کنید: نگهبان باید ترک کند `Admin.ini` بدون تغییر زمانی که بررسی ایمنی مورد نیاز تأیید نشود.

<a id="prepare-a-safe-workspace"></a>
## یک فضای کاری امن آماده کنید

1. مخزن را جدا یا شبیه سازی کنید و یک شاخه متمرکز ایجاد کنید.
2. مفسر پایتون 3 پشتیبانی شده را نصب کنید. هنگامی که Lua را تغییر می دهید `luac -p` می تواند نحو را بررسی کند.
3. [خانه اسناد](%D8%A7%D8%B3%D9%86%D8%A7%D8%AF.md), [معماری](%D9%85%D8%B9%D9%85%D8%A7%D8%B1%DB%8C.md) و [مرز شواهد](%D9%85%D8%B1%D8%B2_%D8%B4%D9%88%D8%A7%D9%87%D8%AF.md) برای منطقه ای که تغییر خواهید داد.
4. بازرسی `git status` قبل از ویرایش و حفظ کارهای نامرتبط.
5. فقط از وسایل مصنوعی یا ضدعفونی شده استفاده کنید.

هرگز گزارش های سرور خصوصی، پوشه های ذخیره شده، شناسه های پخش کننده، `Admin.ini`، نقاط پایانی اعلان خصوصی، اعتبارنامه ها، مسیرهای خصوصی، خروجی زمان اجرا، یا شواهد زنده کپی شده.

<a id="make-a-focused-change"></a>
## تغییر متمرکزی ایجاد کنید

- نام‌گذاری، قالب‌بندی، بررسی‌های ایمنی و مالکیت ماژول موجود را دنبال کنید.
- یک مالک اسناد متعارف را برای هر رویه یا واقعیت دقیق نگه دارید.
- در صورت تغییر رفتار یا خروجی عمومی، اسناد و نمونه‌های کاربر را به‌روزرسانی کنید.
- در صورت عملی بودن، یک آزمایش رگرسیون برای رفع اشکال اضافه کنید.
- تأیید حساب، حفاظت از حساب مورد اعتماد، تأیید پشتیبان، تشخیص تغییرات خارجی، مقایسه فایل ذخیره‌شده، بازیابی، یا پیش‌فرض‌های فقط بازبینی را تضعیف نکنید تا یک قبولی آزمایشی انجام دهید.

<a id="run-the-relevant-checks"></a>
## بررسی‌های مربوطه را اجرا کنید

برای تغییرات فقط در اسناد، اجرا کنید:

```powershell
python -B tools\generate_documentation_audit.py --check
python -B -m unittest discover tests -p "test_documentation*.py"
git diff --check
```

برای تغییرات منبع، پیکربندی، بسته بندی یا آزمایش، بررسی های مربوطه را نیز از [بررسی اعتبار سنجی و انتشار](%D8%A7%D8%B9%D8%AA%D8%A8%D8%A7%D8%B1_%D8%B3%D9%86%D8%AC%DB%8C_%D9%88_%D8%A7%D9%86%D8%AA%D8%B4%D8%A7%D8%B1.md)، از جمله بررسی‌های نحوی Lua، اعتبارسنجی مخزن، آزمایش‌های خط لوله عمومی، و مجموعه کامل تست واحد. گزارش هر چک نادیده گرفته شده یا در دسترس نیست. آن را به عنوان تصویب توصیف نکنید.

<a id="submit-the-change-for-review"></a>
## تغییر را برای بررسی ارسال کنید

یک درخواست کشش متمرکز را فقط پس از بررسی کامل تفاوت باز کنید. شامل:

- مشکل و رفتار مورد نظر؛
- پرونده‌های دقیق و قراردادهای عمومی تغییر کردند؛
- دستورهای اجرا شده و نتایج آنها؛
- تأثیر حریم خصوصی، سازگاری، و اجرای آن؛ و
- محدودیت‌های باقی مانده یا کارهای بعدی.

شواهد زمان اجرا تولید شده یا بایگانی های انتشار را وارد نکنید مگر اینکه تغییر صریحاً آنها را ایجاب کند و آنها را تأیید کند. مشارکت اجازه انتشار، استقرار، آزمایش سرور زنده، اقدام اجرایی، یا انتشار در سایت شخص ثالث را نمی دهد.

آسیب‌پذیری‌ها را از طریق [مسیر امنیتی خصوصی](%D8%A7%D9%85%D9%86%DB%8C%D8%AA.md)، یک مشکل عمومی یا درخواست کشش معمولی نیست.
