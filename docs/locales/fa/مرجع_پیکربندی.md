# مفاهیم پیکربندی

> **منبع انگلیسی متعارف:** [CONFIG_REFERENCE.md](../../CONFIG_REFERENCE.md). این اسناد بومی سازی شده دستورات، مسیرها، کلیدها، مقادیر وضعیت، هش ها و نام فایل ها را دقیق حفظ می کند. اگر عبارت فنی متفاوت است، از منبع انگلیسی استفاده کنید.


این توضیح توضیح می‌دهد که هر ناحیه پیکربندی اصلی چه چیزی را کنترل می‌کند، چه زمانی اجرا می‌شود، و چگونه با شواهد و دروازه‌های ایمنی تعامل دارد. این کاتالوگ فیلد دقیق یا رویه های نمایه را ندارد.

برای تنظیمات از پیش تعیین شده وظیفه محور و مراحل تغییر ایمن، از [`CONFIG_PROFILES.md`](%D9%BE%DB%8C%DA%A9%D8%B1%D8%A8%D9%86%D8%AF%DB%8C_%D9%86%D9%85%D8%A7%DB%8C%D9%87%E2%80%8C%D9%87%D8%A7.md). برای هر فیلد منبع دقیق، پیش‌فرض، نوع، تغییرناپذیر، جلوه خروجی و قانون بازیابی، از [`CONFIG_FIELD_CATALOG.md`](%DA%A9%D8%A7%D9%86%D9%81%DB%8C%DA%AF_%DA%A9%D8%A7%D8%AA%D8%A7%D9%84%D9%88%DA%AF_%D9%81%DB%8C%D9%84%D8%AF.md); اعتباردهنده به ازای هر ارسال `config.lua` فیلد برگ.

<a id="top-level-safety"></a>
## ایمنی سطح بالا

| گزینه | پیش‌فرض | معنا |
|---|---:|---|
| `enabled` | `true` | سوئیچ اصلی محافظ |
| `enforcement.review_only_mode` | `true` | Record/recommend |
| `enforcement.auto_ban` | `false` | به‌طور پیش‌فرض به‌طور خودکار ممنوع نکنید |
| `enforcement.write_admin_ini` | `false` | ننویسید Admin.ini به طور پیش فرض |

اینها را تا زمانی که صاحب سرور خروجی را بازبینی نکرده باشد، ایمن نگه دارید.

<a id="saved"></a>
## `saved`

 نحوه یافتن سرور را توسط نگهبان کنترل می کند `Saved/` و خانواده فایل هایی که می تواند اسکن کند.

از زمانی استفاده کنید:

```text
Saved root auto-detection fails.
World folder changed.
Provider or container path is unusual.
```

بررسی کنید:

```text
runtime/saved_path_probe.json
RandomDayGuard/SavedRoot.txt
```

قانون:

```text
SavedRoot.txt -> AbioticFactor/Saved
not -> Worlds/<WorldName>
```

<a id="log_tail"></a>
## `log_tail`

خواندن گزارش زنده را کنترل می‌کند.

گزینه های مفید:

| گزینه | مقدار ایمن | چرا |
|---|---|---|
| `enabled` | `true` | برای دفاع زنده مورد نیاز است |
| `start_at_end_on_first_run` | `true` | از گزارش‌های قدیمی به‌عنوان رویدادهای زنده اجتناب می‌کند |
| `tail_backup_logs` | `false` | گزارش‌های پشتیبان‌گیری سابقه دارند، زنده نیستند |
| `max_lines_per_poll` | محدود | حلقه نظرسنجی را پاسخگو نگه می دارد |

بررسی کنید:

```text
runtime/log_offsets.tsv
runtime/evidence/session_events.jsonl
runtime/current/poll_status.json
```

<a id="runtime"></a>
## `runtime`

نظرسنجی و بودجه را کنترل می‌کند.

قانون اصلی سلامت:

```text
poll_id increases
poll_in_flight returns false
poll_scheduled is true
```

بررسی کنید:

```text
runtime/current/poll_status.json
```

اگر `poll_id` متوقف می شود، چیزی حلقه را مسدود می کند.

<a id="source_accounting"></a>
## `source_accounting`

پوشش و محدوده منبع شواهد صریح را کنترل می کند.

| کلید | پیش‌فرض | معنا |
|---|---:|---|
| `enabled` | `true` | حسابداری منبع را برای گزارش های مسیر عمومی می نویسد. |
| `require_terminal_status` | `true` | به هر منبع نیاز دارد که یک پایانه صریح یا وضعیت ناقص را نشان دهد. |
| `distinguish_current_from_historical` | `true` | شواهد فعلی و تاریخی را جدا نگه می دارد. |
| `slow_world_scan_blocks_current_reports` | `false` | به گزارش‌های فعلی اجازه می‌دهد بیان کنند که اسکن دنیای محدود به تعویق افتاده یا جزئی است. |
| `changed_file_manifest` | مسیر مانیفست خط پایه | مرجع استفاده شده برای محدود شدهhistorical/world حسابداری. |

حالت های منبع `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied` یا `error`.

تنظیم `source_accounting.enabled = false` خروجی وضعیت را بی‌صدا حذف نمی‌کند. خط لوله هنوز `runtime/final_logs/source_accounting_latest.json` با `enabled=false`, `status="unavailable"` و `disabled_reason="source_accounting_disabled"`. همچنین ثبت وضعیت تاریخی را با حسابداری غیرقابل دسترس می نویسد. از آنجا که حسابداری منبع بخشی از قرارداد گزارش است، هر مسیر به `missing`; در حالی که حسابداری غیرفعال است، هیچ مسیری به عنوان تکمیل تلقی نمی شود.

<a id="reports"></a>
## `reports`

خط لوله گزارش محلی عمومی را کنترل می کند.

پیش‌فرض‌ها هر پنج مسیر را فعال می‌کنند و زیر `runtime/final_logs`:

```text
server_status
daily_rollup
player_activity
case_review
critical_guard
```

هر مسیر باید خروجی ساختاریافته و ترجمه شده به همراه اثبات را در `route_proof.json`. غیرفعال کردن یک مسیر `missing` اثبات به جای تظاهر به تکمیل آن.

<a id="notification"></a>
## `notification`

صندوق خروجی فایل محلی عمومی اختیاری. به طور پیش‌فرض غیرفعال است و چیزی به یک ارائه‌دهنده خارجی ارسال نمی‌کند.

پیش‌فرض‌ها:

```lua
notification = {
    enabled = false,
    mode = "local_file_outbox",
    include_expected_empty = false,
},
```

هر مسیر اعلان به طور پیش فرض غیرفعال است. هنگامی که به عمد فعال شود، صندوق خروجی ممکن است فقط یک گزارش ترجمه شده تکمیل شده را بعد از `route_proof.json` نوشته شده است. شواهد و گزارش های محلی همچنان معتبر هستند. تحویل خاص ارائه‌دهنده، نقاط پایانی تحویل، اعتبارنامه‌ها، و پل‌ها بخشی از قرارداد عمومی مراقبت‌کننده مستقل نیستند.

<a id="scanning"></a>
## `scanning`

اسکن خط پایه، نقطه بازرسی و بازخوانی فایل تغییر یافته را کنترل می کند.

از زمانی استفاده کنید:

```text
building first world baseline
resuming after crash
refreshing changed files later
```

بررسی کنید:

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/baselines/file_manifest.tsv
```

تنظیمات مهم:

```lua
scanning = {
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
    changed_file_detection = true,
},
```

<a id="forensic_rollup"></a>
## `forensic_rollup`

بسته آپلود سریع روزانه و آخرین گزارش‌های زبان ساده را کنترل می‌کند.

خروجی ها:

```text
runtime/current/forensic_today.json
runtime/current/forensic_today.md
runtime/current/forensic_today.txt
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

از زمانی استفاده کنید:

```text
You want one daily folder that summarizes what happened.
You want a plain-language TXT to upload for quick analysis.
```

بررسی کنید:

```text
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

قانون:

```text
Daily summaries are rebuildable indexes.
Source evidence remains authoritative.
```

<a id="logging"></a>
## `logging`

حجم رویداد و تجمع کم اهمیت را کنترل می‌کند.

از زمانی استفاده کنید:

```text
actor-touch events are noisy
raw event files grow too quickly
```

الگوی ایمن:

```lua
logging = {
    low_importance_mode = "aggregate",
    write_low_importance_raw_events = false,
},
```

<a id="retention"></a>
## `retention`

مدت زمان نگهداری فایل‌ها و زمان JSONL چرخش می‌کنند.

از زمانی استفاده کنید:

```text
disk usage grows too fast
you need more audit history
you need shorter live-history windows
```

گزینه های مهم:

```text
detailed_retention_days
rotate_jsonl_when_bytes_exceed
max_raw_events_lines
keep_enforced_forever
keep_evidence_forever
```

<a id="warning_bursts"></a>
## `warning_bursts`

تشخیص پنجره هشدار را کنترل می کند.

مثال:

```text
ActorChannelFailure
DeployableSaveWarning
UpdateActorToWorldSave
ServerMove warnings
```

قانون:

```text
Warnings are context until correlated with mapped sessions and thresholds.
```

<a id="crash_correlation"></a>
## `crash_correlation`

کنترل‌های تکرار شده crash/reconnect بررسی.

پیش‌فرض‌های ایمن:

```lua
crash_correlation = {
    single_crash_never_bans = true,
    require_same_account = true,
},
```

شمارنده های مفید:

```text
server_crash_overlap_count
post_crash_reconnect_count
unclean_disconnect_count
```

<a id="join_leave"></a>
## `join_leave`

ردیابی موج و ردیابی موج را کنترل می‌کند.

پیش‌فرض ایمن:

```lua
join_leave = {
    churn_alone_never_bans = true,
},
```

برای:

```text
rapid reconnect loops
join waves
short-session patterns
```

<a id="raid_detection"></a>
## `raid_detection`

حساب‌های گروهی فعال در پنجره‌های مرتبط.

قانون:

```text
A raid case groups accounts for review.
It does not make every account guilty.
```

هر حساب اجباری همچنان به شواهد خاص حساب نیاز دارد.

<a id="object_registry"></a>
## `object_registry`

کنترل‌ها object/class استخراج نشانه از شواهد ذخیره شده قابل خواندن.

خروجی ها:

```text
runtime/object_registry_partial.json
runtime/object_registry.json
runtime/object_registry_counts.tsv
```

قانون:

```text
Object/class context is not a ban reason by itself.
```

<a id="world_state"></a>
## `world_state`

کنترل‌ها boot/current/session عکس های فوری از وضعیت جهان.

خروجی ها:

```text
runtime/world_state/current/world_state_latest.json
runtime/world_state/sessions/<date>/<session_id>_<account_id>/
```

برای بررسی جلسه و زمینه جهان استفاده کنید.

<a id="enforcement"></a>
## `enforcement`

توصیه ها و Admin.ini می نویسد.

قبل از اینکه گارد بتواند ممنوعیت اضافه کند، هر عبارت زیر باید درست باشد:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
account identity is mapped
not trusted
not moderator
threshold is met
```

اگر یک عبارت نادرست باشد یا قابل بررسی نباشد، گارد خارج می شود `Admin.ini` بدون تغییر و دلیل را ثبت می کند.

<a id="admin_ini"></a>
## `admin_ini`

نوشتن ایمن فایل را کنترل می کند.

قوانین:

```text
Back up before writing.
Preserve existing bans.
Preserve moderators.
Write clean BannedPlayer=<ID> only.
```

<a id="restart_request"></a>
## `restart_request`

فایل‌های نشانگر محلی اختیاری را که فرآیند متعلق به اپراتور دیگری ممکن است بازرسی کند، کنترل می‌کند. سرور را دوباره راه اندازی نمی کند و نمی کشد.

پیش‌فرض‌ها:

```lua
restart_request = {
    enabled = false,
    restart_marker_file = "runtime/request_restart.flag",
    restart_reason_file = "runtime/restart_reason.json",
},
```

خروجی ها:

```text
runtime/request_restart.flag
runtime/restart_reason.json
```

هیچ پانل میزبانی، پل ارائه دهنده، یا اتوماسیون راه اندازی مجدد همراه نیست. فعال کردن ایجاد نشانگر ثابت نمی کند که یک فرآیند خارجی درخواست را مصرف کرده یا سرور را دوباره راه اندازی کرده است.
