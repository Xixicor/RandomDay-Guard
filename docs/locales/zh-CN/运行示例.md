# 有效的操作示例

> **规范的英文来源:** [EXAMPLE_RUNS.md](../../EXAMPLE_RUNS.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


这些示例使用发明的值来解释预期的状态转换；它们不是实时兼容性或玩家证据。

<a id="successful-current-cycle"></a>
## 成功的当前周期

输入：可读活动日志，version/boot/epoch, `poll_id=41`，已完成的当前轮询，可写accounting/history/report根，无阻止慢扫描策略。

预期：

```text
server_status = full
player_activity = full or limited_expected_empty
case_review = full or limited_expected_empty
daily_rollup = full or limited_expected_empty
critical_guard = full or limited_expected_empty
```

每条启用的路线都有JSON/TXT 输出和 `route_proof.json` 中的相同谱系。路线状态取决于其自身的主题，而不是一般的成功消息。

<a id="expected-empty-player-and-case-routes"></a>
## 预期为空的玩家和案件路线

输入：当前周期证明已完成；没有当前或保留的玩家行；没有保留案例，也没有当前的REVIEW/BAN-ELIGIBLE帐户。

预期：

```text
player_activity.route_proof_status = limited_expected_empty
player_activity.expected_empty = true
player_activity.players = []

case_review.route_proof_status = limited_expected_empty
case_review.expected_empty = true
case_review.cases = []
```

翻译后的报告称，没有观察到符合条件的有界主体。他们还表示，这并不能证明没有人曾连接过，也不能证明没有上下文被遗漏。未创建占位符player/case。

<a id="partial-bounded-scan"></a>
## 部分有界扫描

输入：最新的log/poll; `scan_checkpoint.json` 或 `scan_progress.json`存在；扫描不完整；默认`slow_world_scan_blocks_current_reports=false`.

预期：

```text
world_save_scan.status = partial
source accounting = partial
server_status may still be full for fresh current state
historical routes name the scan limitation
```

仅当操作员希望可选的慢速源阻止当前报告时才设置`slow_world_scan_blocks_current_reports=true`。恢复是为了让扫描工作器恢复，而不是删除检查点。

<a id="missing-current-cycle-proof"></a>
## 缺少当前周期证明

输入：活动日志不可用，`poll_id=0`，或boot/epoch/last-poll沿袭丢失。

预期：

```text
current_cycle_proof_complete = false
all route proof statuses = missing
each configured route envelope status = suppressed_current_cycle
delivery_eligible = false
delivery_attempted = false
```

抑制的信封是审核记录，而不是排队的交付。旧的最终日志仅保留历史记录。修复第一个缺失的 lineage/source 字段并生成更新的循环。

<a id="malformed-optional-adminini-source"></a>
## 格式错误的可选Admin.ini源

输入：`Admin.ini`存在，但未通过干净的结构验证。

预期：

```text
admin_ini.status = malformed
source reference preserved
write/enforcement path closed
```

保留文件并恢复已审阅的文件干净的格式。在运行时证据中保留解释性文本；每个 `Admin.ini` 禁令条目仅保留`BannedPlayer=<ID>`.

<a id="required-active-log-probe-error"></a>
## 所需的活动日志探测错误

输入：有界所需的活动日志探测失败，并出现已清理的读取错误。

预期：

```text
source_accounting.sources[active_log].status = error
source_accounting.sources[active_log].detail = "bounded active-log probe failed: <sanitized reason>"
coverage_status = unavailable
all route proof statuses = missing
```

`error` 及其有界详细信息保留在源行上。顶级报告使用 `unavailable`，路由证明将保留`missing`，直到较新的当前周期证明所需的来源。

<a id="incompatible-or-stale-baseline"></a>
## 不兼容或过时的基线

输入：已更改package/source身份或stale/incompatible基线

预期：验证或运行时状态记录不兼容性；扫描状态不声明已完成重用。保留先前的证据，开始明确的基线重建，并等待新的终端证明。没有记录原因的强制重建不是默认恢复。

<a id="paired-report-write-failure"></a>
## 配对报告写入失败

输入：JSON写入成功，但TXT写入失败，或相反。

预期：

```text
route_proof_status = missing
completed = false
coverage_status = unavailable
output_write_detail = "paired JSON/TXT write failed: <sanitized reason>"
next_action = repair both route output writes
```

写入器尽力重写两个同级报告以在失败时收敛。一个成功的兄弟姐妹不能继续作为成功的宣称。有界写入详细信息不会创建第五个顶级覆盖值。

<a id="route-proof-write-failure"></a>
## 路由验证写入失败

输入：路由对已写入，但`route_proof.json`无法替换。

预期：所有报告均被重写`missing`，所有通知结果均已写入`route_proof_write_failed`，并且不接受任何信封。配置的路由可能有一个 `suppressed_current_cycle` 审核信封，其传递标志为 false。修复输出根并重新生成相同的当前周期。

<a id="review-only-enforcement-example"></a>
## 仅审查执行示例

配置：

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

预期：可以写入分数、案例和建议； `Admin.ini` 保持不变。这是公共默认值。

<a id="approved-write-success-example"></a>
## 批准写入成功示例

只有单独批准的测试才能设置所有三个写入开关。它还必须证明干净的数字身份、trust/moderator排除、阈值资格、有效Admin.ini path/parse、备份成功、写入成功、读回相等性和特定于帐户的证据。

预期：

```text
runtime/backups/Admin_<timestamp>_<source-fingerprint>_<clean-ID>.ini
Admin.ini contains one clean BannedPlayer=<ID>
runtime/enforced_bans.jsonl and evidence mirror record success
```

成功的示例不会为其他帐户启用自动强制执行。

<a id="writereadback-failure-with-rollback"></a>
## Write/readback回滚失败

输入：每个预写门已通过；替换写或读回失败； `rollback_on_readback_failure=true`并且已验证的备份可用。

预期：故障证据记录该阶段和`rollback_success`；原始Admin.ini 字节已恢复，并且帐户不会报告为已成功执行。如果回滚也失败，请停止写入，保留两者 files/evidence，并从备份中手动恢复。

<a id="local-outbox-example"></a>
## 本地发件箱示例

输入：在 `local_file_outbox` 模式下启用通知、启用路由、完成路由证明以及 `full` 或明确允许预期为空。

预期信封：

```text
schema = randomdayguard.notification/v1
completed_output = true
status = ready_for_local_consumer
delivery_eligible = true
delivery_backend = none
delivery_attempted = false
```

对于 missing/ineligible输出，同一路径可能包含`status=suppressed_current_cycle`, `completed_output=false` 一致，并且 `delivery_eligible=false`。这两个文件都只能本地写入。没有捆绑或推断任何提供商、传输、交付或已读收据。

See [`OUTPUT_SCHEMA_REFERENCE.md`](%E8%BE%93%E5%87%BA%E6%9E%B6%E6%9E%84%E5%8F%82%E8%80%83.md), [`CONFIG_FIELD_CATALOG.md`](%E9%85%8D%E7%BD%AE%E5%AD%97%E6%AE%B5%E7%9B%AE%E5%BD%95.md) 一致，并且 [`TROUBLESHOOTING.md`](%E6%95%85%E9%9A%9C%E6%8E%92%E9%99%A4.md).
