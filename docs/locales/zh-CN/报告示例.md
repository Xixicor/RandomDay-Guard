# 五个 Guard 报告的示例

> **规范的英文来源:** [REPORT_EXAMPLES.md](../../REPORT_EXAMPLES.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


这些示例是根据版本中包含的示例数据生成的；姓名和账号都是虚构的。它们显示测试的报告字段、计算和路线边界。真实的报告会用从该服务器收集的信息来替换它们，并在事实不可用时进行说明。

每个报告都有一项工作。服务器健康状况不会重复玩家历史记录，每日评论不会每隔几分钟发送一次，并且安静的玩家或案件路线不会收到填充消息。当前报告可能已准备就绪，而有界历史扫描仍在进行中；在这种情况下，报告会命名差距，而不是将旧历史记录显示为完整。

## Critical Guard

> **Critical Guard: Report Writing Stopped**  **Started:** 21:14  **Affected function:** Player report writer  **影响：**无法完成新玩家摘要。  **服务器：**保持在线。  **监控：** 证据收集仍在继续，但可读报告有所延迟。  **上次成功报告：** 21:09  **失败：**无法保存报告输出。  **可能的原因：**目标不可用或拒绝写入。  **Action:** 检查 Guard 运行时输出位置。 Do not restart the game server unless monitoring also stops.

当问题清除后，相同的路由会记录恢复情况：

> **Critical Guard Resolved: Report Writing Restored**  **Resumed:** 21:22  **Interruption:** 8 minutes  **Result:**中断期间收集的证据已保存，延迟报告已完成。

Critical Guard 仅出现故障。常规状态、每日历史记录、玩家活动和普通的预期空结果保留在各自的报告中。

<a id="when-a-route-is-quiet"></a>
## 当路线安静时

安静路线记录直接结果，而不向 Discord 发送填充内容：

> **已检查； nothing for this report.** The required records were available and no matching player activity, case, or Guard failure occurred during this report window.

这是一个完全空的结果。它与缺失报告不同，后者无法检查所需来源或无法创建可读输出。

每个可读报告都遵循相同的路径：

```text
collected evidence -> normalized values -> dictionary mapping -> route calculations -> readable report -> Discord notification
```
