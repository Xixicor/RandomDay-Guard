<a id="evidence-boundary"></a>
# 证据边界

> **规范的英文来源:** [EVIDENCE_BOUNDARY.md](../../EVIDENCE_BOUNDARY.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


使用此页面来决定要执行的操作RandomDayGuard 可以报告哪些内容仍需要人工审核。

<a id="core-rule"></a>
## 核心规则

RandomDayGuard 记录来自服务器拥有的文件的有限观察结果。它必须识别每个实质性结论的来源、范围、收集状态和限制。

结构化证据具有权威性。一份翻译报告解释了证据；它无法添加结构化记录中缺少的事实。

<a id="evidence-source-classes"></a>
## 证据源类

| 源类 | 典型用途 | 本身无法证明 |
|---|---|---|
| `admin_ini` | 现有管理状态并经过审计write/readback上下文 | 谁导致了事件 |
| `active_log` | 活动日志中可见的当前server/session事件 | 意图、所有权或直接损害 |
| `recent_backup_logs` | 历史日志上下文 | 发生当前事件 |
| `playerdata_filenames` | 证实帐户标识符干净存在 | 超出所公开标识符的行为、内疚或身份所有权 |
| `existing_cases` | 事先审查上下文 | 先前的解释仍然正确 |
| `existing_reports` | 早期的总结和决定 | 未经当前证实的当前事实 |
| `existing_evidence` | 历史结构化证据 | 当前活动 |
| 有界世界保存扫描 | 慢world/class上下文 | 玩家操作、所有权、盗窃、复制或损坏 |

每个源记录availability/readability、文件计数、源引用、当前或历史范围以及明确的`does_not_prove`声明。

<a id="source-states"></a>
## 来源状态

| 状态 | 运算符含义 |
|---|---|
| `available` | 来源可读且已收集证据。 |
| `expected_empty` | 来源可读且合法地没有匹配记录。 |
| `partial` | 收集了一些证据；覆盖范围不完整。 |
| `deferred` | 有意推迟有界工作。 |
| `unavailable` | 此环境中不存在源。 |
| `malformed` | 源存在但无法安全解析。 |
| `permission_denied` | 看门狗缺乏读取权限。 |
| `error` | 收集另一个记录失败原因。 |

预期为空是一个有效的观察结果。绝不能将其转化为捏造的玩家、案件、事件或指控。

<a id="current-versus-historical-evidence"></a>
## 当前证据与历史证据

当前证据属于活动收集窗口或服务器纪元。历史证据来自以前的日志、案例、报告、证据记录、备份或基线。

历史证据可以提供上下文。它无法默默地填补当前证据的空白。报告必须标记两个范围并分别引用其来源。

<a id="corroboration-rule"></a>
## 佐证规则

这些是有用的上下文，但本身并不是直接证据：

- 显示名称或名称相似性；
- 时间巧合；
- 断开或重新连接流失；
- 一次崩溃或警告突发；
- 类、路径、参与者、地图或对象计数标记；
- 自动分组案例中的成员资格；
- 没有当前来源确认的先前报告。

执行在没有直接揭露事实的证据的情况下，不得声称有罪、意图、作弊、所有权、盗窃、复制、直接损坏、直接使用容器、直接库存操作、精确的实时坐标、实时 ping 或内存级别行为。

<a id="truthful-report-language"></a>
## 真实的报告语言

使用：

```text
Observed: the account was active in the recorded crash window.
Interpretation: repeated overlap warrants operator review.
Unknown: the cause of the crash.
Does not prove: that the account caused the crash.
Next action: compare the cited current session and lifecycle records.
```

避免：

```text
The player crashed the server.
The player stole or duplicated items.
The world token proves who used the object.
```

<a id="report-reading-order"></a>
## 报告阅读顺序

每份面向公众的报告都应解释：

1. 简单的含义。
2. 为什么重要。
3. 技术证明和来源参考。
4. 下一步行动。
5. 限制、未知数和未经证明的声明。
