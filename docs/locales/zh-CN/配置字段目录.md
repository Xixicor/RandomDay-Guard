# 完整配置字段目录

> **规范的英文来源:** [CONFIG_FIELD_CATALOG.md](../../CONFIG_FIELD_CATALOG.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


由 `python -B tools/generate_documentation_audit.py --write` 从 `RandomDayGuard/config.lua` 生成。生成器解析纯数据 Lua 表而不执行它。 `python -B tools/generate_documentation_audit.py --check` 存储库验证器需要精确生成的内容和每个叶子一个语义行。数组和可编辑映射算作一片叶子并显示其已发送的内容。

<a id="global-rules"></a>
## 全局规则

- 仅编辑`RandomDayGuard/config.lua`；下面的每个示例都被设计为直接插入其附带的`return { ... }`表中。
- 唯一的顶级真值是`complete`, `complete_with_gaps`, `partial` 一致，并且 `unavailable`.
- `deferred`, `error`, `malformed` 一致，并且 `permission_denied`是源级条件；路由证明仍然存在`full`, `limited_expected_empty`，或`missing`.
- 设置不能覆盖所需的证据、帐户确认、可信帐户保护、备份验证、已保存文件比较、恢复或当前周期证明。
- 路径保持本地和通用。切勿提交帐户 ID、凭据、提供商路线、私人事件或现场证据。

| `source_accounting` | 记录源范围、可用性、当前与历史边界和顶级真相。 | 每个公开报告路径都取决于当前源核算和当前周期沿袭。 | 禁用、非终端或不可写的记帐会强制路由证明丢失。 | 恢复记帐、修复命名源以及重新生成当前周期报告和证明。 |
| `reports` | 选择本地报告路由、输出根和刷新节奏。 | 路由需要源记帐、结构化和翻译的输出以及匹配路由证明。 | 禁用的路由或paired-write/proof失败丢失，永远不会成功。 | 恢复route/output根并通过route_proof.json. |
| `notification` | 控制可选提供商中立的本地文件发件箱。 | 排队需要配置路由并在路由证明持久后完成翻译报告。 | 不支持的模式、丢失证明或本地写入失败不会产生交付声明。 | 保持通知禁用状态或修复本地发件箱并从经过验证的报告重新生成。 |
| `scanning` | 控制可恢复direct/recursive发现、基线、检查点和更改文件扫描。 | 每tick文件、字节和时间预算绑定发现和扫描；检查点自己恢复。 | 不安全的发现或耗尽的工作仍然存在partial/deferred并且无法证明预期为空。 | 恢复有界设置并恢复检查点或构建新的批准基线。 |
| `admin_ini` | 定义检查的Admin.ini路径和突变安全性机制。 | 每次写入都需要经过验证的备份、重复预防、外部更改检测和完整的已保存文件比较。 | 解析、路径、备份、替换、外部更改或读回失败会关闭强制执行。 | 在重试之前恢复已验证的备份并验证干净的BannedPlayer=<ID> lines before retrying. |
| `object_registry` | 控制保存数据类令牌提取和第一基线处理。 | 模式提供类类别、高风险审查、累积增量和世界背景。 | Missing/over-broad模式扭曲背景；类的存在永远不能证明玩家的操作。 | 恢复已审阅的模式并根据可读的已保存证据重建注册表。 |

| `warning_bursts` | 定义警告系列、滚动窗口和review/critical计数。 | 每个系列都必须启用并关联激活已配置的映射玩家。 | 不好windows/counts过度触发或抑制上下文；单独的突发并不是禁止的基础。 | 恢复家庭默认设置并检查引用的log/session证据。 |
| `crash_correlation` | 控制重复失败和崩溃后重新连接相关性。 | 相同帐户、非白名单、宽限窗口和滚动历史记录门符合 | 一次崩溃或不明确的帐户重叠无法授权执行。 | 恢复保守门并重建lifecycle/session相关性。 |

<a id="change-and-recovery-procedure"></a>
## 更改和恢复过程

1. 备份已审核的`config.lua`外部包暂存。
2. 更改最小所属表并将每个字段保留在其记录的位置类型。
3. 当共享运行时工作树稳定时，运行生成器`--check`，重点进行文档测试，`luac -p`在`config.lua` 一致，并且 `tools/validate_repo.py`上。
4. 重新启动 Guard 并检查上面指定的所有者特定state/output。
5. 在任何加载、来源、证明或写入失败时，恢复发货值或审查的备份；执行失败仍保持失败关闭状态。
