# 架构和生命周期

> **规范的英文来源:** [ARCHITECTURE.md](../../ARCHITECTURE.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


RandomDayGuard 是一 UE4SS 看门狗加一个隔离报告模块。它读取服务器拥有的文件，维护有界的本地状态，并写入本地证据并审查输出。它没有提供程序、控制面板、通知服务，RandomDay，或网络依赖。

<a id="end-to-end-data-flow"></a>
## 端到端数据流

1. UE4SS 加载单个规范入口点 `RandomDayGuard/Scripts/main.lua`。当前软件包不提供小写字母变体重复项。
2. 加载器读取`config.lua`、三个数据字典和可选`SavedRoot.txt`。版本标识必须与 `VERSION`, `MANIFEST.json` 一致，并且 `BUILD_MARKER.txt`.
3. Saved-root discovery 检查有界已知候选者和直接已知文件。它记录了`runtime/saved_path_probe.json`中可读的内容；单独查找目录并不能覆盖证据。
4. 直接层从安全偏移量跟踪活动服务器日志。它将生命周期、会话、帐户、警告、重新连接和其他观察到的事件规范化为仅附加证据和当前快照。
5. 慢速层清单将文件保存在有界块中。它写入进度和检查点，恢复未完成的工作，比较更改的文件清单，并生成部分然后最终的 object/world 上下文。
6. 审核逻辑仅关联可用的证据。弱文件名、计时、类计数、相对坐标、流失、单次崩溃或 ping 仍然存在上下文，无法单独授权执行。
7. 单独的报告工作人员调用`Scripts/public_pipeline.lua`。它清点源类，记录当前范围与历史范围，将周期绑定到 version/boot/epoch/poll/source新鲜感，写了五个特定路线JSON/TXT 配对，然后写入 `route_proof.json`.
8. 当明确启用时，本地发件箱会在路径证明存在后从已完成的报告中复制引用。它记录了`delivery_backend="none"` 和 `delivery_attempted=false`;运输不在本产品范围内。

<a id="ownership-and-asynchronous-boundaries"></a>
## 所有权和异步边界

| 所有者 | 有限工作 | 不得阻止或暗示 |
|---|---|---|
| 启动 | 配置、保存根、活动日志、纪元、索引、初始状态。 | 成功的装载机标记并不能证明证据或路线。 |
| 投票回调 | 新日志字节，状态更新，event/session/account输出，调度。 | 递归发现或报告消耗缓慢。 |
| 扫描工作人员 | 清单发现、文件解析、检查点、partial/final基线。 | 当前日志进度；部分并不意味着失败。 |
| 举报工作人员 | 来源统计、翻译、报告对、路线证明、本地发件箱。 | 强制执行或外部交付。 |
| 可选强制执行 | 确认帐户和分数，保护可信帐户和重复帐户，验证备份，拒绝外部文件更改，然后验证保存的结果。 | 绕过任何所需安全检查的报告分数、路线状态或案例成员资格。 |

只有在`poll_id`前进时，民意调查循环才能保持健康， `poll_in_flight` 返回 false，并且计划保持活动状态。这证明了民意调查组件，而不是报告管道。慢速扫描可能是 `partial` 或 `deferred`；默认`slow_world_scan_blocks_current_reports=false`允许新的当前路由继续进行，同时命名历史限制。

<a id="state-and-lifecycle"></a>
## 状态和生命周期

| 状态 | 条目 | 终端或下一个状态 | 错误和恢复 |
|---|---|---|---|
| 启动 | UE4SS 调用加载程序。 | 使用启动 ID 和纪元运行 poll/scan/report 工作程序。 | `startup_error` 是当前启动的关键证据；修复config/path/source并重新启动。 |
| 当前轮询 | 预定的有界回调开始。 | 已完成的轮询记录时间戳和重新安排。 | `poll_error`是当前启动的关键证据；恢复有限工作并确认更新的民意调查。 |
| 扫描待处理 | 找到基线所需的或不完整的检查点。 | `partial`/`deferred`，然后`scan_complete`. | 恢复检查点；仅当记录了stale/incompatible证据时才重建。 |
| 源记帐 | 报告工作人员库存八个源类。 | `complete`, `complete_with_gaps`, `partial`，或`unavailable`. | Disabled/failed记帐强制所有路由`missing`. |
| 路由生成 | 当前周期沿袭和源记账可用。 | `full`, `limited_expected_empty`，或`missing`. | 配对JSON/TXT或路由验证写入失败将路由收敛到`missing`. |
| 本地发件箱 | 路由已启用、完成且符合条件。 | 待处理的本地信封和通知状态结果。 | 没有书面证明或不完整证明意味着没有信封；推断未交付。 |
| 执行审核 | 帐户特定证据达到自动操作的配置分数。 | 仅审核建议或明确启用的`Admin.ini`更新。 | 失败或不可用的安全检查会停止更新；启用恢复后，失败的最终比较将恢复经过验证的备份。 |

<a id="current-and-historical-evidence"></a>
## 当前和历史证据

当前证据属于活动boot/poll并且永远不会仅根据保留的文件名重建。历史证据包括旋转原木，耐用account/session历史记录，保留cases/reports/evidence，以及有限的世界保存扫描。报告公开单独的当前和历史数组和计数。静默重启不得删除持久上下文，并且历史记录不得呈现为当前存在。

<a id="completion-and-recovery-boundary"></a>
## 完成和恢复边界

一条路由的完成需要匹配当前周期版本、启动 ID、纪元 ID、正轮询 ID、新的活动日志状态、两个路由输出及其在 `route_proof.json` 中的条目。通知索赔还需要同周期本地信封；外部交付永远不是公开证明的一部分。

如果最终报告丢失或早于当前状态poll/source state, continue from the first mismatched lineage or failed write.请勿更改不相关的路线、措辞或强制设置。 See [`OUTPUT_SCHEMA_REFERENCE.md`](%E8%BE%93%E5%87%BA%E6%9E%B6%E6%9E%84%E5%8F%82%E8%80%83.md), [`TROUBLESHOOTING.md`](%E6%95%85%E9%9A%9C%E6%8E%92%E9%99%A4.md) 一致，并且 [`SOURCE_MODULE_REFERENCE.md`](%E6%BA%90%E6%A8%A1%E5%9D%97%E5%8F%82%E8%80%83.md).
