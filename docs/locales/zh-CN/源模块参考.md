# 源模块参考

> **规范的英文来源:** [SOURCE_MODULE_REFERENCE.md](../../SOURCE_MODULE_REFERENCE.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


此页面映射了该版本允许的每个源、配置、数据、兼容性加载程序和运行时占位符类 allowlist. The machine index is [`TRACEABILITY_INDEX.json`](../../TRACEABILITY_INDEX.json);此页面是可读的规范解释。每个生成的机器行都命名一个不同的 path/class、用途、所属源块、公共设置、副作用、操作员可见状态、故障、恢复和规范文档。

<a id="ue4ss-loader-and-watchdog"></a>
## UE4SS加载程序和看门狗

`Scripts/main.lua`拥有独立看门狗的启动、Saved-root 发现、当前日志尾部、服务器纪元和会话、有界轮询和扫描、object/world上下文、审核评分、`Admin.ini` 安全门、遗留操作输出以及单独的报告工作人员交接。它必须保持实时民意调查的范围，同时缓慢的历史工作独立恢复。心跳、启动标记或增加`poll_id` 仅证明该组件；路由完成需要相同的当前启动、纪元、轮询、源新鲜度、报告对和路由证明。

源和包只有一个权限：`RandomDayGuard/Scripts/main.lua`。小写 `scripts/` 副本不是源代码树或版本的一部分。在 Windows 或 Linux 上提取包时，保持一种规范拼写可以防止大小写冲突失败。

<a id="public-reporting-module"></a>
## 公共报告模块

`Scripts/public_pipeline.lua`接收回调而不是主机凭据或提供程序适配器。它列出了八个源类，记录终端和不完整状态，将当前玩家与保留的历史记录分开，按顺序翻译每条路线`Observed`, `Interpretation`, `Unknown`, `Does not prove`, `Next action` 一致，并且 `Source references`，然后写入路由证明。可选的通知模式仅写入本地JSON信封；它从不声明交付或捆绑交付endpoint/bridge.

`tests/lua/public_pipeline_runtime_test.lua`中的可执行装置使用Lua加载此交付的模块，证明完整和预期为空的路由，证明缺少当前源循环失败关闭，并证明不完整的路由不会进入发件箱。

<a id="configuration-and-data"></a>
## 配置和数据

[`CONFIG_FIELD_CATALOG.md`](%E9%85%8D%E7%BD%AE%E5%AD%97%E6%AE%B5%E7%9B%AE%E5%BD%95.md) 和 [`TRACEABILITY_INDEX.json`](../../TRACEABILITY_INDEX.json) 由 `tools/generate_documentation_audit.py` 从 `config.lua`、包白名单和源发现的输出类。准确生成的内容和一对一的覆盖范围经过验证。这三个 JSON 字典是标签和映射，而不是证据源。操作员可以编辑配置、保存根选择和启用；源代码、字典、清单和打包的自述文件均属于发行版。

<a id="package-layout"></a>
## 包布局

构建器仅允许三个根合法文件，即 `RandomDayGuard/` 上面的路径以及空的运行时占位符。它按字节对成员进行排序，修复ZIP 元数据，打包规范加载程序一次，扫描每个成员的私有材料，为每个成员记录 SHA-256，将名称和字节绑定到一个内容摘要中，并构建两次。测试拒绝每一个案例折叠冲突，并证明正常提取只会为每个存档条目生成一个物理文件。

公共存储库仅保留当前版本文件夹。构建器会检查其 ZIP、校验和、注释、版本标记和源代码树是否一致。

<a id="code-comment-contract"></a>
## 代码注释契约

运行时注释是简洁的维护者契约，而不是第二个手册。每个发布的运行时模块必须在其打开注释块中放置一个规范链接：

```lua
-- Documentation: docs/SOURCE_MODULE_REFERENCE.md#ue4ss-loader-and-watchdog
```

非明显状态、调度、write/readback/rollback、源发现、翻译、证据、输出模式、路由节奏和编辑块在适用的情况下使用带有这些标签的集中注释：

```lua
-- Public contract: <invariant or consequence>
-- Evidence boundary: <what the input cannot prove>
-- Failure behavior: <how the block fails closed or recovers>
-- Documentation: docs/<canonical-file>.md#<existing-anchor>
```

主加载程序还具有一个用于配置加载、保存的发现、原子的集中所有者注释替换、执行和调度。这些注释说明了控制流和故障边界；它们不会改变运行时行为。

验证器需要每个运行时模块的模块级`Documentation:`链接，解析每个注释路径和锚点，需要两个运行时模块中的集中契约和失败注释，并将相同的规范链接与`TRACEABILITY_INDEX.json`进行比较。注释是可追溯性的，而不是运行时证明。

<a id="contributor-change-checklist"></a>
## 贡献者更改清单

1. 更新一个所属模块及其重点固定装置。
2. 更新规范配置、架构、输出、证据或生命周期部分。
3. 配置后运行`python -B tools/generate_documentation_audit.py --write`，打包路径、生成的输出类、所有者或恢复合同更改。
4. 配置后运行`python -B tools/generate_documentation_audit.py --check`、重点单元测试、Lua 可用的真实 Lua 固定装置、完整的验证器、两个独立的确定性构建，以及 `git diff --check`.
5. 在创建版本之前查看生成的 ZIP成员列表、校验和和私有材料扫描。
