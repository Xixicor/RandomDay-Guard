# 配置概念

> **规范的英文来源:** [CONFIG_REFERENCE.md](../../CONFIG_REFERENCE.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


此解释描述了每个主要配置区域控制的内容、何时运行以及如何与证据和安全门交互。它不拥有确切的字段目录或配置文件程序。

对于面向任务的预设和安全更改步骤，请使用[`CONFIG_PROFILES.md`](%E9%85%8D%E7%BD%AE%E9%85%8D%E7%BD%AE%E6%96%87%E4%BB%B6.md)。对于每个精确的源字段、默认值、类型、不变量、输出效果和恢复规则，使用生成的 [`CONFIG_FIELD_CATALOG.md`](%E9%85%8D%E7%BD%AE%E5%AD%97%E6%AE%B5%E7%9B%AE%E5%BD%95.md)； the validator requires one row there for every shipped `config.lua` 叶字段设置一行。

<a id="top-level-safety"></a>
## 顶级安全性

| 选项 | 默认 | 含义 |
|---|---:|---|
| `enabled` | `true` | 主开关防护 |
| `enforcement.review_only_mode` | `true` | Record/recommend仅限 |
| `enforcement.auto_ban` | `false` | 默认情况下不自动禁止 |
| `enforcement.write_admin_ini` | `false` | 默认情况下不写入Admin.ini |

在服务器所有者审阅输出之前保持这些安全。

<a id="saved"></a>
## `saved`

控制防护如何找到服务器`Saved/`文件夹及其所属文件可以扫描。

使用时机：

```text
Saved root auto-detection fails.
World folder changed.
Provider or container path is unusual.
```

检查：

```text
runtime/saved_path_probe.json
RandomDayGuard/SavedRoot.txt
```

规则：

```text
SavedRoot.txt -> AbioticFactor/Saved
not -> Worlds/<WorldName>
```

<a id="log_tail"></a>
## `log_tail`

控制实时日志读取。

有用选项：

| 选项 | 安全值 | 为什么 |
|---|---|---|
| `enabled` | `true` | 实时防御需要 |
| `start_at_end_on_first_run` | `true` | 避免将旧日志作为实时事件 |
| `tail_backup_logs` | `false` | 备份日志是历史记录，而非实时 |
| `max_lines_per_poll` | 有界 | 保持轮询循环响应 |

检查：

```text
runtime/log_offsets.tsv
runtime/evidence/session_events.jsonl
runtime/current/poll_status.json
```

<a id="runtime"></a>
## `runtime`

控制轮询和预算。

主要健康规则：

```text
poll_id increases
poll_in_flight returns false
poll_scheduled is true
```

检查：

```text
runtime/current/poll_status.json
```

如果`poll_id`停止，则表示有东西阻塞了循环。

<a id="source_accounting"></a>
## `source_accounting`

控制显式证据源的覆盖范围和范围。

| 关键 | 默认 | 含义 |
|---|---:|---|
| `enabled` | `true` | 为公共路线报告写入源记帐。 |
| `require_terminal_status` | `true` | 要求每个源公开显式终端或不完整的终端状态。 |
| `distinguish_current_from_historical` | `true` | 将当前和历史证据分开。 |
| `slow_world_scan_blocks_current_reports` | `false` | 允许当前报告说明有界世界扫描已推迟或部分进行。 |
| `changed_file_manifest` | 基线清单路径 | 用于有界historical/world会计的参考。 |

源状态`available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied`，或`error`.

设置`source_accounting.enabled = false`不会静默删除状态输出。管道仍然使用 `runtime/final_logs/source_accounting_latest.json`。它还会写入不可用记账的历史状态记录。由于源记帐是报告契约的一部分，因此每条路由都无法关闭到 `enabled=false`, `status="unavailable"` 一致，并且 `disabled_reason="source_accounting_disabled"` 写入 `missing`；禁用计费时，任何路由都不会被视为已完成。

<a id="reports"></a>
## `reports`

控制通用本地报告管道。

默认启用所有五个路由并在`runtime/final_logs`:

```text
server_status
daily_rollup
player_activity
case_review
critical_guard
```

每条路由中写入结构化和翻译的输出以及`route_proof.json`中的证明。禁用路由会产生`missing`证据，而不是假装它已完成。

<a id="notification"></a>
## `notification`

可选的通用本地文件发件箱。默认情况下它处于禁用状态，并且不会向外部提供商发送任何内容。

默认值：

```lua
notification = {
    enabled = false,
    mode = "local_file_outbox",
    include_expected_empty = false,
},
```

默认情况下禁用每个通知路由。当有意启用时，发件箱可能在写入 `route_proof.json` 后仅使用已完成的翻译报告。当地证据和报告仍然具有权威性。特定于提供商的交付、交付端点、凭据和桥接器不属于公共独立看门狗合同的一部分。

<a id="scanning"></a>
## `scanning`

控制基线扫描、检查点和更改文件刷新。

使用时机：

```text
building first world baseline
resuming after crash
refreshing changed files later
```

检查：

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/baselines/file_manifest.tsv
```

重要设置：

```lua
scanning = {
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
    changed_file_detection = true,
},
```

<a id="forensic_rollup"></a>
## `forensic_rollup`

控制每日快速上传包和最终的纯语言日志。

输出：

```text
runtime/current/forensic_today.json
runtime/current/forensic_today.md
runtime/current/forensic_today.txt
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

使用时机：

```text
You want one daily folder that summarizes what happened.
You want a plain-language TXT to upload for quick analysis.
```

检查：

```text
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

规则：

```text
Daily summaries are rebuildable indexes.
Source evidence remains authoritative.
```

<a id="logging"></a>
## `logging`

控制事件量和低重要性聚合。

使用时机：

```text
actor-touch events are noisy
raw event files grow too quickly
```

安全模式：

```lua
logging = {
    low_importance_mode = "aggregate",
    write_low_importance_raw_events = false,
},
```

<a id="retention"></a>
## `retention`

控制文件保留时间以及JSONL日志何时轮换。

使用时机：

```text
disk usage grows too fast
you need more audit history
you need shorter live-history windows
```

重要选项：

```text
detailed_retention_days
rotate_jsonl_when_bytes_exceed
max_raw_events_lines
keep_enforced_forever
keep_evidence_forever
```

## `warning_bursts`

控制警告窗口检测。

示例：

```text
ActorChannelFailure
DeployableSaveWarning
UpdateActorToWorldSave
ServerMove warnings
```

规则：

```text
Warnings are context until correlated with mapped sessions and thresholds.
```

<a id="crash_correlation"></a>
## `crash_correlation`

控制重复审核crash/reconnect。

安全默认值：

```lua
crash_correlation = {
    single_crash_never_bans = true,
    require_same_account = true,
},
```

有用计数器：

```text
server_crash_overlap_count
post_crash_reconnect_count
unclean_disconnect_count
```

<a id="join_leave"></a>
## `join_leave`

控制流失和加入浪潮跟踪。

安全默认值：

```lua
join_leave = {
    churn_alone_never_bans = true,
},
```

用于：

```text
rapid reconnect loops
join waves
short-session patterns
```

<a id="raid_detection"></a>
## `raid_detection`

对相关窗口中活动的帐户进行分组。

规则：

```text
A raid case groups accounts for review.
It does not make every account guilty.
```

每个强制帐户仍需要帐户特定的证据。

## `object_registry`

控制object/class从可读的已保存证据中提取令牌。

输出：

runtime/object_registry_partial.json
runtime/object_registry.json
runtime/object_registry_counts.tsv

Object/class context is not a ban reason by itself.

<a id="world_state"></a>
## `world_state`

控制boot/current/session世界状态快照。

输出：

```text
runtime/world_state/current/world_state_latest.json
runtime/world_state/sessions/<date>/<session_id>_<account_id>/
```

用于会话审查和世界背景。

<a id="enforcement"></a>
## `enforcement`

控制建议和实际Admin.ini写入。

在 Guard 可以添加禁令之前，以下每项陈述都必须为真：

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
account identity is mapped
not trusted
not moderator
threshold is met
```

如果一项陈述错误或无法检查，Guard 将保持`Admin.ini`不变并记录原因。

<a id="admin_ini"></a>
## `admin_ini`

控制安全文件写入。

规则：

```text
Back up before writing.
Preserve existing bans.
Preserve moderators.
Write clean BannedPlayer=<ID> only.
```

<a id="restart_request"></a>
## `restart_request`

控制其他操作员拥有的进程可能检查的可选本地标记文件。它不会重新启动或终止服务器。

默认值：

```lua
restart_request = {
    enabled = false,
    restart_marker_file = "runtime/request_restart.flag",
    restart_reason_file = "runtime/restart_reason.json",
},
```

输出：

```text
runtime/request_restart.flag
runtime/restart_reason.json
```

没有捆绑托管面板、提供商桥接或重新启动自动化。启用标记创建并不能证明外部进程消耗了请求或重新启动了服务器。
