# 安全策略

> **规范的英文来源:** [SECURITY.md](../../../SECURITY.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


<a id="report-a-vulnerability-privately"></a>
## 私下报告漏洞

使用[GitHub私人漏洞报告](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) 将机密报告发送给存储库所有者。如果该表格不可用，请使用 [所有者的公开GitHub个人资料](https://github.com/Xixicor) to request a private contact channel without including vulnerability details.

请勿打开包含漏洞利用步骤、凭据、私人服务器路径、玩家标识符、`Admin.ini`、保存的数据、Webhook URL 或实时证据文件的公共问题。

<a id="include-useful-evidence"></a>
## 包括有用的证据

提供：

- 受影响的RandomDayGuard 版本或提交；
- 受影响的组件和预期的安全行为；
- 使用已清理的固定装置的最小复制步骤；
- 观察到的影响及其是否可重复；以及
- 任何不暴露私人数据的拟议缓解措施。

不要发送真正的秘密。用清晰的占位符替换私有路径、帐户标识符、主机名和令牌，同时保留重现问题所需的结构。

<a id="expect-review-first-handling"></a>
## 预期审查优先处理

报告是维护人员审查的证据，而不是授权访问服务器、测试实时目标、发布漏洞利用详细信息或削弱故障关闭默认值的证据。所有者将通过私人报告验证范围并协调任何披露。
