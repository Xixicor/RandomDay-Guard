# 输出和状态架构参考

> **规范的英文来源:** [OUTPUT_SCHEMA_REFERENCE.md](../../OUTPUT_SCHEMA_REFERENCE.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


这是生成的面向操作员的文件的规范契约。它独自拥有精确的输出路径、字段名称、允许的值、沿袭要求和路由模式。程序指南链接到此处，而不是重新定义这些事实。

运行时证据具有权威性；文件名、调度程序心跳、翻译后的报告或本地发件箱对象仅证明其自己的字段和沿袭。

<a id="public-report-routes"></a>
## 公共报告路由

报告工作人员在`runtime/final_logs/`:

| 路由 | 合同 | `full`下拥有五个路由要求 | 预期为空的含义 |
|---|---|---|---|
| `server_status` | 当前调度程序、活动日志、扫描挂起和源覆盖状态。 | 活动日志中可见的当前boot/epoch/poll沿袭、新活动日志、accounting/history写入和JSON/TXT 对。 | 不用于健康的当前周期；缺少的血统是`missing`. |
| `daily_rollup` | 活动日志中可见的当前day/window跨服务器、玩家、案例、扫描和覆盖范围的连续性。 | 历史会计终端足以完成路线和当前周期证明。 | 没有保留玩家，也没有审查案例。 |
| `player_activity` | 分离当前和历史player/account观察。 | 当前周期证明加上一行或多行current/historical行。 | 有界输入中没有符合条件的玩家行；没有综合主题。 |
| `case_review` | 命名保留案例和当前review/BAN-ELIGIBLE候选者。 | 当前周期证据加上一个或多个带有来源参考的命名案例。 | 没有命名案例符合审查标准；没有合成案例。 |
| `critical_guard` | 当前启动调度程序、启动、轮询或证据完整性故障。 | 当前周期证明加上当前严重故障。 | 当前没有严重故障；没有综合案例。旧文本错误不拥有此路由。 |

每个启用的路由都会写入`<route>_latest.json` 和 `<route>_latest.txt`。直到`runtime/final_logs/route_proof.json`记录相同的版本、启动、纪元、轮询和源新鲜度，配对才完成。

<a id="report-json-schema"></a>
## 报告JSON架构

所有路线JSON 使用 `schema="randomdayguard.report/v1"`.

| 字段 | 类型 | 含义和不变 |
|---|---|---|
| `schema` | 字符串 | 完全`randomdayguard.report/v1`. |
| `generated_ts`, `report_date` | 字符串 | 生成时间戳和报告日期。 |
| `version` | 字符串 | Runtime/package此周期的标识。 |
| `boot_id`, `epoch_id` | 字符串 | 当前进程启动和服务器连续性纪元。两者都是完成所必需的。 |
| `poll_id` | 整数 | 正当前轮询标识符。 Zero/missing无法完成路线。 |
| `source_freshness` | 对象 | `status`, `checked_ts`、活动日志状态、上次轮询时间戳和上次完成轮询时间戳。 |
| `current_cycle_proof_complete` | 布尔值 | 仅当谱系和新active-log/current-poll证据一致时才为真。 |
| `route` | 枚举 | 上述五种路线之一。 |
| `route_proof_status` | 枚举 | `full`, `limited_expected_empty`，或`missing`. |
| `coverage_status` | 枚举 | 完全`complete`, `complete_with_gaps`, `partial`，或`unavailable`. |
| `completed`, `expected_empty` | 布尔值 | `completed` 仅对于 `missing`; `expected_empty` 为 false 仅对于 `limited_expected_empty`. |
| `observed` | 字符串数组 | 具体保留facts/counts/statuses. |
| `interpretation` | 字符串数组 | 根据证据校准的谨慎含义。 |
| `unknown` | 字符串数组 | 缺少身份、历史、来源或上下文。 |
| `does_not_prove` | 字符串数组 | 证据无法支持的结论。 |
| `next_action` | 字符串 | 最安全的有界操作员操作。 |
| `source_references` | 字符串数组 | 排序唯一runtime/Saved引用。 |
| `enforcement_authority` | 布尔值 | 始终为假。报告从不授权写入。 |
| `output_paths` | 两个字符串 | JSON 和 TXT 在配对写入之前添加的路径。 |

`coverage_status`仅是顶级记帐。源记录单独拥有`available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied` 一致，并且 `error`。路由证明单独拥有`full`, `limited_expected_empty` 一致，并且 `missing`;价值观永远不会跨越这些界限。

路由扩展：

- `server_status`: `scheduler_status`, `active_log_status` 一致，并且 `server_metrics`。这些指标记录当前纪元开始、最新完成的轮询时间戳和 ID、活跃玩家计数、active/backup-log计数，扫描pending/progress 值，以及 configured/usable/unavailable 源组记帐。当没有来源公开这些事实时，他们不会发明正常运行时间、重新启动计数、备份时间戳或中断持续时间。
- `player_activity`: `player_activity_present`, `movement`, `same_day_sessions`, `current_player_count`, `current_evidence_player_count`, `historical_player_count`, `historical_session_count`, `current_players`, `historical_players`，和兼容性数组`players`。每个当日会话都会保留其会话 ID、帐户 ID、已知的显示名称，join/leave 时间戳、干净退出和生命周期标志以及源引用。保留身份和PlayerData 存在仍然是上下文，而不是今天的活动证明。
- `case_review`: `cases`, `review_subjects`, `current_case_count` 一致，并且 `retained_case_count`。当前评论主题记录其case/account ID、已知时显示名称、状态、分数、身份置信度，first/last 观察结果、警告计数、原因、当前活动标记和来源引用。保留的案例本身不会创建当前主题。
- `critical_guard`: `critical_failure_present` 和 `current_boot_error_only=true`.
- `daily_rollup`: `daily_maturity`, `once_per_day_continuity`, `dedupe_window` 一致，并且 `daily_metrics`。这些指标记录报告日期、活跃玩家、当天活动的帐户、加入、离开、干净和不干净的退出、生命周期回报、当前指定的审核主题、保留的案例，current/retained身份计数和源组覆盖范围。

<a id="translated-txt-schema"></a>
## 已翻译TXT架构

配对的文本文件以操作员可读的结果开头，并将沿袭详细信息移动到末尾。它保留了这个确切的部分顺序：

```text
RandomDayGuard <route title>
Generated: <timestamp>

Summary
<one plain-language route summary>

What Guard observed
- ...

What it means
- ...

What remains unknown
- ...

Recommended next step
...

Evidence boundary
- ...

Rating explanation
- ...

Technical record
- Route: <route>
- Version: <version>
- Cycle: boot=<boot> epoch=<epoch> poll=<poll>
- Source freshness: <status>
- Route result: <full|limited_expected_empty|missing>
- Coverage: <status>

Translation notes
- ...

Source references
- ...
```

翻译仅使用结构化报告字段和批准的字典映射。它无法添加结构化报告中缺少的参与者、案例、交付、因果关系、所有权、意图或执行资格。技术细节仍然可用，但不会取代可读结果。

<a id="source-accounting-schema"></a>
## 源会计架构

`runtime/final_logs/source_accounting_latest.json` 使用 `randomdayguard.source-accounting/v1` 生成 reason/status, enablement/disabled原因，current/historical区别，更改文件清单，源记录，usable/unavailable类别列表和声明限制。

每个源记录包含：

| 字段 | 类型 | 含义 |
|---|---|---|
| `source_class` | 字符串 | 以下八个类别之一。 |
| `scope` | `current` 或 `historical` | 时间所有权；范围永远不会静默合并。 |
| `required` | 布尔值 | 只有 `active_log` 是当前周期路由新鲜度所必需的。 |
| `status` | 枚举 | 下面列出了源结果。 |
| `terminal` | 布尔值 | False 仅适用于 `partial` 和 `deferred`. |
| `available`, `readable` | 布尔值 | True 仅适用于`available` 和 `expected_empty`. |
| `file_count` | 整数 | 绑定帐户file/reference计数。 |
| `source_references` | 数组 | 已排序的唯一源paths/references. |
| `detail` | 字符串 | 有界结果或错误详细信息。 |
| `does_not_prove` | 字符串 | 可用性不是意图、所有权、损坏、重复或执行证据。 |

源类：

| 源类 | 范围 | 它贡献了什么 | 它无法证明什么 |
|---|---|---|---|
| `active_log` | 当前，必需 | 可读的活动服务器日志和最新的民意调查沿袭。 | 完整的历史记录或玩家罪责。 |
| `admin_ini` | 当前，可选 | 结构上有效的当前moderator/ban状态，或预期缺席。 | 玩家行为或有效原因元数据。 |
| `recent_backup_logs` | 历史 | 可读rotated/backup日志引用。 | 当前存在或当前启动状态。 |
| `playerdata_filenames` | 当前上下文 | 所选保存根目录下的有限可读文件名引用。 | 文件所有权、实时存在、身份内容或不当行为。 |
| `existing_cases` | 历史 | 保留命名案例files/index在当前输出之前捕获的记录。 | 当前活动或旧结论的正确性。 |
| `existing_reports` | 历史 | 保留final/forensic/warning报告引用。 | 权威来源替换。 |
| `existing_evidence` | 历史 | 保留证据引用。 | 服务器从未暴露的事件的完整性。 |
| `world_save_scan` | 历史 | 完整、部分、延迟或不可用有界scan/checkpoint状态。 | 特定玩家的操作或所有权。 |

来源状态值：

| 状态 | 终端 | 操作员含义和操作 |
|---|---:|---|
| `available` | 是 | 存在可读的有用来源；查看其参考文献。 |
| `expected_empty` | 是 | 可选来源已检查且合法absent/empty。不要发明数据。 |
| `partial` | 否 | 有界工作或库存限制不完整；允许恢复。 |
| `deferred` | 否 | 工作有意待定；等待所属的工作人员。 |
| `unavailable` | 是 | Source/path/tool 不存在或不可用；仅在路线需要时进行修复。 |
| `malformed` | 是 | 内容未通过结构验证；保留它并修复格式。 |
| `permission_denied` | 是 | 访问被明确拒绝；恢复最低权限读取访问权限。 |
| `error` | 是 | 源级别受限probe/read意外失败；检查`detail`而不暴露秘密。 |

顶级`coverage_status`正是`complete`, `complete_with_gaps`, `partial`，或`unavailable`。所需的源级别`error`, `malformed`，或`permission_denied`汇总到顶级`unavailable`；源代码级`deferred`汇总到顶级`partial`。禁用源记帐仍然会写入不可用状态，并强制每条路由到`missing`.

<a id="historical-status-schema"></a>
## 历史状态架构

`runtime/final_logs/historical_backfill_latest.json` 使用 `randomdayguard.history/v1`: `generated_ts`、记帐`status`, `resumable=true`, `changed_file_refresh=true`, `current_evidence_is_not_history=true`、源记帐数组、不可用类和有界`next_action`.

`runtime/history/public_accounts.tsv`是具有以下标头的持久公共历史记录：

```text
account_id	ban_id	display_name	identity_confidence	status	score	first_seen	last_seen	source_references
```

行按帐户 ID 排序，字段为 single-line/tab-safe，引用为 sorted/unique。该文件在安静重启时保留历史上下文；它永远不会将历史转换为当前的存在。

<a id="route-proof-schema"></a>
## 路由证明架构

`runtime/final_logs/route_proof.json` 使用 `randomdayguard.route-proof/v1`并记录顶级生成时间戳、版本、启动、纪元、轮询、源新鲜度、当前周期完整性、允许的状态和`routes`数组。

每个路由条目包含route/status, version/boot/epoch/poll、源新鲜度对象、当前周期完整性、输出路径和源参考。已禁用的路线记录`status="missing"` 和 `reason="route_disabled"`。如果路由验证写入失败，则在接受任何候选通知之前，每条路由都会被重写为 incomplete/missing。

<a id="notification-schemas"></a>
## 通知架构

可选的公共模式仅是本地文件发件箱。

`runtime/notifications/pending/<route>_latest.json` 使用 `randomdayguard.notification/v1`带有生成的时间戳，version/boot/epoch/ poll/source新鲜度、路由，`completed_output`、路由验证状态、结构化和翻译的报告路径、源参考、`delivery_backend="none"` 一致，并且 `delivery_attempted=false`。合格的输出使用`status="ready_for_local_consumer"`, `delivery_eligible=true` 一致，并且 `delivery_allowed=true`。已配置但 missing/ineligible 路由仍会使用 `status="suppressed_current_cycle"` 写入审核信封，传送标志均为 false，并且 `suppression_reason="route_or_completion_policy_blocked"`。因此，`pending/` 下存在文件本身并不意味着已排队或符合条件。

`runtime/notifications/notification_status.json` 使用 `randomdayguard.notification-status/v1` 具有相同的谱系、`generic_local_outbox_only=true`, `delivery_attempted=false` 和每个路由`queued`/`outcome` 行。 `full` 符合资格；仅当 `include_expected_empty=true`; `missing` 永远不符合条件时，expected-empty 才符合条件。当路由验证写入失败时，状态结果为 `route_proof_write_failed`；仍然可以写入抑制的审核信封，但它不是被接受的输出。

| `runtime/current/forensic_today.json`, `.md`, `.txt`, `runtime/forensic_days/YYYY-MM-DD/**`, `runtime/final_logs/YYYY-MM-DD/**` | 取证汇总。 | 当前和日期的可重建审核索引。 | 从源证据重建；永远不要将摘要视为权威。 |
| `runtime/final_logs/source_accounting_latest.json`, `historical_backfill_latest.json`, `<route>_latest.json`, `<route>_latest.txt`, `route_proof.json` | 公共报告工作人员。 | 上述架构和完成规则。 | 首先修复不匹配的lineage/source/write；丢失始终丢失。 |
| `runtime/notifications/pending/<route>_latest.json`, `runtime/notifications/notification_status.json` | 可选的本地发件箱。 | 符合条件或明确禁止的本地信封加上状态。 | Missing/ineligible路由可能有禁止的文件，但从不排队；检查交付标志并推断没有外部交付。 |

Overwrite/append/retention behavior is controlled by the producing section in [`CONFIG_FIELD_CATALOG.md`](%E9%85%8D%E7%BD%AE%E5%AD%97%E6%AE%B5%E7%9B%AE%E5%BD%95.md). Package ZIPs contain only empty `.gitkeep` 占位符；发布包中的任何 `runtime/` 下的空 evidence/output 字节均未通过验证。

<a id="failure-and-recovery-matrix"></a>
## 失败和恢复矩阵

| 失败 | 所需状态 | 安全恢复 | 无效推理 |
|---|---|---|---|
| 当前沿袭absent/stale | 所有路由`missing`. | 恢复active-log/current-poll 证明并重新生成。 | 旧路线文件当前未完成。 |
| 可选源预期为空 | 源`expected_empty`；符合条件的路线可能是`limited_expected_empty`. | 除非源应该存在，否则无法修复。 | 空并非不可用，也不能证明历史不存在。 |
| 扫描不完整 | 源`partial` 或 `deferred`. | 允许有界恢复；保持当前路由策略明确。 | 部分不损坏。 |
| 所需来源不可用 | `coverage_status=unavailable`；依赖路由`missing`. | 修复选定的Saved/log访问。 | 其他正常来源不会替换所需的来源。 |
| 所需的来源探测错误 | 来源状态`error` 有界 `detail`; `coverage_status=unavailable`；依赖路由`missing`. | 修复指定的source/probe 并生成一个更新的周期。 | 源错误不是第五个顶级覆盖值。 |
| 配对报告写入失败 | `coverage_status=unavailable`;路线收敛到 `missing`. | 修复文件系统并重写两个对成员以及证明。 | 一个同级文件未完成，写入失败不是顶级`error`. |
| 路由验证写入失败 | 每条重写的路线都缺失；没有符合条件的发件箱；配置的路由可能会收到抑制的审核信封。 | 修复路由验证写入并重新生成同周期输出。 | 看起来有效的报告JSON 或抑制的信封不是路由证明。 |
| 通知写入失败 | 结果`local_outbox_write_failed`. | 修复本地输出根目录；从已完成的报告中重新生成。 | 没有发生外部传递。 |
| Admin.ini交易失败 | 执行被阻止backup/write/readback/rollback证据。 | 恢复经过验证的备份；保持仅限审核。 | 阈值或报告不能成为绕过恢复的理由。 |

See [`EVIDENCE_BOUNDARY.md`](%E8%AF%81%E6%8D%AE%E8%BE%B9%E7%95%8C.md), [`ARCHITECTURE.md`](%E6%9E%B6%E6%9E%84.md) 一致，并且 [`SOURCE_MODULE_REFERENCE.md`](%E6%BA%90%E6%A8%A1%E5%9D%97%E5%8F%82%E8%80%83.md).
