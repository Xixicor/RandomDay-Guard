# 贡献

> **规范的英文来源:** [CONTRIBUTING.md](../../../CONTRIBUTING.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


RandomDayGuard接受对解析器、文档、测试和公共安全验证的集中、可重复的改进。让每项更改都受到公共项目合同的约束并保留审查优先的行为：Guard 必须离开`Admin.ini` 当无法确认所需的安全检查时不变。

<a id="prepare-a-safe-workspace"></a>
## 准备一个安全的工作空间

1. 分叉或克隆存储库并创建一个重点分支。
2. 安装受支持的 Python 3 解释器。当你改变Lua时安装一个Lua编译器所以`luac -p` 可以检查语法。
3. 阅读[文档主页](%E6%96%87%E6%A1%A3.md), [架构](%E6%9E%B6%E6%9E%84.md) 一致，并且 [证据边界](%E8%AF%81%E6%8D%AE%E8%BE%B9%E7%95%8C.md) 代表您要更改的区域。
4. 检查`git status` 在编辑之前并保留不相关的工作。
5. 仅使用合成或消毒的固定装置。

切勿提交私有服务器日志、保存的文件夹、玩家标识符、`Admin.ini`、私有通知端点、凭据、私有路径、运行时输出或复制的实时证据。

<a id="make-a-focused-change"></a>
## 进行有针对性的更改

- 遵循现有的命名、格式、安全检查和模块所有权。
- 保留一个规范每个过程或确切事实的文档所有者。
- 当行为或公共输出发生变化时，更新用户文档和示例。
- 在可行的情况下添加回归测试以修复错误。
- 不要削弱帐户确认、受信任帐户保护、备份验证、外部更改检测、保存文件比较、恢复或仅审核默认设置来使测试通过。

<a id="run-the-relevant-checks"></a>
## 运行相关检查

对于仅文档更改，请运行：

```powershell
python -B tools\generate_documentation_audit.py --check
python -B -m unittest discover tests -p "test_documentation*.py"
git diff --check
```

对于源、配置、打包或测试更改，还可以从 [验证和发布审核](%E9%AA%8C%E8%AF%81%E5%92%8C%E5%8F%91%E5%B8%83.md)，包括 Lua 语法检查、存储库验证、公共管道测试和完整的单元测试套件。报告每一项跳过或不可用的检查；不要将其描述为已通过。

<a id="submit-the-change-for-review"></a>
## 提交更改以供审核

仅在审核完整差异后才打开重点拉取请求。包括：

- 问题和预期行为；
- 更改的确切文件和公共合同；
- 运行的命令及其结果；
- 隐私、兼容性和执行影响；以及
- 剩余限制或后续工作。

不要包含生成的运行时证据或发布档案，除非更改明确要求并验证它们。贡献并不授权在第三方网站上发布、部署、实时服务器测试、强制执行操作或发布。

通过 [私人安全路线](%E5%AE%89%E5%85%A8.md)，不是公共问题或普通拉取请求。
