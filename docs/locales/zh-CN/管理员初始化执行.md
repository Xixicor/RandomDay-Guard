# Admin.ini强制执行

> **规范的英文来源:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). 此本地化文档保留了准确的命令、路径、键、状态值、哈希值和文件名。如果技术措辞不同，请使用英文来源。


RandomDayGuard 不会更改默认设置中的服务器禁止列表。它仅创建报告供管理员查看。本页为有意启用的管理员解释了可选的自动禁止列表更新。

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## Guard 在更改禁止列表之前会检查哪些内容

Guard adds a ban only when every answer below is **是**:

1. 当前证据是否有足够的置信度识别某个特定帐户？
2. 该帐户既不是管理员也不是管理员帐户标记为可信？
3. 该帐户是否尚未在禁止列表中？
4. 该帐户是否达到配置的自动操作分数？
5. Guard 可以读取当前的`Admin.ini`并保存相同的备份？
6. Guard 准备更新时`Admin.ini`保持不变吗？
7. 保存后，完整的文件是否与预期结果完全匹配？

If any answer is **否**, or cannot be checked, Guard leaves `Admin.ini`不变，并且在其报告中记录原因。如果保存开始但最终检查失败，Guard 将恢复已验证的备份。

<a id="file-format"></a>
## 文件格式

`Admin.ini`必须仅接收干净的禁止行：

```ini
BannedPlayer=<ID>
```

- 无名称。
- 无注释。
- 无原因。
- 否后缀。

<a id="safe-defaults"></a>
## 安全默认值

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## 禁止 ID 来源

最佳来源：

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

运行时接受完整数字 ID 或完整记录的`<digits>_+_|<non-space token>`连接表单，并从中派生数字禁止 ID。拒绝具有未知后缀的任意数字前缀；它们不会被截断为禁令 ID。

正确：

```ini
BannedPlayer=2535422284688820
```

错误：

```ini
BannedPlayer=ExamplePlayer
```

同样错误：

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## 确切设置 Guard 检查

这些设置实现上述检查。每个列出的条件都必须为真：

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

如果任何条件为假或无法检查，Guard 会保持禁令列表不变并记录阻止它的原因。

<a id="transaction-safety"></a>
## 交易安全

唯一`Admin.ini` 突变路径按顺序执行以下步骤：

1. 读取并在结构上验证权威字节。
2. 从同一快照派生审核者、受信任和现有禁止状态。
3. 在 `runtime/backups/` 并逐字节验证它。
4. 重读`Admin.ini` 立即更换并拒绝任何外部更改。
5. 通过配置的受控替换路径写入候选项。
6. 要求完整的读回字节等于完整的候选字节。
7. 读回失败时，仅在当前文件仍然是 Guard 写入的确切候选文件时恢复已验证的备份。如果另一个编写者更改了它，Guard 会拒绝回滚而不是覆盖未知的外部字节。

重复的 ID 是幂等的：不会写入第二行，也不会写入第二个备份。备份名称包括时间戳、源字节指纹和干净 ID，因此单独的尝试无法共享旧的一秒文件名。

<a id="local-regression-proof"></a>
## 本地回归证明

`tests/lua/enforcement_runtime_test.lua` 启动一次附带的加载程序，然后执行其真正的本地`append_ban()` 关闭存储库下的隔离合成文件 `.tmp/` 目录。它涵盖了插入、重复幂等性、moderator/trusted 拒绝、弱和格式错误的身份拒绝、字节精确备份验证、并发修改拒绝、读回失败后成功回滚以及拒绝覆盖写入后外部更改。它的文件系统包装器拒绝固定根之外的任何突变；没有真实的服务器路径或真实的`Admin.ini`。

运行它`python tools/test_public_pipeline.py`。固定通行证仅证明本地交易行为。它不启用强制执行、授权生产写入或证明特定于主机的权限。

## 要检查的文件

```text
runtime/account_evidence.json

runtime/enforced_bans.jsonl
runtime/enforced.txt

```

<a id="rollback"></a>
## 回滚

1. 停止服务器。
2. 恢复最新的Admin.ini 备份来自 `runtime/backups/`.
3. 根据需要删除不正确的`BannedPlayer=<ID>`行。
4. 启动服务器。
5. 重新打开Admin.ini并确认该行仍然存在或已删除。
6. 保留`enforced_bans.jsonl`审核。
