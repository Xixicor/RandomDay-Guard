# Тоглогчийн хяналтын ажлын урсгал

> **Каноник англи эх сурвалж:** [PLAYER_REVIEW_WORKFLOW.md](../../PLAYER_REVIEW_WORKFLOW.md). Энэ локалчлагдсан баримт бичиг нь яг командууд, замууд, түлхүүрүүд, төлөвийн утгууд, хэшүүд болон файлын нэрийг хадгалдаг. Хэрэв техникийн үг хэллэг өөр байвал англи эх сурвалжийг ашиглана уу.


Энэ хуудсыг нэг тоглогч, бүртгэл эсвэл кейс ашиглах. Зорилго нь автоматаар буруутгах биш, дахин давтагдах боломжтой хяналтын шийдвэр юм.

<a id="quick-path"></a>
## Шуурхай зам

1. Нээх `runtime/final_logs/player_activity_latest.json`.
2. Маршрутын төлөвийг `runtime/final_logs/route_proof.json`.
3. Ямар ажиглалт одоо байгаа, аль нь түүхэн болохыг тодорхойлох.
4. Ишлэгдсэн таниулбар болон сессийн эх сурвалжийг шалгана уу.
5. Хянах `case_review_latest.json`холбоотой тохиолдол байгаа үед.
6. Үл мэдэгдэх болон `does_not_prove` үйлдэл сонгохын өмнө.
7. Тус тусад нь хэрэгжүүлэх гарцууд нотлогдоогүй тохиолдолд хэрэгжилтийг идэвхгүй болго.

<a id="1-confirm-route-proof"></a>
## 1. Маршрутын баталгааг баталгаажуулах

Тоглогчийн замыг дараах байдлаар тайлбарлана уу:

| Төлөв | Үйлдэл |
|---|---|
| `full` | Эх сурвалжийн хязгаарыг хянаж байх зуураа үргэлжлүүлнэ үү. |
| `limited_expected_empty` | Зөвхөн байгаа сэдвүүдээр үргэлжлүүлэх; алга болсон тоглогч эсвэл гэрийг бүү зохион бүтээ. |
| `missing` | Тоглогчийн шийдвэрийг зогсоож, маршрутын алдааг олж засварлана уу. |

Эрүүл хуваарилагч нь маршрутын баталгааг орлохгүй.

<a id="2-establish-identity"></a>
## 2. Өөрийгөө тодорхойлох

Серверт илэрсэн таних нотлох баримтаар баталгаажсан цэвэр данс танигчийг илүүд үзэх, боломжтой бол PlayerData файлын нэр. Түүхий эх сурвалжийн лавлагааг хадгална уу.

Хэрэгжүүлж болохгүй:

- зөвхөн харагдах нэр;
- мэдэгдэл эсвэл байршуулах самбарт харагдах нэр;
- цаг хугацааны ижил төстэй байдал;
- харигдаагүй эсвэл итгэл үнэмшил багатай таних тэмдэг;
- Одоогийн баталгаагүй түүхэн тайлан.

<a id="3-separate-current-from-historical"></a>
## 3. Урсгалыг түүхээс салгах

Одоогийн нотолгоо нь идэвхтэй тайлагналын цонх эсвэл серверийн эрин үеийг тодорхойлдог. Түүхэн нотолгоо нь хэв маягийг тайлбарлаж болох ч одоогийн цонхны хоосон зайг чимээгүйхэн дүүргэж чадахгүй.

Хоёр хүрээг бие даан бүртгэх:

```text
Current observations:
Current source references:
Historical context:
Historical source references:
```

<a id="4-review-observations-and-interpretation"></a>
## 4. Ажиглалт, тайлбарыг хянана уу

Эдгээр тайлангийн хэсгүүдийг тодорхой уншина уу:

```text
observed
interpretation
unknown
does_not_prove
next_action
source_references
```

Аливаа материаллаг шийдвэрийн хувьд иш татсан бүтэцлэгдсэн нотлох баримтыг дахин нээнэ үү. Орчуулга нь шинэ нотлох баримт биш харин навигаци, тайлбар юм.

<a id="5-calibrate-the-decision"></a>
## 5. Шийдвэрийг тохируулна уу

| Шийдвэр | Хэзээ ашиглах |
|---|---|
| `INFO` | Хэвийн эсвэл бага контекст ажиглалт. |
| `WATCH` | Хянах үнэ цэнэ сул эсвэл бүрэн бус дохио. |
| `REVIEW` | Холбоотой нотолгоо нь администраторын дүгнэлтийг шаарддаг. |
| `BAN-ELIGIBLE` | Цэвэр таниулбар болон тохируулсан нотлох баримтын босго хангагдсан; бичих хаалга хүчинтэй хэвээр байна. |
| `AUTO-BANNED` | Хэрэгжүүлэлтийг тодорхой идэвхжүүлсэн бөгөөд нөөцлөх, бичих, дахин сэргээх болон аудитыг амжилттай хийсэн. |

Ямар ч шийдвэрийн шошго нь гэм буруу эсвэл санаа зорилгыг нотлохгүй.

<a id="6-apply-the-evidence-boundary"></a>
## 6. Нотлох баримтын хил хязгаарыг хэрэглэнэ

Гэмтэл, дахин холбогдох, анхааруулга, object/class токенууд болон тохиолдлын бүлэглэл нь хянагдахыг дэмждэг. Ганцаараа тэд хууран мэхлэлт, хулгай, давхардал, өмчлөгч, шууд хохирол, ослын шалтгаантай холбоотой болохыг нотлохгүй.

Хэрэв таниулах, задлан шинжлэх, нөөцлөх, бичих, буцаах, буцаах зэрэг сул эсвэл амжилтгүй болсон бол хэрэгжилтийг хааж болохгүй.
