# Admin.ini хэрэгжүүлэх

> **Каноник англи эх сурвалж:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). Энэ локалчлагдсан баримт бичиг нь яг командууд, замууд, түлхүүрүүд, төлөвийн утгууд, хэшүүд болон файлын нэрийг хадгалдаг. Хэрэв техникийн үг хэллэг өөр байвал англи эх сурвалжийг ашиглана уу.


RandomDayGuard нь анхдагч тохиргоондоо серверийн хоригийн жагсаалтыг өөрчлөхгүй. Энэ нь зөвхөн админд хянуулах тайланг үүсгэдэг. Энэ хуудсанд үүнийг зориудаар идэвхжүүлдэг админуудад зориулсан хориглох жагсаалтын автомат шинэчлэлтийг тайлбарласан болно.

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## Хориглох жагсаалтыг өөрчлөхийн өмнө хамгаалагч юу шалгадаг вэ

Харуул зөвхөн доорх хариулт бүр **тийм**:

1. Одоогийн нотлох баримтууд нь тодорхой нэг дансыг хангалттай итгэлтэйгээр тодорхойлсон уу?
2. Акаунт нь модератор биш, админ итгэмжлэгдсэн бүртгэл биш үү?
3. Бүртгэл аль хэдийн хоригийн жагсаалтад ороогүй байна уу?
4. Бүртгэл тохируулсан автомат үйлдлийн оноонд хүрсэн үү?
5. Одоог уншиж хамгаалж чадна `Admin.ini` мөн ижил нөөцлөлтийг хадгалах уу?
6. Хийсэн `Admin.ini` өөрчлөгдөхгүй байх уу?
7. Хадгалсны дараа бүх файл нь төлөвлөсөн үр дүндээ яг таарч байна уу?

Хэрэв ямар нэг хариулт байвал **үгүй**эсвэл шалгах боломжгүй, хамгаалагч явлаа `Admin.ini` өөрчлөгдөөгүй бөгөөд шалтгааныг тайландаа тэмдэглэнэ. Хадгалж эхэлсэн ч эцсийн шалгалт амжилтгүй болвол Guard баталгаажсан нөөцлөлтийг сэргээнэ.

<a id="file-format"></a>
## Файлын формат

`Admin.ini` зөвхөн цэвэр хоригийн мөрүүдийг хүлээн авах ёстой:

```ini
BannedPlayer=<ID>
```

- Нэр байхгүй.
- Сэтгэгдэл байхгүй.
- Шалтгаан байхгүй.
- Дагавар байхгүй.

<a id="safe-defaults"></a>
## Аюулгүй өгөгдмөл

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## ID эх сурвалжийг хориглох

Шилдэг эх сурвалж:

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

Ажиллах хугацаа нь бүрэн тоон ID эсвэл бүрэн баримтжуулсан `<digits>_+_|<non-space token>` холболтын хэлбэр бөгөөд үүнээс тоон хоригийн ID-г гаргаж авдаг. Үл мэдэгдэх дагавартай дурын тоон угтвараас татгалзсан; тэдгээр нь хоригийн ID болж хасагдаагүй.

Зөв:

```ini
BannedPlayer=2535422284688820
```

Буруу:

```ini
BannedPlayer=ExamplePlayer
```

Мөн буруу:

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## Яг тохиргоог Хамгаалагч шалгана

Эдгээр тохиргоо нь дээр дурдсан шалгалтуудыг хэрэгжүүлдэг. Бүртгэгдсэн нөхцөл бүр үнэн байх ёстой:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

Хэрэв ямар нэг нөхцөл худал эсвэл шалгах боломжгүй бол Guard хоригийн жагсаалтыг хэвээр үлдээж, юу зогсоосныг тэмдэглэнэ.

<a id="transaction-safety"></a>
## Гүйлгээний аюулгүй байдал

Ганц `Admin.ini` мутацийн зам нь дараах алхмуудыг дарааллаар гүйцэтгэдэг:

1. Эрх бүхий байтуудыг уншиж, бүтцийн хувьд баталгаажуулна уу.
2. Тэр агшин агшнаас зохицуулагч, итгэмжлэгдсэн болон одоо байгаа хоригийн төлөвийг гаргаж авах.
3. Өвөрмөц нөөцлөлтийг `runtime/backups/` ба байтыг байтаар шалгана уу.
4. Дахин уншина уу `Admin.ini` солихын өмнө нэн даруй, гадны аливаа өөрчлөлтөөс татгалз.
5. Нэр дэвшигчийг тохируулсан удирдлагатай солих замаар бичнэ үү.
6. Нэр дэвшигчийн бүтэн байттай тэнцүү байхын тулд бүрэн дахин байтыг шаардах.
7. Дахин дахин алдаа гарвал баталгаажуулсан нөөцлөлтийг зөвхөн одоогийн файл нь Guard-ын бичсэн яг нэр дэвшигч хэвээр байх үед сэргээ. Хэрэв өөр зохиолч үүнийг өөрчилсөн бол Guard үл мэдэгдэх гадаад байтыг дарж бичихийн оронд буцаахаас татгалзана.

Давхардсан ID-ууд нь тодорхой бус байна: хоёр дахь мөр болон хоёр дахь нөөцлөлт бичигдээгүй. Нөөцлөлтийн нэрэнд цагийн тэмдэг, эх байт хурууны хээ, цэвэр ID зэрэг багтдаг тул тус тусад нь оролдвол нэг секундын хуучин файлын нэрийг хуваалцах боломжгүй.

<a id="local-regression-proof"></a>
## Орон нутгийн регрессийн баталгаа

`tests/lua/enforcement_runtime_test.lua` нь ачуулсан ачаалагчийг нэг удаа ачаалж, дараа нь өөрийн жинхэнэ локалыг ажиллуулна `append_ban()` репозиторын доорх тусгаарлагдсан синтетик файлуудын эсрэг хаах `.tmp/` лавлах. Энэ нь оруулах, давхардсан idempotency, moderator/trusted татгалзсан, сул, буруу хэлбэрийн таниулбараас татгалзсан, яг байт нөөц баталгаажуулалт, нэгэн зэрэг өөрчлөлт оруулахаас татгалзсан, дахин сэргээлт амжилтгүй болсны дараа амжилттай буцаах, бичсэний дараах гадаад өөрчлөлтийг дарж бичихээс татгалзах. Түүний файлын системийн боодол нь бэхэлгээний үндэсээс гадуурх аливаа мутацаас татгалздаг; бодит серверийн зам байхгүй эсвэл бодит `Admin.ini` ашиглаж байна.

Үүнийг ажиллуулна уу `python tools/test_public_pipeline.py`. Бэхэлгээний дамжуулалт нь зөвхөн орон нутгийн гүйлгээний үйлдлийг нотолж байна. Энэ нь хэрэгжилтийг идэвхжүүлдэггүй, үйлдвэрлэл бичихийг зөвшөөрдөггүй эсвэл хостын тусгай зөвшөөрлийг нотлохгүй.

<a id="rollback"></a>
## Буцах

1. Серверийг зогсоо.
2. Сүүлчийн хувилбарыг сэргээнэ үү Admin.ini нөөцлөлт `runtime/backups/`.
3. Бурууг арилгах `BannedPlayer=<ID>` мөр.
4. Серверийг эхлүүлнэ үү.
5. Дахин нээх Admin.ini ба мөр хэвээр байгаа эсвэл устгагдсан эсэхийг баталгаажуулна уу.
6. Хадгалах `enforced_bans.jsonl` аудит хийх.
