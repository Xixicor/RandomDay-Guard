# Муу жүжигчдийн хэв маяг ба уян хатан байдал

> **Каноник англи эх сурвалж:** [BAD_ACTOR_PATTERNS_AND_RESILIENCE.md](../../BAD_ACTOR_PATTERNS_AND_RESILIENCE.md). Энэ локалчлагдсан баримт бичиг нь яг командууд, замууд, түлхүүрүүд, төлөвийн утгууд, хэшүүд болон файлын нэрийг хадгалдаг. Хэрэв техникийн үг хэллэг өөр байвал англи эх сурвалжийг ашиглана уу.


Хамгаалагч ослын урвуулан ашиглах, зэргэлдээх үйлдлүүдийг хянах, сэргээх төлөвлөлтөд хэрхэн тусалдаг талаар ойлгохын тулд энэ хуудсыг ашиглана уу.

<a id="what-the-guard-can-help-with"></a>
## Харуул юунд туслах вэ

| Загвар | Юуг шалгах вэ |
|---|---|
| Гэмтэлтэй холбоотой өгөөж | Ижил бүртгэл гэмтлийн өмнө идэвхтэй байсан бөгөөд дахин эхлүүлсний дараа буцаж ирдэг |
| Хурдан холболтыг шалгах | Давтан join/leave эсвэл timeout/reconnect гогцоо |
| Олон дансны кластерууд | Долгионд нэгдэх, анхааруулах цонх, алдааны цонхыг хуваалцах |
| Сэрэмжлүүлэгийн тэсрэлт | Давтан ActorChannelFailure эсвэл хадгалах анхааруулах цонхнууд |
| Хязгааргүй контекст | PlayerData/map/world унших боломжтой үед контекст |
| Хадгалах-мэдрэгч давхцал | Дэлхийд хадгалсан контекст давхардсан зураглал |
| Хувийн мэдээллийн төөрөгдөл | ConnectID зураглал хийх шаардлагатай нэрс |

<a id="why-it-avoids-memory-access"></a>
## Яагаад санах ойд хандахаас зайлсхийдэг вэ

RandomDayGuard сервер эзэмшдэг файлуудаас ажилладаг:

```text
Saved/Logs/*.log
Admin.ini
World saves
PlayerData
Backups
runtime evidence
```

Энэ нь түүнийг үйлчлүүлэгчийн санах ойн төлөвөөс хамааралгүй болгож, тоглоомын шинэчлэлтүүдэд эмзэг болгодог.

Арилжаа:

```text
It cannot prove hidden live actions unless the server writes evidence.
```

<a id="crash-correlated-returners"></a>
## Гэмтэлтэй холбоотой буцагчид

Загвар:

```text
Account joins.
Server crashes or restarts.
Same account reconnects quickly.
Pattern repeats.
```

Ашигтай файлууд:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="rapid-reconnect-probers"></a>
## Шуурхай дахин холбох шалгагч

Загвар:

```text
join -> leave -> join -> leave -> join
```

Ашигтай файлууд:

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
```

<a id="multi-account-clusters"></a>
## Олон дансны кластерууд

Загвар:

```text
Several accounts join in the same window.
Warnings or crashes follow.
Some accounts rotate or reconnect after restart.
```

Ашигтай файлууд:

```text
runtime/raid_cases/
runtime/forensic_days/YYYY-MM-DD/raid_cases.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

Дүрэм:

```text
A cluster is not a mass-ban list.
Each account still needs its own evidence.
```

<a id="sticky-backup-recommendation"></a>
## Наалттай нөөцлөх зөвлөмж

Үүний дараа наалттай нөөцлөлт үүсгэнэ үү:

```text
first full baseline completes
object_registry.json exists
file_manifest.tsv exists
world_state_latest.json has scan_complete=true
Admin.ini is verified
trusted IDs are configured
```

Нөөцлөх:

```text
RandomDayGuard/config.lua
RandomDayGuard/SavedRoot.txt
RandomDayGuard/runtime/baselines/
RandomDayGuard/runtime/object_registry.json
RandomDayGuard/runtime/world_state/current/world_state_latest.json
Saved/SaveGames/Server/Admin.ini
```

<a id="recovery-model"></a>
## Сэргээх загвар

```text
Clean install
-> verify live defense
-> complete first baseline
-> create sticky backup
-> run server normally
-> use daily rollups for review
-> restore sticky backup if needed
```
