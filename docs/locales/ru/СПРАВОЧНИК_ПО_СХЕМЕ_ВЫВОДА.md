# Справочник по схеме вывода и состояния

> **Канонический английский источник:** [OUTPUT_SCHEMA_REFERENCE.md](../../OUTPUT_SCHEMA_REFERENCE.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


Это канонический контракт для созданных файлов, ориентированных на оператора. Только он владеет точными путями вывода, именами полей, допустимыми значениями, требованиями к происхождению и схемами маршрутов. Процедурные руководства ссылаются сюда, а не переопределяют эти факты.

Доказательства времени выполнения являются авторитетными; имя файла, контрольный сигнал планировщика, переведенный отчет или локальный объект исходящих сообщений не доказывают ничего, кроме собственных полей и происхождения.

<a id="public-report-routes"></a>
## Маршруты общедоступных отчетов

Рабочий отчет владеет пятью маршрутами в соответствии с `runtime/final_logs/`:

| Маршрут | Контрактом | `full` требование | Ожидаемое-пустое значение |
|---|---|---|---|
| `server_status` | Текущий планировщик, активный журнал, ожидание сканирования и состояние покрытия источника. | Текущие boot/epoch/poll происхождение, свежий активный журнал, accounting/history записи и JSON/TXT. | Не используется для нормального текущего цикла; недостающая родословная — это `missing`. |
| `daily_rollup` | Текущие day/window непрерывность на сервере, игроках, кейсах, сканировании и охвате. | Терминала исторического учета, достаточного для маршрута и завершения проверки текущего цикла. | Нет сохраненных игроков и нет дел для проверки. |
| `player_activity` | Отдельные текущие и исторические player/account наблюдения. | Доказательство текущего цикла плюс одна или несколько current/historical строк. | Нет подходящих строк игрока в ограниченных входных данных; нет синтетического предмета. |
| `case_review` | Именованные сохраненные случаи и текущие review/BAN-ELIGIBLE кандидаты. | Доказательство текущего цикла плюс один или несколько поименованных случаев со ссылками на источники. | Ни один названный случай не соответствует критериям проверки; нет синтетического случая. |
| `critical_guard` | Ошибка планировщика текущей загрузки, запуска, опроса или целостности свидетельств. | Подтверждение текущего цикла плюс текущий критический сбой. | Нет текущего критического сбоя; старые текстовые ошибки не владеют этим маршрутом. |

Каждый включенный маршрут записывает `<route>_latest.json` и `<route>_latest.txt`. Пара не будет завершена до тех пор, пока `runtime/final_logs/route_proof.json` не запишет одну и ту же версию, загрузку, эпоху, опрос и актуальность источника.

<a id="report-json-schema"></a>
## Схема отчета JSON

Все пути маршрута JSON использует `schema="randomdayguard.report/v1"`.

| Поле | Тип | Значение и инвариант |
|---|---|---|
| `schema` | строку | Точно `randomdayguard.report/v1`. |
| `generated_ts`, `report_date` | строку | Отметка времени создания и дата отчета. |
| `version` | строку | Runtime/package идентификатор для этого цикла. |
| `boot_id`, `epoch_id` | строку | Текущая эпоха загрузки процесса и непрерывности сервера. Оба необходимы для завершения. |
| `poll_id` | integer | Положительный идентификатор текущего опроса. Zero/missing не может завершить маршрут. |
| `source_freshness` | объект | `status`, `checked_ts`, статус активного журнала, временная метка последнего опроса и временная метка последнего завершенного опроса. |
| `current_cycle_proof_complete` | логическое значение | Истина, только если происхождение и свежие active-log/current-poll доказательства совпадают. |
| `route` | enum | Один из пяти маршрутов выше. |
| `route_proof_status` | enum | `full`, `limited_expected_empty` или `missing`. |
| `coverage_status` | enum | Точно `complete`, `complete_with_gaps`, `partial` или `unavailable`. |
| `completed`, `expected_empty` | логическое значение | `completed` неверно только для `missing`; `expected_empty` верно только для `limited_expected_empty`. |
| `observed` | массива строк | Сохраняется конкретность facts/counts/statuses. |
| `interpretation` | массива строк | Осторожное значение, откалиброванное в соответствии с доказательствами. |
| `unknown` | массива строк | Отсутствует идентификатор, история, источник или контекст. |
| `does_not_prove` | массива строк | Выводы, которые не могут быть подтверждены доказательствами. |
| `next_action` | строку | Самое безопасное ограниченное действие оператора. |
| `source_references` | массива строк | Сортированные уникальные runtime/Saved ссылки. |
| `enforcement_authority` | логическое значение | Всегда ложно. Отчет никогда не разрешает запись. |
| `output_paths` | две строки | JSON и TXT добавляются перед парной записью. |

`coverage_status` предназначен только для учета верхнего уровня. Исходные записи принадлежат отдельно `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied`, а `error`. Доказательство маршрута отдельно принадлежит `full`, `limited_expected_empty`, а `missing`; значения никогда не пересекают эти границы.

Расширения маршрутов:

- `server_status`: `scheduler_status`, `active_log_status`, а `server_metrics`. Метрики записывают начало текущей эпохи, дату и идентификатор последнего завершенного опроса, количество активных игроков, количество active/backup-log, сканирование значений pending/progress и configured/usable/unavailable учет исходной группы. Они не изобретают время безотказной работы, количество перезапусков, временные метки резервного копирования или продолжительность простоя, если ни один источник не раскрывает эти факты.
- `player_activity`: `player_activity_present`, `movement`, `same_day_sessions`, `current_player_count`, `current_evidence_player_count`, `historical_player_count`, `historical_session_count`, `current_players`, `historical_players` и массив совместимости `players`. Каждый сеанс в тот же день сохраняет свой идентификатор сеанса, идентификатор учетной записи, отображаемое имя, если оно известно, join/leave временные метки, флаги чистого выхода и жизненного цикла, а также ссылки на источники. Сохраненная идентичность и PlayerData присутствие остаются контекстом, а не доказательством активности сегодня.
- `case_review`: `cases`, `review_subjects`, `current_case_count`, а `retained_case_count`. Текущий субъект проверки записывает свой case/account идентификатор, отображаемое имя, если оно известно, статус, оценку, достоверность идентичности, first/last наблюдение, количество предупреждений, причины, флаг текущей активности и ссылки на источники. Сохраненные случаи сами по себе не создают текущий субъект.
- `critical_guard`: `critical_failure_present` и `current_boot_error_only=true`.
- `daily_rollup`: `daily_maturity`, `once_per_day_continuity`, `dedupe_window`, а `daily_metrics`. Метрики записывают дату отчета, активных игроков, учетные записи с активностью в тот же день, присоединения, выхода, чистые и нечистые выходы, возвраты жизненного цикла, текущие названные субъекты проверки, сохраненные дела, current/retained количество идентификаторов и охват исходной группы.

<a id="translated-txt-schema"></a>
## Переведено TXT

Парный текстовый файл приводит к читаемому оператором результату и перемещает детали происхождения до конца. Он сохраняет именно этот порядок разделов:

```text
RandomDayGuard <route title>
Generated: <timestamp>

Summary
<one plain-language route summary>

What Guard observed
- ...

What it means
- ...

What remains unknown
- ...

Recommended next step
...

Evidence boundary
- ...

Rating explanation
- ...

Technical record
- Route: <route>
- Version: <version>
- Cycle: boot=<boot> epoch=<epoch> poll=<poll>
- Source freshness: <status>
- Route result: <full|limited_expected_empty|missing>
- Coverage: <status>

Translation notes
- ...

Source references
- ...
```

Перевод использует только поля структурированного отчета и утвержденные сопоставления словарей. Он не может добавлять игроков, дела, доставку, причинно-следственную связь, право собственности, намерение или правоприменение, отсутствующие в структурированном отчете. Технические детали остаются доступными без смещения читаемого результата.

<a id="source-accounting-schema"></a>
## Исходная схема учета

`runtime/final_logs/source_accounting_latest.json` использует `randomdayguard.source-accounting/v1` с reason/status, enablement/disabled причиной, current/historical различием, манифестом измененного файла, исходными записями, usable/unavailable классом списки и лимит претензий.

Каждая исходная запись содержит:

| Поле | Тип | Значение |
|---|---|---|
| `source_class` | строку | Один из восьми классов, указанных ниже. |
| `scope` | `current` или `historical` | Владение временем; области никогда не объединяются автоматически. |
| `required` | логическое значение | Только `active_log` требуется для обновления маршрута текущего цикла. |
| `status` | enum | Исходный результат указан ниже. |
| `terminal` | логическое значение | False только для `partial` и `deferred`. |
| `available`, `readable` | логическое значение | True только для `available` и `expected_empty`. |
| `file_count` | integer | Ограниченный учет file/reference количество. |
| `source_references` | array | Отсортированный уникальный источник paths/references. |
| `detail` | строку | Ограниченный результат или подробная информация об ошибке. |
| `does_not_prove` | строку | Доступность не является доказательством намерения, владения, повреждения, дублирования или принудительного исполнения. |

Классы источника:

| Исходный класс | Объем | Что он дает | Что он не может доказать |
|---|---|---|---|
| `active_log` | текущий, необходимый | Читаемый журнал активного сервера и свежий опрос. | Полная история или вина игрока. |
| `admin_ini` | текущее, необязательно | Структурно допустимое текущее moderator/ban состояние или ожидаемое отсутствие. | Метаданные о поведении игрока или действительной причине. |
| `recent_backup_logs` | исторические | читаемые rotated/backup ссылки на журналы. | текущее присутствие или текущее состояние загрузки. |
| `playerdata_filenames` | текущий контекст | ограниченные читаемые ссылки на имена файлов в выбранном сохраненном корне. | Владение файлом, присутствие в реальном времени, идентификационное содержимое или неправомерное поведение. |
| `existing_cases` | исторические | Сохраняются именованные записи files/index, записанные до текущих выходных данных. | Текущая активность или правильность старых выводов. |
| `existing_reports` | исторические | Сохраняется final/forensic/warning отчет ссылки. | Замена авторитетного источника. |
| `existing_evidence` | исторические | Сохраненные ссылки на доказательства. | Полнота событий, которые сервер никогда не раскрывал. |
| `world_save_scan` | исторические | Полное, частичное, отложенное или недоступное ограниченное scan/checkpoint состояние. | Действие или право собственности конкретного игрока. |

Значения статуса источника:

| Статус | Терминал | Значение и действие оператора |
|---|---:|---|
| `available` | да | Чтение полезный источник существует; просмотрите его ссылки. |
| `expected_empty` | да | Необязательный источник проверен и является законным absent/empty. Не изобретайте данные. |
| `partial` | нет | Ограниченная работа или лимит инвентаря неполный; разрешить возобновление. |
| `deferred` | нет | Работа намеренно отложена; дождаться рабочего-владельца. |
| `unavailable` | да | Source/path/tool отсутствует или непригоден для использования; восстанавливайте только в том случае, если это необходимо для маршрута. |
| `malformed` | да | Контент не прошел структурную проверку; сохранить его и восстановить формат. |
| `permission_denied` | да | Доступ был явно запрещен; восстановить доступ для чтения с наименьшими привилегиями. |
| `error` | да | Ограничено на уровне источника probe/read неожиданно произошел сбой; проверять `detail`, не раскрывая секретов. |

Верхний уровень `coverage_status` - это именно `complete`, `complete_with_gaps`, `partial` или `unavailable`. Требуемый уровень `error`, `malformed` или `permission_denied` сворачивается до `unavailable` верхнего уровня; уровень источника `deferred` сворачивается до `partial`. Отключение учета источника по-прежнему записывает статус недоступности и заставляет каждый маршрут обращаться к `missing`.

<a id="historical-status-schema"></a>
## схеме исторического статуса

`runtime/final_logs/historical_backfill_latest.json` использует `randomdayguard.history/v1`: `generated_ts`, учету `status`, `resumable=true`, `changed_file_refresh=true`, `current_evidence_is_not_history=true`, массиву учета источника, недоступным классам и ограниченной `next_action`.

`runtime/history/public_accounts.tsv` устойчивой общедоступной истории с этим заголовком:

```text
account_id	ban_id	display_name	identity_confidence	status	score	first_seen	last_seen	source_references
```

Строки сортируются по идентификатору учетной записи, поля – single-line/tab-safe, а ссылки – sorted/unique. Этот файл сохраняет исторический контекст при тихом перезапуске; он никогда не преобразует историю в настоящее присутствие.

<a id="route-proof-schema"></a>
## Схема подтверждения маршрута

`runtime/final_logs/route_proof.json` использует `randomdayguard.route-proof/v1` и записывает временную метку создания верхнего уровня, версию, загрузку, эпоху, опрос, актуальность источника, полноту текущего цикла, разрешенные статусы и массив `routes`.

Каждая запись маршрута содержит route/status, version/boot/epoch/poll объект source-freshness, полнота текущего цикла, пути вывода и ссылки на источники. Отключенный маршрут записывает `status="missing"` и `reason="route_disabled"`. Если запись с защитой от маршрута не удалась, каждый маршрут перезаписывается как incomplete/missing перед принятием любого кандидата на уведомление.

<a id="notification-schemas"></a>
## Схемы уведомлений

Необязательный общедоступный режим - только исходящие сообщения локального файла.

`runtime/notifications/pending/<route>_latest.json` использует `randomdayguard.notification/v1` с сгенерированной меткой времени, version/boot/epoch/ poll/source свежесть, маршрут, `completed_output`, статус защищенности от маршрутизации, структурированные и переведенные пути отчетов, ссылки на источники, `delivery_backend="none"`, а `delivery_attempted=false`. В допустимых выходных данных используется `status="ready_for_local_consumer"`, `delivery_eligible=true`, а `delivery_allowed=true`. Настроенный, но missing/ineligible маршрут по-прежнему записывает конверт аудита с `status="suppressed_current_cycle"`, оба флага доставки ложны и `suppression_reason="route_or_completion_policy_blocked"`. Поэтому наличие файла в `pending/` само по себе не означает, что он поставлен в очередь или соответствует критериям.

`runtime/notifications/notification_status.json` использует `randomdayguard.notification-status/v1` с тем же происхождением, `generic_local_outbox_only=true`, `delivery_attempted=false` и строками для каждого маршрута `queued`/`outcome`. `full` соответствует требованиям; ожидаемо-пустое допустимо только в том случае, если `include_expected_empty=true`; `missing` никогда не подходит. При ошибке записи с защитой от маршрутизации результатом статуса будет `route_proof_write_failed`; конверт подавленного аудита все еще может быть записан, но он не принимается.

<a id="runtime-output-inventory"></a>
## Инвентаризация выходных данных во время выполнения

Индекс прослеживаемости имеет одну машинную строку для каждого пути или класса динамических файлов. В этом читаемом реестре файлы группируются по назначению оператора.

| Путь или шаблон | Producer/trigger | Политика и полезные состояния | Failure/recovery |
|---|---|---|---|
| `runtime/loader_probe.txt`, `runtime/loader_probe.json` | Запись загрузчика. | Перезаписанный запуск identity/probe. | Отсутствие не доказывает нагрузку; проверьте UE4SS журналы и включение. |
| `runtime/config_load_error.txt` | Ошибка загрузки конфигурации. | Только ошибки, сохраняется ограниченная причина. | Восстановите действительную общедоступную конфигурацию и перезапустите. |
| `runtime/saved_path_probe.json` | Сохраненное корневое разрешение. | Candidate/readability учета. | Устанавливайте `SavedRoot.txt` или исправьте общий кандидат. |
| `runtime/startup_status.json`, `runtime/startup_error.txt`, `runtime/current/startup_error.json` | Жизненный цикл запуска. | Последняя ошибка запуска и текущая загрузка. | Только соответствующая загрузка имеет текущий критический статус. |
| `runtime/runtime_version.json`, `runtime/runtime_capabilities.json`, `runtime/public_pipeline_status.json` | Startup/report Интеграция. | Последняя version/capability/handoff состояние. | Завершение дрейфа версий или возможностей утверждает. |
| `runtime/poll_status.json`, `runtime/current/poll_status.json`, `runtime/poll_error.txt`, `runtime/current/poll_error.json` | Опрос finalizer/error. | Последняя poll/scheduler/in-flight состояние и текущая ошибка загрузки. | Исправить ограниченный обратный вызов и потребовать новый завершенный опрос. |
| `runtime/logs/current.jsonl`, `runtime/raw_events.jsonl` | Регистратор событий. | Ограничено append/rotation. | Сохранить предыдущие байты; ремонт disk/retention, прежде чем полагаться на пробелы. |
| `runtime/log_offsets.tsv`, `runtime/log_registry.json` | Журнал tail/registry. | Последние смещения и канонические идентификаторы журнала. | Тщательно перестройте; журналы резервного копирования остаются историческими. |

| `runtime/current_server_epoch.json`, `runtime/server_epochs.jsonl`, `runtime/epochs/**` | владельца эпохи. | Текущая плюс сохраненные эпохи сервера. | Начать новую эпоха после ремонта; не перезаписывайте старую историю. |

<a id="failure-and-recovery-matrix"></a>
## Матрица сбоя и восстановления

| Сбой | Требуемое состояние | Безопасное восстановление | Неверный вывод |
|---|---|---|---|
| Текущее происхождение absent/stale | Все маршруты `missing`. | Восстановите active-log/current-poll проверить и восстановить. | Старые файлы маршрутов не являются текущими завершенными. |
| Необязательный источник ожидается пустым | Источник `expected_empty`; подходящим маршрутом может быть `limited_expected_empty`. | Нет восстановления, если источник не существует. | Пустое значение не является недоступным и не доказывает историческое отсутствие. |
| Сканирование неполное | Источник `partial` или `deferred`. | Разрешить ограниченное возобновление; сохраняйте текущую политику маршрутизации явной. | Частичное не является повреждением. |
| Требуемый источник недоступен | `coverage_status=unavailable`; зависимые маршруты `missing`. | Исправить выбранный Saved/log доступ. | Другие работоспособные источники не заменяют требуемый источник. |
| Необходимые ошибки проверки источника | Состояние источника `error` с ограниченным `detail`; `coverage_status=unavailable`; зависимые маршруты `missing`. | Восстановить именованный source/probe и создать новый цикл. | Ошибка источника не является пятым значением покрытия верхнего уровня. |
| Ошибка записи парного отчета | `coverage_status=unavailable`; маршрут сходится к `missing`. | Восстановить файловую систему и перезаписать оба члена пары плюс доказательство. | Один родственный файл не завершен, и ошибка записи не является верхним уровнем `error`. |
| Ошибка записи с защитой от маршрутизации | Каждый переписанный маршрут отсутствует; нет подходящего исходящего ящика; настроенные маршруты могут получать подавленные конверты аудита. | Исправить запись, защищенную от маршрутизации, и восстановить выходные данные того же цикла. | Действительный отчет JSON или скрытый конверт не являются доказательством маршрута. |
| Ошибка записи уведомления | Результат `local_outbox_write_failed`. | Восстановить корень локального вывода; восстановить из завершенного отчета. | Внешняя доставка не произошла. |
| Admin.ini транзакция не удалась | Принудительное применение заблокировано с помощью backup/write/readback/rollback доказательства. | Восстановить проверенную резервную копию; остаются только для проверки. | Пороговое значение или отчет не могут служить основанием для обхода восстановления. |
