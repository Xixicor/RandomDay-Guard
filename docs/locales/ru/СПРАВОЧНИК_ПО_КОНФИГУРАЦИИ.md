# Концепциями конфигурации

> **Канонический английский источник:** [CONFIG_REFERENCE.md](../../CONFIG_REFERENCE.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


Это объяснение описывает, чем управляет каждая основная область конфигурации, когда она запускается и как она взаимодействует с доказательствами и шлюзами безопасности. Он не владеет точным каталогом полей или процедурами профиля.

Для предустановок, ориентированных на задачи, и шагов безопасного изменения используйте [`CONFIG_PROFILES.md`](%D0%9F%D0%A0%D0%9E%D0%A4%D0%98%D0%9B%D0%98_%D0%9A%D0%9E%D0%9D%D0%A4%D0%98%D0%93%D0%A3%D0%A0%D0%90%D0%A6%D0%98%D0%98.md). Для каждого точного исходного поля, значения по умолчанию, типа, инварианта, эффекта вывода и правила восстановления используйте сгенерированный [`CONFIG_FIELD_CATALOG.md`](%D0%9A%D0%90%D0%A2%D0%90%D0%9B%D0%9E%D0%93_%D0%9F%D0%9E%D0%9B%D0%95%D0%99_%D0%9A%D0%9E%D0%9D%D0%A4%D0%98%D0%93%D0%A3%D0%A0%D0%90%D0%A6%D0%98%D0%98.md); валидатору требуется одна строка для каждой отправленной `config.lua` конечного поля.

<a id="top-level-safety"></a>
## Безопасность верхнего уровня

| Опция | По умолчанию | Значение |
|---|---:|---|
| `enabled` | `true` | Главный переключатель для Guard |
| `enforcement.review_only_mode` | `true` | Record/recommend |
| `enforcement.auto_ban` | `false` | Не блокировать автоматически по умолчанию |
| `enforcement.write_admin_ini` | `false` | Не записывать Admin.ini по умолчанию |

Сохранять их в безопасности до тех пор, пока владелец сервера не проверит выходные данные.

<a id="saved"></a>
## `saved`

Управляет тем, как охранник находит папку `Saved/` на сервере и какой файл семьи, которые он может сканировать.

Используйте, когда:

```text
Saved root auto-detection fails.
World folder changed.
Provider or container path is unusual.
```

Проверка:

```text
runtime/saved_path_probe.json
RandomDayGuard/SavedRoot.txt
```

Правило:

```text
SavedRoot.txt -> AbioticFactor/Saved
not -> Worlds/<WorldName>
```

<a id="log_tail"></a>
## `log_tail`

Управляет чтением журнала в реальном времени.

Полезные параметры:

| Опция | Безопасное значение | Почему |
|---|---|---|
| `enabled` | `true` | Необходимо для оперативной защиты |
| `start_at_end_on_first_run` | `true` | Избегает старых журналов как текущих событий. |
| `tail_backup_logs` | `false` | Резервные журналы представляют собой историю, а не актуальные |
| `max_lines_per_poll` | ограниченные | Поддерживает отзывчивость цикла опроса |

Проверка:

```text
runtime/log_offsets.tsv
runtime/evidence/session_events.jsonl
runtime/current/poll_status.json
```

<a id="runtime"></a>
## `runtime`

Управляет опросами и бюджетами.

Основное правило работоспособности:

```text
poll_id increases
poll_in_flight returns false
poll_scheduled is true
```

Проверка:

```text
runtime/current/poll_status.json
```

Если `poll_id` останавливается, что-то блокирует цикл.

<a id="source_accounting"></a>
## `source_accounting`

Управляет явным покрытием и областью источника доказательств.

| Key | По умолчанию | Значение |
|---|---:|---|
| `enabled` | `true` | Записывает учет источника для отчетов об общедоступных маршрутах. |
| `require_terminal_status` | `true` | Требует, чтобы каждый источник предоставил явный терминал или неполное состояние. |
| `distinguish_current_from_historical` | `true` | Сохраняет текущие и исторические данные отдельно. |
| `slow_world_scan_blocks_current_reports` | `false` | Позволяет текущим отчетам указывать, что сканирование ограниченного мира является отложенным или частичным. |
| `changed_file_manifest` | базовый путь манифеста | Ссылка, используемая для ограниченного historical/world учета. |

Состояния источника `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied` или `error`.

Настройка `source_accounting.enabled = false` не удаляет вывод статуса автоматически. Конвейер по-прежнему записывает `runtime/final_logs/source_accounting_latest.json` с помощью `enabled=false`, `status="unavailable"`, а `disabled_reason="source_accounting_disabled"`. Он также записывает запись исторического статуса с недоступным учетом. Поскольку учет источника является частью контракта отчета, каждый маршрут не закрывается к `missing`; ни один маршрут не считается завершенным, пока учет отключен.

<a id="reports"></a>
## `reports`

Управляет общим локальным конвейером отчетов.

По умолчанию включены все пять маршрутов и запись в `runtime/final_logs`:

```text
server_status
daily_rollup
player_activity
case_review
critical_guard
```

Каждый маршрут должен записывать структурированные и переведенные выходные данные плюс подтверждение в `route_proof.json`. Отключение маршрута создает `missing` подтверждение, а не делает вид, что он завершен.

<a id="notification"></a>
## `notification`

Необязательная общая исходящая папка локального файла. По умолчанию он отключен и ничего не отправляет внешнему поставщику.

Значения по умолчанию:

```lua
notification = {
    enabled = false,
    mode = "local_file_outbox",
    include_expected_empty = false,
},
```

Все маршруты уведомлений отключены по умолчанию. Если эта опция включена намеренно, исходящие сообщения могут использовать только готовый переведенный отчет после записи `route_proof.json`. Местные данные и отчеты остаются авторитетными. Доставка для конкретного поставщика, конечные точки доставки, учетные данные и мосты не являются частью публичного контракта независимого сторожевого таймера.

<a id="scanning"></a>
## `scanning`

Управляет базовым сканированием, контрольными точками и обновлением измененных файлов.

Используйте, когда:

```text
building first world baseline
resuming after crash
refreshing changed files later
```

Проверка:

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/baselines/file_manifest.tsv
```

Важные настройки:

```lua
scanning = {
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
    changed_file_detection = true,
},
```

<a id="forensic_rollup"></a>
## `forensic_rollup`

Управляет быстрой ежедневной загрузкой пакета и итоговыми журналами в открытом виде.

Выходы:

```text
runtime/current/forensic_today.json
runtime/current/forensic_today.md
runtime/current/forensic_today.txt
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

Используйте, когда:

```text
You want one daily folder that summarizes what happened.
You want a plain-language TXT to upload for quick analysis.
```

Проверка:

```text
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

Правило:

```text
Daily summaries are rebuildable indexes.
Source evidence remains authoritative.
```

<a id="logging"></a>
## `logging`

Управляет объемом событий и агрегированием низкой важности.

Используйте, когда:

```text
actor-touch events are noisy
raw event files grow too quickly
```

Безопасный шаблон:

```lua
logging = {
    low_importance_mode = "aggregate",
    write_low_importance_raw_events = false,
},
```

<a id="retention"></a>
## `retention`

Управляет сроком хранения файлов и моментом ротации JSONL журналов.

Используйте, когда:

```text
disk usage grows too fast
you need more audit history
you need shorter live-history windows
```

Важные параметры:

```text
detailed_retention_days
rotate_jsonl_when_bytes_exceed
max_raw_events_lines
keep_enforced_forever
keep_evidence_forever
```

<a id="warning_bursts"></a>
## `warning_bursts`

Управляет обнаружением окна предупреждения.

Примеры:

```text
ActorChannelFailure
DeployableSaveWarning
UpdateActorToWorldSave
ServerMove warnings
```

Правило:

```text
Warnings are context until correlated with mapped sessions and thresholds.
```

<a id="crash_correlation"></a>
## `crash_correlation`

Управляет повторным crash/reconnect просмотром.

Безопасные настройки по умолчанию:

```lua
crash_correlation = {
    single_crash_never_bans = true,
    require_same_account = true,
},
```

Полезные счетчики:

```text
server_crash_overlap_count
post_crash_reconnect_count
unclean_disconnect_count
```

<a id="join_leave"></a>
## `join_leave`

Управляет оттоком и отслеживанием волн присоединения.

Безопасно по умолчанию:

```lua
join_leave = {
    churn_alone_never_bans = true,
},
```

Используется для:

```text
rapid reconnect loops
join waves
short-session patterns
```

<a id="raid_detection"></a>
## `raid_detection`

группирования учетных записей, активных в связанных окнах.

Правило:

```text
A raid case groups accounts for review.
It does not make every account guilty.
```

каждой принудительной учетной записи по-прежнему требуются доказательства, специфичные для учетной записи.

<a id="object_registry"></a>
## `object_registry`

Элементы управления object/class извлечение токенов из читаемых сохраненных доказательств.

Выходы:

```text
runtime/object_registry_partial.json
runtime/object_registry.json
runtime/object_registry_counts.tsv
```

Правило:

```text
Object/class context is not a ban reason by itself.
```

<a id="world_state"></a>
## `world_state`

Элементы управления boot/current/session снимков состояния мира.

Выходы:

```text
runtime/world_state/current/world_state_latest.json
runtime/world_state/sessions/<date>/<session_id>_<account_id>/
```

Используется для просмотра сеанса и мирового контекста.

<a id="enforcement"></a>
## `enforcement`

Управляет рекомендациями и фактическими Admin.ini записями.

Прежде чем Guard сможет добавить запрет, каждое приведенное ниже утверждение должно быть истинным:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
account identity is mapped
not trusted
not moderator
threshold is met
```

Если одно утверждение неверно или не может быть проверено, Guard уходит `Admin.ini` без изменений и записывает причину.

<a id="admin_ini"></a>
## `admin_ini`

Управляет безопасной записью файлов.

Правила:

```text
Back up before writing.
Preserve existing bans.
Preserve moderators.
Write clean BannedPlayer=<ID> only.
```

<a id="restart_request"></a>
## `restart_request`

Управляет дополнительными файлами локальных маркеров, которые может проверять другой процесс, принадлежащий оператору. Он не перезапускает и не завершает работу сервера.

Значения по умолчанию:

```lua
restart_request = {
    enabled = false,
    restart_marker_file = "runtime/request_restart.flag",
    restart_reason_file = "runtime/restart_reason.json",
},
```

Выходы:

```text
runtime/request_restart.flag
runtime/restart_reason.json
```

В комплект не входит панель хостинга, мост провайдера или автоматизация перезапуска. Включение создания маркера не доказывает, что внешний процесс обработал запрос или перезапустил сервер.
