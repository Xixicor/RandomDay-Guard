# Admin.ini Принуждение

> **Канонический английский источник:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


RandomDayGuard не изменяет список банов сервера в настройках по умолчанию. Он создает отчеты только для просмотра администратором. На этой странице объясняется дополнительное автоматическое обновление списка банов для администраторов, которые намеренно включают его.

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## Что Guard проверяет перед изменением списка банов

Guard добавляет запрет только тогда, когда каждый ответ ниже **да**:

1. Идентифицировали ли текущие данные одну конкретную учетную запись с достаточной уверенностью?
2. Является ли эта учетная запись ни модератору или учетной записи, которую администратор пометил как доверенную?
3. Эта учетная запись еще не внесена в список банов?
4. Достигла ли учетная запись настроенного показателя автоматических действий?
5. Может ли Guard прочитать текущий `Admin.ini` и сохранить идентичную резервную копию?
6. Оставался ли `Admin.ini` неизменным, пока Guard готовил обновление?
7. После сохранения весь файл точно соответствует желаемому результату?

Если какой-либо ответ **нет** или не может быть проверен, Guard покидает состояние `Admin.ini` без изменений и записывает причину в свои отчеты. Если сохранение начинается, но окончательная проверка не удалась, Guard восстанавливает проверенную резервную копию.

<a id="file-format"></a>
## Формат файла

`Admin.ini` должен содержать только чистые строки запрета:

```ini
BannedPlayer=<ID>
```

- Нет имен.
- Нет комментариев.
- Нет причин.
- Нет суффиксы.

<a id="safe-defaults"></a>
## Безопасные настройки по умолчанию

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## Источник идентификатора запрета

Лучший источник:

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

Среда выполнения принимает либо полностью числовой идентификатор, либо полную документированную `<digits>_+_|<non-space token>` форму подключения и извлекает из него числовой идентификатор запрета. Произвольные числовые префиксы с неизвестным суффиксом отклоняются; они не усекаются до идентификатора бана.

Правильно:

```ini
BannedPlayer=2535422284688820
```

Неверно:

```ini
BannedPlayer=ExamplePlayer
```

Также неверно:

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## Точные настройки Проверки защиты

Эти настройки реализуют описанные выше проверки. Каждое перечисленное условие должно быть истинным:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

Если какое-либо условие ложно или не может быть проверено, Guard оставляет список банов без изменений и записывает, что его остановило.

<a id="transaction-safety"></a>
## Безопасность транзакций

Единственный путь мутации `Admin.ini` выполняет следующие действия в следующем порядке:

1. Чтение и структурная проверка авторитетных байтов.
2. Извлечение статуса модератора, доверенного статуса и существующего запрета из одного и того же снимка.
3. Запись уникальной резервной копии в разделе `runtime/backups/` и проверьте его побайтно.
4. Перечитайте `Admin.ini` непосредственно перед заменой и отклоните любые внешние изменения.
5. Запишите кандидата по настроенному пути контролируемой замены.
6. Требуйте, чтобы полные считанные байты равнялись полным байтам кандидата.
7. При сбое чтения восстанавливайте проверенную резервную копию только в том случае, если текущий файл все еще является точным кандидатом, записанным Guard. Если его изменил другой автор, Guard откажется от отката, а не перезапишет неизвестные внешние байты.

Дубликаты идентификаторов идемпотентны: ни вторая строка, ни вторая резервная копия не записываются. Имена резервных копий включают временную метку, отпечаток исходного байта и чистый идентификатор, поэтому отдельные попытки не могут использовать старое односекундное имя файла.

<a id="local-regression-proof"></a>
## Локальная защита от регрессии

`tests/lua/enforcement_runtime_test.lua` загружает поставляемый загрузчик один раз, а затем выполняет его настоящее локальное `append_ban()` закрытие изолированных синтетических файлов под каталогом репозитория `.tmp/`. Он охватывает вставку, идемпотентность дубликатов, moderator/trusted отклонение, отклонение слабых и неверных идентификаторов, точную побайтовую проверку резервной копии, отклонение одновременной модификации, успешный откат после неудачного считывания и отказ от перезаписи внешних изменений после записи. Его оболочки файловой системы отвергают любые мутации за пределами корня устройства; реальный путь к серверу или настоящий `Admin.ini` не используется.

Запустите его через `python tools/test_public_pipeline.py`. Проход фиксации подтверждает только поведение локальной транзакции. Он не включает принудительное применение, авторизацию рабочей записи или проверку разрешений, специфичных для хоста.

## Файлы для проверки

```text
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv

runtime/enforced_bans.jsonl
runtime/enforced.txt

```

<a id="rollback"></a>
## Откат

1. Остановите сервер.
2. Восстановить последнюю Admin.ini резервную копию из `runtime/backups/`.
3. При необходимости удалите неверную строку `BannedPlayer=<ID>`.
4. Запустите сервер.
5. Снова откройте Admin.ini и подтвердите, что строка сохранилась или была удалена.
6. Сохраните `enforced_bans.jsonl` для аудит.
