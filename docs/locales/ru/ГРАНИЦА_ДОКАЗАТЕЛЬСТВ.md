<a id="evidence-boundary"></a>
# Граница доказательств

> **Канонический английский источник:** [EVIDENCE_BOUNDARY.md](../../EVIDENCE_BOUNDARY.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


Используйте эту страницу, чтобы решить, что RandomDayGuard может сообщать, а то, что все еще требует проверки человеком.

<a id="core-rule"></a>
## Основное правило

RandomDayGuard записывает ограниченные наблюдения из файлов, принадлежащих серверу. Он должен идентифицировать источник, объем, состояние коллекции и ограничения для каждого существенного заключения.

Структурированные доказательства являются авторитетными. Переведенный отчет объясняет доказательства; он не может добавлять факты, отсутствующие в структурированной записи.

<a id="evidence-source-classes"></a>
## Классы источников доказательств

| Исходный класс | Типичное использование | Само по себе не доказывает |
|---|---|---|
| `admin_ini` | Существующее административное состояние и проверено write/readback контекст | Кто вызвал инцидент |
| `active_log` | Текущие server/session события, видимые в активном журнале | Намерение, право собственности или прямой ущерб |
| `recent_backup_logs` | Контекст исторического журнала | Произошло текущее событие |
| `playerdata_filenames` | Подтверждение того, что чистая существует идентификатор учетной записи | Поведение, вина или право собственности на личность, выходящие за рамки раскрытого идентификатора |
| `existing_cases` | Контекст предыдущей проверки | Что предыдущая интерпретация остается верной |
| `existing_reports` | Предыдущие сводки и решения | Текущая истина без текущих подтверждений |
| `existing_evidence` | Исторические структурированные доказательства | Текущая деятельность |
| ограниченное сканирование с сохранением мира | Медленно world/class контекст | Действие игрока, владение, кража, дублирование или повреждение |

Каждый источник записывает availability/readability, количество файлов, ссылки на источники, текущую или историческую область действия и явную `does_not_prove` заявление.

<a id="source-states"></a>
## Источник указывает

| Состояние | Оператор означает |
|---|---|
| `available` | Источник был доступен для чтения, и доказательства были собраны. |
| `expected_empty` | Источник был доступен для чтения и на законных основаниях не имел соответствующей записи. |
| `partial` | Некоторые доказательства были собраны; покрытие неполное. |
| `deferred` | Ограниченная работа была намеренно отложена. |
| `unavailable` | Источник отсутствует в этой среде. |
| `malformed` | Источник существует, но не может быть безопасно проанализирован. |
| `permission_denied` | У сторожевого таймера нет разрешения на чтение. |
| `error` | Не удалось собрать другую запись причина. |

Ожидаемое пустое значение является допустимым наблюдением. Их ни в коем случае нельзя превращать в сфабрикованного игрока, дело, инцидент или обвинение.

<a id="current-versus-historical-evidence"></a>
## Текущие и исторические доказательства

Текущие доказательства относятся к активному окну сбора или эпохе сервера. Исторические свидетельства берутся из предыдущих журналов, дел, отчетов, записей доказательств, резервных копий или базовых показателей.

Исторические свидетельства могут обеспечить контекст. Он не может молча заполнить пробел в существующих доказательствах. В отчетах должны быть указаны обе области и указаны их источники отдельно.

<a id="corroboration-rule"></a>
## Правило подтверждения

Это полезный контекст, но сами по себе они не являются прямым доказательством:

- отображать имена или сходство имен;
- совпадение по времени;
- отключение или повторное подключение;
- один сбой или пакет предупреждений;
- токены класса, пути, актера, карты или количества объектов;
- членство в автоматически сгруппированном случае;
- предыдущие отчеты без подтверждения текущего источника.

Не заявляйте о вине, намерении, мошенничестве, владении, краже, дублировании, прямом повреждении, прямом использовании контейнера, прямом инвентаризации, точных текущих координатах, реальном пинге или поведении на уровне памяти без доказательств, которые непосредственно раскрывают этот факт.

<a id="truthful-report-language"></a>
## Правдивый язык отчета

Используйте:

```text
Observed: the account was active in the recorded crash window.
Interpretation: repeated overlap warrants operator review.
Unknown: the cause of the crash.
Does not prove: that the account caused the crash.
Next action: compare the cited current session and lifecycle records.
```

Избегайте:

```text
The player crashed the server.
The player stole or duplicated items.
The world token proves who used the object.
```

<a id="report-reading-order"></a>
## Порядок чтения отчета

Каждый общедоступный отчет должен объяснять:

1. Простой смысл.
2. Почему это важно.
3. Техническое подтверждение и ссылки на источники.
4. Следующее действие.
5. Ограничения, неизвестные и недоказанные утверждения.
