<a id="detection-signals"></a>
# Сигналы обнаружения

> **Канонический английский источник:** [DETECTION_SIGNALS.md](../../DETECTION_SIGNALS.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


Сигналы — это входные данные проверки, а не автоматические обвинения.

<a id="signal-table"></a>
## Таблица сигналов

| Сигнал | Значение | Сильнее, когда... | Само по себе недостаточно |
|---|---|---|---|
| Идентификатор входа | Сопоставляет имя с идентификатором учетной записи | ConnectID присутствует | Бан |
| Чистый выход | Обычное закрытие сеанса | Присоединиться и выйти из матча | Подозрение |
| Быстрое повторное подключение | Churn/probing контекст | Быстро повторяется | Бан |
| Нечистое отключение | Сеанс закрылся некорректно | Повторяется или перекрывает сбои | Бан |
| Перекрытие сбоев | Аккаунт активен при сбое | Повторяется тот же аккаунт | Бан |
| Возврат после сбоя | Аккаунт возвращается после перезапуска | Повторяется в разные эпохи | Бан по одному событию |
| Пакет предупреждений | Окно предупреждения сервера | Перекрывает сопоставленные сеансы | Бан по одному пакету |
| Сохранение актера при касании | Контекст сохранения мира | Коррелирует с сессии | Подтверждение use/theft |
| дельты объекта | World/class изменения | Коррелирует с сессии | Бан только за счет |
| Случай рейда | Кластер с несколькими учетными записями | Центральная учетная запись повторяется | Массовый бан всех учетных записей |

<a id="login-identity"></a>
## Идентификатор входа

Лучший источник:

```text
Login request
Name=
ConnectID=
UniqueId=
```

Использовать для сопоставления:

```text
display/log name -> account_id -> ban_id
```

<a id="rapid-reconnect"></a>
## Быстрое повторное подключение

Шаблон:

```text
join -> leave -> join -> leave -> join
```

Использовать для проверки при повторении.

Безопасность:

```text
churn_alone_never_bans = true
```

<a id="crash-overlap-and-post-crash-return"></a>
## Перекрытие при сбое и возврат после сбоя

Шаблон:

```text
account active before crash
server restarts
same account returns quickly
```

Использовать для проверки при повторении в разные эпохи.

Безопасность:

```text
single_crash_never_bans = true
```

<a id="warning-bursts"></a>
## Пакеты предупреждений

Примеры:

```text
ActorChannelFailure
DeployableSaveWarning
UpdateActorToWorldSave
ServerMove warnings
```

Использовать в качестве контекста до тех пор, пока не будут связаны с сопоставленными сеансами и пороговыми значениями.

<a id="actor-save-touch"></a>
## Сохранение актера при касании

Значение:

```text
The server evidence referenced a class or actor.
```

Не имеет значения:

```text
A player opened it.
A player stole from it.
A player duplicated through it.
A player damaged it.
```

<a id="raid-cases"></a>
## Случаи рейда

В случае рейда учетные записи группируются по времени и общим окнам.

Правило:

```text
Do not auto-ban every account in a raid case.
Each account needs account-specific evidence.
```
