# Проверка и выпуск

> **Канонический английский источник:** [VALIDATION_AND_RELEASE.md](../../VALIDATION_AND_RELEASE.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


Эта страница предназначена для участников и сопровождающих выпусков. Операторам сервера не нужно запускать эти команды для установки RandomDayGuard.

<a id="user-visible-proof"></a>
## Видимо для пользователя доказательство

Выпуск понятен, если новый оператор может установить его, найти первый отчет о состоянии сервера, выделить пять маршрутов отчета и выполнить одно четкое действие из проработанного примера. Задачи чтения не должны требовать Git, PowerShell, Python или знания контрольной суммы.

<a id="contributor-checks"></a>
## Проверяет участник

```powershell
python -B tools/validate_repo.py
python -B tools/test_public_pipeline.py
python -B -m unittest discover tests
```

Когда `luac` доступен:

```powershell
luac -p RandomDayGuard/Scripts/main.lua
luac -p RandomDayGuard/Scripts/public_pipeline.lua
```

Тесты приспособлений Lua охватывают загрузчик, планировщик, маршруты отчетов и дополнительные Admin.ini транзакции записи. Принудительные приспособления используют только временные файлы и проверяют личность, отклонение доверенной учетной записи, пороговые значения, резервное копирование, отказ от одновременных изменений, обратное чтение и откат.

<a id="package-proof"></a>
## Пакет. доказательство

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

- Все маркеры версии совпадают `VERSION`.
- Только текущая версия существует в `releases/`.
- ZIP содержит канонические `RandomDayGuard/Scripts/main.lua` путь и не содержит загрузчика с вариантами нижнего регистра.
- Вывод во время выполнения, частная конфигурация, учетные данные, локальные пути, кэши и артефакты тестирования исключаются.
- Общедоступная конфигурация остается доступной только для просмотра при отключенном принудительном применении.
- Пять примеров обработанных отчетов остаются согласованными с владельцем маршрута и приспособлением для тестирования выпуска.
- ZIP байты, являются детерминированными и совпадают `CHECKSUMS.sha256`.
- Проверяются все ссылки на локальную документацию и 27 страниц ввода языковых стандартов.

<a id="avoid-validation-environment-pitfalls"></a>
## Избегайте ошибок среды проверки

- Запускайте проверки записи репозитория последовательно, чтобы избежать конфликтов временных файлов.
- В Windows проверяйте имена заархивированных элементов или написание перечисляемых путей, а не поиск файлов без учета регистра при проверке на наличие дубликатов загрузчики.
- Отсутствующая `luac` команда или среда выполнения Lua — это недоступная возможность, а не прохождение теста синтаксиса или времени выполнения.
- Фикстура подтверждает только смоделированные входные данные. Это не доказывает, что работающий сервер создал текущий отчет.
- Записывайте тайм-ауты команд и частичный вывод вместо предположения о завершении.

<a id="repair-failed-repository-validation"></a>
## Восстановить неудачную проверку репозитория

Начните с первого сообщенного пути или контракта. Исправьте этот элемент, повторите узкий тест, а затем повторите полную матрицу. Не скрывайте недостающую возможность, удаляя тест, который ее требует.

<a id="known-limits-and-release-decision"></a>
## Известные ограничения и решение о выпуске

Локальные проверки подтверждают контракты на исходный код, приспособление, пакет и документацию. Конкретная установка сервера, длительное окно стабильности или отображение клиента требуют отдельного результата интеграции. Запишите этот результат с указанием его сборки, конфигурации, продолжительности и наблюдаемых результатов, прежде чем подавать соответствующее заявление.
