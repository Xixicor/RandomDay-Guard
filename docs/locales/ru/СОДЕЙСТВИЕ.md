# Содействие

> **Канонический английский источник:** [CONTRIBUTING.md](../../../CONTRIBUTING.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


RandomDayGuard допускает целенаправленные, воспроизводимые улучшения анализаторов, документации, тестов и общедоступной проверки. Сохраняйте каждое изменение привязанным к публичному контракту проекта и сохраняйте принцип «сначала проверка». Guard должен оставить `Admin.ini` без изменений, если требуемая проверка безопасности не может быть подтверждена.

<a id="prepare-a-safe-workspace"></a>
## Подготовьте безопасное рабочее пространство

1. Разветвите или клонируйте репозиторий и создайте целевую ветвь.
2. Установите поддерживаемый интерпретатор Python 3. Установите компилятор Lua при изменении Lua, чтобы `luac -p` мог проверить синтаксис.
3. Прочитайте [главную страницу документации](%D0%94%D0%9E%D0%9A%D0%A3%D0%9C%D0%95%D0%9D%D0%A2%D0%90%D0%A6%D0%98%D0%AF.md), [архитектуру](%D0%90%D0%A0%D0%A5%D0%98%D0%A2%D0%95%D0%9A%D0%A2%D0%A3%D0%A0%D0%90.md), а [границы доказательств](%D0%93%D0%A0%D0%90%D0%9D%D0%98%D0%A6%D0%90_%D0%94%D0%9E%D0%9A%D0%90%D0%97%D0%90%D0%A2%D0%95%D0%9B%D0%AC%D0%A1%D0%A2%D0%92.md) для области, которую вы будете изменять.
4. Проверьте `git status` перед редактированием и сохраните несвязанную работу.
5. Используйте только синтетические или очищенные приспособления.

Никогда не отправляйте журналы частного сервера, сохраненные папки, идентификаторы игроков, `Admin.ini`, конечные точки частных уведомлений, учетные данные, частные пути, выходные данные среды выполнения или копии живых доказательств.

<a id="make-a-focused-change"></a>
## Внесите целенаправленное изменение

- Следуйте существующим именованиям, форматированию, проверкам безопасности и владельцам модулей.
- Сохраняйте одного владельца канонической документации для каждой процедуры или конкретного факта.
- Обновляйте пользовательскую документацию и примеры при изменении поведения или общедоступных результатов.
- Добавляйте регрессионный тест для исправления ошибок, когда это практически возможно.
- Не ослабляйте подтверждение учетной записи, защиту доверенной учетной записи, проверку резервной копии, обнаружение внешних изменений, сравнение сохраненных файлов, восстановление или настройки по умолчанию только для просмотра. чтобы пройти тест.

<a id="run-the-relevant-checks"></a>
## Выполните соответствующие проверки.

Для внесения изменений только в документацию выполните:

```powershell
python -B tools\generate_documentation_audit.py --check
python -B -m unittest discover tests -p "test_documentation*.py"
git diff --check
```

Для изменений источника, конфигурации, упаковки или тестирования также запустите соответствующие проверки из [Проверка и проверка выпуска](%D0%9F%D0%A0%D0%9E%D0%92%D0%95%D0%A0%D0%9A%D0%90_%D0%98_%D0%92%D0%AB%D0%9F%D0%A3%D0%A1%D0%9A.md), включая проверку синтаксиса Lua, проверку репозитория, тесты общедоступного конвейера и полный набор модульных тестов. Сообщайте о каждой пропущенной или недоступной проверке; не описывайте его как пройденный.

<a id="submit-the-change-for-review"></a>
## Отправьте изменение на проверку

Открывайте целевой запрос на включение только после просмотра полной разницы. Включите:

- проблему и предполагаемое поведение;
- изменены точные файлы и общедоступные контракты;
- выполняемые команды и их результаты;
- конфиденциальность, совместимость и влияние принудительного исполнения; и
- оставшиеся ограничения или дальнейшая работа.

Не включайте созданные во время выполнения доказательства или архивы выпуска, если изменение явно не требует и не подтверждает их. Вклад не разрешает выпуск, развертывание, тестирование на реальном сервере, принудительные действия или публикацию на стороннем сайте.

Сообщайте об уязвимостях через [частный маршрут безопасности](%D0%91%D0%95%D0%97%D0%9E%D0%9F%D0%90%D0%A1%D0%9D%D0%9E%D0%A1%D0%A2%D0%AC.md), а не через публичную проблему или обычный запрос на включение.
