# Справочник по исходному модулю

> **Канонический английский источник:** [SOURCE_MODULE_REFERENCE.md](../../SOURCE_MODULE_REFERENCE.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


На этой странице отображаются все источники, конфигурации, данные, загрузчик совместимости и класс заполнителя времени выполнения. допущен в список разрешенных выпусков. Машинный индекс: [`TRACEABILITY_INDEX.json`](../../TRACEABILITY_INDEX.json); эта страница представляет собой читаемое каноническое объяснение. Каждая сгенерированная машинная строка называет отдельные path/class, назначение, владелец исходного блока, общедоступные настройки, побочные эффекты, видимые оператору состояния, сбои, восстановление и канонический документ.

<a id="ue4ss-loader-and-watchdog"></a>
## UE4SS загрузчик и сторожевой таймер

`Scripts/main.lua` владеет запуском независимого сторожевого таймера, обнаружением сохраненного корня, текущим хвостом журнала, эпохами и сеансами сервера, ограниченным опросом и сканированием, object/world контекстом, оценкой обзора, `Admin.ini` защитные ворота, устаревшие операционные выходные данные и отдельная передача отчета работнику. Он должен ограничить опросы в реальном времени, в то время как медленная историческая работа возобновляется независимо. Сердцебиение, маркер запуска или увеличение `poll_id` подтверждают только этот компонент; Для завершения маршрута требуются одинаковые текущая загрузка, эпоха, опрос, актуальность источника, пара отчетов и подтверждение маршрута.

Источник и пакет имеют одни и те же полномочия: `RandomDayGuard/Scripts/main.lua`. Копия `scripts/` в нижнем регистре не является частью дерева исходного кода или выпуска. Сохранение одного канонического написания предотвращает ошибки из-за коллизии регистра при извлечении пакета в Windows или Linux.

<a id="public-reporting-module"></a>
## Модуль общедоступных отчетов

`Scripts/public_pipeline.lua` получает обратные вызовы вместо учетных данных хоста или адаптеров поставщика. Он инвентаризирует восемь исходных классов, записывает терминальные и незавершенные состояния, отделяет текущих игроков от сохраненной истории, преобразует каждый маршрут в порядке `Observed`, `Interpretation`, `Unknown`, `Does not prove`, `Next action`, а `Source references`, затем записывает подтверждение маршрута. Дополнительный режим уведомления записывает только локальный JSON конверт; он никогда не заявляет о доставке и не объединяет доставку endpoint/bridge.

Исполняемый файл в `tests/lua/public_pipeline_runtime_test.lua` загружает этот отправленный модуль с помощью Lua, доказывает полные и ожидаемо-пустые маршруты, доказывает, что цикл отсутствия текущего источника завершается неудачно, и доказывает, что неполные маршруты не попадают в исходящие.

<a id="package-layout"></a>
## Макет пакета

Сборщик допускает только три корневых легальных файла, `RandomDayGuard/` пути выше и пустые заполнители среды выполнения. Он упорядочивает элементы побайтно, исправляет ZIP упаковывают канонический загрузчик один раз, сканируют каждого члена на предмет личных материалов, записывают SHA-256 для каждого члена, связывают имена и байты в один дайджест контента и выполняют двойную компоновку. Тесты отвергают каждое столкновение регистров и доказывают, что при обычном извлечении на каждую запись архива создается ровно один физический файл.

В общедоступном репозитории хранится только папка текущего выпуска. Разработчик проверяет соответствие ZIP, контрольной суммы, примечаний, маркеров версий и дерева исходного кода.

<a id="code-comment-contract"></a>
## Контракт комментариев кода

Комментарии времени выполнения представляют собой краткие контракты сопровождающего, а не второе руководство. Каждый поставляемый модуль среды выполнения должен разместить одну каноническую ссылку в блоке вступительных комментариев:

```lua
-- Documentation: docs/SOURCE_MODULE_REFERENCE.md#ue4ss-loader-and-watchdog
```

Неочевидное состояние, планирование, write/readback/rollback, source-discovery, Translation, Evidence, Output-Schema, Route-Cadence и Redaction. В блоках, где это применимо, используются сфокусированные комментарии со следующими метками:

```lua
-- Public contract: <invariant or consequence>
-- Evidence boundary: <what the input cannot prove>
-- Failure behavior: <how the block fails closed or recovers>
-- Documentation: docs/<canonical-file>.md#<existing-anchor>
```

Основной загрузчик также имеет один специальный комментарий владельца для конфигурации. загрузка, сохраненное обнаружение, атомарная замена, принудительное выполнение и планирование. В этих комментариях указаны границы потока управления и ошибок; они не меняют поведение во время выполнения.

Валидатор требует ссылку `Documentation:` на уровне модуля для каждого модуля времени выполнения, разрешает каждый путь комментария и привязку, требует целенаправленного контракта и комментариев об ошибках в обоих модулях времени выполнения и сравнивает одни и те же канонические ссылки с `TRACEABILITY_INDEX.json`. Комментарий можно отслеживать, а не проверять во время выполнения.

<a id="contributor-change-checklist"></a>
## Контрольный список изменений участника

1. Обновите один модуль-владелец и его целевое приспособление.
2. Обновите каноническую конфигурацию, схему, выходные данные, доказательства или раздел жизненного цикла.
3. Запустите `python -B tools/generate_documentation_audit.py --write` после конфигурация, путь к пакету, сгенерированный выходной класс, владелец или изменения контракта восстановления.
4. Запустите `python -B tools/generate_documentation_audit.py --check`, целевые модульные тесты, реальная фиксация Lua, в которой доступен Lua, полный валидатор, две независимые детерминированные сборки и `git diff --check`.
5. Проверьте сгенерированный список участников ZIP, контрольную сумму и сканирование личных материалов перед созданием выпуска.
