<a id="memory-economy-and-output-files"></a>
# экономии памяти и выходных файлах

> **Канонический английский источник:** [MEMORY_ECONOMY_AND_OUTPUTS.md](../../MEMORY_ECONOMY_AND_OUTPUTS.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


На этой странице объясняется, какие файлы увеличиваются, какие файлы перезаписываются и что загружать для быстрого просмотра.

<a id="fast-answer"></a>
## Быстрый ответ

| Вопрос | Открытый |
|---|---|
| Жив ли охранник? | `runtime/current/poll_status.json` |
| Кого видели? | `runtime/account_evidence.json` |
| Что случилось с сеансами? | `runtime/evidence/session_events.jsonl` |
| Что произошло сегодня? | `runtime/forensic_days/YYYY-MM-DD/` |
| Что такое простой язык резюме? | `runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt` |
| Каков ход сканирования? | `runtime/scan_progress.json` |
| Каков мировой контекст? | `runtime/world_state/current/world_state_latest.json` |
| Какие баны были написаны? | `runtime/enforced_bans.jsonl` |

<a id="output-model"></a>
## Модель вывода

| Тип | Поведение | Примеры |
|---|---|---|
| Текущие снимки | Перезаписаны | `runtime/current/*.json` |
| Журналы событий | Только добавление | `runtime/evidence/*.jsonl` |
| Таблицы | Обновлены или добавлены | `*.tsv` |
| Базовые показатели | Используются повторно после завершения | `runtime/baselines/*` |
| Ежедневные сводные данные | Обновляются на месте | `runtime/forensic_days/YYYY-MM-DD/*` |
| Окончательные журналы | Ежедневная сводка на простом языке | `runtime/final_logs/YYYY-MM-DD/*` |

<a id="current-snapshots"></a>
## Текущие снимки

Они остаются небольшими и отвечают на вопрос, «что актуально на данный момент».

```text
runtime/current/poll_status.json
runtime/current/session_state.json
runtime/current/active_accounts.json
runtime/current/forensic_today.json
runtime/current/forensic_today.md
runtime/current/forensic_today.txt
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/world_state/current/world_state_latest.json
```

<a id="player-summaries"></a>
## Сводки игроков

Это первые файлы, которые необходимо проверить на предмет проверки учетной записи.

```text
runtime/account_evidence.json
runtime/account_evidence.tsv
```

Они суммируют:

```text
account_id
ban_id
name
identity_confidence
first_seen
last_seen
join_count
leave_count
status
score
```

<a id="event-logs"></a>
## Журналы событий

Они сохраняют временная шкала.

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/warning_events.jsonl
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/evidence/live_defense_events.jsonl
```

<a id="daily-forensic-rollups"></a>
## Ежедневные сводные отчеты

Это пакеты быстрой загрузки.

```text
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

Загрузите одну из этих папок, если вам нужен быстрый анализ периода.

<a id="scan-and-baseline-files"></a>
## Файлы сканирования и базовых показателей

Используйте их, чтобы понять, является ли мировой контекст частичным или завершено.

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/object_registry_partial.json
runtime/object_registry.json
runtime/object_registry_counts.tsv
runtime/baselines/last_completed_baseline.json
runtime/baselines/file_manifest.tsv
```

<a id="enforcement-files"></a>
## Файлы принудительного исполнения

Используйте их только тогда, когда принудительное применение включено.

```text
runtime/enforced.txt
runtime/enforced_bans.jsonl
runtime/ban_queue.json
runtime/evidence/enforced_bans.jsonl
```

`Admin.ini` должен получать только:

```ini
BannedPlayer=<ID>
```

<a id="what-updates-when-a-player-joins"></a>
## Какие обновления при присоединении игрока

Ожидаемые обновления:

```text
runtime/account_evidence.json
runtime/account_evidence.tsv
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/current/session_state.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="what-updates-when-the-server-crashes-or-restarts"></a>
## Какие обновления при сбое сервера или перезапускает

Ожидаемые обновления:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/crash_reconnects.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="what-updates-when-the-scan-progresses"></a>
## Какие обновления по ходу сканирования

Ожидаемые обновления:

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/object_registry_partial.json
runtime/world_state/current/world_state_latest.json
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
```

<a id="what-to-upload-for-quick-analysis"></a>
## Что загрузить для быстрого анализа

Лучший пакет:

```text
runtime/final_logs/YYYY-MM-DD/
```

Более полный пакет:

```text
runtime/forensic_days/YYYY-MM-DD/
```

Полный пакет доказательств:

```text
runtime/account_evidence.json
runtime/evidence/session_events.jsonl
runtime/server_lifecycle_events.jsonl
runtime/warning_events.jsonl
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```
