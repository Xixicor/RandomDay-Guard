# Модели злоумышленников и устойчивость

> **Канонический английский источник:** [BAD_ACTOR_PATTERNS_AND_RESILIENCE.md](../../BAD_ACTOR_PATTERNS_AND_RESILIENCE.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


. Используйте эту страницу, чтобы понять, как защита помогает проверять злоупотребления при сбоях, поведение, связанное с эксплойтами, и планировать восстановление.

<a id="what-the-guard-can-help-with"></a>
## Чем защита может помочь

| Шаблон | Что проверить |
|---|---|
| Возвраты, коррелированные со сбоями | Та же учетная запись активна до сбоя и возвращается после перезапуска |
| Быстрая проверка повторного подключения | Повторяющиеся join/leave или timeout/reconnect циклы |
| Кластеры с несколькими учетными записями | Присоединение волн, общие окна предупреждений, общие окна сбоев |
| Предупреждение о взрывном стрессе | Повторяющиеся ActorChannelFailure или окна с предупреждением о сохранении |
| Контекст за пределами границ | PlayerData/map/world контекст, когда он доступен для чтения |
| Перекрытие при сохранении-прикосновении | Перекрытие контекста при сохранении во всем мире |
| Спутница идентификации | Имена, которым требуется сопоставление ConnectID |

<a id="why-it-avoids-memory-access"></a>
## Почему он избегает доступа к памяти

RandomDayGuard работает с файлами, принадлежащими серверу:

```text
Saved/Logs/*.log
Admin.ini
World saves
PlayerData
Backups
runtime evidence
```

Это делает его менее зависимым от состояния памяти на стороне клиента и менее уязвимым при обновлениях игры.

Компромисс:

```text
It cannot prove hidden live actions unless the server writes evidence.
```

<a id="crash-correlated-returners"></a>
## Возвраты, коррелирующие со сбоями

Шаблон:

```text
Account joins.
Server crashes or restarts.
Same account reconnects quickly.
Pattern repeats.
```

Полезные файлы:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="rapid-reconnect-probers"></a>
## Быстрый повторно подключить пробники

Шаблон:

```text
join -> leave -> join -> leave -> join
```

Полезные файлы:

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
```

<a id="multi-account-clusters"></a>
## Кластеры с несколькими учетными записями

Шаблон:

```text
Several accounts join in the same window.
Warnings or crashes follow.
Some accounts rotate or reconnect after restart.
```

Полезные файлы:

```text
runtime/raid_cases/
runtime/forensic_days/YYYY-MM-DD/raid_cases.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

Правило:

```text
A cluster is not a mass-ban list.
Each account still needs its own evidence.
```

<a id="sticky-backup-recommendation"></a>
## Рекомендация по закреплению резервной копии

Создать прикрепленную резервную копию после:

```text
first full baseline completes
object_registry.json exists
file_manifest.tsv exists
world_state_latest.json has scan_complete=true
Admin.ini is verified
trusted IDs are configured
```

Резервное копирование:

```text
RandomDayGuard/config.lua
RandomDayGuard/SavedRoot.txt
RandomDayGuard/runtime/baselines/
RandomDayGuard/runtime/object_registry.json
RandomDayGuard/runtime/world_state/current/world_state_latest.json
Saved/SaveGames/Server/Admin.ini
```

<a id="recovery-model"></a>
## Модель восстановления

```text
Clean install
-> verify live defense
-> complete first baseline
-> create sticky backup
-> run server normally
-> use daily rollups for review
-> restore sticky backup if needed
```
