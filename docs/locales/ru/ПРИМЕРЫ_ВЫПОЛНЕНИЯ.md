# Примеры рабочих операций

> **Канонический английский источник:** [EXAMPLE_RUNS.md](../../EXAMPLE_RUNS.md). Эта локализованная документация сохраняет точные команды, пути, ключи, значения статуса, хэши и имена файлов. Если технические формулировки отличаются, используйте источник на английском языке.


В этих примерах используются придуманные значения для объяснения ожидаемых переходов состояний; они не являются живой совместимостью или свидетельством игрока.

<a id="successful-current-cycle"></a>
## Успешный текущий цикл

Входные данные: читаемый активный журнал, version/boot/epoch, `poll_id=41`, завершенный текущий опрос, записываемые accounting/history/report корни, отсутствие политики блокировки медленного сканирования.

Ожидается:

```text
server_status = full
player_activity = full or limited_expected_empty
case_review = full or limited_expected_empty
daily_rollup = full or limited_expected_empty
critical_guard = full or limited_expected_empty
```

Каждый включенный маршрут имеет JSON/TXT и та же линия происхождения в `route_proof.json`. Статус маршрута зависит от его собственных субъектов, а не от общего сообщения об успехе.

<a id="expected-empty-player-and-case-routes"></a>
## Ожидаемый пустой маршрут игрока и кейса

Входные данные: доказательство текущего цикла завершено; нет текущих или сохраненных строк игроков; ни сохраненного случая, ни текущей REVIEW/BAN-ELIGIBLE учетной записи.

Ожидается:

```text
player_activity.route_proof_status = limited_expected_empty
player_activity.expected_empty = true
player_activity.players = []

case_review.route_proof_status = limited_expected_empty
case_review.expected_empty = true
case_review.cases = []
```

В переведенных отчетах говорится, что не наблюдалось ни одного подходящего ограниченного субъекта. Они также говорят, что это не доказывает, что никто никогда не был подключен или что никакой контекст не упущен. Заполнитель player/case не создается.

<a id="partial-bounded-scan"></a>
## Частичное ограниченное сканирование

Входные данные: свежий текущий log/poll; `scan_checkpoint.json` или `scan_progress.json` существует; сканирование неполное; по умолчанию `slow_world_scan_blocks_current_reports=false`.

Ожидается:

```text
world_save_scan.status = partial
source accounting = partial
server_status may still be full for fresh current state
historical routes name the scan limitation
```

Устанавливайте `slow_world_scan_blocks_current_reports=true` только тогда, когда оператор хочет, чтобы этот дополнительный медленный источник блокировал текущие отчеты. Восстановление позволяет работнику сканирования возобновить работу, а не удалять контрольную точку.

<a id="missing-current-cycle-proof"></a>
## Отсутствует подтверждение текущего цикла

Входные данные: активный журнал недоступен, `poll_id=0` или boot/epoch/last-poll происхождение отсутствует.

Ожидается:

```text
current_cycle_proof_complete = false
all route proof statuses = missing
each configured route envelope status = suppressed_current_cycle
delivery_eligible = false
delivery_attempted = false
```

Подавленный конверт представляет собой запись аудита, а не доставку в очереди. Старые окончательные журналы остаются только историческими. Исправьте первое отсутствующее поле lineage/source и создайте новый цикл.

<a id="malformed-optional-adminini-source"></a>
## Неверный необязательный Admin.ini источник

Входные данные: `Admin.ini` существует, но не проходит чистую структурную проверку.

Ожидается:

```text
admin_ini.status = malformed
source reference preserved
write/enforcement path closed
```

Сохраните файл и восстановить проверенный чистый формат. Храните пояснительный текст в доказательствах во время выполнения; каждая `Admin.ini` запись о запрете остается только `BannedPlayer=<ID>`.

<a id="required-active-log-probe-error"></a>
## Требуется ошибка проверки активного журнала

Входные данные: ограниченная обязательная проверка активного журнала завершается неудачно с исправленной ошибкой чтения.

Ожидается:

```text
source_accounting.sources[active_log].status = error
source_accounting.sources[active_log].detail = "bounded active-log probe failed: <sanitized reason>"
coverage_status = unavailable
all route proof statuses = missing
```

`error` остается в исходной строке с ее ограниченными подробностями. В отчете верхнего уровня используется `unavailable`, а подтверждение маршрута остается `missing` до тех пор, пока новый текущий цикл не подтвердит требуемый источник.

<a id="incompatible-or-stale-baseline"></a>
## Несовместимый или устаревший базовый уровень

Входные данные: измененный package/source идентификатор или stale/incompatible базовый уровень манифест.

Ожидается: проверка или статус выполнения фиксируют несовместимость; состояние сканирования не утверждает, что повторное использование завершено. Сохраните предыдущие доказательства, начните явное восстановление базовой линии и ждите новых окончательных доказательств. Принудительное перестроение без записанной причины не является восстановлением по умолчанию.

<a id="paired-report-write-failure"></a>
## Ошибка записи парного отчета

Входные данные: JSON запись успешна, но TXT запись не удалась, или наоборот.

Ожидается:

```text
route_proof_status = missing
completed = false
coverage_status = unavailable
output_write_detail = "paired JSON/TXT write failed: <sanitized reason>"
next_action = repair both route output writes
```

Создатель делает все возможное, чтобы перезаписать обоих одноуровневых отчетов, чтобы они сходились в случае сбоя. Один успешный брат или сестра не может оставаться претендующим на успех. Ограниченная информация о записи не создает пятое значение покрытия верхнего уровня.

<a id="route-proof-write-failure"></a>
## Ошибка записи с защитой от маршрутизации

Входные данные: пары маршрутов были записаны, но `route_proof.json` не могут быть заменены.

Ожидается: все отчеты переписаны `missing`, все результаты уведомлений `route_proof_write_failed`, и конверт не принимается. Настроенный маршрут может иметь `suppressed_current_cycle` конверт аудита с ложными флагами доставки. Исправьте выходной корень и заново создайте тот же текущий цикл.

<a id="review-only-enforcement-example"></a>
## Пример принудительного применения только для просмотра

Конфигурация:

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

Ожидается: могут быть записаны оценки, случаи и рекомендации; `Admin.ini` остается без изменений. Это общедоступное значение по умолчанию.

<a id="approved-write-success-example"></a>
## Утвержденный пример успешной записи

Только отдельно утвержденный тест может установить все три переключателя записи. Он также должен подтверждать чистую числовую идентичность, trust/moderator исключение, пороговое соответствие, валидность Admin.ini path/parse, успешность резервного копирования, успех записи, равенство обратного чтения и доказательства для конкретной учетной записи.

Ожидается:

```text
runtime/backups/Admin_<timestamp>_<source-fingerprint>_<clean-ID>.ini
Admin.ini contains one clean BannedPlayer=<ID>
runtime/enforced_bans.jsonl and evidence mirror record success
```

Успешный пример не включает автоматическое применение для других учетных записей.

<a id="writereadback-failure-with-rollback"></a>
## Write/readback сбой при откате

Входные данные: каждый пройденный шлюз предварительной записи; замена записи или обратного чтения не удалась; `rollback_on_readback_failure=true` и проверенная резервная копия доступна.

Ожидается: свидетельство сбоя записывает этап и `rollback_success`; исходные Admin.ini байты восстанавливаются, и учетная запись не считается успешно примененной. Если откат также не удался, остановите запись, сохраните оба файла files/evidence и выполните восстановление вручную из резервной копии.

<a id="local-outbox-example"></a>
## Пример локального исходящего ящика

Входные данные: уведомление включено в режиме `local_file_outbox`, маршрут включен, завершено подтверждение маршрута и либо `full`, либо явно разрешено ожидаемо-пусто.

Ожидаемый конверт:

```text
schema = randomdayguard.notification/v1
completed_output = true
status = ready_for_local_consumer
delivery_eligible = true
delivery_backend = none
delivery_attempted = false
```

Для missing/ineligible вывод, вместо этого тот же путь может содержать `status=suppressed_current_cycle`, `completed_output=false`, а `delivery_eligible=false`. Любой файл доказывает только локальную запись. Никакой поставщик, транспорт, доставка или уведомление о прочтении не связываются и не подразумеваются.
