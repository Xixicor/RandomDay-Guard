# Admin.ini επιβολή

> **Κανονική αγγλική πηγή:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). Αυτή η τοπική τεκμηρίωση διατηρεί ακριβείς εντολές, διαδρομές, κλειδιά, τιμές κατάστασης, κατακερματισμούς και ονόματα αρχείων. Εάν η τεχνική διατύπωση διαφέρει, χρησιμοποιήστε την αγγλική πηγή.


RandomDayGuard δεν αλλάζει τη λίστα απαγόρευσης διακομιστή στην προεπιλεγμένη ρύθμιση. Δημιουργεί αναφορές μόνο για έλεγχο από έναν διαχειριστή. Αυτή η σελίδα εξηγεί την προαιρετική αυτόματη ενημέρωση λίστας αποκλεισμού για διαχειριστές που την ενεργοποιούν σκόπιμα.

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## Τι ελέγχει ο Φρουρός πριν αλλάξει τη λίστα απαγόρευσης

Το Guard προσθέτει απαγόρευση μόνο όταν κάθε απάντηση παρακάτω είναι **ναι**:

1. Τα τρέχοντα στοιχεία προσδιόρισαν έναν συγκεκριμένο λογαριασμό με επαρκή εμπιστοσύνη;
2. Ο λογαριασμός δεν είναι ούτε επόπτης ούτε λογαριασμός που ο διαχειριστής έχει επισημανθεί ως αξιόπιστος;
3. Ο λογαριασμός δεν βρίσκεται ήδη στη λίστα απαγόρευσης;
4. Έφτασε ο λογαριασμός στη διαμορφωμένη βαθμολογία αυτόματης ενέργειας;
5. Μπορεί το Guard να διαβάσει το τρέχον `Admin.ini` και να αποθηκεύσετε ένα πανομοιότυπο αντίγραφο ασφαλείας;
6. Έκανε `Admin.ini` μείνετε αμετάβλητο όσο η Guard ετοίμαζε την ενημέρωση;
7. Μετά την αποθήκευση, το πλήρες αρχείο ταιριάζει ακριβώς με το επιδιωκόμενο αποτέλεσμα;

Εάν κάποια απάντηση είναι **όχι**, ή δεν μπορεί να ελεγχθεί, ο Φρουρός φεύγει `Admin.ini` αμετάβλητο και καταγράφει τον λόγο στις αναφορές του. Εάν ξεκινήσει η αποθήκευση αλλά ο τελικός έλεγχος αποτύχει, το Guard επαναφέρει το επαληθευμένο αντίγραφο ασφαλείας.

<a id="file-format"></a>
## Μορφή αρχείου

`Admin.ini` πρέπει να λαμβάνει μόνο καθαρές γραμμές αποκλεισμού:

```ini
BannedPlayer=<ID>
```

- Δεν υπάρχουν ονόματα.
- Δεν υπάρχουν σχόλια.
- Δεν υπάρχουν λόγοι.
- Δεν υπάρχουν επιθήματα.

<a id="safe-defaults"></a>
## Ασφαλείς προεπιλογές

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## Πηγή αποκλεισμού αναγνωριστικού

Καλύτερη πηγή:

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

Ο χρόνος εκτέλεσης δέχεται είτε ένα πλήρως αριθμητικό αναγνωριστικό είτε το πλήρες τεκμηριωμένο `<digits>_+_|<non-space token>` φόρμα σύνδεσης και αντλεί το αριθμητικό αναγνωριστικό αποκλεισμού από αυτήν. Τα αυθαίρετα αριθμητικά προθέματα με άγνωστο επίθημα απορρίπτονται. δεν περικόπτονται σε αναγνωριστικό απαγόρευσης.

Σωστό:

```ini
BannedPlayer=2535422284688820
```

Λάθος:

```ini
BannedPlayer=ExamplePlayer
```

Επίσης λάθος:

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## Ακριβείς ρυθμίσεις Έλεγχοι φρουράς

Αυτές οι ρυθμίσεις υλοποιούν τους ελέγχους που περιγράφονται παραπάνω. Κάθε συνθήκη που παρατίθεται πρέπει να είναι αληθής:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

Εάν κάποια συνθήκη είναι ψευδής ή δεν μπορεί να ελεγχθεί, ο Guard αφήνει τη λίστα απαγόρευσης αμετάβλητη και καταγράφει τι την εμπόδισε.

<a id="transaction-safety"></a>
## Ασφάλεια συναλλαγών

Η σόλα `Admin.ini` εκτελεί αυτά τα βήματα με τη σειρά:

1. Διαβάστε και επικυρώστε δομικά τα έγκυρα byte.
2. Αποκτήστε κατάσταση επόπτη, αξιόπιστου και υπάρχοντος αποκλεισμού από το ίδιο στιγμιότυπο.
3. Γράψτε ένα μοναδικό αντίγραφο ασφαλείας στο `runtime/backups/` και επαληθεύστε το byte για byte.
4. Επανάγνωση `Admin.ini` αμέσως πριν την αντικατάσταση και απορρίψτε οποιαδήποτε εξωτερική αλλαγή.
5. Εγγράψτε τον υποψήφιο μέσω της διαμορφωμένης ελεγχόμενης διαδρομής αντικατάστασης.
6. Απαιτούνται τα πλήρη byte ανάγνωσης για να ισούται με τα πλήρη υποψήφια byte.
7. Σε περίπτωση αποτυχίας επαναφοράς, επαναφέρετε το επαληθευμένο αντίγραφο ασφαλείας μόνο όσο το τρέχον αρχείο εξακολουθεί να είναι το ακριβές υποψήφιο που έχει γράψει ο Guard. Εάν κάποιος άλλος συγγραφέας το άλλαξε, το Guard αρνείται την επαναφορά αντί να αντικαταστήσει άγνωστα εξωτερικά byte.

Τα διπλότυπα αναγνωριστικά είναι αδύναμα: δεν γράφονται δεύτερη γραμμή και δεύτερο αντίγραφο ασφαλείας. Τα εφεδρικά ονόματα περιλαμβάνουν χρονική σήμανση, δακτυλικό αποτύπωμα πηγής byte και καθαρό αναγνωριστικό, έτσι ώστε οι ξεχωριστές προσπάθειες να μην μπορούν να μοιραστούν το παλιό όνομα αρχείου ενός δευτερολέπτου.

<a id="local-regression-proof"></a>
## Απόδειξη τοπικής παλινδρόμησης

`tests/lua/enforcement_runtime_test.lua` εκκινεί το φορτωτή που αποστέλλεται μία φορά και στη συνέχεια εκτελεί το πραγματικό του τοπικό `append_ban()` κλείσιμο έναντι μεμονωμένων συνθετικών αρχείων κάτω από το αποθετήριο `.tmp/`. Καλύπτει την εισαγωγή, τη διπλή αδυναμία, moderator/trusted απόρριψη, απόρριψη αδύναμης και λανθασμένης ταυτότητας, επαλήθευση αντιγράφων ασφαλείας ακριβούς byte, ταυτόχρονη απόρριψη τροποποίησης, επιτυχής επαναφορά μετά από αποτυχημένη ανάγνωση και άρνηση αντικατάστασης μιας εξωτερικής αλλαγής μετά την εγγραφή. Τα περιτυλίγματα του συστήματος αρχείων του απορρίπτουν οποιαδήποτε μετάλλαξη εκτός της ρίζας του προσαρτήματος. καμία πραγματική διαδρομή διακομιστή ή πραγματική `Admin.ini`.

Εκτέλεσε το `python tools/test_public_pipeline.py`. Ένα πάσο προσαρμογής αποδεικνύει μόνο τη συμπεριφορά τοπικής συναλλαγής. Δεν ενεργοποιεί την επιβολή, δεν εξουσιοδοτεί μια εγγραφή παραγωγής ή δεν αποδεικνύει δικαιώματα για συγκεκριμένο υπολογιστή.

runtime/enforced_bans.jsonl
runtime/enforced.txt

<a id="rollback"></a>
## Επιστροφή

1. Διακοπή του διακομιστή.
2. Επαναφέρετε τα πιο πρόσφατα Admin.ini αντίγραφο ασφαλείας από `runtime/backups/`.
3. Καταργήστε το εσφαλμένο `BannedPlayer=<ID>` γραμμή εάν χρειάζεται.
4. Εκκινήστε τον διακομιστή.
5. Ανοίξτε ξανά Admin.ini και επιβεβαιώστε ότι η γραμμή συνεχίστηκε ή καταργήθηκε.
6. Διατήρηση `enforced_bans.jsonl` για έλεγχο.
