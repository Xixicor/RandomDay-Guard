# Ξεκινήστε εδώ: διαβάστε την πρώτη αναφορά Φρουράς

> **Κανονική αγγλική πηγή:** [START_HERE.md](../../START_HERE.md). Αυτή η τοπική τεκμηρίωση διατηρεί ακριβείς εντολές, διαδρομές, κλειδιά, τιμές κατάστασης, κατακερματισμούς και ονόματα αρχείων. Εάν η τεχνική διατύπωση διαφέρει, χρησιμοποιήστε την αγγλική πηγή.


Αυτός ο οδηγός ξεκινά μετά από RandomDayGuard είναι εγκατεστημένο και ενεργοποιημένο. Αποδεικνύεται ένα χρήσιμο αποτέλεσμα χωρίς να ζητά από έναν νέο χειριστή να επιθεωρήσει τον πηγαίο κώδικα, τα εσωτερικά του πακέτου ή τα αρχεία κατάστασης μόνο για μηχανή.

<a id="what-happens-after-the-server-starts"></a>
## Τι συμβαίνει μετά την εκκίνηση του διακομιστή

Ο φρουρός περιμένει τον διακομιστή του παιχνιδιού και UE4SS για φόρτωση, βρίσκει τις διαθέσιμες εγγραφές του διακομιστή και ξεκινά μια σάρωση περιορισμένου φόντου. Μπορεί να αναφέρει την τρέχουσα υγεία του διακομιστή ενώ το παλαιότερο ιστορικό εξακολουθεί να ευρετηριάζεται.

Η πρώτη αναφορά πρέπει να είναι **Κατάσταση διακομιστή**. Απαντά εάν το Guard ολοκληρώνει τους κύκλους παρακολούθησης τώρα, όταν ξεκίνησε η τρέχουσα εκτέλεση διακομιστή εάν είναι διαθέσιμη αυτή η χρονική σήμανση, πόσο active/rotated υπάρχει κάλυψη καταγραφής και σάρωσης, πόσες συσκευές αναπαραγωγής είναι συνδεδεμένες, ποιες ομάδες πηγών λείπουν και εάν απαιτείται ενέργεια χειριστή.

Μια σάρωση παρασκηνίου που εξακολουθεί να προχωρά αποτελεί περιορισμό στην ιστορική κάλυψη και όχι αυτόματα αποτυχία εκκίνησης. Το Guard καταγράφει τον δρομέα σάρωσης, τα αρχεία που ολοκληρώθηκαν, τα αρχεία που ανακαλύφθηκαν και τον τελευταίο χρόνο προόδου. Εάν αυτές οι τιμές σταματήσουν να αλλάζουν σε επαναλαμβανόμενους κύκλους παρακολούθησης, αντιμετωπίστε την ιστορική διαδρομή ως σταματημένη και ακολουθήστε τον κλάδο σάρωσης στην Αντιμετώπιση προβλημάτων. Μην απορρίπτετε τα τρέχοντα αποτελέσματα καταγραφής και περιόδου σύνδεσης μόνο επειδή το παλαιότερο ιστορικό δεν είναι πλήρες.

<a id="read-the-first-server-status-report"></a>
## Διαβάστε την πρώτη αναφορά κατάστασης διακομιστή

1. Εκκινήστε κανονικά τον αποκλειστικό διακομιστή.
2. Περιμένετε για τον διακομιστή του παιχνιδιού και UE4SS για να ολοκληρώσετε την έναρξη.
3. Άνοιγμα RandomDayGuard's φάκελο τελικών αναφορών και επιλέξτε την πιο πρόσφατη αναγνώσιμη αναφορά κατάστασης διακομιστή.
4. Επιβεβαιώστε ότι η αναφορά περιέχει:
   - **Σύνοψη**
   - **Τι παρατήρησε ο Φρουρός**
   - **Τι σημαίνει**
   - **Τι παραμένει άγνωστο**
   - **Συνιστάται το επόμενο βήμα**
   - **Τεχνικό αρχείο**
5. Σε **Τι παρατήρησε ο Φρουρός**, επιβεβαιώστε τις τελευταίες εξελίξεις του κύκλου παρακολούθησης και τα ονόματα των αναφορών που είναι διαθέσιμα στο αρχείο καταγραφής, τη σάρωση, τη συσκευή αναπαραγωγής και την κάλυψη πηγής.
6. Αν το επόμενο βήμα λέει ότι δεν απαιτείται παρέμβαση, διατηρήστε την αναφορά ως το πρώτο επιτυχημένο αποτέλεσμα. Εάν ονομάσει μια πηγή που λείπει ή μια διαδικασία που έχει διακοπεί, ακολουθήστε αυτό ακριβώς το σύμπτωμα στο [Αντιμετώπιση προβλημάτων](%CE%91%CE%9D%CE%A4%CE%99%CE%9C%CE%95%CE%A4%CE%8F%CE%A0%CE%99%CE%A3%CE%97_%CE%A0%CE%A1%CE%9F%CE%92%CE%9B%CE%97%CE%9C%CE%86%CE%A4%CE%A9%CE%9D.md).

Η αναφορά ενδέχεται να συνδέεται με τεχνικά στοιχεία για μια βαθύτερη ανασκόπηση. Ένας κανονικός χειριστής μπορεί να διαβάσει πρώτα την αναφορά και να ανοίξει αυτές τις αναφορές μόνο όταν πρέπει να ελεγχθεί το απλό αποτέλεσμα.

<a id="understand-quiet-reports"></a>
## Κατανοήστε τις αθόρυβες αναφορές

Η δραστηριότητα του παίκτη, ο έλεγχος υπόθεσης και το Critical Guard βασίζονται σε συμβάντα. Ένας αθόρυβος διακομιστής δεν πρέπει να παράγει μια φανταστική συσκευή αναπαραγωγής, θήκη ή αποτυχία απλώς να γεμίσει ένα κανάλι. Το αναγνώσιμο αποτέλεσμα μπορεί να λέει ότι η πηγή ελέγχθηκε και τίποτα δεν ανήκε σε αυτήν την αναφορά.

Η ημερήσια συνάθροιση είναι διαφορετική: παρέχει μία αξιολόγηση ανά ημερομηνία αναφοράς χρησιμοποιώντας τις περιόδους σύνδεσης της ίδιας ημέρας, τρέχοντα θέματα αξιολόγησης, που διατηρούνται identity/case περιβάλλον, σάρωση προόδου και κενά πηγής που μπορεί πραγματικά να διαβάσει το Guard. Τα γεγονότα που απουσιάζουν από τα διαθέσιμα αρχεία διακομιστή παραμένουν άγνωστα αντί να εκτιμώνται.

<a id="test-one-ordinary-player-session"></a>
## Δοκιμάστε μια συνηθισμένη περίοδο λειτουργίας προγράμματος αναπαραγωγής

Αφού είναι τρέχουσα η πρώτη αναφορά κατάστασης διακομιστή:

1. Επιτρέψτε σε έναν γνωστό παίκτη να εγγραφεί και να αποχωρήσει κανονικά.
2. Περιμένετε για τον επόμενο κύκλο αναφοράς.
3. Ανοίξτε τη δραστηριότητα του προγράμματος αναπαραγωγής.
4. Επιβεβαιώστε ότι προσδιορίζει τον λογαριασμό ή το εμφανιζόμενο όνομα που είναι διαθέσιμο στο Guard, τους χρόνους συμμετοχής και αποχώρησης, το καθαρό ή ημιτελές αποτέλεσμα της περιόδου σύνδεσης, το προηγούμενο ιστορικό όταν είναι διαθέσιμο και μια επόμενη ενέργεια.

Η αναφορά περιόδου σύνδεσης πρέπει να περιέχει τα δεδομένα που παρατηρήθηκαν. Δεν θα πρέπει να αντικατασταθεί από μια λίστα ονομάτων αρχείων ή μια γενική δήλωση ότι υπάρχουν εγγραφές.
