# Kebijakan keamanan

> **Sumber kanonis bahasa Inggris:** [SECURITY.md](../../../SECURITY.md). Dokumentasi yang dilokalkan ini mempertahankan perintah, jalur, kunci, nilai status, hash, dan nama file yang tepat. Jika kata-kata teknisnya berbeda, gunakan sumber bahasa Inggris.


<a id="report-a-vulnerability-privately"></a>
## Laporkan kerentanan secara pribadi

Gunakan [GitHub pelaporan kerentanan pribadi](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) untuk mengirim laporan rahasia ke pemilik repositori. Jika formulir tersebut tidak tersedia, gunakan [profil GitHub publik pemilik](https://github.com/Xixicor) untuk meminta saluran kontak pribadi tanpa menyertakan detail kerentanan.

Jangan membuka terbitan publik yang berisi langkah-langkah eksploitasi, kredensial, jalur server pribadi, pengidentifikasi pemain, `Admin.ini`, Data tersimpan, URL webhook, atau file bukti langsung.

<a id="include-useful-evidence"></a>
## Sertakan bukti yang berguna

Berikan:

- versi atau penerapan RandomDayGuard yang terpengaruh;
- komponen yang terpengaruh dan perilaku aman yang diharapkan;
- langkah reproduksi minimal menggunakan perlengkapan yang disanitasi;
- dampak yang diamati dan apakah dampak tersebut dapat diulang; dan
- setiap usulan mitigasi yang tidak mengekspos data pribadi.

Jangan mengirimkan rahasia nyata. Ganti jalur pribadi, pengidentifikasi akun, nama host, dan token dengan placeholder yang jelas sambil mempertahankan struktur yang diperlukan untuk mereproduksi masalah.

<a id="expect-review-first-handling"></a>
## Harapkan penanganan peninjauan terlebih dahulu

Laporan adalah bukti untuk peninjauan pengelola, bukan otorisasi untuk mengakses server, menguji target aktif, memublikasikan detail eksploitasi, atau melemahkan default yang gagal-ditutup. Pemilik akan memvalidasi cakupan dan mengoordinasikan pengungkapan apa pun melalui laporan pribadi.
