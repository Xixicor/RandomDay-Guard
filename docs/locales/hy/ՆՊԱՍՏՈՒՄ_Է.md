# Նպաստում է

> **Կանոնական անգլերեն աղբյուր:** [CONTRIBUTING.md](../../../CONTRIBUTING.md). Այս տեղայնացված փաստաթուղթը պահպանում է ճշգրիտ հրամաններ, ուղիներ, բանալիներ, կարգավիճակի արժեքներ, հեշեր և ֆայլերի անուններ: Եթե ​​տեխնիկական ձևակերպումը տարբերվում է, օգտագործեք անգլերեն աղբյուրը:


RandomDayGuard ընդունում է կենտրոնացված, վերարտադրելի բարելավումներ վերլուծիչների, փաստաթղթերի, թեստերի և հանրային անվտանգ վավերացման համար: Պահպանեք յուրաքանչյուր փոփոխություն սահմանափակված հանրային նախագծի պայմանագրով և պահպանեք առաջին վերանայման պահվածքը. պահակը պետք է հեռանա `Admin.ini` անփոփոխ, երբ անհրաժեշտ անվտանգության ստուգումը հնարավոր չէ հաստատել:

<a id="prepare-a-safe-workspace"></a>
## Պատրաստեք անվտանգ աշխատանքային տարածք

1. Տեղադրեք կամ կլոնավորեք պահոցը և ստեղծեք կենտրոնացված մասնաճյուղ:
2. Տեղադրեք Python 3-ի աջակցվող թարգմանիչ: Տեղադրեք Lua կոմպիլյատոր, երբ փոխեք Lua so `luac -p` կարող է ստուգել շարահյուսությունը:
3. Կարդացեք [փաստաթղթերի տուն](%D5%93%D4%B1%D5%8D%D5%8F%D4%B1%D4%B9%D5%82%D4%B9%D4%B5%D5%90.md), [ճարտարապետություն](%D5%83%D4%B1%D5%90%D5%8F%D4%B1%D5%90%D4%B1%D5%8A%D4%B5%D5%8F%D5%88%D5%92%D4%B9%D5%85%D5%88%D5%92%D5%86.md) և [ապացույցների սահման](%D4%B1%D5%8A%D4%B1%D5%91%D5%88%D5%92%D5%85%D5%91%D5%86%D4%B5%D5%90%D4%BB_%D5%8D%D4%B1%D5%80%D5%84%D4%B1%D5%86.md) այն տարածքի համար, որը դուք կփոխեք:
4. Ստուգեք `git status` նախքան խմբագրելն ու պահպանել անկապ աշխատանքը:
5. Օգտագործեք միայն սինթետիկ կամ ախտահանված հարմարանքներ:

Երբեք մի ներկայացրեք մասնավոր սերվերի մատյաններ, Պահված պանակներ, նվագարկիչների նույնացուցիչներ, `Admin.ini`, մասնավոր ծանուցման վերջնակետեր, հավատարմագրեր, մասնավոր ուղիներ, գործարկման ժամանակի ելք կամ պատճենված կենդանի ապացույցներ:

<a id="make-a-focused-change"></a>
## Կատարեք կենտրոնացված փոփոխություն

- Հետևեք գոյություն ունեցող անվանմանը, ձևաչափմանը, անվտանգության ստուգումներին և մոդուլի սեփականությանը:
- Պահպանեք մեկ կանոնական փաստաթղթերի սեփականատեր յուրաքանչյուր ընթացակարգի կամ ճշգրիտ փաստի համար:
- Թարմացրեք օգտվողի փաստաթղթերը և օրինակները, երբ վարքագիծը կամ հանրային ելքը փոխվում է:
- Ավելացրեք ռեգրեսիայի թեստ վրիպակների շտկման համար, երբ դա գործնական է:
- Թեստային անցում կատարելու համար մի թուլացրեք հաշվի հաստատումը, վստահելի հաշվի պաշտպանությունը, պահուստավորման հաստատումը, արտաքին փոփոխության հայտնաբերումը, պահված ֆայլերի համեմատությունը, վերականգնումը կամ միայն վերանայման կանխադրված կարգավորումները:

<a id="run-the-relevant-checks"></a>
## Գործարկել համապատասխան ստուգումները

Միայն փաստաթղթերի փոփոխությունների համար գործարկեք՝

```powershell
python -B tools\generate_documentation_audit.py --check
python -B -m unittest discover tests -p "test_documentation*.py"
git diff --check
```

Աղբյուրի, կազմաձևման, փաթեթավորման կամ թեստային փոփոխությունների համար կատարեք նաև կիրառելի ստուգումները [Վավերացում և թողարկման վերանայում](%D5%8E%D4%B1%D5%8E%D4%B5%D5%90%D4%B1%D5%91%D5%88%D5%92%D5%84_%D4%B5%D5%92_%D4%B9%D5%88%D5%82%D4%B1%D5%90%D4%BF%D5%88%D5%92%D5%84.md), ներառյալ Lua-ի շարահյուսական ստուգումները, պահեստի վավերացումը, հանրային խողովակաշարի թեստերը և ամբողջական միավորի թեստային փաթեթը: Հաղորդել յուրաքանչյուր բաց թողնված կամ անհասանելի ստուգման մասին. մի նկարագրեք այն որպես անցած:

<a id="submit-the-change-for-review"></a>
## Փոփոխությունը ներկայացրեք վերանայման

Բացեք կենտրոնացված ձգման հարցումը միայն ամբողջական տարբերությունը դիտելուց հետո: Ներառել՝

- խնդիրը և նախատեսված վարքագիծը;
- ճշգրիտ ֆայլերը և հանրային պայմանագրերը փոխվել են;
- հրամանները գործարկվում են և դրանց արդյունքները;
- գաղտնիության, համատեղելիության և կիրառման ազդեցությունը; և
- մնացած սահմանափակումներ կամ հետագա աշխատանք:

Մի ներառեք ստեղծված գործարկման ժամանակի ապացույցները կամ թողարկման արխիվները, եթե փոփոխությունը բացահայտորեն չի պահանջում և չի վավերացնում դրանք: Ներդրումը չի թույլատրում թողարկում, տեղակայում, ուղիղ սերվերի փորձարկում, հարկադիր գործողություն կամ հրապարակում երրորդ կողմի կայքում:

Հաղորդեք խոցելիության մասին [անվտանգության մասնավոր երթուղին](%D4%B1%D5%86%D5%8E%D5%8F%D4%B1%D5%86%D4%B3%D5%88%D5%92%D4%B9%D5%85%D5%88%D5%92%D5%86.md), ոչ հանրային խնդիր կամ սովորական ձգման հարցում:
