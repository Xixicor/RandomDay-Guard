# Վավերացում և թողարկում

> **Կանոնական անգլերեն աղբյուր:** [VALIDATION_AND_RELEASE.md](../../VALIDATION_AND_RELEASE.md). Այս տեղայնացված փաստաթուղթը պահպանում է ճշգրիտ հրամաններ, ուղիներ, բանալիներ, կարգավիճակի արժեքներ, հեշեր և ֆայլերի անուններ: Եթե ​​տեխնիկական ձևակերպումը տարբերվում է, օգտագործեք անգլերեն աղբյուրը:


Այս էջը ներդրողների և թողարկումների սպասարկողների համար է: Սերվերի օպերատորները կարիք չունեն գործարկել այս հրամանները՝ տեղադրելու համար RandomDayGuard.

<a id="user-visible-proof"></a>
## Օգտատիրոջ տեսանելի ապացույց

Թողարկումը հասկանալի է, երբ նոր օպերատորը կարող է տեղադրել այն, գտնել սերվերի կարգավիճակի առաջին հաշվետվությունը, տարբերակել հաշվետվության հինգ երթուղիները և հետևել մեկ հստակ գործողության աշխատանքային օրինակից: Ընթերցողի առաջադրանքները չպետք է պահանջեն Git, PowerShell, Python կամ checksum գիտելիքներ:

<a id="contributor-checks"></a>
## Աջակցողի ստուգումներ

```powershell
python -B tools/validate_repo.py
python -B tools/test_public_pipeline.py
python -B -m unittest discover tests
```

Երբ `luac` հասանելի է՝

```powershell
luac -p RandomDayGuard/Scripts/main.lua
luac -p RandomDayGuard/Scripts/public_pipeline.lua
```

Lua ամրագրման թեստերը ներառում են բեռնիչը, ժամանակացույցը, հաշվետվության երթուղիները և կամընտիր Admin.ini գրեք գործարքը: Կիրառման հարմարանքները օգտագործում են միայն ժամանակավոր ֆայլեր և ստուգում են ինքնությունը, վստահելի հաշվի մերժումը, շեմերը, պահուստավորումը, միաժամանակ փոփոխության մերժումը, հետադարձ կապը և հետադարձումը:

<a id="package-proof"></a>
## Փաթեթի ապացույց

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

- Բոլոր տարբերակի նշիչները համընկնում են `VERSION`.
- `releases/`.
- ZIP պարունակում է կանոնական `RandomDayGuard/Scripts/main.lua` ուղի և փոքրատառերի տարբերակով բեռնիչ չկա:
- Գործարկման ժամանակի ելքը, մասնավոր կոնֆիգուրացիան, հավատարմագրերը, տեղական ուղիները, քեշերը և փորձնական արտեֆակտները բացառված են:
- Հանրային կոնֆիգուրացիան մնում է միայն վերանայման դեպքում, երբ կիրառումն անջատված է:
- Հինգ մշակված հաշվետվության օրինակները համահունչ են երթուղու սեփականությանը և թողարկման փորձարկման սարքին:
- ZIP բայթերը որոշիչ են և համընկնում են `CHECKSUMS.sha256`.
- Տեղական փաստաթղթերի բոլոր հղումները և 27 տեղային մուտքի էջերը վավերացվում են:

<a id="avoid-validation-environment-pitfalls"></a>
## Խուսափեք վավերացման միջավայրի որոգայթներից

- Պահեստում գրելու ստուգումները հաջորդաբար կատարեք` ժամանակավոր ֆայլերի վեճերից խուսափելու համար:
- Windows-ում կրկնօրինակ բեռնիչների առկայությունը ստուգելիս ստուգեք արխիվացված անդամների անունները կամ թվարկված ուղիների ուղղագրությունը, այլ ոչ թե մեծատառերի անզգույշ ֆայլերի որոնումը:
- Բացակայում է `luac` հրամանը կամ Lua runtime-ը անհասանելի հնարավորություն է, այլ ոչ թե անցնող շարահյուսություն կամ գործարկման ժամանակի թեստ:
- Մի սարքավորումն ապացուցում է միայն իր մոդելավորված մուտքերը: Այն չի ապացուցում, որ կենդանի սերվերը ընթացիկ հաշվետվություն է պատրաստել:
- Գրանցեք հրամանների ժամանակի վերջնաժամկետը և մասնակի ելքը` ավարտված լինելու փոխարեն:

## Վերականգնել պահեստի անհաջող վավերացումը

Սկսեք առաջին հաղորդված ուղուց կամ պայմանագրից: Ուղղեք այդ տարրը, նորից կատարեք նեղ թեստը, ապա նորից գործարկեք ամբողջական մատրիցը: Մի թաքցրեք բացակայող հնարավորությունը՝ հեռացնելով այն պահանջող թեստը:

<a id="known-limits-and-release-decision"></a>
## Հայտնի սահմանափակումներ և թողարկման որոշում

Տեղական ստուգումները ապացուցում են աղբյուրի, հարմարանքների, փաթեթի և փաստաթղթերի պայմանագրերը: Սերվերի հատուկ տեղադրումը, կայունության երկարատև պատուհանը կամ հաճախորդի ցուցադրումը պահանջում է առանձին ինտեգրման արդյունք: Գրանցեք այդ արդյունքը իր կառուցման, կազմաձևման, տևողության և դիտարկված արդյունքի հետ նախքան համապատասխան պահանջ ներկայացնելը:
