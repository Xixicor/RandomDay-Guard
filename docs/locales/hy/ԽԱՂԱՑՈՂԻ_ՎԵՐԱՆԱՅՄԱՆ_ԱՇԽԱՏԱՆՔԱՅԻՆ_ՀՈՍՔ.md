# Խաղացողի վերանայման աշխատանքային հոսք

> **Կանոնական անգլերեն աղբյուր:** [PLAYER_REVIEW_WORKFLOW.md](../../PLAYER_REVIEW_WORKFLOW.md). Այս տեղայնացված փաստաթուղթը պահպանում է ճշգրիտ հրամաններ, ուղիներ, բանալիներ, կարգավիճակի արժեքներ, հեշեր և ֆայլերի անուններ: Եթե ​​տեխնիկական ձևակերպումը տարբերվում է, օգտագործեք անգլերեն աղբյուրը:


Օգտագործեք այս էջը մեկ խաղացողի, հաշվի կամ գործի համար: Նպատակը վերարտադրվող վերանայման որոշումն է, ոչ թե ավտոմատացված մեղադրանքը:

<a id="quick-path"></a>
## Արագ ճանապարհ

1. Բացեք `runtime/final_logs/player_activity_latest.json`.
2. Հաստատեք երթուղու կարգավիճակը `runtime/final_logs/route_proof.json`.
3. Նշեք, թե որ դիտարկումներն են ընթացիկ և որոնք` պատմական:
4. Ստուգեք նշված ինքնությունը և աշխատաշրջանի աղբյուրի հղումները:
5. Դիտել `case_review_latest.json` երբ գոյություն ունի փոխկապակցված դեպք:
6. Գրանցեք անհայտները և `does_not_prove` նախքան գործողություն ընտրելը:
7. Կարգավորումը թողեք անջատված, քանի դեռ հաստատված չեն առանձին կիրառման դարպասները:

<a id="1-confirm-route-proof"></a>
## 1. Հաստատեք երթուղու ապացույցը

Մեկնաբանեք նվագարկչի երթուղին այսպես.

| Կարգավիճակ | Գործողություն |
|---|---|
| `full` | Շարունակեք, մինչ դեռ վերանայում եք աղբյուրի սահմանաչափերը: |
| `limited_expected_empty` | Շարունակեք միայն փաստացի առկա թեմաներով; մի հորինեք բացակայող խաղացող կամ պատյան: |
| `missing` | Դադարեցրեք նվագարկչի որոշումը և շտկեք երթուղին: |

Առողջ ժամանակացույցը չի փոխարինում երթուղու հաստատմանը:

<a id="2-establish-identity"></a>
## 2. Հաստատեք ինքնությունը

Նախընտրեք մաքուր հաշվի նույնացուցիչ, որը հաստատված է սերվերի կողմից բացահայտված ինքնության ապացույցներով և, որտեղ առկա է, PlayerData ֆայլերի անուններ: Պահպանեք հում աղբյուրի հղումը:

Մի պարտադրել հետևյալից.

- միայն ցուցադրվող անուն;
- անուն, որը տեսանելի է ծանուցման կամ հոսթինգի վահանակում;
- ժամանակային նմանություն;
- չքարտեզագրված կամ թույլ վստահության ինքնություն;
- պատմական զեկույց առանց ընթացիկ հաստատման:

<a id="3-separate-current-from-historical"></a>
## 3. Առանձնացրեք ընթացիկը պատմական

Ընթացիկ ապացույցները նկարագրում են ակտիվ հաշվետվությունների պատուհանը կամ սերվերի դարաշրջանը: Պատմական ապացույցները կարող են բացատրել օրինաչափությունը, սակայն այն չի կարող լուռ լրացնել ընթացիկ պատուհանի բացերը:

Արձանագրեք երկու շրջանակներն անկախ`

```text
Current observations:
Current source references:
Historical context:
Historical source references:
```

<a id="4-review-observations-and-interpretation"></a>
## 4. Վերանայեք դիտարկումները և մեկնաբանությունները

Կարդացեք այս հաշվետվության բաժինները հստակ.

```text
observed
interpretation
unknown
does_not_prove
next_action
source_references
```

Վերաբացեք նշված կառուցվածքային ապացույցները ցանկացած էական որոշման համար: Թարգմանությունը նավարկություն և բացատրություն է, այլ ոչ թե նոր ապացույց:

<a id="5-calibrate-the-decision"></a>
## 5. Ստուգեք որոշումը

| Որոշում | Օգտագործել, երբ |
|---|---|
| `INFO` | Նորմալ կամ ցածր համատեքստի դիտարկում: |
| `WATCH` | Թույլ կամ թերի ազդանշանն արժե վերահսկել: |
| `REVIEW` | Կապված ապացույցները պահանջում են ադմինիստրատորի դատողություն: |
| `BAN-ELIGIBLE` | Մաքուր ինքնությունը և կազմաձևված ապացույցների շեմերը բավարարված են. գրել դարպասները դեռ գործում են: |
| `AUTO-BANNED` | Կարգավորումը հստակորեն միացված է, և կրկնօրինակում, գրում, հետադարձ ընթերցում և աուդիտ հաջողվել է: |

Որևէ որոշման պիտակ չի ապացուցում մեղքը կամ դիտավորությունը:

<a id="6-apply-the-evidence-boundary"></a>
## 6. Կիրառեք ապացույցների սահմանը

Խափանումներ, նորից միացումներ, զգուշացումներ, object/class նշանները և դեպքերի խմբավորումը կարող են աջակցել վերանայմանը: Միայնակ, դրանք չեն ապացուցում խաբեությունը, գողությունը, կրկնօրինակումը, սեփականության իրավունքը, ուղղակի վնասը կամ միջադեպի պատճառաբանությունը:

Եթե նույնականացումը, վերլուծությունը, պահուստավորումը, գրելը, հետադարձ կապը կամ հետադարձ կապը թույլ են կամ ձախողվում են, ապա կիրառումը պետք է չփակվի:

<a id="review-note-template"></a>
## Դիտեք նշումների ձևանմուշը

```text
Review time:
Route proof status:
Coverage status:
Account ID:
Display name as observed:
Identity confidence and source:
Current observations:
Historical context:
Interpretation:
Unknown:
Does not prove:
Decision:
Next action:
Source references:
Operator:
```
