# Անվտանգության քաղաքականություն

> **Կանոնական անգլերեն աղբյուր:** [SECURITY.md](../../../SECURITY.md). Այս տեղայնացված փաստաթուղթը պահպանում է ճշգրիտ հրամաններ, ուղիներ, բանալիներ, կարգավիճակի արժեքներ, հեշեր և ֆայլերի անուններ: Եթե ​​տեխնիկական ձևակերպումը տարբերվում է, օգտագործեք անգլերեն աղբյուրը:


<a id="report-a-vulnerability-privately"></a>
## Հաղորդել խոցելիության մասին մասնավոր կերպով

Օգտագործեք [GitHub մասնավոր խոցելիության մասին հաշվետվություն](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) պահոցի սեփականատիրոջը գաղտնի հաշվետվություն ուղարկելու համար: Եթե ​​այդ ձևը հասանելի չէ, օգտագործեք [սեփականատիրոջ հանրային GitHub պրոֆիլ](https://github.com/Xixicor) մասնավոր կոնտակտային ալիք խնդրելու համար՝ առանց խոցելիության մանրամասները ներառելու:

Մի բացեք հանրային խնդիր, որը պարունակում է շահագործման քայլեր, հավատարմագրեր, մասնավոր սերվերի ուղիներ, խաղացողի նույնացուցիչներ, `Admin.ini`, Պահված տվյալներ, վեբ-կապերի URL-ներ կամ կենդանի ապացույցների ֆայլեր:

<a id="include-useful-evidence"></a>
## Ներառել օգտակար ապացույցներ

Տրամադրել՝

- ազդակիր RandomDayGuard տարբերակ կամ ստանձնել;
- ազդակիր բաղադրիչը և սպասվող անվտանգ վարքագիծը;
- նվազագույն վերարտադրման քայլեր` ախտահանված սարքերի միջոցով;
- դիտարկվող ազդեցությունը և արդյոք այն կրկնելի է. և
- ցանկացած առաջարկվող մեղմացում, որը չի բացահայտում մասնավոր տվյալները:

Մի ուղարկեք իրական գաղտնիքներ: Փոխարինեք մասնավոր ուղիները, հաշվի նույնացուցիչները, հոսթների անունները և նշանները հստակ տեղապահներով՝ պահպանելով խնդիրը վերարտադրելու համար անհրաժեշտ կառուցվածքը:

<a id="expect-review-first-handling"></a>
## Ակնկալվում է առաջին վերանայում

Զեկույցը վկայում է սպասարկողի վերանայման համար, այլ ոչ թե սերվեր մուտք գործելու թույլտվություն, կենդանի թիրախ փորձարկելու, շահագործման մանրամասներ հրապարակելու կամ ձախողմամբ փակված կանխադրույթները թուլացնելու համար: Սեփականատերը կհաստատի շրջանակը և կհամակարգի ցանկացած բացահայտում մասնավոր հաշվետվության միջոցով:
