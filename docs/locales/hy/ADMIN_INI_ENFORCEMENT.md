# Admin.ini կիրառում

> **Կանոնական անգլերեն աղբյուր:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). Այս տեղայնացված փաստաթուղթը պահպանում է ճշգրիտ հրամաններ, ուղիներ, բանալիներ, կարգավիճակի արժեքներ, հեշեր և ֆայլերի անուններ: Եթե ​​տեխնիկական ձևակերպումը տարբերվում է, օգտագործեք անգլերեն աղբյուրը:


RandomDayGuard-ը չի փոխում սերվերի արգելքի ցանկը իր լռելյայն կարգավորումներում: Այն ստեղծում է միայն հաշվետվություններ, որպեսզի ադմինը վերանայի: Այս էջը բացատրում է կամընտիր ավտոմատ արգելքի ցանկի թարմացումը ադմինների համար, ովքեր միտումնավոր միացրել են այն:

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## Ինչ է ստուգում Պահակը նախքան արգելքի ցուցակը փոխելը

Guard-ն արգելք է ավելացնում միայն այն դեպքում, երբ ստորև ներկայացված յուրաքանչյուր պատասխանը **այո**:

1. Արդյո՞ք ընթացիկ ապացույցները բավարար վստահությամբ բացահայտեցին մեկ կոնկրետ հաշիվ:
2. Ադմինիստրատորի կողմից նշված հաշիվը ոչ մոդերատոր է, ոչ էլ հաշիվ:
3. Հաշիվն արդեն արգելված ցանկում չէ՞:
4. Հաշիվը հասե՞լ է կազմաձևված ավտոմատ գործողությունների միավորին:
5. Կարո՞ղ է Պահակը կարդալ ընթացիկ `Admin.ini` և պահե՞լ նույնական կրկնօրինակը:
6. Արվել է `Admin.ini` մնա անփոփոխ, մինչ Գվարդիան պատրաստում էր թարմացումը:
7. Պահելուց հետո ամբողջական ֆայլը ճշգրտորեն համապատասխանում է նախատեսված արդյունքին:

Եթե որևէ պատասխան **ոչ** կամ չի կարող ստուգվել, Գարդը հեռանում է `Admin.ini` անփոփոխ է և իր հաշվետվություններում նշում է պատճառը: Եթե ​​պահպանումը սկսվում է, բայց վերջնական ստուգումը ձախողվում է, Guard-ը վերականգնում է ստուգված կրկնօրինակը:

<a id="file-format"></a>
## Ֆայլի ձևաչափ

`Admin.ini` պետք է ստանա միայն մաքուր արգելքի տողեր.

```ini
BannedPlayer=<ID>
```

- Անուններ չկան:
- Մեկնաբանություններ չկան:
- Պատճառներ չկան:
- Ածանցներ չկան:

<a id="safe-defaults"></a>
## Ապահով լռելյայն

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## Արգելել ID-ի աղբյուրը

Լավագույն աղբյուրը՝

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

Գործարկման ժամանակը ընդունում է կամ ամբողջությամբ թվային ID կամ ամբողջական փաստաթղթավորված `<digits>_+_|<non-space token>` կապի ձևը և դրանից բխում է արգելքի թվային ID-ն: Անհայտ վերջածանցով կամայական թվային նախածանցները մերժվում են. դրանք չեն կրճատվել որպես արգելքի ID:

Ճիշտ՝

```ini
BannedPlayer=2535422284688820
```

Սխալ է՝

```ini
BannedPlayer=ExamplePlayer
```

Նաև սխալ է՝

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## Ճշգրիտ կարգավորումներ Պահակային ստուգումներ

Այս կարգավորումներն իրականացնում են վերը նկարագրված ստուգումները: Յուրաքանչյուր թվարկված պայման պետք է լինի ճշմարիտ.

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

Եթե որևէ պայման կեղծ է կամ չի կարող ստուգվել, Գվարդը թողնում է արգելքի ցուցակը անփոփոխ և արձանագրում, թե ինչն է խանգարել դրան:

<a id="transaction-safety"></a>
## Գործարքի անվտանգություն

Միակը `Admin.ini` մուտացիայի ուղին կատարում է հետևյալ քայլերը հերթականությամբ.

1. Կարդացեք և կառուցվածքայինորեն հաստատեք հեղինակավոր բայթերը:
2. Վերցրեք մոդերատորը, վստահելի և գոյություն ունեցող արգելված վիճակը նույն նկարից:
3. Գրեք եզակի կրկնօրինակում `runtime/backups/` և ստուգեք այն բայթի դիմաց:
4. Կրկին կարդալ `Admin.ini` փոխարինումից անմիջապես առաջ և մերժեք ցանկացած արտաքին փոփոխություն:
5. Գրեք թեկնածուին կազմաձևված վերահսկվող փոխարինման ճանապարհով:
6. Պահանջեք ամբողջական ընթերցման բայթեր, որպեսզի հավասարվեն ամբողջական թեկնածու բայթերին:
7. Ընթերցման ձախողման դեպքում վերականգնեք ստուգված կրկնօրինակը միայն այն ժամանակ, երբ ընթացիկ ֆայլը դեռևս Guard-ի կողմից գրված ճշգրիտ թեկնածուն է: Եթե ​​մեկ այլ գրող փոխում է այն, Guard-ը հրաժարվում է վերադարձնել, այլ ոչ թե վերագրել անհայտ արտաքին բայթերը:

Կրկնօրինակ ID-ները անզոր են. երկրորդ տող և երկրորդ կրկնօրինակ չի գրվում: Պահուստային անունները ներառում են ժամանակի դրոշմ, աղբյուր-բայթ մատնահետք և մաքուր ID, այնպես որ առանձին փորձերը չեն կարող կիսել հին մեկ վայրկյանանոց ֆայլի անունը:

<a id="local-regression-proof"></a>
## Տեղական ռեգրեսիայի ապացույց

`tests/lua/enforcement_runtime_test.lua` բեռնում է առաքված բեռնիչը մեկ անգամ, այնուհետև գործարկում է իր իրական տեղականը `append_ban()` փակում պահեստի տակ գտնվող մեկուսացված սինթետիկ ֆայլերի դեմ `.tmp/` գրացուցակ: Այն ընդգրկում է տեղադրումը, կրկնակի անզորությունը, moderator/trusted մերժում, թույլ և սխալ ձևով ինքնության մերժում, բայթ-ճշգրիտ պահուստավորման ստուգում, միաժամանակյա փոփոխության մերժում, անհաջող ընթերցումից հետո հաջող վերադարձ և հետգրելու արտաքին փոփոխությունը վերագրանցելու մերժում: Նրա ֆայլային համակարգի փաթաթանները մերժում են ցանկացած մուտացիա՝ հարմարանքների արմատից դուրս; չկա իրական սերվերի ուղի կամ իրական `Admin.ini` օգտագործվում է:

Գործարկել այն `python tools/test_public_pipeline.py`: Սարքավորումների անցագիրը ապացուցում է միայն տեղական գործարքի վարքագիծը: Այն չի թույլատրում ուժի մեջ մտնելը, չի թույլատրում արտադրական գրությունը կամ հաստատում է հյուրընկալողի հատուկ թույլտվությունները:
