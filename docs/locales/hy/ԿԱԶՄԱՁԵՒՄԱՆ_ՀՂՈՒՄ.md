# Կազմաձևման հասկացություններ

> **Կանոնական անգլերեն աղբյուր:** [CONFIG_REFERENCE.md](../../CONFIG_REFERENCE.md). Այս տեղայնացված փաստաթուղթը պահպանում է ճշգրիտ հրամաններ, ուղիներ, բանալիներ, կարգավիճակի արժեքներ, հեշեր և ֆայլերի անուններ: Եթե ​​տեխնիկական ձևակերպումը տարբերվում է, օգտագործեք անգլերեն աղբյուրը:


Այս բացատրությունը նկարագրում է, թե ինչ է վերահսկում յուրաքանչյուր հիմնական կազմաձևման տարածք, երբ այն աշխատում է և ինչպես է այն փոխազդում ապացույցների և անվտանգության դարպասների հետ: Նրան չեն պատկանում դաշտերի ճշգրիտ կատալոգը կամ պրոֆիլի ընթացակարգերը:

Խնդիրներին ուղղված նախադրյալների և անվտանգ փոփոխության քայլերի համար օգտագործեք [`CONFIG_PROFILES.md`](%D4%BF%D4%B1%D5%90%D4%B3%D4%B1%D5%8E%D5%88%D5%90%D4%B5%D5%94_%D5%8A%D5%90%D5%88%D5%96%D4%BB%D4%BC%D5%86%D4%B5%D5%90%D4%B8.md): Յուրաքանչյուր ճշգրիտ աղբյուրի դաշտի, լռելյայն, տեսակի, անփոփոխ, ելքային էֆեկտի և վերականգնման կանոնների համար օգտագործեք ստեղծված [`CONFIG_FIELD_CATALOG.md`](%D4%BF%D4%B1%D5%90%D4%B3%D4%B1%D5%8E%D5%88%D5%90%D4%B5%D4%BC_%D4%B4%D4%B1%D5%87%D5%8F%D4%B1%D5%85%D4%BB%D5%86_%D4%BF%D4%B1%D5%8F%D4%B1%D4%BC%D5%88%D4%B3.md); վավերացնողը պահանջում է մեկ տող այնտեղ յուրաքանչյուր առաքված `config.lua` տերևային դաշտ:

<a id="reading-this-page"></a>
## Այս էջը կարդալը

Յուրաքանչյուր կազմաձևման տարածք պատասխանում է՝

```text
What it controls
When it runs
What to check
What can go wrong
```

<a id="top-level-safety"></a>
## Անվտանգության բարձր մակարդակ

| Ընտրանք | Լռելյայն | Իմաստը |
|---|---:|---|
| `enabled` | `true` | Գլխավոր անջատիչ պահակի համար |
| `enforcement.review_only_mode` | `true` | Record/recommend միայն |
| `enforcement.auto_ban` | `false` | Լռելյայն ինքնաբերաբար մի արգելեք |
| `enforcement.write_admin_ini` | `false` | Մի գրեք Admin.ini լռելյայն |

Պահպանեք դրանք ապահով, քանի դեռ սերվերի սեփականատերը չի վերանայել արդյունքները:

<a id="saved"></a>
## `saved`

Վերահսկում է, թե ինչպես է պահակը գտնում սերվերը `Saved/` թղթապանակ և ֆայլերի որ ընտանիքները կարող է սկանավորել:

Օգտագործել, երբ՝

```text
Saved root auto-detection fails.
World folder changed.
Provider or container path is unusual.
```

Ստուգեք՝

```text
runtime/saved_path_probe.json
RandomDayGuard/SavedRoot.txt
```

Կանոն՝

```text
SavedRoot.txt -> AbioticFactor/Saved
not -> Worlds/<WorldName>
```

<a id="log_tail"></a>
## `log_tail`

Կառավարում է կենդանի մատյանների ընթերցումը:

Օգտակար ընտրանքներ.

| Ընտրանք | Ապահով արժեք | Ինչու |
|---|---|---|
| `enabled` | `true` | Անհրաժեշտ է ուղիղ պաշտպանության համար |
| `start_at_end_on_first_run` | `true` | Խուսափում է հին տեղեկամատյաններից որպես կենդանի իրադարձություններ |
| `tail_backup_logs` | `false` | Պահուստային մատյանները պատմություն են, ոչ թե կենդանի |
| `max_lines_per_poll` | սահմանափակված | Արձագանքում է հարցումների շրջանակը |

Ստուգեք՝

```text
runtime/log_offsets.tsv
runtime/evidence/session_events.jsonl
runtime/current/poll_status.json
```

<a id="runtime"></a>
## `runtime`

Վերահսկում է հարցումները և բյուջեները:

Առողջության հիմնական կանոնը՝

```text
poll_id increases
poll_in_flight returns false
poll_scheduled is true
```

Ստուգեք՝

```text
runtime/current/poll_status.json
```

Եթե `poll_id` կանգ է առնում, ինչ-որ բան արգելափակում է հանգույցը:

<a id="source_accounting"></a>
## `source_accounting`

Վերահսկում է ակնհայտ ապացույցների աղբյուրի ծածկույթն ու շրջանակը:

| Բանալին | Լռելյայն | Իմաստը |
|---|---:|---|
| `enabled` | `true` | Գրում է աղբյուրի հաշվառում հանրային երթուղու հաշվետվությունների համար: |
| `require_terminal_status` | `true` | Յուրաքանչյուր աղբյուրից պահանջում է բացահայտել հստակ տերմինալ կամ թերի վիճակը: |
| `distinguish_current_from_historical` | `true` | Առանձին պահում է ընթացիկ և պատմական ապացույցները: |
| `slow_world_scan_blocks_current_reports` | `false` | Թույլ է տալիս ընթացիկ հաշվետվություններին նշել, որ սահմանափակ աշխարհի սկանավորումը հետաձգված է կամ մասնակի: |
| `changed_file_manifest` | ելակետային մանիֆեստի ուղին | Հղում օգտագործվում է սահմանափակված historical/world հաշվառում: |

Աղբյուրի վիճակներն են `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied` կամ `error`.

Կարգավորում `source_accounting.enabled = false`-ը լուռ չի հեռացնում կարգավիճակի ելքը: Խողովակաշարը դեռ գրում է `runtime/final_logs/source_accounting_latest.json` `enabled=false`, `status="unavailable"` և `disabled_reason="source_accounting_disabled"`: Այն նաև գրում է պատմական կարգավիճակի գրառումը անհասանելի հաշվառմամբ։ Քանի որ աղբյուրի հաշվառումը հաշվետվության պայմանագրի մաս է կազմում, յուրաքանչյուր երթուղի ձախողվում է `missing`; Երբ հաշվառումն անջատված է, ոչ մի երթուղի չի համարվում ավարտված:

<a id="reports"></a>
## `reports`

Կառավարում է ընդհանուր տեղական հաշվետվությունների խողովակաշարը:

Լռելյայնները միացնում են բոլոր հինգ երթուղիները և գրում `runtime/final_logs`:

```text
server_status
daily_rollup
player_activity
case_review
critical_guard
```

Յուրաքանչյուր երթուղի պետք է գրի կառուցվածքային և թարգմանված արդյունք և ապացույց `route_proof.json`: Երթուղին անջատելը առաջացնում է `missing` ապացույց, այլ ոչ թե ձևացնել, որ այն ավարտված է:

<a id="notification"></a>
## `notification`

Ընդհանուր տեղական ֆայլի ելքային արկղ կամընտիր: Այն լռելյայն անջատված է և ոչինչ չի ուղարկում արտաքին մատակարարին:

Լռելյայն`

```lua
notification = {
    enabled = false,
    mode = "local_file_outbox",
    include_expected_empty = false,
},
```

Ծանուցման յուրաքանչյուր երթուղի լռելյայն անջատված է: Երբ միտումնավոր միացված է, ելքային արկղը կարող է սպառել միայն ավարտված թարգմանված հաշվետվությունը `route_proof.json` գրված է: Տեղական ապացույցներն ու զեկույցները մնում են հեղինակավոր: Հատուկ մատակարարի առաքումը, առաքման վերջնակետերը, հավատարմագրերը և կամուրջները հանրային անկախ դիտորդական պայմանագրի մաս չեն:

<a id="scanning"></a>
## `scanning`

Կառավարում է բազային սկանավորումը, ստուգման կետը և փոփոխված ֆայլի թարմացումը:

Օգտագործել, երբ՝

```text
building first world baseline
resuming after crash
refreshing changed files later
```

Ստուգեք՝

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/baselines/file_manifest.tsv
```

Կարևոր կարգավորումներ.

```lua
scanning = {
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
    changed_file_detection = true,
},
```

<a id="forensic_rollup"></a>
## `forensic_rollup`

Կառավարում է արագ ամենօրյա վերբեռնման փաթեթը և վերջնական պարզ լեզվով մատյանները:

Ելքներ՝

```text
runtime/current/forensic_today.json
runtime/current/forensic_today.md
runtime/current/forensic_today.txt
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

Օգտագործել, երբ՝

```text
You want one daily folder that summarizes what happened.
You want a plain-language TXT to upload for quick analysis.
```

Ստուգեք՝

```text
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

Կանոն՝

```text
Daily summaries are rebuildable indexes.
Source evidence remains authoritative.
```

<a id="logging"></a>
## `logging`

Կառավարում է իրադարձությունների ծավալը և ցածր կարևորության համախմբումը:

Օգտագործել, երբ՝

```text
actor-touch events are noisy
raw event files grow too quickly
```

Ապահով օրինակ՝

```lua
logging = {
    low_importance_mode = "aggregate",
    write_low_importance_raw_events = false,
},
```

<a id="retention"></a>
## `retention`

Վերահսկում է, թե որքան երկար են պահվում ֆայլերը և երբ JSONL մատյանները պտտվում են:

Օգտագործել, երբ՝

```text
disk usage grows too fast
you need more audit history
you need shorter live-history windows
```

Կարևոր ընտրանքներ.

```text
detailed_retention_days
rotate_jsonl_when_bytes_exceed
max_raw_events_lines
keep_enforced_forever
keep_evidence_forever
```

<a id="warning_bursts"></a>
## `warning_bursts`

Կառավարում է նախազգուշացման պատուհանի հայտնաբերումը:

Օրինակներ՝

```text
ActorChannelFailure
DeployableSaveWarning
UpdateActorToWorldSave
ServerMove warnings
```

Կանոն՝

```text
Warnings are context until correlated with mapped sessions and thresholds.
```

<a id="crash_correlation"></a>
## `crash_correlation`

Վերահսկիչները կրկնվում են crash/reconnect վերանայում:

Ապահով կանխադրվածներ.

```lua
crash_correlation = {
    single_crash_never_bans = true,
    require_same_account = true,
},
```

Օգտակար հաշվիչներ.

```text
server_crash_overlap_count
post_crash_reconnect_count
unclean_disconnect_count
```

<a id="join_leave"></a>
## `join_leave`

Կառավարում է շեղումը և միացման ալիքի հետևումը:

Ապահով լռելյայն`

```lua
join_leave = {
    churn_alone_never_bans = true,
},
```

Օգտագործել՝

```text
rapid reconnect loops
join waves
short-session patterns
```

<a id="raid_detection"></a>
## `raid_detection`

Խմբերի հաշիվներն ակտիվ են հարակից պատուհաններում:

Կանոն՝

```text
A raid case groups accounts for review.
It does not make every account guilty.
```

Յուրաքանչյուր պարտադրված հաշիվ դեռ կարիք ունի հաշվին հատուկ ապացույցների:

<a id="object_registry"></a>
## `object_registry`

Վերահսկիչներ object/class նշանի հանում ընթեռնելի Պահված ապացույցներից:

Ելքներ՝

```text
runtime/object_registry_partial.json
runtime/object_registry.json
runtime/object_registry_counts.tsv
```

Կանոն՝

```text
Object/class context is not a ban reason by itself.
```

<a id="world_state"></a>
## `world_state`

Վերահսկիչներ boot/current/session աշխարհի պետությունների պատկերներ:

Ելքներ՝

```text
runtime/world_state/current/world_state_latest.json
runtime/world_state/sessions/<date>/<session_id>_<account_id>/
```

Օգտագործեք նստաշրջանի վերանայման և աշխարհի համատեքստի համար:

<a id="enforcement"></a>
## `enforcement`

Կառավարում է առաջարկությունները և փաստացի Admin.ini գրում է:

Նախքան Guard-ը կարողանա արգելք ավելացնել, ստորև բերված բոլոր հայտարարությունները պետք է ճշմարիտ լինեն.

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
account identity is mapped
not trusted
not moderator
threshold is met
```

Եթե հայտարարություններից մեկը կեղծ է կամ հնարավոր չէ ստուգել, ​​Գվարդը հեռանում է `Admin.ini` անփոփոխ է և նշում է պատճառը:

<a id="admin_ini"></a>
## `admin_ini`

Կառավարում է ֆայլի անվտանգ գրումը:

Կանոններ՝

```text
Back up before writing.
Preserve existing bans.
Preserve moderators.
Write clean BannedPlayer=<ID> only.
```

<a id="restart_request"></a>
## `restart_request`

Կառավարում է ընտրովի տեղական նշիչի ֆայլերը, որոնք կարող է ստուգել մեկ այլ օպերատորին պատկանող գործընթաց: Այն չի վերագործարկում և չի սպանում սերվերը:

Լռելյայն`

```lua
restart_request = {
    enabled = false,
    restart_marker_file = "runtime/request_restart.flag",
    restart_reason_file = "runtime/restart_reason.json",
},
```

Ելքներ՝

```text
runtime/request_restart.flag
runtime/restart_reason.json
```

Ոչ մի հոսթինգ վահանակ, մատակարարի կամուրջ կամ վերագործարկելու ավտոմատացում փաթեթավորված չէ: Մարկեր ստեղծելու ակտիվացումը չի ապացուցում, որ արտաքին գործընթացն սպառել է հարցումը կամ վերագործարկել սերվերը:
