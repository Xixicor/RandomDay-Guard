# Աշխատած գործողության օրինակներ

> **Կանոնական անգլերեն աղբյուր:** [EXAMPLE_RUNS.md](../../EXAMPLE_RUNS.md). Այս տեղայնացված փաստաթուղթը պահպանում է ճշգրիտ հրամաններ, ուղիներ, բանալիներ, կարգավիճակի արժեքներ, հեշեր և ֆայլերի անուններ: Եթե ​​տեխնիկական ձևակերպումը տարբերվում է, օգտագործեք անգլերեն աղբյուրը:


Այս օրինակները օգտագործում են հորինված արժեքները՝ բացատրելու սպասվող վիճակների անցումները. դրանք կենդանի համատեղելիության կամ խաղացողի ապացույց չեն:

<a id="successful-current-cycle"></a>
## Հաջողված ընթացիկ ցիկլը

Մուտքեր. ընթեռնելի ակտիվ մատյան, version/boot/epoch, `poll_id=41`, ավարտված ընթացիկ հարցում, գրավոր accounting/history/report արմատներ, դանդաղ սկանավորման քաղաքականություն չկա:

Սպասվում է.

```text
server_status = full
player_activity = full or limited_expected_empty
case_review = full or limited_expected_empty
daily_rollup = full or limited_expected_empty
critical_guard = full or limited_expected_empty
```

Յուրաքանչյուր միացված երթուղի ունի JSON/TXT ելքը և նույն տոհմը `route_proof.json`: Երթուղու կարգավիճակը կախված է իր սեփական թեմաներից, այլ ոչ թե ընդհանուր հաջողության հաղորդագրությունից:

<a id="expected-empty-player-and-case-routes"></a>
## Նվագարկիչի և պատյանների ակնկալվող դատարկ երթուղիներ

Մուտքեր. ընթացիկ ցիկլի ապացույցն ավարտված է; խաղացողների ընթացիկ կամ պահպանված տողեր չկան. ոչ պահպանված գործ և ոչ ընթացիկ REVIEW/BAN-ELIGIBLE հաշիվ:

Սպասվում է.

```text
player_activity.route_proof_status = limited_expected_empty
player_activity.expected_empty = true
player_activity.players = []

case_review.route_proof_status = limited_expected_empty
case_review.expected_empty = true
case_review.cases = []
```

Թարգմանված զեկույցներում ասվում է, որ ոչ մի իրավասու սահմանափակված առարկա չի դիտարկվել: Նրանք նաև ասում են, որ սա չի ապացուցում, որ ոչ ոք երբևէ կապ չունի կամ որևէ ենթատեքստ բացակայում է: Տեղապահ չկա player/case ստեղծվել է:

<a id="partial-bounded-scan"></a>
## Մասնակի սահմանափակված սկանավորում

Մուտքեր՝ թարմ հոսանք log/poll; `scan_checkpoint.json` կամ `scan_progress.json` գոյություն ունի; սկանավորումը թերի է; լռելյայն `slow_world_scan_blocks_current_reports=false`.

Սպասվում է.

```text
world_save_scan.status = partial
source accounting = partial
server_status may still be full for fresh current state
historical routes name the scan limitation
```

Սահմանել `slow_world_scan_blocks_current_reports=true` միայն այն դեպքում, երբ օպերատորը ցանկանում է, որ այդ կամընտիր դանդաղ աղբյուրը արգելափակի ընթացիկ հաշվետվությունները: Վերականգնումը թույլ է տալիս սկանավորողին վերսկսել, այլ ոչ թե ջնջել անցակետը:

<a id="missing-current-cycle-proof"></a>
## Ընթացիկ ցիկլի ապացույցը բացակայում է

Մուտքեր. ակտիվ մատյան անհասանելի է, `poll_id=0` կամ boot/epoch/last-poll տոհմը բացակայում է:

Սպասվում է.

```text
current_cycle_proof_complete = false
all route proof statuses = missing
each configured route envelope status = suppressed_current_cycle
delivery_eligible = false
delivery_attempted = false
```

Սեղմված ծրարը աուդիտի գրառում է, այլ ոչ թե հերթագրված առաքում: Հին վերջնական տեղեկամատյանները մնում են միայն պատմական: Վերանորոգեք առաջին բացակայող lineage/source դաշտ և ստեղծեք ավելի նոր ցիկլ:

<a id="malformed-optional-adminini-source"></a>
## Սխալ է ընտրովի Admin.ini աղբյուր

Մուտքեր՝ `Admin.ini` գոյություն ունի, սակայն չի հաջողվում մաքուր կառուցվածքային վավերացում:

Սպասվում է.

```text
admin_ini.status = malformed
source reference preserved
write/enforcement path closed
```

Պահպանեք ֆայլը և վերականգնեք վերանայված մաքուր ձևաչափը: Պահպանեք բացատրական տեքստը գործարկման ժամանակի ապացույցներում; յուրաքանչյուրը `Admin.ini` մուտքի արգելքը մնում է միայն `BannedPlayer=<ID>`.

<a id="required-active-log-probe-error"></a>
## Պահանջվում է ակտիվ գրանցամատյանի հետաքննության սխալ

Մուտքեր. սահմանափակված պահանջվող ակտիվ մատյան զոնդը ձախողվում է ախտահանված ընթերցման սխալի պատճառով:

Սպասվում է.

```text
source_accounting.sources[active_log].status = error
source_accounting.sources[active_log].detail = "bounded active-log probe failed: <sanitized reason>"
coverage_status = unavailable
all route proof statuses = missing
```

`error` մնում է սկզբնաղբյուր տողում իր սահմանափակ մանրամասներով: Վերին մակարդակի զեկույցում օգտագործվում է `unavailable`, իսկ երթուղու ապացույցը մնում է `missing`, քանի դեռ նոր ընթացիկ ցիկլը չի ​​ապացուցի անհրաժեշտ աղբյուրը:

<a id="incompatible-or-stale-baseline"></a>
## Անհամատեղելի կամ հնացած ելակետ

Մուտքագրումներ՝ փոխված package/source ինքնությունը կամ stale/incompatible ելակետային մանիֆեստ:

Սպասվում է. վավերացման կամ գործարկման կարգավիճակը գրանցում է անհամատեղելիությունը. սկան վիճակը չի պահանջում ավարտված վերօգտագործման համար: Պահպանեք նախորդ ապացույցները, սկսեք բացահայտ ելակետային վերակառուցում և սպասեք նոր տերմինալի ապացույցի: Առանց գրանցված պատճառի հարկադիր վերակառուցումը լռելյայն վերականգնում չէ:

<a id="paired-report-write-failure"></a>
## Զուգակցված զեկույցի գրման ձախողում

Մուտքեր՝ JSON գրելը հաջողվում է, բայց TXT գրելը ձախողվում է, կամ հակառակը:

Սպասվում է.

```text
route_proof_status = missing
completed = false
coverage_status = unavailable
output_write_detail = "paired JSON/TXT write failed: <sanitized reason>"
next_action = repair both route output writes
```

Գրողը՝ լավագույն ջանքերը, վերաշարադրում է երկու եղբայրներին ու քույրերին՝ ձախողման հետ կապված: Մեկ հաջողակ քույր ու եղբայր չի կարող մնալ որպես հաջողության պահանջ: Սահմանափակ գրելու դետալը հինգերորդ վերին մակարդակի ծածկույթի արժեք չի ստեղծում:

<a id="route-proof-write-failure"></a>
## Գրման երթուղիներից պաշտպանված ձախողում

Մուտքեր. երթուղիների զույգերը գրվել են, բայց `route_proof.json` չի կարող փոխարինվել:

Սպասվում է. բոլոր հաշվետվությունները վերաշարադրվում են `missing`, ծանուցման բոլոր արդյունքներն են `route_proof_write_failed`, և ոչ մի ծրար չի ընդունվում: Կազմաձևված երթուղին կարող է ունենալ `suppressed_current_cycle` աուդիտի ծրար առաքման դրոշներով կեղծ: Վերանորոգեք ելքային արմատը և վերականգնեք նույն ընթացիկ ցիկլը:

<a id="review-only-enforcement-example"></a>
## Միայն վերանայման կիրառման օրինակ

Կարգավորում`

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

Սպասվում է. կարող են գրվել միավորներ, դեպքեր և առաջարկություններ; `Admin.ini` մնում է անփոփոխ: Սա հանրային լռելյայն է:

<a id="approved-write-success-example"></a>
## Գրելու հաջողության հաստատված օրինակ

Միայն առանձին հաստատված թեստը կարող է սահմանել գրելու բոլոր երեք անջատիչները: Այն նաև պետք է ապացուցի մաքուր թվային ինքնությունը, trust/moderator բացառում, սահմանային իրավունք, վավեր Admin.ini path/parse, կրկնօրինակման հաջողություն, գրելու հաջողություն, հետադարձ հավասարություն և հաշվի հատուկ ապացույցներ:

Սպասվում է.

```text
runtime/backups/Admin_<timestamp>_<source-fingerprint>_<clean-ID>.ini
Admin.ini contains one clean BannedPlayer=<ID>
runtime/enforced_bans.jsonl and evidence mirror record success
```

Հաջողված օրինակը թույլ չի տալիս ավտոմատ կիրառումը այլ հաշիվների համար:

<a id="writereadback-failure-with-rollback"></a>
## Write/readback ձախողում հետ վերադարձով

Մուտքեր. յուրաքանչյուր նախնական գրելու դարպասն անցել է; փոխարինման գրելը կամ հետադարձը ձախողվում է. `rollback_on_readback_failure=true` և հաստատված կրկնօրինակը հասանելի է:

Սպասվում է. ձախողման ապացույցները գրանցում են փուլը և `rollback_success`; բնօրինակը Admin.ini բայթերը վերականգնվում են, և հաշիվը չի հաղորդվում, քանի որ հաջողությամբ կիրառվել է: Եթե ​​հետադարձը նույնպես ձախողվի, դադարեցրեք գրելը, պահպանեք երկուսն էլ files/evidence և ձեռքով վերականգնեք պահուստից:

<a id="local-outbox-example"></a>
## Տեղական ելքային արկղի օրինակ

Մուտքեր. ծանուցումը միացված է `local_file_outbox` ռեժիմ, երթուղին միացված է, ավարտված երթուղու ապացույց և կամ `full` կամ բացահայտորեն թույլատրված է սպասվում-դատարկ:

Սպասվող ծրար.

```text
schema = randomdayguard.notification/v1
completed_output = true
status = ready_for_local_consumer
delivery_eligible = true
delivery_backend = none
delivery_attempted = false
```

missing/ineligible ելք, փոխարենը նույն ճանապարհը կարող է պարունակել `status=suppressed_current_cycle`, `completed_output=false` և `delivery_eligible=false`: Ցանկացած ֆայլ ապացուցում է միայն տեղական գրությունը: Ոչ մի մատակարարի, տրանսպորտի, առաքման կամ ընթերցման անդորրագիր չի հավաքվում կամ ենթադրվում է:

Տես [`OUTPUT_SCHEMA_REFERENCE.md`](%D4%B5%D4%BC%D5%94%D4%BB_%D5%8D%D4%BD%D4%B5%D5%84%D4%B1%D5%85%D4%BB_%D5%80%D5%82%D5%88%D5%92%D5%84.md), [`CONFIG_FIELD_CATALOG.md`](%D4%BF%D4%B1%D5%90%D4%B3%D4%B1%D5%8E%D5%88%D5%90%D4%B5%D4%BC_%D4%B4%D4%B1%D5%87%D5%8F%D4%B1%D5%85%D4%BB%D5%86_%D4%BF%D4%B1%D5%8F%D4%B1%D4%BC%D5%88%D4%B3.md) և [`TROUBLESHOOTING.md`](%D4%BD%D5%86%D4%B4%D4%BB%D5%90%D5%86%D4%B5%D5%90%D4%BB_%D5%8E%D4%B5%D5%90%D4%B1%D5%91%D5%88%D5%92%D5%84.md).
