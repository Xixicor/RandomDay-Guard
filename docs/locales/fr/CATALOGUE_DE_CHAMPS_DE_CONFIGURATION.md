# Catalogue de champs de configuration complet

> **Source canonique en anglais:** [CONFIG_FIELD_CATALOG.md](../../CONFIG_FIELD_CATALOG.md). Cette documentation localisée conserve les commandes, chemins, clés, valeurs d'état, hachages et noms de fichiers exacts. Si la formulation technique diffère, utilisez la source anglaise.


Généré par `python -B tools/generate_documentation_audit.py --write` à partir de `RandomDayGuard/config.lua`. Le générateur analyse la table Lua de données pures sans l'exécuter. `python -B tools/generate_documentation_audit.py --check` et le validateur du référentiel nécessitent un contenu généré exact et une ligne sémantique par feuille. Les tableaux et les cartes modifiables comptent comme une feuille et affichent leur contenu expédié.

<a id="global-rules"></a>
## Règles globales

- Modification uniquement `RandomDayGuard/config.lua` ; chaque exemple ci-dessous est conçu pour une insertion directe dans la table `return { ... }` fournie.
- Les seules valeurs de vérité de niveau supérieur sont `complete`, `complete_with_gaps`, `partial` et `unavailable`.
- `deferred`, `error`, `malformed` et `permission_denied` sont des conditions au niveau de la source ; la preuve d'itinéraire reste `full`, `limited_expected_empty`, ou `missing`.
- Un paramètre ne peut pas remplacer les preuves requises, la confirmation du compte, la protection des comptes de confiance, la vérification des sauvegardes, la comparaison des fichiers enregistrés, la récupération ou la preuve du cycle en cours.
- Les chemins restent locaux et génériques. Ne validez jamais les identifiants de compte, les informations d'identification, les itinéraires des fournisseurs, les incidents privés ou les preuves en direct.

<a id="change-and-recovery-procedure"></a>
## Procédure de modification et de récupération

1. Sauvegardez le package externe `config.lua` examiné.
2. Modifiez la plus petite table propriétaire et conservez chaque champ dans sa documentation documentée. type.
3. Exécutez le générateur `--check`, tests de documentation ciblés, `luac -p` sur `config.lua` et `tools/validate_repo.py` lorsque l'arbre de travail d'exécution partagé est stable.
4. Redémarrez Guard et inspectez le state/output spécifique au propriétaire nommé. ci-dessus.
5. En cas d'échec de chargement, de source, de preuve ou d'écriture, restaurez la valeur expédiée ou la sauvegarde révisée ; les échecs d'application restent fermés.
