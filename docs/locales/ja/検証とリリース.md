# 検証とリリース

> **正規の英語ソース:** [VALIDATION_AND_RELEASE.md](../../VALIDATION_AND_RELEASE.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


このページは、寄稿者およびリリース メンテナを対象としています。サーバー オペレーターは、インストールするためにこれらのコマンドを実行する必要はありません。RandomDayGuard.

<a id="user-visible-proof"></a>
## ユーザーに表示証明

新しいオペレーターがリリースをインストールし、最初のサーバー ステータス レポートを見つけ、5 つのレポート ルートを区別し、実際の例から 1 つの明確なアクションに従うことができれば、リリースは理解できます。リーダー タスクには、Git、PowerShell、Python、チェックサムの知識は必要ありません。

<a id="contributor-checks"></a>
## 投稿者がチェックする

```powershell
python -B tools/validate_repo.py
python -B tools/test_public_pipeline.py
python -B -m unittest discover tests
```

場合 `luac` が利用可能です:

```powershell
luac -p RandomDayGuard/Scripts/main.lua
luac -p RandomDayGuard/Scripts/public_pipeline.lua
```

Lua フィクスチャ テストは、ローダー、スケジューラ、レポート ルート、およびオプションのAdmin.ini書き込みトランザクションをカバーし、強制フィクスチャは一時ファイルのみを使用し、ID、信頼できるアカウントの拒否、しきい値、バックアップ、同時変更の拒否、リードバック、ロールバックを検証します。

<a id="package-proof"></a>
## パッケージ証拠

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

- すべてのバージョン マーカーが一致します`VERSION`.
- 現在のバージョンのみが`releases/`.
- ZIP には正規の `RandomDayGuard/Scripts/main.lua`パスが含まれており、小文字の大文字と小文字のバリアント ローダーは含まれていません。
- ランタイム出力、プライベート構成、認証情報、ローカル パス、キャッシュ、テスト アーティファクトは除外されます。
- パブリック構成は、適用が無効になっているためレビュー専用のままです。
- 5 つの作業済みレポートの例は、ルート所有権およびリリース テスト フィクスチャとの一貫性が保たれます。
- ZIP バイトが含まれており、決定的で一致します `CHECKSUMS.sha256`.
- すべてのローカル ドキュメント リンクと 27 のロケール エントリ ページが検証されます。

<a id="avoid-validation-environment-pitfalls"></a>
## 検証環境の落とし穴を回避します

- リポジトリ書き込みチェックを連続的に実行して、一時ファイルの競合を回避します。
- Windows では、大文字と小文字を区別しないファイル検索ではなく、アーカイブされたメンバー名または列挙されたパスのスペルを検査します。重複したローダーをチェックしています。
- 欠落している`luac`コマンドまたは Lua ランタイムは、使用できない機能であり、構文テストやランタイム テストに合格したわけではありません。
- フィクスチャは、モデル化された入力のみを証明します。これは、ライブ サーバーが現在のレポートを作成したことを証明するものではありません。
- 完了したと仮定するのではなく、コマンド タイムアウトと部分的な出力を記録します。

<a id="repair-failed-repository-validation"></a>
## 失敗したリポジトリ検証を修復します。

最初に報告されたパスまたはコントラクトから開始します。その項目を修正し、狭い範囲のテストを再実行してから、完全なマトリックスを再実行します。不足している機能を必要とするテストを削除して、不足している機能を隠さないでください。

<a id="known-limits-and-release-decision"></a>
## 既知の制限とリリースの決定

ローカル チェックにより、ソース、フィクスチャ、パッケージ、ドキュメントの契約が証明されます。特定のサーバーのインストール、長時間実行される安定性ウィンドウ、またはクライアントの表示には、別の統合結果が必要です。一致する主張を行う前に、その結果をビルド、構成、期間、および観察された出力とともに記録してください。
