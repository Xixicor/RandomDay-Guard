# トラブルシューティング

> **正規の英語ソース:** [TROUBLESHOOTING.md](../../TROUBLESHOOTING.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


このページは、Guard がロードされない場合、ソースが収集できない場合、レポートが表示されない場合、またはルート証明が期待したものと矛盾する場合に使用します。デシジョン ツリーから開始して 1 つのブランチをたどります。専用の[ステータスとエラーのリファレンス](%E3%82%B9%E3%83%86%E3%83%BC%E3%82%BF%E3%82%B9%E3%81%A8%E3%82%A8%E3%83%A9%E3%83%BC%E3%81%AE%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9.md)は、失敗したレイヤーが判明した後にのみ使用してください。

設定を変更したり再インストールしたりする前に、現在のランタイム ファイルを保存してください。古いアーティファクトまたは欠落しているアーティファクトは、失敗したステージを示します。再起動を繰り返すと、その証拠が消去される可能性があります。

<a id="choose-the-failure-path"></a>
## 障害パスの選択

<a id="1-decide-whether-guard-loaded"></a>
### 1. Guard がロードされているかどうかを決定します。

- **`runtime/`ファイルが存在しません:** [欠落しているランタイム ファイルを復元します。](#restore-missing-runtime-files)に従ってください。インストール パス、正規ローダー、`enabled.txt` と一致する必要があり、`mods.txt`を確認してください。
- **現在のステータス ファイルが存在することを確認します。** Guard は状態を書き込むのに十分な範囲までロードされています。ステップ 2 に進みます。再インストールは最初の応答ではありません。

<a id="2-decide-whether-the-scheduler-is-advancing"></a>
### 2.スケジューラが進んでいるかどうかを決定します。

開く:

```text
runtime/current/startup_status.json
runtime/current/poll_status.json
```

- **カウンタとタイムスタンプが進みます:** ステップ 3 に進みます。
- **`poll_id` は静的です。`poll_in_flight` true のまま、またはスケジューラのステータスが実行中でありません:** [スタックしたポーリング ループを回復します。](#recover-a-stuck-poll-loop).
- **スケジューラの進行が継続している間、ベースライン スキャンが保留中です:** これは自動的に起動が失敗するわけではないので注意してください。バックログまたはスキャンの進行が停止した場合にのみ調査してください。

<a id="3-classify-route-proof"></a>
### 3.ルート証明を分類する

開く `runtime/final_logs/route_proof.json`すべてのルートを個別に検査します。

- **`full`:** 予期しない文言と現在の文言を比較し、 `source_references` と系統。文言だけが間違っているように見えるため、配信を変更しないでください。
- **`limited_expected_empty`:** ソース アカウンティングが正当な空の結果をサポートしていることを確認してください。合成プレーヤーやケースを作成しないでください。
- **`missing`:** [欠落しているルートを診断し、](#diagnose-a-missing-route).

<a id="4-classify-source-coverage"></a>
### 4.ソース カバレッジを分類する

- **`partial`, `deferred`, `unavailable`, `malformed`, `permission_denied`または `error`:** [不完全なソース カバレッジを解釈する](#interpret-incomplete-source-coverage)その後、[ステータスとエラーのリファレンス](%E3%82%B9%E3%83%86%E3%83%BC%E3%82%BF%E3%82%B9%E3%81%A8%E3%82%A8%E3%83%A9%E3%83%BC%E3%81%AE%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9.md).
- **構造化ソースは最新ですが、翻訳または保留中の出力が古い場合に正確なコードを検索します。**配信エンドポイントではなく、完了ハンドオフを診断します。配信構成を変更する前に、両方のタイムスタンプを保存し、レポートとディスパッチのステータスを検査します。

<a id="5-follow-the-matching-branch"></a>
### 5.一致するブランチをたどってください

- 不完全な ID: [マップされていないプレーヤーをマッピングします。](#map-an-unmapped-player).
- 日次継続性の欠如: [欠落している日次ロールアップを復元する](#restore-a-missing-daily-rollup).
- 明示的に承認された施行テストが書き込まれませんでした: [ブロックされたAdmin.ini書き込みを診断する](#diagnose-a-blocked-adminini-write).
- ZIP 抽出に失敗しました: [Windows 抽出を解決しますケースの衝突](#resolve-a-windows-extraction-folder-collision).
- フィクスチャ、パッケージ、またはリポジトリのチェックに失敗しました: [検証とリリースのレビュー](%E6%A4%9C%E8%A8%BC%E3%81%A8%E3%83%AA%E3%83%AA%E3%83%BC%E3%82%B9.md#avoid-validation-environment-pitfalls).

<a id="6-stop-with-one-proved-outcome"></a>
### 6. 1 つの証明された結果で終了する

トラブルシューティング パスは次の場合に終了します。

- ルートは現在のものであり、`full`;
- ルートは現在のものであり、`limited_expected_empty` 指定された理由による;
- 1 つの正確なブロッカー、証拠パス、次のアクションが記録されます。または
- ロールバックにより、以前の既知の状態が復元され、失敗した証拠が保存されます。

「サーバーは実行中です」、ハートビートの増加、または HTTP 成功だけでは、レポート ルートが完了したことを証明するものではありません。

<a id="diagnose-a-missing-route"></a>
## 欠落しているルートを診断し、

開く `runtime/final_logs/route_proof.json`比較します。`server_status`, `daily_rollup`, `player_activity`, `case_review` と一致する必要があり、`critical_guard`.

1. ルートの理由、系統、生成時刻を読み取り、
2. 名前付きの構造化ソースが存在し、同じサイクルに属していることを確認します。
3. その mtime を翻訳済みの出力および保留中のエンベロープと比較します。
4. 最終ログが翻訳済みまたは保留中の出力よりも新しい場合は、古い完了ディスパッチを記録し、最初にそのハンドオフを修復します。
5. すべてのローカル出力が最新であるが、配信が完了していない場合

スケジューラの健全性や 1 つの成功通知を 5 ルート証明にプロモートしないでください。

<a id="interpret-incomplete-source-coverage"></a>
## 不完全なソース カバレッジを解釈する

| 状態 | 対処方法 |
|---|---|
| `partial` | 収集された証拠のみを使用し、完全なカバレッジの主張を回避します。 |
| `deferred` | 後で期限付きで確認する設定を変更する前に作業を進めます。 |
| `unavailable` | 環境の制限を記録します。証明されたパスまたは権限の問題のみを修正してください。 |
| `malformed` | ソースを保持し、エラーを解析します。欠損値を推測しないでください。 |
| `permission_denied` | 必要な狭い読み取り権限のみを付与してください。 |
| `error` | 詳細を保存し、ルートに依存する前に名前付きステージを診断します。 |

<a id="restore-missing-runtime-files"></a>
## 欠落しているランタイム ファイルを復元します。

確認:

```text
mods.txt contains RandomDayGuard : 1
RandomDayGuard/enabled.txt exists
RandomDayGuard/Scripts/main.lua exists
```

正しいインストール ルートは次のとおりです。

```text
AbioticFactor/Binaries/Win64/ue4ss/Mods/RandomDayGuard/
```

このネストされたレイアウトを拒否します:

```text
Mods/RandomDayGuard/RandomDayGuard/Scripts/main.lua
```

ファイルは正しいが、UE4SS は Guard を開始しませんでした。保存します `UE4SS.log` を保存し、その起動タイムスタンプを実際のゲーム プロセスの開始と比較します。

<a id="resolve-a-windows-extraction-folder-collision"></a>
## Windows 抽出フォルダーの競合を解決する

古いリリースでは、名前が大文字のみ異なるプログラム ディレクトリが使用されていました。一部の Windows 抽出ツールは、ZIP が既存のフォルダー上に配置されると、これらの名前をマージします。

1. インストールされた MOD やその証拠ではなく、失敗した一時抽出のみを削除します。
2. 新しい空の一時ディレクトリを作成します。
3. 現在のリリースをそこから抽出します。
4. 1 つのRandomDayGuardフォルダーと 1 つのプログラム ディレクトリが生成されることを確認します。
5. Windows が依然として衝突を報告する場合は、リリースを再度ダウンロードし、リリースのバージョンと使用したエクストラクターを報告してください。

インストールされたフォルダに新しいリリースを抽出しないでください。 [`../INSTALL.md`](%E3%82%A4%E3%83%B3%E3%82%B9%E3%83%88%E3%83%BC%E3%83%AB.md).

<a id="load-the-expected-version"></a>
## 期待されるバージョンをロードする

ソース マーカーとビルド マーカーを確認します:

```sh
grep -n "local VERSION" RandomDayGuard/Scripts/main.lua
cat RandomDayGuard/BUILD_MARKER.txt
```

同意しない場合:

1. サーバーを停止します。
2. インストールされたフォルダー、確認された構成、および実行時の証拠をバックアップします。
3. 目的のパッケージをステージングして検査します。
4. パッケージ管理のプログラム ファイルとデータ ファイルのみを置き換えます。
5. 正規ローダーが存在し、小文字の重複が追加されていないことを確認します。
6. 実行時出力を判断する前に、一度開始して現在のマーカーを読み戻します。

<a id="correct-a-missing-saved-root"></a>
## 欠落している保存されたルートを修正する

開く `runtime/saved_path_probe.json`。完全な非生物的要素への検証済みの絶対パスを入力します。 `Saved/` ディレクトリへのフル パスを入力します。その下の 1 つの個別のワールドではなく、`SavedRoot.txt`;ワールド ディレクトリのみを指定しないでください。境界ルートの外側のパスは拒否されたままでなければなりません。

<a id="recover-a-stalled-historical-scan"></a>
## 停止した履歴スキャンを回復する

現在の監視と履歴の検出は別のものです。大規模なアーカイブには多くの制限されたサイクルが必要な場合があるため、1 つの変更されていない観察だけでは、アーカイブが停止していると判断するのに十分ではありません。

1. 開く `runtime/current/report_worker_status.json`.
2. 記録 `scan_cursor`、検出されたファイル、完了したファイル、および `last_progress_ts`.
3. 通常のレポート ワーカーの機会を少なくとも 2 回待って、同じフィールドを再度比較します。
4. カーソル、完了したカウント、または進行時間が進んでも、スキャンはまだ動作中です。範囲内のままにしておきます。
5. ポーリング ID と現在のレポートが続行している間にすべての進行状況フィールドが変更されない場合は、ステータス ファイルを保存し、ワーカー フェーズによって指定されたソース クラスを確認します。再試行する前にソース パスを修復するか、読み取りエラーを行ってください。

履歴スキャンが停止すると、古いレコードが必要な結論が制限されます。アクティブ ログと現在のサイクル プルーフが新しい現在のレポートは無効になりません。

<a id="recover-a-stuck-poll-loop"></a>
## スタックしたポーリング ループを回復します。

開く:

```text
runtime/current/poll_status.json
runtime/poll_error.txt
```

記録 `poll_id`, `poll_completed_count`, `poll_in_flight`, `poll_stage`, `scheduler_status`制限された間隔で 2 回タイムスタンプを付けます。

- カウンタが進んでも、ループはスタックしません。後のワーカー ステージを診断します。
- `poll_in_flight=true`変更せず、再起動する前に最後の進行ステージとエラーを保存します。
- スケジューラーが停止した場合は、前のエラーと起動ハンドオフを検査します。

1 つのライフサイクルの停止を補うために 2 番目のループ所有者を追加しないでください。

<a id="start-the-scan-after-log-backlog"></a>
## ログ バックログ後にスキャンを開始します。

`runtime/current/poll_status.json` で、以下を比較します。

```text
active_log_caught_up
active_log_unread_bytes
log_backlog_pending
```

履歴スキャンは、アクティブ ログに未読のバイトがある間待機する必要があります。後のポーリングでバックログが減少することを確認します。ポーリングを進めると未読数が固定されるのは、ソーステールの問題です。修正されたポーリングはスケジューラの問題です。

<a id="preserve-scan-progress-after-a-crash"></a>
## クラッシュ後にスキャンの進行状況を保存する

保存して比較:

```text
runtime/scan_checkpoint.json
runtime/scan_progress.json
runtime/baselines/file_manifest.tsv
```

チェックポイントまたはマニフェストが見つからないか、保存されたルートまたはワールドが変更されているか、チェックポイントが古いとマークされているかどうかを確認します。進行状況を新しく表示するために有効なベースラインを削除しないでください。

<a id="diagnose-a-blocked-adminini-write"></a>
## ブロックされたAdmin.ini書き込みを診断する

強制テストは、明示的な承認と使い捨てのテスト ファイルを使用してのみ実行し、ライブ サーバー ファイルでは決して実行しないでください。まず、テスト設定が Guard に次の書き込みを要求していることを確認します。

```lua
review_only_mode = false
auto_ban = true
write_admin_ini = true
```

クリーンフォルダーの更新手順に従い、記録された失敗の理由を読みます。 Guard は 1 つのアカウントを特定し、モデレーターと信頼できるアカウントを保護し、アカウント固有の十分な証拠を見つけ、新しいバックアップを作成して検証し、他のプログラムがファイルを変更していないことを確認し、目的の更新を保存し、完全に保存されたファイルをその目的の結果と比較する必要があります。いずれかのステップが失敗するか、チェックできない場合は、禁止リストを変更しないでください。完全なルート、ソースについては、[Admin.ini 強制](%E7%AE%A1%E7%90%86%E8%80%85%E6%96%BD%E8%A1%8C.md).

<a id="restore-a-missing-daily-rollup"></a>
## 欠落している日次ロールアップを復元する

有効のままであることを確認します。`forensic_rollup.enabled = true`を参照し、以下を検査します。

```text
runtime/current/forensic_today.json
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

これらが欠落している場合は、起動、ポーリング、レポート ワーカー、およびソース アカウンティングのステータスをこの順序で確認します。日次ロールアップは、サーバー ステータス通知を繰り返すのではなく、1 日あたり 1 つの継続性レコードです。
