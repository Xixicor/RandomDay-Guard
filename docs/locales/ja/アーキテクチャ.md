# アーキテクチャとライフサイクル

> **正規の英語ソース:** [ARCHITECTURE.md](../../ARCHITECTURE.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


RandomDayGuard は 1 つです UE4SS ウォッチドッグと 1 つの独立したレポート モジュール。サーバー所有のファイルを読み取り、限定されたローカル状態を維持し、ローカル証拠を書き込み、出力をレビューします。プロバイダー、コントロール パネル、通知サービスはありません。RandomDay、またはネットワーク依存関係。

<a id="end-to-end-data-flow"></a>
## エンドツーエンドのデータ フロー

1. UE4SS は単一の正規エントリポイントをロードします `RandomDayGuard/Scripts/main.lua`現在のパッケージには、小文字の大文字と小文字が異なる複製は同梱されていません。
2. ローダーは、`config.lua`、3 つのデータ ディクショナリ、およびオプションの `SavedRoot.txt` を読み取ります。バージョン ID は `VERSION`, `MANIFEST.json` と一致する必要があり、`BUILD_MARKER.txt`.
3. 保存されたルート検出チェックでは、限定された既知の候補と直接の既知のファイルがチェックされます。 `runtime/saved_path_probe.json` で読み取れた内容を記録します。ディレクトリを見つけるだけでは証拠はカバーされません。
4. 直接レイヤーは、安全なオフセットからアクティブ サーバー ログを追跡します。ライフサイクル、セッション、アカウント、警告、再接続、およびその他の観察されたイベントを、追加専用の証拠と現在のスナップショットに正規化します。
5. 低速レイヤーのインベントリ 保存されたファイルは、境界のあるチャンクに保存されます。進行状況とチェックポイントを書き込み、未完了の作業を再開し、変更されたファイルのマニフェストを比較し、部分的および最終的なobject/worldコンテキストを生成します。
6. レビュー ロジックは、利用可能な証拠のみを関連付けます。弱いファイル名、タイミング、クラス数、相対座標、チャーン、単一クラッシュ、または ping はコンテキストのままであり、単独で適用を承認することはできません。
7. 別のレポート ワーカーが呼び出します`Scripts/public_pipeline.lua`。ソース クラスのインベントリを作成し、現在のスコープと履歴のスコープを記録し、サイクルを version/boot/epoch/poll/source 鮮度にバインドし、5 つのルート固有の JSON/TXT ペアを書き込み、その後、 `route_proof.json`.
8. 明示的に有効にすると、ローカル送信ボックスはルート証明が存在した後に完成したレポートから参照をコピーします。 `delivery_backend="none"` と `delivery_attempted=false` を記録します。トランスポートはこの製品の外部にあります。

<a id="ownership-and-asynchronous-boundaries"></a>
## 所有権と非同期境界

| 所有者 | 制限された作業 | ブロックしたり暗示したりしてはなりません |
|---|---|---|
| 起動 | 設定、保存されたルート、アクティブ ログ、エポック、インデックス、初期ステータス。 | 成功したローダー マーカーは証拠やルートを証明しません。 |
| ポーリング コールバック | 新しいログ バイト、状態更新、event/session/account出力、スケジュール。 | 遅い再帰的検出またはレポート ドレイン。 |
| スキャン ワーカー | マニフェスト検出、ファイル解析、チェックポイント、partial/finalベースライン。 | 現在のログの進行状況。部分的は失敗ではありません。 |
| レポート ワーカー | ソース アカウンティング、翻訳、レポート ペア、ルート証明、ローカル送信ボックス。 | 施行または外部配信。 |
| オプションの適用 | アカウントとスコアの確認、信頼できるアカウントと重複の保護、バックアップの検証、外部ファイルの変更の拒否、保存された結果の検証。 | レポート スコア、ルート ステータス、またはケース メンバーシップは、必要な安全性チェックをバイパスします。 |

ポーリング ループは、`poll_id` が進行している間のみ正常に維持されます。 `poll_in_flight` は false を返し、スケジュールはアクティブなままになります。これは、レポート パイプラインではなく、投票コンポーネントであることを証明しています。スキャンが遅い場合は、`partial` または `deferred` が発生する可能性があります。デフォルト`slow_world_scan_blocks_current_reports=false`では、過去の制限に名前を付けながら最新のルートを続行できます。

<a id="state-and-lifecycle"></a>
## 状態とライフサイクル

| 状態 | エントリ | ターミナルまたは次の状態 | エラーとリカバリ |
|---|---|---|---|
| 起動 | UE4SS はローダーを呼び出します。 | ブート ID とエポックを使用してpoll/scan/reportワーカーを実行します。 | `startup_error`は、現在のブートの重要な証拠です。 config/path/sourceを修復して再起動します。 |
| 現在のポーリング | スケジュールされた制限付きコールバックが開始されます。 | 完了したポーリングはタイムスタンプを記録し、スケジュールを変更します。 | `poll_error`は、現在のブートの重要な証拠です。制限された作業を復元し、新しいポーリングを確認します。 |
| スキャンが保留中 | ベースラインが必要か、不完全なチェックポイントが見つかりました。 | `partial`/`deferred`、`scan_complete`. | チェックポイントを再開します。 stale/incompatible証拠が記録された場合にのみ再構築します。 |
| ソース アカウンティング | レポート ワーカーは 8 つのソース クラスをインベントリします。 | `complete`, `complete_with_gaps`, `partial`または `unavailable`. | Disabled/failedアカウンティングにより、すべてのルートが`missing`. |
| ルート生成に強制されます | 現在のサイクル リネージとソース アカウンティングが利用可能です。 | `full`, `limited_expected_empty`または `missing`. | ペアリングJSON/TXTまたはルート プルーフ書き込み失敗により、ルートが `missing`. |
| ローカル送信ボックスに収束します | ルートは有効化され、完了し、適格になります。 | 保留中のローカル封筒と通知ステータスの結果。 | 書き込みがない、または証拠が不完全であることは、封筒がないことを意味します。配信は推定されません。 |
| 適用レビュー | アカウント固有の証拠が、自動アクションの設定済みスコアに達します。 | レビューのみの推奨事項または明示的に有効になっている`Admin.ini`アップデート。 | 安全性チェックが失敗したか、利用できない場合、アップデートは停止します。最終比較に失敗すると、リカバリが有効になっているときに検証済みのバックアップが復元されます。 |

<a id="current-and-historical-evidence"></a>
## 現在および過去の証拠

現在の証拠はアクティブなboot/pollに属し、保持されたファイル名だけから再構築されることはありません。歴史的証拠には、耐久性のある回転丸太が含まれます account/session 履歴、保持 cases/reports/evidence、および制限されたワールド保存スキャン。レポートでは、現在および過去の配列とカウントが個別に公開されます。静かな再起動は永続的なコンテキストを消去してはならず、履歴レコードを現在の存在として提示してはなりません。

<a id="completion-and-recovery-boundary"></a>
## 完了と回復の境界

1 つのルートを完了するには、現在のサイクル バージョン、ブート ID、エポック ID、ポジティブ ポーリング ID、最新のアクティブ ログ ステータス、両方のルート出力、および `route_proof.json` のエントリが一致する必要があります。通知クレームにはさらに、同じサイクルのローカル エンベロープが必要です。外部配信は公的証明の一部ではありません。

最終レポートが見つからないか、現在の状態より古い場合は、poll/source 状態を終了し、最初から続行します。リネージュの不一致または書き込みの失敗。無関係なルート、文言、強制設定を変更しないでください。再試行する前に[`OUTPUT_SCHEMA_REFERENCE.md`](%E5%87%BA%E5%8A%9B%E3%82%B9%E3%82%AD%E3%83%BC%E3%83%9E%E3%81%AE%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9.md), [`TROUBLESHOOTING.md`](%E3%83%88%E3%83%A9%E3%83%96%E3%83%AB%E3%82%B7%E3%83%A5%E3%83%BC%E3%83%86%E3%82%A3%E3%83%B3%E3%82%B0.md) と一致する必要があり、[`SOURCE_MODULE_REFERENCE.md`](%E3%82%BD%E3%83%BC%E3%82%B9_%E3%83%A2%E3%82%B8%E3%83%A5%E3%83%BC%E3%83%AB_%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9.md).
