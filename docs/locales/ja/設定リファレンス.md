<a id="configuration-concepts"></a>
# 構成の概念を使用してバックアップします。

> **正規の英語ソース:** [CONFIG_REFERENCE.md](../../CONFIG_REFERENCE.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


この説明では、各主要構成領域が何を制御するのか、いつ実行されるのか、証拠や安全ゲートとどのように相互作用するのかについて説明します。正確なフィールド カタログやプロファイル プロシージャは所有していません。

タスク指向のプリセットおよび安全な変更ステップについては、[`CONFIG_PROFILES.md`](%E8%A8%AD%E5%AE%9A%E3%83%97%E3%83%AD%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB.md)を使用します。すべての正確なソース フィールド、デフォルト、タイプ、不変式、出力効果、および回復ルールに対して、生成された [`CONFIG_FIELD_CATALOG.md`](%E8%A8%AD%E5%AE%9A%E3%83%95%E3%82%A3%E3%83%BC%E3%83%AB%E3%83%89_%E3%82%AB%E3%82%BF%E3%83%AD%E3%82%B0.md) を使用します。バリデータでは、出荷されるすべての行に対して 1 行が必要です。`config.lua`リーフ フィールドごとに 1 行が必要です。

## このページを読む

```text
What it controls
When it runs

What can go wrong
```

<a id="top-level-safety"></a>
## トップレベルの安全性

| オプション | デフォルト | 意味 |
|---|---:|---|
| `enabled` | `true` | マスター スイッチガード |
| `enforcement.review_only_mode` | `true` | Record/recommendのみ |
| `enforcement.auto_ban` | `false` | デフォルトでは自動的に禁止されません |
| `enforcement.write_admin_ini` | `false` | デフォルトではAdmin.iniは書き込まれません |

サーバー所有者が出力を確認するまで、これらを安全に保管してください。

<a id="saved"></a>
## `saved`

ガードがサーバーの `Saved/` フォルダーとファイルを見つける方法を制御します。スキャンできるファミリー。

使用する場合:

```text
Saved root auto-detection fails.
World folder changed.
Provider or container path is unusual.
```

チェック:

```text
runtime/saved_path_probe.json
RandomDayGuard/SavedRoot.txt
```

ルール:

```text
SavedRoot.txt -> AbioticFactor/Saved
not -> Worlds/<WorldName>
```

<a id="log_tail"></a>
## `log_tail`

ライブ ログの読み取りを制御します。

便利なオプション:

| オプション | 安全な値 | 理由 |
|---|---|---|
| `enabled` | `true` | ライブ防御に必要 |
| `start_at_end_on_first_run` | `true` | ライブ イベントとしての古いログを回避します |
| `tail_backup_logs` | `false` | バックアップ ログはライブではなく履歴です |
| `max_lines_per_poll` | 制限付き | ポーリング ループの応答性を維持します |

チェック:

```text
runtime/log_offsets.tsv
runtime/evidence/session_events.jsonl
runtime/current/poll_status.json
```

<a id="runtime"></a>
## `runtime`

ポーリングと予算を制御します。

主な健全性ルール:

```text
poll_id increases
poll_in_flight returns false
poll_scheduled is true
```

チェック:

```text
runtime/current/poll_status.json
```

`poll_id`が停止した場合、何かがループをブロックしています。

<a id="source_accounting"></a>
## `source_accounting`

明示的な証拠ソースのカバレッジと範囲を制御します。

| キー | デフォルト | 意味 |
|---|---:|---|
| `enabled` | `true` | パブリック ルート レポートのソース アカウンティングを書き込みます。 |
| `require_terminal_status` | `true` | 各ソースが明示的なターミナルまたは不完全を公開することを要求します。  |
| `distinguish_current_from_historical` | `true` | 現在の証拠と過去の証拠を分けて保持します。 |
| `slow_world_scan_blocks_current_reports` | `false` | 現在のレポートで、制限されたワールド スキャンが延期または部分的であると記載できるようにします。 |
| `changed_file_manifest` | ベースライン マニフェスト パス | 制限されたhistorical/worldアカウンティングに使用される参照。 |

ソースの状態は `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied`または `error`.

設定 `source_accounting.enabled = false` ではステータス出力が自動的に削除されません。パイプラインは引き続き `runtime/final_logs/source_accounting_latest.json` を書き込みます。また、利用できないアカウンティングを含む履歴ステータス レコードも書き込みます。ソース アカウンティングはレポート コントラクトの一部であるため、すべてのルートは `enabled=false`, `status="unavailable"` と一致する必要があり、`disabled_reason="source_accounting_disabled"` を使用して `missing` に対してフェイル クローズされます。アカウンティングが無効になっている間、ルートは完了として扱われません。

<a id="reports"></a>
## `reports`

一般的なローカル レポート パイプラインを制御します。

デフォルトでは 5 つのルートすべてが有効になり、`runtime/final_logs`:

```text
server_status
daily_rollup
player_activity
case_review
critical_guard
```

各ルートは構造化および翻訳された出力と証明を `route_proof.json` に書き込む必要があります。ルートを無効にすると、ルートが完了したように見せるのではなく、`missing` 証拠が生成されます。

<a id="notification"></a>
## `notification`

オプションの汎用ローカル ファイル送信ボックス。デフォルトでは無効になっており、外部プロバイダには何も送信されません。

デフォルト:

```lua
notification = {
    enabled = false,
    mode = "local_file_outbox",
    include_expected_empty = false,
},
```

すべての通知ルートはデフォルトで無効になっています。意図的に有効にすると、`route_proof.json` が書き込まれた後で、送信ボックスは完成した翻訳済みレポートのみを使用できます。地元の証拠と報告書は依然として信頼できるものです。プロバイダー固有の配信、配信エンドポイント、認証情報、およびブリッジは、パブリックの独立ウォッチドッグ契約の一部ではありません。

<a id="scanning"></a>
## `scanning`

ベースライン スキャン、チェックポイント設定、および変更ファイルの更新を制御します。

使用する場合:

```text
building first world baseline
resuming after crash
refreshing changed files later
```

チェック:

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/baselines/file_manifest.tsv
```

重要な設定:

```lua
scanning = {
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
    changed_file_detection = true,
},
```

<a id="forensic_rollup"></a>
## `forensic_rollup`

毎日のクイック アップロード パッケージと最終的な平文ログを制御します。

出力:

```text
runtime/current/forensic_today.json
runtime/current/forensic_today.md
runtime/current/forensic_today.txt
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

使用する場合:

```text
You want one daily folder that summarizes what happened.
You want a plain-language TXT to upload for quick analysis.
```

チェック:

```text
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

ルール:

```text
Daily summaries are rebuildable indexes.
Source evidence remains authoritative.
```

<a id="logging"></a>
## `logging`

イベントの量と重要度の低い集計を制御します。

使用する場合:

```text
actor-touch events are noisy
raw event files grow too quickly
```

安全なパターン:

```lua
logging = {
    low_importance_mode = "aggregate",
    write_low_importance_raw_events = false,
},
```

ファイルの保存期間とJSONLログのローテーション時期を制御します。

使用する場合:

```text

max_raw_events_lines
```

<a id="enforcement"></a>
## `enforcement`

推奨事項と実際のAdmin.ini書き込みを制御します。

Guard が禁止を追加するには、以下のすべてのステートメントが true である必要があります。

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
account identity is mapped
not trusted
not moderator
threshold is met
```

1 つのステートメントが偽であるかチェックできない場合、Guard は `Admin.ini` を変更せずにその理由を記録します。

<a id="admin_ini"></a>
## `admin_ini`

安全なファイル書き込みを制御します。

ルール:

```text
Back up before writing.
Preserve existing bans.
Preserve moderators.
Write clean BannedPlayer=<ID> only.
```

<a id="restart_request"></a>
## `restart_request`

別のオペレーター所有のプロセスが検査する可能性があるオプションのローカル マーカー ファイルを制御します。サーバーを再起動したり強制終了したりすることはありません。

デフォルト:

```lua
restart_request = {
    enabled = false,
    restart_marker_file = "runtime/request_restart.flag",
    restart_reason_file = "runtime/restart_reason.json",
},
```

出力:

```text
runtime/request_restart.flag
runtime/restart_reason.json
```

ホスティング パネル、プロバイダー ブリッジ、再起動の自動化はバンドルされていません。マーカーの作成を有効にしても、外部プロセスがリクエストを消費したことやサーバーを再起動したことは証明されません。
