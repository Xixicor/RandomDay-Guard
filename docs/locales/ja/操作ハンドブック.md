# 運用ハンドブック

> **正規の英語ソース:** [OPERATIONS_PLAYBOOK.md](../../OPERATIONS_PLAYBOOK.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


これは、RandomDayGuard の通常の読み取り順序です。正常なサーバーを確認するために、JSON、Git、チェックサム、またはコマンドライン ツールについて知る必要はありません。

<a id="daily-operator-flow"></a>
## 毎日のオペレータ フロー

1. 開く `runtime/final_logs/server_status_latest.txt`。 Guard が現在のサーバーの実行を監視しているかどうか、最後のサイクルがいつ完了したか、接続されているプレーヤーの数、ソースまたはスキャンが不完全かどうかを 1 日 1 回通知します。
2. 開く `runtime/final_logs/daily_rollup_latest.txt`個々のレコードをすべて繰り返すことなく、同じ日のセッション、退出、指定されたケースワーク、ID インベントリ、ソース カバレッジを要約します。
3. 開く `runtime/final_logs/player_activity_latest.txt`サーバーが日中に参加、退席、またはアクティブなセッションを行った場合のみ。
4. 開く `runtime/final_logs/case_review_latest.txt`現在の件名に名前を付ける場合のみ。レポートには、アカウント、レビュー状態、スコア、アイデンティティ ソース、次に開くレコードが示されます。
5. 開く `runtime/final_logs/critical_guard_latest.txt`Guard が自身の起動、監視サイクル、またはレポート書き込みでの失敗を報告した場合のみ。

ルートに報告するものが何もない場合、Guard は予期される空の結果を記録します。これは完了したチェックであり、欠落しているレポートではありません。

<a id="what-to-read-inside-a-report"></a>
## レポート内の内容

これらのセクションを順番にお読みください:

1. **概要** - このレポートの内容です。
2. **Guard が観察した内容** - このルートに対して収集された実際のタイムスタンプ、カウント、アカウント、セッション、またはステータス値。
3. **意味** -
4. **不明な点** - 結果に影響を与えるソースまたはスキャンの制限。
5. **推奨される次のステップ** - 監視するか、名前付きサブジェクトを確認するか、Guard を修復するか。
6. **証拠の境界** - レポートの制限スコープ。

正確な構造化された証拠を調べる必要がある読者のために、技術記録とソース参照が最後に表示されます。

<a id="when-a-report-is-missing"></a>
## レポートが欠落している場合

開く `runtime/final_logs/route_proof.json`は、読み取り可能なレポートが欠落しているか、現在の証拠が欠落していると記載されている場合にのみ発生します。各ルートには、次のいずれかの結果があります。

| 結果 | 意味 |
|---|---|
| `full` | ガードは、現在のルート所有の証拠を使用してルートを完了しました。 |
| `limited_expected_empty` | ガードはルートを完了しましたが、適格なイベントが見つからないか、指定された成熟度制限を記録しました。 |
| `missing` | 必要なソース、系統チェック、またはペアのレポートの書き込みが完了しませんでした。 |

欠落しているルートについては、指定されたソースに従うか、レポートにエラーを書き込みます。無関係なルートや通知設定を最初に変更しないでください。

<a id="after-a-crash-or-restart"></a>
## クラッシュまたは再起動後

1. 新しいサーバー実行タイムスタンプと最後に完了した監視サイクルのサーバー ステータスを読み取ります。
2. 現在の起動またはポーリングの失敗について Critical Guard を読み取ります。
3. ライフサイクル変更後に同日のセッションが参加、離脱、または復帰した場合にのみ、プレーヤー アクティビティを読み取ります。
4. 設定を変更する前に、引用されたソース レコードを保存してください。

<a id="before-enabling-optional-adminini-writes"></a>
## オプションを有効にする前に Admin.ini 書き込み

デフォルトのパッケージは変更せずに監視およびレポートを行います`Admin.ini`。上級オペレーターは、ファイルのコピーに対してテストした後、オプションの強制パスを有効にすることができます。次に、Guard はクリーンな数値アカウント ID を要求し、信頼できるアカウントを保護し、バックアップを作成して検証し、同時変更を拒否し、保存されたファイルを読み取り、検証が失敗した場合はバックアップを復元します。完全なセットアップとテスト手順については、[`ADMIN_INI_ENFORCEMENT.md`](%E7%AE%A1%E7%90%86%E8%80%85%E6%96%BD%E8%A1%8C.md) を参照してください。
