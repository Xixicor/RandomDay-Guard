# 実際に実行された操作の例

> **正規の英語ソース:** [EXAMPLE_RUNS.md](../../EXAMPLE_RUNS.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


これらの例では、予想される状態遷移を説明するために発明された値を使用しています。これらはライブ互換性やプレーヤーの証拠ではありません。

<a id="successful-current-cycle"></a>
## 現在のサイクルが成功しました

入力: 読み取り可能なアクティブ ログ、version/boot/epoch, `poll_id=41`、完了した現在のポーリング、書き込み可能な accounting/history/report ルート、ブロッキング スロー スキャン ポリシーなし。

期待値:

```text
server_status = full
player_activity = full or limited_expected_empty
case_review = full or limited_expected_empty
daily_rollup = full or limited_expected_empty
critical_guard = full or limited_expected_empty
```

有効なすべてのルートには JSON/TXT の出力と `route_proof.json` の同じ系統。ルート ステータスは、一般的な成功メッセージではなく、独自のサブジェクトによって決まります。

<a id="expected-empty-player-and-case-routes"></a>
## 期待される空のプレーヤーとケースのルート

入力: 現在のサイクルの証明が完了しました。現在のプレーヤー行または保持されているプレーヤー行はありません。保持されているケースも現在の REVIEW/BAN-ELIGIBLE アカウントもありません。

期待値:

```text
player_activity.route_proof_status = limited_expected_empty
player_activity.expected_empty = true
player_activity.players = []

case_review.route_proof_status = limited_expected_empty
case_review.expected_empty = true
case_review.cases = []
```

翻訳されたレポートには、適格な制限付きサブジェクトは観察されなかったと記載されています。また、これは誰も接続したことがないことや、コンテキストが欠落していることを証明するものではないとも述べています。プレースホルダplayer/caseは作成されません。

<a id="partial-bounded-scan"></a>
## 部分境界スキャン

入力: 最新のlog/poll; `scan_checkpoint.json` または `scan_progress.json`が存在します。スキャンが不完全です。デフォルト `slow_world_scan_blocks_current_reports=false`.

期待値:

```text
world_save_scan.status = partial
source accounting = partial
server_status may still be full for fresh current state
historical routes name the scan limitation
```

オペレータがオプションの低速ソースで現在のレポートをブロックしたい場合にのみ`slow_world_scan_blocks_current_reports=true`を設定します。回復とは、チェックポイントを削除するのではなく、スキャン ワーカーが再開できるようにすることです。

<a id="missing-current-cycle-proof"></a>
## 現在のサイクルの証明がありません

入力: アクティブ ログが利用できません、`poll_id=0`または boot/epoch/last-pollリネージがありません。

期待値:

```text
current_cycle_proof_complete = false
all route proof statuses = missing
each configured route envelope status = suppressed_current_cycle
delivery_eligible = false
delivery_attempted = false
```

抑制されたエンベロープは、キューに入れられた配信ではなく、監査レコードです。古い最終ログは履歴のみが残ります。最初の欠落している lineage/source フィールドを修復し、新しいサイクルを生成します。

<a id="malformed-optional-adminini-source"></a>
## 不正な形式のオプションの Admin.ini ソース

入力: `Admin.ini` は存在しますが、明確な構造検証に失敗します。

期待値:

```text
admin_ini.status = malformed
source reference preserved
write/enforcement path closed
```

ファイルを保存し、レビューされたクリーンなフォーマットを復元します。説明テキストを実行時の証拠として保存します。各`Admin.ini`禁止エントリは`BannedPlayer=<ID>`.

<a id="required-active-log-probe-error"></a>
## 必須アクテ​​ィブ ログ プローブ エラー

入力: 制限された必須アクテ​​ィブ ログ プローブがサニタイズ読み取りエラーで失敗します。

期待値:

```text
source_accounting.sources[active_log].status = error
source_accounting.sources[active_log].detail = "bounded active-log probe failed: <sanitized reason>"
coverage_status = unavailable
all route proof statuses = missing
```

`error` は制限された詳細とともにソース行に残ります。最上位のレポートは `unavailable` を使用し、新しい現在のサイクルで必要なソースが証明されるまでルート証明は `missing` のままです。

<a id="incompatible-or-stale-baseline"></a>
## 互換性のないベースラインまたは古いベースライン

入力: 変更された package/source ID または stale/incompatible ベースライン

期待: 検証または実行時のステータスに非互換性が記録されます。スキャン状態は再利用が完了したとは主張しません。以前の証拠を保存し、明示的なベースラインの再構築を開始し、新しい最終的な証拠を待ちます。記録された理由のない強制的な再構築は、デフォルトのリカバリではありません。

<a id="paired-report-write-failure"></a>
## ペアのレポート書き込み失敗

入力: JSON書き込みは成功しますが、TXT書き込みは失敗します。またはその逆。

期待値:

```text
route_proof_status = missing
completed = false
coverage_status = unavailable
output_write_detail = "paired JSON/TXT write failed: <sanitized reason>"
next_action = repair both route output writes
```

ライターは、失敗時に収束するように両方の兄弟をベストエフォートで書き換えます。成功した兄弟の 1 人を成功の主張として残すことはできません。境界書き込み詳細では、5 番目のトップレベル カバレッジ値は作成されません。

<a id="route-proof-write-failure"></a>
## ルートプルーフ書き込み失敗

入力: ルート ペアは書き込まれましたが、`route_proof.json`置き換えることはできません。

期待値: すべてのレポートが書き換えられます。`missing`、すべての通知結果は`route_proof_write_failed`、封筒は受け付けられません。設定されたルートには、配信フラグが false の `suppressed_current_cycle` 監査エンベロープが含まれる場合があります。出力ルートを修復し、同じ現在のサイクルを再生成します。

<a id="review-only-enforcement-example"></a>
## レビューのみの適用例

構成:

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

期待: スコア、ケース、推奨事項が記述される可能性があります。 `Admin.ini` は変更されません。これは公開デフォルトです。

<a id="approved-write-success-example"></a>
## 承認された書き込み成功例

別途承認されたテストのみが 3 つの書き込みスイッチすべてを設定できます。また、クリーンな数値 ID、trust/moderator 除外、しきい値の適格性、有効Admin.ini path/parse、バックアップの成功、書き込みの成功、リードバックの同等性、およびアカウント固有の証拠も証明する必要があります。

期待値:

```text
runtime/backups/Admin_<timestamp>_<source-fingerprint>_<clean-ID>.ini
Admin.ini contains one clean BannedPlayer=<ID>
runtime/enforced_bans.jsonl and evidence mirror record success
```

成功した例では、他のアカウントに対する自動適用は有効になっていません。

<a id="writereadback-failure-with-rollback"></a>
## Write/readback ロールバックによる失敗

入力: すべての事前書き込みゲートが通過しました。置換書き込みまたはリードバックは失敗します。 `rollback_on_readback_failure=true`検証済みのバックアップが利用可能です。

期待: 障害の証拠はステージと`rollback_success`を記録します。元の Admin.ini バイトが復元され、アカウントは正常に適用されたとは報告されません。ロールバックも失敗した場合は、書き込みを停止し、files/evidence の両方を保存し、バックアップから手動で復元します。

<a id="local-outbox-example"></a>
## ローカル送信ボックスの例

入力: `local_file_outbox` モードで有効な通知、有効なルート、完了したルート証明、`full` または明示的に許可Expected-empty.

予期されるエンベロープ:

```text
schema = randomdayguard.notification/v1
completed_output = true
status = ready_for_local_consumer
delivery_eligible = true
delivery_backend = none
delivery_attempted = false
```

missing/ineligible 出力。同じパスに `status=suppressed_current_cycle`, `completed_output=false` と一致する必要があり、`delivery_eligible=false` が含まれる場合があります。どちらのファイルもローカル書き込み専用であることがわかります。プロバイダー、トランスポート、配信、または開封確認はバンドルまたは推測されません。

参照[`OUTPUT_SCHEMA_REFERENCE.md`](%E5%87%BA%E5%8A%9B%E3%82%B9%E3%82%AD%E3%83%BC%E3%83%9E%E3%81%AE%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9.md), [`CONFIG_FIELD_CATALOG.md`](%E8%A8%AD%E5%AE%9A%E3%83%95%E3%82%A3%E3%83%BC%E3%83%AB%E3%83%89_%E3%82%AB%E3%82%BF%E3%83%AD%E3%82%B0.md) と一致する必要があり、[`TROUBLESHOOTING.md`](%E3%83%88%E3%83%A9%E3%83%96%E3%83%AB%E3%82%B7%E3%83%A5%E3%83%BC%E3%83%86%E3%82%A3%E3%83%B3%E3%82%B0.md).
