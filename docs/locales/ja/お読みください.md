# RandomDayGuard 日本語ガイド

> [!IMPORTANT]
> ## プロジェクト状況 — RandomDay のテスト終了
>
> RandomDay のテスト運用は完了し、公開テストサーバーはまもなく終了します。
>
> この運用では、RandomDay と RandomDayGuard を組み合わせ、プロファイルの反復ローテーション、通常時および中断時のサーバー再起動、復旧とロールバックの確認、拡張 Mod との統合、サーバー証拠の収集、運用者レポートの確認を実施しました。
>
> これにより、目標としていた知見を得られました。実際の専用サーバーのライフサイクル全体でローテーションする sandbox プロファイルがどう動作するか、RandomDay が対応する拡張 Mod とどう連携するか、そして RandomDayGuard が欠落や推測を事実として示すことなく、サーバーが記録した証拠をどこまで有用かつ慎重な監視に変換できるか、という知見です。
>
> **テストサーバーで使用した構成:**
>
> - RandomDay 非公開の開発ビルド `v0.41.76`
> - RandomDayGuard 非公開の開発ビルド `v0.46.130`
> - Chaotic Spawn Engine / DynamicSpawns `0.8.5 Hotfix 1`
> - Lethal Lasers `1.0 UE4SS`
> - ANTE Up `0.26`
> - Encounter Director integration — RandomDay が所有する DynamicSpawns 拡張であり、単独配布の Mod ではありません
> - UE4SS `v3.0.1 Beta #0` (Git `01e0a584`; Nexus `v3.0.1-940-g01e0a584`)
> - Abiotic Factor 専用サーバー `1.4.0.27939`
>
> 現在の公開パッケージは、引き続き RandomDay `v0.3.16-alpha` と RandomDayGuard `v0.4.12-alpha` です。
>
> 両プロジェクトの開発は、現在一時停止しています。既存のリリースとドキュメントは引き続き利用でき、また作業を続けたいと感じたときに戻る可能性があります。
>
> この構成は運用中に使用したものを記録するもので、最低バージョン要件でも、今後のゲーム、loader、Mod バージョンとの互換性を保証するものでもありません。正式に記録された最後のサイクルでは Abiotic Factor `1.4.0.27939` を使用しました。

**v0.4.12-alpha**

RandomDayGuard は Abiotic Factor 専用サーバーから取得した範囲限定の証拠を、
運用者が読めるレポートに整理します。サーバー状態、日次集計、プレイヤー活動、
ケース確認、重大障害は別々の経路で出力されます。

## インストール

[インストールガイド](%E3%82%A4%E3%83%B3%E3%82%B9%E3%83%88%E3%83%BC%E3%83%AB.md)に従ってください。Mod の場所は
`ue4ss/Mods/RandomDayGuard`、`mods.txt` の設定は `RandomDayGuard : 1` です。
入れ子の配置や重複した `Scripts` フォルダーは残さないでください。

## 最初のレポートを確認する

`runtime/current/startup_status.json`、
`runtime/final_logs/latest_dossier.json`、
`runtime/final_logs/route_proof.json` の順に確認します。各経路は `full`、
`limited_expected_empty`、`missing` のいずれかを示します。要約と参照元は同じ
処理サイクルのものでなければなりません。

## 設定と運用

公開初期値は `review_only_mode = true`、`auto_ban = false`、
`write_admin_ini = false` です。[開始手順](%E3%81%93%E3%81%93%E3%81%8B%E3%82%89%E9%96%8B%E5%A7%8B.md)、
[運用](%E6%93%8D%E4%BD%9C%E3%83%8F%E3%83%B3%E3%83%89%E3%83%96%E3%83%83%E3%82%AF.md)、[設定](%E8%A8%AD%E5%AE%9A%E3%83%97%E3%83%AD%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB.md)、
[トラブル対応](%E3%83%88%E3%83%A9%E3%83%96%E3%83%AB%E3%82%B7%E3%83%A5%E3%83%BC%E3%83%86%E3%82%A3%E3%83%B3%E3%82%B0.md)を参照してください。構造化された証拠が
技術記録であり、翻訳はその内容を読みやすくします。

コマンド、パス、キー、状態値は実ファイルと一致させるため英語のままです。

## アルファ版と2つの証拠経路

これはアルファ版です。文書化された収集、報告、復旧経路はテスト済みですが、互換性、履歴範囲、報告品質は引き続き改善中です。

現在経路はアクティブログ、現在の起動・スケジューラー状態、現在のセッションを使うため、現在の報告をすぐ作成できます。履歴経路は保存ログ、PlayerDataファイル名、既存証拠とケースを制限された手順で確認します。

`runtime/current/report_worker_status.json`

複数サイクルにわたり `runtime/current/report_worker_status.json` の `scan_cursor` と `last_progress_ts` を比較してください。進んでいればスキャン中です。現在報告が進む一方で変化しなければ履歴スキャンは停止しています。現在の事実は利用できますが、古い履歴が必要な結論は制限されます。
