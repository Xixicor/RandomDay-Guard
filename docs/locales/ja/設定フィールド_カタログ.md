# 完全な設定フィールド カタログ

> **正規の英語ソース:** [CONFIG_FIELD_CATALOG.md](../../CONFIG_FIELD_CATALOG.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


`python -B tools/generate_documentation_audit.py --write` によって生成。ジェネレーターは、純粋なデータの Lua テーブルを実行せずに解析します。 `RandomDayGuard/config.lua`から `python -B tools/generate_documentation_audit.py --check` とリポジトリ バリデータには、正確に生成されたコンテンツとリーフごとに 1 つのセマンティック行が必要です。配列と編集可能なマップは 1 つのリーフとしてカウントされ、出荷された内容が表示されます。

<a id="global-rules"></a>
## グローバル ルール

- 編集のみ`RandomDayGuard/config.lua`;以下のすべての例は、出荷された `return { ... }` テーブル内に直接挿入できるように形作られています。
- トップレベルの真理値は、`complete`, `complete_with_gaps`, `partial` と一致する必要があり、`unavailable`.
- `deferred`, `error`, `malformed` と一致する必要があり、`permission_denied` ソースレベルの条件だけです。ルート証明は残ります`full`, `limited_expected_empty`または `missing`.
- 必要な証拠、アカウント確認、信頼できるアカウント保護、バックアップ検証、保存されたファイルの比較、リカバリ、現在のサイクル証明を設定で上書きすることはできません。
- パスはローカルで汎用的なままです。アカウント ID、認証情報、プロバイダー ルート、プライベート インシデント、または生きた証拠を決してコミットしないでください。

<a id="change-and-recovery-procedure"></a>
## 変更と復元の手順

1. レビュー済みのファイルをバックアップする `config.lua`パッケージのステージング外。
2. 最小の所有テーブルを変更し、すべてのフィールドを文書化されたタイプに保ちます。
3. ジェネレーターを実行する `--check`、集中的なドキュメント テスト、`luac -p` 上の `config.lua` と一致する必要があり、`tools/validate_repo.py` 共有ランタイム ワークツリーが安定しているとき。
4. Guard を再起動し、所有者固有のファイルを検査します。state/output 上記の名前。
5. ロード、ソース、プルーフ、または書き込みの失敗が発生した場合は、出荷時の値またはレビュー済みのバックアップを復元します。強制の失敗はフェールクローズされたままになります。
