<a id="evidence-boundary"></a>
# 証拠の境界

> **正規の英語ソース:** [EVIDENCE_BOUNDARY.md](../../EVIDENCE_BOUNDARY.md). このローカライズされたドキュメントには、正確なコマンド、パス、キー、ステータス値、ハッシュ、ファイル名が保存されています。技術的な表現が異なる場合は、英語のソースを使用してください。


このページを使用して、何を決定するかを決定します。 RandomDayGuard はレポートできますが、人間によるレビューが必要なものも含めます。

<a id="core-rule"></a>
## 基本ルール

RandomDayGuard は、サーバー所有のファイルから限定された観察を記録します。すべての重要な結論について、ソース、範囲、収集状態、および制限を特定する必要があります。

構造化された証拠には信頼性があります。翻訳されたレポートで証拠が説明されています。構造化レコードにない事実を追加することはできません。

<a id="evidence-source-classes"></a>
## 証拠ソース クラス

| ソース クラス | 一般的な使用法 | それ自体では証明されません |
|---|---|---|
| `admin_ini` | 既存の管理状態と監査対象write/readbackコンテキスト | 誰インシデントの原因 |
| `active_log` | アクティブ ログに表示される現在のserver/sessionイベント | 意図、所有権、または直接的な損害 |
| `recent_backup_logs` | 履歴ログのコンテキスト | 現在のイベントが発生しました |
| `playerdata_filenames` | クリーンなアカウント識別子であることの裏付け存在する | 暴露された識別子を超えた行動、罪悪感、またはアイデンティティの所有権 |
| `existing_cases` | 以前のレビューのコンテキスト | 以前の解釈が依然として正しいこと |
| `existing_reports` | 以前の要約と決定 | 現在の確証のない現在の真実 |
| `existing_evidence` | 歴史的構造化証拠 | 現在の活動 |
| 制限付きワールドセーブ スキャン | 遅いworld/classコンテキスト | プレーヤーのアクション、所有権、盗難、複製、または損傷 |

各ソース レコードavailability/readability、ファイル数、ソース参照、現在または過去の範囲、および明示的な `does_not_prove`

<a id="source-states"></a>
## ソースの状態

| 状態 | 演算子の意味 |
|---|---|
| `available` | ソースは読み取り可能で、証拠が収集されました。 |
| `expected_empty` | ソースは読み取り可能で、合法的に一致する記録はありませんでした。 |
| `partial` | いくつかの証拠が収集されました。カバレッジが不完全です。 |
| `deferred` | 制限された作業は意図的に延期されました。 |
| `unavailable` | ソースがこの環境に存在しません。 |
| `malformed` | ソースは存在しますが、安全に解析できません。 |
| `permission_denied` | ウォッチドッグに読み取り権限がありません。 |
| `error` | 別の記録の収集に失敗しました。  |

空の期待値は有効な観察です。捏造されたプレーヤー、事件、事件、または告発に決して変換してはなりません。

<a id="current-versus-historical-evidence"></a>
## 現在の証拠と過去の証拠

現在の証拠は、アクティブな収集ウィンドウまたはサーバー エポックに属します。歴史的証拠は、以前のログ、ケース、レポート、証拠記録、バックアップ、またはベースラインから得られます。

歴史的証拠はコンテキストを提供します。現在の証拠のギャップを黙って埋めることはできません。レポートでは、両方の範囲にラベルを付け、ソースを個別に引用する必要があります。

<a id="corroboration-rule"></a>
## 確証ルール

これらは有用なコンテキストですが、それ自体では直接の証明にはなりません:

- 表示名または名前の類似性、
- タイミングの一致。
- 切断または再接続のチャーン、
- 1 回のクラッシュまたは警告バースト、
- クラス、パス、アクター、マップ、またはオブジェクト数のトークン、
- 自動的にグループ化されたケースのメンバーシップ、
- 現在のソースの確認なしの以前のレポート。

事実を直接暴露する証拠がない限り、罪悪感、故意、不正行為、所有権、盗難、複製、直接的な損害、直接的なコンテナの使用、直接的な在庫操作、正確なライブ座標、ライブ ping、またはメモリ レベルの動作を主張しないでください。

<a id="truthful-report-language"></a>
## 真実のレポート言語

使用:

```text
Observed: the account was active in the recorded crash window.
Interpretation: repeated overlap warrants operator review.
Unknown: the cause of the crash.
Does not prove: that the account caused the crash.
Next action: compare the cited current session and lifecycle records.
```

回避:

```text
The player crashed the server.
The player stole or duplicated items.
The world token proves who used the object.
```

<a id="report-reading-order"></a>
## レポートを読む順序

すべての公開レポートでは、次のことを説明する必要があります。

1. 単純な意味。
2. 重要な理由。
3. 技術的証明とソース参照。
4. 次のアクション。
5. 限界、未知の点、および証明されていない主張。
