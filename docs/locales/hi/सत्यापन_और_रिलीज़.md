# सत्यापन और रिलीज़

> **कैनोनिकल अंग्रेजी स्रोत:** [VALIDATION_AND_RELEASE.md](../../VALIDATION_AND_RELEASE.md). यह स्थानीयकृत दस्तावेज़ सटीक कमांड, पथ, कुंजियाँ, स्थिति मान, हैश और फ़ाइल नाम सुरक्षित रखता है। यदि तकनीकी शब्दांकन भिन्न है, तो अंग्रेजी स्रोत का उपयोग करें।


यह पृष्ठ योगदानकर्ताओं और रिलीज़ अनुरक्षकों के लिए है। सर्वर ऑपरेटरों को RandomDayGuard.

<a id="user-visible-proof"></a>
## उपयोगकर्ता-दृश्य प्रमाण

एक रिलीज़ तब समझ में आती है जब एक नया ऑपरेटर इसे स्थापित कर सकता है, पहली सर्वर-स्थिति रिपोर्ट ढूंढ सकता है, पांच रिपोर्ट मार्गों को अलग कर सकता है, और एक काम किए गए उदाहरण से एक स्पष्ट कार्रवाई का पालन कर सकता है। पाठक कार्यों के लिए Git की आवश्यकता नहीं होनी चाहिए, PowerShell, पायथन, या चेकसम ज्ञान।

<a id="contributor-checks"></a>
## योगदानकर्ता जाँच

```powershell
python -B tools/validate_repo.py
python -B tools/test_public_pipeline.py
python -B -m unittest discover tests
```

कब `luac` उपलब्ध है:

```powershell
luac -p RandomDayGuard/Scripts/main.lua
luac -p RandomDayGuard/Scripts/public_pipeline.lua
```

लुआ फिक्स्चर परीक्षण लोडर, शेड्यूलर, रिपोर्ट रूट और वैकल्पिक को कवर करते हैं Admin.ini लेनदेन लिखें। प्रवर्तन फिक्स्चर केवल अस्थायी फ़ाइलों का उपयोग करते हैं और पहचान, विश्वसनीय-खाता अस्वीकृति, थ्रेसहोल्ड, बैकअप, समवर्ती-परिवर्तन इनकार, रीडबैक और रोलबैक को सत्यापित करते हैं।

<a id="package-proof"></a>
## पैकेज प्रमाण

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

- सभी संस्करण मार्कर मेल खाते हैं `VERSION`.
- केवल वर्तमान संस्करण `releases/`.
- द ZIP में विहित `RandomDayGuard/Scripts/main.lua` पथ और कोई लोअरकेस-वेरिएंट लोडर नहीं।
- रनटाइम आउटपुट, निजी कॉन्फ़िगरेशन, क्रेडेंशियल, स्थानीय पथ, कैश और परीक्षण कलाकृतियों को बाहर रखा गया है।
- प्रवर्तन अक्षम होने पर सार्वजनिक कॉन्फ़िगरेशन केवल समीक्षा के लिए बना रहता है।
- पांच कार्य रिपोर्ट उदाहरण रूट स्वामित्व और रिलीज़ परीक्षण स्थिरता के अनुरूप बने हुए हैं।
- ZIP बाइट्स नियतात्मक हैं और `CHECKSUMS.sha256`.
- सभी स्थानीय दस्तावेज़ लिंक और 27 स्थानीय प्रविष्टि पृष्ठ मान्य हैं।

<a id="avoid-validation-environment-pitfalls"></a>
## सत्यापन पर्यावरण संबंधी कठिनाइयों से बचें

- अस्थायी-फ़ाइल विवाद से बचने के लिए रिपोजिटरी-लेखन जांच क्रमानुसार चलाएँ।
- विंडोज़ पर, डुप्लिकेट लोडर की जांच करते समय केस-असंवेदनशील फ़ाइल लुकअप के बजाय संग्रहीत सदस्य नाम या गणना पथ वर्तनी का निरीक्षण करें।
- एक अनुपलब्ध `luac` कमांड या लुआ रनटाइम एक अनुपलब्ध क्षमता है, पासिंग सिंटैक्स या रनटाइम टेस्ट नहीं।
- एक फिक्सचर केवल अपने मॉडल किए गए इनपुट को साबित करता है। यह साबित नहीं करता कि लाइव सर्वर ने वर्तमान रिपोर्ट तैयार की है।
- पूरा मानने के बजाय कमांड टाइमआउट और आंशिक आउटपुट रिकॉर्ड करें।

<a id="repair-failed-repository-validation"></a>
## मरम्मत विफल रिपॉजिटरी सत्यापन

पहले रिपोर्ट किए गए पथ या अनुबंध से प्रारंभ करें। उस आइटम को ठीक करें, संकीर्ण परीक्षण फिर से चलाएँ, फिर संपूर्ण मैट्रिक्स फिर से चलाएँ। जिस परीक्षण की आवश्यकता है उसे हटाकर किसी लुप्त क्षमता को न छिपाएं।

<a id="known-limits-and-release-decision"></a>
## ज्ञात सीमाएँ और रिलीज़ निर्णय

स्थानीय जांच स्रोत, फिक्स्चर, पैकेज और दस्तावेज़ीकरण अनुबंधों को साबित करती है। एक विशिष्ट सर्वर इंस्टॉलेशन, लंबे समय तक चलने वाली स्थिरता विंडो या क्लाइंट डिस्प्ले के लिए एक अलग एकीकरण परिणाम की आवश्यकता होती है। मिलान दावा करने से पहले उस परिणाम को उसके निर्माण, कॉन्फ़िगरेशन, अवधि और देखे गए आउटपुट के साथ रिकॉर्ड करें।
