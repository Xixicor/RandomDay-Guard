<a id="configuration-concepts"></a>
# कॉन्फ़िगरेशन अवधारणाएँ

> **कैनोनिकल अंग्रेजी स्रोत:** [CONFIG_REFERENCE.md](../../CONFIG_REFERENCE.md). यह स्थानीयकृत दस्तावेज़ सटीक कमांड, पथ, कुंजियाँ, स्थिति मान, हैश और फ़ाइल नाम सुरक्षित रखता है। यदि तकनीकी शब्दांकन भिन्न है, तो अंग्रेजी स्रोत का उपयोग करें।


यह स्पष्टीकरण बताता है कि प्रत्येक प्रमुख कॉन्फ़िगरेशन क्षेत्र क्या नियंत्रित करता है, यह कब चलता है, और यह साक्ष्य और सुरक्षा द्वारों के साथ कैसे इंटरैक्ट करता है। इसके पास सटीक फ़ील्ड कैटलॉग या प्रोफ़ाइल प्रक्रियाएँ नहीं हैं।

कार्य-उन्मुख प्रीसेट और सुरक्षित परिवर्तन चरणों के लिए, [`CONFIG_PROFILES.md`](%E0%A4%95%E0%A5%89%E0%A4%A8%E0%A5%8D%E0%A4%AB%E0%A4%BC%E0%A4%BF%E0%A4%97%E0%A4%B0_%E0%A4%AA%E0%A5%8D%E0%A4%B0%E0%A5%8B%E0%A4%AB%E0%A4%BC%E0%A4%BE%E0%A4%87%E0%A4%B2.md). प्रत्येक सटीक स्रोत फ़ील्ड, डिफ़ॉल्ट, प्रकार, अपरिवर्तनीय, आउटपुट प्रभाव और पुनर्प्राप्ति नियम के लिए, जेनरेट किए गए [`CONFIG_FIELD_CATALOG.md`](%E0%A4%95%E0%A5%89%E0%A4%A8%E0%A5%8D%E0%A4%AB%E0%A4%BC%E0%A4%BF%E0%A4%97_%E0%A4%AB%E0%A4%BC%E0%A5%80%E0%A4%B2%E0%A5%8D%E0%A4%A1_%E0%A4%95%E0%A5%88%E0%A4%9F%E0%A4%B2%E0%A5%89%E0%A4%97.md); सत्यापनकर्ता को प्रत्येक भेजे गए `config.lua` लीफ़ फ़ील्ड.

<a id="reading-this-page"></a>
## यह पेज पढ़ रहा हूं

प्रत्येक कॉन्फ़िगरेशन क्षेत्र उत्तर देता है:

```text
What it controls
When it runs
What to check
What can go wrong
```

<a id="top-level-safety"></a>
## शीर्ष-स्तरीय सुरक्षा

| विकल्प | डिफ़ॉल्ट | मतलब |
|---|---:|---|
| `enabled` | `true` | गार्ड के लिए मास्टर स्विच |
| `enforcement.review_only_mode` | `true` | Record/recommend केवल |
| `enforcement.auto_ban` | `false` | डिफ़ॉल्ट रूप से स्वचालित रूप से प्रतिबंध न लगाएं |
| `enforcement.write_admin_ini` | `false` | मत लिखें Admin.ini डिफ़ॉल्ट रूप से |

जब तक सर्वर मालिक आउटपुट की समीक्षा नहीं कर लेता, तब तक इन्हें सुरक्षित रखें।

<a id="saved"></a>
## `saved`

यह नियंत्रित करता है कि गार्ड सर्वर को कैसे ढूंढता है `Saved/` फ़ोल्डर और यह किस फ़ाइल परिवार को स्कैन कर सकता है।

कब उपयोग करें:

```text
Saved root auto-detection fails.
World folder changed.
Provider or container path is unusual.
```

चेक करें:

```text
runtime/saved_path_probe.json
RandomDayGuard/SavedRoot.txt
```

नियम:

```text
SavedRoot.txt -> AbioticFactor/Saved
not -> Worlds/<WorldName>
```

<a id="log_tail"></a>
## `log_tail`

लाइव लॉग रीडिंग को नियंत्रित करता है।

उपयोगी विकल्प:

| विकल्प | सुरक्षित मान | क्यों |
|---|---|---|
| `enabled` | `true` | लाइव डिफेंस के लिए आवश्यक |
| `start_at_end_on_first_run` | `true` | पुराने लॉग को लाइव इवेंट के रूप में लेने से बचें |
| `tail_backup_logs` | `false` | बैकअप लॉग इतिहास हैं, लाइव नहीं |
| `max_lines_per_poll` | बाउंडेड | पोल लूप को प्रतिक्रियाशील रखता है |

चेक करें:

```text
runtime/log_offsets.tsv
runtime/evidence/session_events.jsonl
runtime/current/poll_status.json
```

<a id="runtime"></a>
## `runtime`

मतदान और बजट को नियंत्रित करता है।

मुख्य स्वास्थ्य नियम:

```text
poll_id increases
poll_in_flight returns false
poll_scheduled is true
```

चेक करें:

```text
runtime/current/poll_status.json
```

यदि `poll_id` रुक जाता है, कुछ लूप को अवरुद्ध कर रहा है।

<a id="source_accounting"></a>
## `source_accounting`

स्पष्ट साक्ष्य-स्रोत कवरेज और दायरे को नियंत्रित करता है।

| कुंजी | डिफ़ॉल्ट | मतलब |
|---|---:|---|
| `enabled` | `true` | सार्वजनिक रूट रिपोर्ट के लिए स्रोत लेखांकन लिखता है। |
| `require_terminal_status` | `true` | प्रत्येक स्रोत को एक स्पष्ट टर्मिनल या अपूर्ण स्थिति को उजागर करने की आवश्यकता होती है। |
| `distinguish_current_from_historical` | `true` | वर्तमान और ऐतिहासिक साक्ष्यों को अलग रखता है। |
| `slow_world_scan_blocks_current_reports` | `false` | वर्तमान रिपोर्टों को यह बताने की अनुमति देता है कि बाउंडेड वर्ल्ड स्कैनिंग स्थगित या आंशिक है। |
| `changed_file_manifest` | बेसलाइन मेनिफेस्ट पथ | बाउंडेड के लिए उपयोग किया गया संदर्भ historical/world लेखांकन। |

स्रोत स्थितियाँ `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied`, या `error`.

सेटिंग `source_accounting.enabled = false` स्टेटस आउटपुट को चुपचाप नहीं हटाता है। पाइपलाइन अभी भी लिखती है `runtime/final_logs/source_accounting_latest.json` `enabled=false`, `status="unavailable"`, और `disabled_reason="source_accounting_disabled"`. यह अनुपलब्ध लेखांकन के साथ ऐतिहासिक-स्थिति रिकॉर्ड भी लिखता है। क्योंकि स्रोत लेखांकन रिपोर्ट अनुबंध का हिस्सा है, प्रत्येक मार्ग `missing`; लेखांकन अक्षम होने पर किसी भी मार्ग को पूर्ण नहीं माना जाता है।

<a id="reports"></a>
## `reports`

सामान्य स्थानीय रिपोर्टिंग पाइपलाइन को नियंत्रित करता है।

डिफ़ॉल्ट्स सभी पांच मार्गों को सक्षम करते हैं और `runtime/final_logs`:

```text
server_status
daily_rollup
player_activity
case_review
critical_guard
```

प्रत्येक रूट को `route_proof.json`. किसी रूट को अक्षम करने से `missing` यह दिखावा करने के बजाय कि यह पूरा हो गया है, इसका प्रमाण दें।

<a id="notification"></a>
## `notification`

वैकल्पिक जेनेरिक लोकल-फ़ाइल आउटबॉक्स। यह डिफ़ॉल्ट रूप से अक्षम है और बाहरी प्रदाता को कुछ भी नहीं भेजता है।

डिफ़ॉल्ट:

```lua
notification = {
    enabled = false,
    mode = "local_file_outbox",
    include_expected_empty = false,
},
```

प्रत्येक अधिसूचना मार्ग डिफ़ॉल्ट रूप से अक्षम है। जानबूझकर सक्षम किए जाने पर, आउटबॉक्स `route_proof.json` लिखा है। स्थानीय साक्ष्य और रिपोर्टें आधिकारिक बनी हुई हैं। प्रदाता-विशिष्ट डिलीवरी, डिलीवरी समापन बिंदु, क्रेडेंशियल्स और ब्रिज सार्वजनिक स्वतंत्र-प्रहरी अनुबंध का हिस्सा नहीं हैं।

<a id="scanning"></a>
## `scanning`

बेसलाइन स्कैन, चेकपॉइंटिंग और बदली हुई फ़ाइल रीफ्रेश को नियंत्रित करता है।

कब उपयोग करें:

```text
building first world baseline
resuming after crash
refreshing changed files later
```

चेक करें:

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/baselines/file_manifest.tsv
```

महत्वपूर्ण सेटिंग्स:

```lua
scanning = {
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
    changed_file_detection = true,
},
```

<a id="forensic_rollup"></a>
## `forensic_rollup`

त्वरित दैनिक अपलोड पैकेज और अंतिम सरल भाषा लॉग को नियंत्रित करता है।

आउटपुट:

```text
runtime/current/forensic_today.json
runtime/current/forensic_today.md
runtime/current/forensic_today.txt
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

कब उपयोग करें:

```text
You want one daily folder that summarizes what happened.
You want a plain-language TXT to upload for quick analysis.
```

चेक करें:

```text
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

नियम:

```text
Daily summaries are rebuildable indexes.
Source evidence remains authoritative.
```

<a id="logging"></a>
## `logging`

घटना की मात्रा और कम-महत्व एकत्रीकरण को नियंत्रित करता है।

कब उपयोग करें:

```text
actor-touch events are noisy
raw event files grow too quickly
```

सुरक्षित पैटर्न:

```lua
logging = {
    low_importance_mode = "aggregate",
    write_low_importance_raw_events = false,
},
```

<a id="retention"></a>
## `retention`

नियंत्रित करता है कि फ़ाइलें कितनी देर तक रखी जाएंगी और कब JSONL लॉग घूमते हैं।

कब उपयोग करें:

```text
disk usage grows too fast
you need more audit history
you need shorter live-history windows
```

महत्वपूर्ण विकल्प:

```text
detailed_retention_days
rotate_jsonl_when_bytes_exceed
max_raw_events_lines
keep_enforced_forever
keep_evidence_forever
```

<a id="warning_bursts"></a>
## `warning_bursts`

चेतावनी-विंडो पहचान को नियंत्रित करता है।

उदाहरण:

```text
ActorChannelFailure
DeployableSaveWarning
UpdateActorToWorldSave
ServerMove warnings
```

नियम:

```text
Warnings are context until correlated with mapped sessions and thresholds.
```

<a id="crash_correlation"></a>
## `crash_correlation`

नियंत्रण दोहराया गया crash/reconnect समीक्षा।

सुरक्षित डिफ़ॉल्ट:

```lua
crash_correlation = {
    single_crash_never_bans = true,
    require_same_account = true,
},
```

उपयोगी काउंटर:

```text
server_crash_overlap_count
post_crash_reconnect_count
unclean_disconnect_count
```

<a id="join_leave"></a>
## `join_leave`

मंथन और जॉइन-वेव ट्रैकिंग को नियंत्रित करता है।

सुरक्षित डिफ़ॉल्ट:

```lua
join_leave = {
    churn_alone_never_bans = true,
},
```

इसके लिए उपयोग करें:

```text
rapid reconnect loops
join waves
short-session patterns
```

<a id="raid_detection"></a>
## `raid_detection`

समूह खाते संबंधित विंडो में सक्रिय हैं।

नियम:

```text
A raid case groups accounts for review.
It does not make every account guilty.
```

प्रत्येक लागू खाते को अभी भी खाता-विशिष्ट साक्ष्य की आवश्यकता होती है।

<a id="object_registry"></a>
## `object_registry`

नियंत्रण object/class पठनीय सहेजे गए साक्ष्य से टोकन निष्कर्षण।

आउटपुट:

```text
runtime/object_registry_partial.json
runtime/object_registry.json
runtime/object_registry_counts.tsv
```

नियम:

```text
Object/class context is not a ban reason by itself.
```

<a id="world_state"></a>
## `world_state`

नियंत्रण boot/current/session विश्व-स्थिति स्नैपशॉट।

आउटपुट:

```text
runtime/world_state/current/world_state_latest.json
runtime/world_state/sessions/<date>/<session_id>_<account_id>/
```

सत्र समीक्षा और विश्व संदर्भ के लिए उपयोग करें।

<a id="enforcement"></a>
## `enforcement`

सिफारिशों और वास्तविक Admin.ini लिखता है।

गार्ड द्वारा प्रतिबंध लगाने से पहले, नीचे दिया गया प्रत्येक कथन सत्य होना चाहिए:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
account identity is mapped
not trusted
not moderator
threshold is met
```

यदि एक कथन गलत है या जाँचा नहीं जा सकता, तो गार्ड चला जाता है `Admin.ini` अपरिवर्तित है और कारण रिकॉर्ड करता है।

<a id="admin_ini"></a>
## `admin_ini`

सुरक्षित फ़ाइल लेखन को नियंत्रित करता है।

नियम:

```text
Back up before writing.
Preserve existing bans.
Preserve moderators.
Write clean BannedPlayer=<ID> only.
```

<a id="restart_request"></a>
## `restart_request`

वैकल्पिक स्थानीय मार्कर फ़ाइलों को नियंत्रित करता है जिनका कोई अन्य ऑपरेटर-स्वामित्व वाली प्रक्रिया निरीक्षण कर सकती है। यह सर्वर को पुनरारंभ या बंद नहीं करता है।

डिफ़ॉल्ट:

```lua
restart_request = {
    enabled = false,
    restart_marker_file = "runtime/request_restart.flag",
    restart_reason_file = "runtime/restart_reason.json",
},
```

आउटपुट:

```text
runtime/request_restart.flag
runtime/restart_reason.json
```

कोई होस्टिंग पैनल, प्रदाता ब्रिज या रीस्टार्ट ऑटोमेशन बंडल नहीं किया गया है। मार्कर निर्माण को सक्षम करने से यह साबित नहीं होता है कि किसी बाहरी प्रक्रिया ने अनुरोध का उपभोग कर लिया है या सर्वर को पुनरारंभ कर दिया है।
