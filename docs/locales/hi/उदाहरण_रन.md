# कार्य संचालन उदाहरण

> **कैनोनिकल अंग्रेजी स्रोत:** [EXAMPLE_RUNS.md](../../EXAMPLE_RUNS.md). यह स्थानीयकृत दस्तावेज़ सटीक कमांड, पथ, कुंजियाँ, स्थिति मान, हैश और फ़ाइल नाम सुरक्षित रखता है। यदि तकनीकी शब्दांकन भिन्न है, तो अंग्रेजी स्रोत का उपयोग करें।


ये उदाहरण अपेक्षित स्थिति परिवर्तनों को समझाने के लिए आविष्कृत मानों का उपयोग करते हैं; वे लाइव अनुकूलता या खिलाड़ी साक्ष्य नहीं हैं।

<a id="successful-current-cycle"></a>
## सफल वर्तमान चक्र

इनपुट: पढ़ने योग्य सक्रिय लॉग, version/boot/epoch, `poll_id=41`, वर्तमान मतदान पूर्ण, लिखने योग्य accounting/history/report रूट्स, कोई ब्लॉकिंग स्लो-स्कैन पॉलिसी नहीं।

अपेक्षित:

```text
server_status = full
player_activity = full or limited_expected_empty
case_review = full or limited_expected_empty
daily_rollup = full or limited_expected_empty
critical_guard = full or limited_expected_empty
```

प्रत्येक सक्षम मार्ग में JSON/TXT आउटपुट और `route_proof.json`. मार्ग की स्थिति उसके अपने विषयों पर निर्भर करती है, सामान्य सफलता संदेश पर नहीं।

<a id="expected-empty-player-and-case-routes"></a>
## अपेक्षित-रिक्त प्लेयर और केस रूट

इनपुट: वर्तमान-चक्र प्रमाण पूरा हो गया है; कोई मौजूदा या बरकरार खिलाड़ी पंक्ति नहीं; कोई बरकरार रखा गया मामला नहीं और कोई मौजूदा REVIEW/BAN-ELIGIBLE खाता.

अपेक्षित:

```text
player_activity.route_proof_status = limited_expected_empty
player_activity.expected_empty = true
player_activity.players = []

case_review.route_proof_status = limited_expected_empty
case_review.expected_empty = true
case_review.cases = []
```

अनुवादित रिपोर्टों में कहा गया है कि कोई भी योग्य सीमाबद्ध विषय नहीं देखा गया। वे यह भी कहते हैं कि इससे यह साबित नहीं होता कि कोई भी इससे जुड़ा नहीं है या कोई संदर्भ गायब नहीं है। कोई प्लेसहोल्डर नहीं player/case बनाया गया है।

<a id="partial-bounded-scan"></a>
## आंशिक बाउंडेड स्कैन

इनपुट: ताजा करंट log/poll; `scan_checkpoint.json` या `scan_progress.json` मौजूद है; स्कैन अधूरा है; डिफ़ॉल्ट`slow_world_scan_blocks_current_reports=false`.

अपेक्षित:

```text
world_save_scan.status = partial
source accounting = partial
server_status may still be full for fresh current state
historical routes name the scan limitation
```

सेट करें `slow_world_scan_blocks_current_reports=true` केवल तभी जब ऑपरेटर वर्तमान रिपोर्ट को अवरुद्ध करने के लिए उस वैकल्पिक धीमे स्रोत को चाहता है। पुनर्प्राप्ति स्कैन कर्मचारी को फिर से शुरू करने की अनुमति देने के लिए है, न कि चेकपॉइंट को हटाने के लिए।

<a id="missing-current-cycle-proof"></a>
## वर्तमान-चक्र प्रमाण गुम है

इनपुट: सक्रिय लॉग अनुपलब्ध, `poll_id=0`, या boot/epoch/last-poll वंशावली गायब है।

अपेक्षित:

```text
current_cycle_proof_complete = false
all route proof statuses = missing
each configured route envelope status = suppressed_current_cycle
delivery_eligible = false
delivery_attempted = false
```

दबाया गया लिफाफा एक ऑडिट रिकॉर्ड है, कतारबद्ध डिलीवरी नहीं। पुराने अंतिम लॉग केवल ऐतिहासिक ही रहते हैं। पहले लापता lineage/source फ़ील्ड और एक नया चक्र उत्पन्न करें।

<a id="malformed-optional-adminini-source"></a>
## विकृत वैकल्पिक Admin.ini स्रोत

इनपुट: `Admin.ini` मौजूद है लेकिन स्वच्छ संरचनात्मक सत्यापन विफल रहता है।

अपेक्षित:

```text
admin_ini.status = malformed
source reference preserved
write/enforcement path closed
```

फ़ाइल को सुरक्षित रखें और समीक्षा किए गए साफ़ प्रारूप को पुनर्स्थापित करें। रनटाइम साक्ष्य में व्याख्यात्मक पाठ रखें; प्रत्येक `Admin.ini` प्रतिबंध प्रविष्टि केवल `BannedPlayer=<ID>`.

<a id="required-active-log-probe-error"></a>
## आवश्यक सक्रिय-लॉग जांच त्रुटि

इनपुट: बाउंडेड आवश्यक सक्रिय-लॉग जांच एक सेनिटाइज़्ड रीड त्रुटि के साथ विफल हो जाती है।

अपेक्षित:

```text
source_accounting.sources[active_log].status = error
source_accounting.sources[active_log].detail = "bounded active-log probe failed: <sanitized reason>"
coverage_status = unavailable
all route proof statuses = missing
```

`error` अपने सीमित विवरण के साथ स्रोत पंक्ति पर बना रहता है। शीर्ष-स्तरीय रिपोर्ट `unavailable`, और रूट प्रूफ़ रहता है `missing` जब तक कि एक नया वर्तमान चक्र आवश्यक स्रोत साबित न हो जाए।

<a id="incompatible-or-stale-baseline"></a>
## असंगत या पुरानी आधार रेखा

इनपुट: बदला गया package/sourceपहचान या stale/incompatible बेसलाइन मेनिफेस्ट।

अपेक्षित: सत्यापन या रनटाइम स्थिति असंगति को रिकॉर्ड करती है; स्कैन स्थिति पूर्ण पुन: उपयोग का दावा नहीं करती है। पूर्व साक्ष्य को सुरक्षित रखें, एक स्पष्ट बेसलाइन पुनर्निर्माण शुरू करें, और नए टर्मिनल प्रमाण की प्रतीक्षा करें। रिकॉर्ड किए गए कारण के बिना जबरन पुनर्निर्माण डिफ़ॉल्ट पुनर्प्राप्ति नहीं है।

<a id="paired-report-write-failure"></a>
## युग्मित रिपोर्ट लिखने में विफलता

इनपुट: JSON लिखना सफल होता है लेकिन TXT लिखना विफल रहता है, या इसका उल्टा होता है।

अपेक्षित:

```text
route_proof_status = missing
completed = false
coverage_status = unavailable
output_write_detail = "paired JSON/TXT write failed: <sanitized reason>"
next_action = repair both route output writes
```

लेखक दोनों भाई-बहनों को विफलता पर एकाग्र करने के लिए सर्वोत्तम प्रयास करता है। एक सफल भाई-बहन सफलता का दावा बनकर नहीं रह सकता। बंधा हुआ लेखन विवरण पांचवां शीर्ष-स्तरीय कवरेज मान नहीं बनाता है।

<a id="route-proof-write-failure"></a>
## रूट-प्रूफ़ लेखन विफलता

इनपुट: रूट जोड़े लिखे गए थे लेकिन `route_proof.json` को बदला नहीं जा सकता।

अपेक्षित: सभी रिपोर्ट दोबारा लिखी गई हैं `missing`, सभी अधिसूचना परिणाम `route_proof_write_failed`, और कोई लिफाफा स्वीकार नहीं किया जाता है। एक कॉन्फ़िगर किए गए मार्ग में `suppressed_current_cycle` डिलीवरी फ़्लैग वाला ऑडिट लिफ़ाफ़ा ग़लत है। आउटपुट रूट की मरम्मत करें और उसी वर्तमान चक्र को पुन: उत्पन्न करें।

<a id="review-only-enforcement-example"></a>
## केवल-समीक्षा प्रवर्तन उदाहरण

कॉन्फ़िगर:

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

अपेक्षित: स्कोर, मामले और सिफ़ारिशें लिखी जा सकती हैं; `Admin.ini` अपरिवर्तित रहता है। यह सार्वजनिक डिफ़ॉल्ट है.

<a id="approved-write-success-example"></a>
## स्वीकृत लेखन सफलता का उदाहरण

केवल एक अलग से स्वीकृत परीक्षण ही तीनों लेखन स्विच सेट कर सकता है। इसे स्वच्छ संख्यात्मक पहचान भी साबित करनी होगी, trust/moderator बहिष्करण, सीमा पात्रता, मान्य Admin.ini path/parse, बैकअप सफलता, लेखन सफलता, रीडबैक समानता, और खाता-विशिष्ट साक्ष्य।

अपेक्षित:

```text
runtime/backups/Admin_<timestamp>_<source-fingerprint>_<clean-ID>.ini
Admin.ini contains one clean BannedPlayer=<ID>
runtime/enforced_bans.jsonl and evidence mirror record success
```

सफल उदाहरण अन्य खातों के लिए स्वचालित प्रवर्तन सक्षम नहीं करता है।

<a id="writereadback-failure-with-rollback"></a>
## Write/readback रोलबैक में विफलता

इनपुट: प्रत्येक प्री-राइट गेट पास हुआ; प्रतिस्थापन लेखन या रीडबैक विफल रहता है; `rollback_on_readback_failure=true` और सत्यापित बैकअप उपलब्ध है।

अपेक्षित: विफलता साक्ष्य चरण को रिकॉर्ड करता है और `rollback_success`; मूल Admin.ini बाइट्स बहाल कर दिए गए हैं और खाते को सफलतापूर्वक लागू नहीं किया गया है। यदि रोलबैक भी विफल हो जाता है, तो लिखना बंद करें, दोनों को सुरक्षित रखें files/evidence, और बैकअप से मैन्युअल रूप से पुनर्प्राप्त करें।

<a id="local-outbox-example"></a>
## स्थानीय आउटबॉक्स उदाहरण

इनपुट: अधिसूचना `local_file_outbox` मोड, रूट सक्षम, पूर्ण रूट प्रूफ, और या तो `full` या स्पष्ट रूप से अपेक्षित-रिक्त की अनुमति है।

अपेक्षित लिफ़ाफ़ा:

```text
schema = randomdayguard.notification/v1
completed_output = true
status = ready_for_local_consumer
delivery_eligible = true
delivery_backend = none
delivery_attempted = false
```

के लिए missing/ineligible आउटपुट, इसके बजाय उसी पथ में `status=suppressed_current_cycle`, `completed_output=false`, और `delivery_eligible=false`. कोई भी फ़ाइल केवल स्थानीय लेखन साबित करती है। कोई प्रदाता, परिवहन, वितरण, या पठन रसीद बंडल या अनुमानित नहीं है।
