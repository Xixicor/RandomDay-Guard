<a id="bad-actor-patterns-and-resilience"></a>
# खराब-अभिनेता पैटर्न और लचीलापन

> **कैनोनिकल अंग्रेजी स्रोत:** [BAD_ACTOR_PATTERNS_AND_RESILIENCE.md](../../BAD_ACTOR_PATTERNS_AND_RESILIENCE.md). यह स्थानीयकृत दस्तावेज़ सटीक कमांड, पथ, कुंजियाँ, स्थिति मान, हैश और फ़ाइल नाम सुरक्षित रखता है। यदि तकनीकी शब्दांकन भिन्न है, तो अंग्रेजी स्रोत का उपयोग करें।


यह समझने के लिए इस पृष्ठ का उपयोग करें कि गार्ड क्रैश दुरुपयोग, शोषण-आसन्न व्यवहार और पुनर्प्राप्ति योजना की समीक्षा करने में कैसे मदद करता है।

<a id="what-the-guard-can-help-with"></a>
## गार्ड इसमें क्या मदद कर सकता है

| पैटर्न | क्या जांचें |
|---|---|
| क्रैश-सहसंबद्ध रिटर्न | क्रैश होने से पहले वही खाता सक्रिय है और पुनरारंभ होने के बाद वापस आ रहा है |
| रैपिड रीकनेक्ट प्रोबिंग | दोहराया गया join/leave या timeout/reconnect लूप्स |
| मल्टी-अकाउंट क्लस्टर | ज्वाइन वेव्स, साझा चेतावनी विंडो, साझा विफलता विंडो |
| चेतावनी विस्फोट तनाव | दोहराया गया ActorChannelFailure या सेव-चेतावनी विंडो |
| आउट-ऑफ-बाउंड संदर्भ | PlayerData/map/world पढ़ने योग्य होने पर संदर्भ |
| सेव-टच ओवरलैप | विश्व-सेव संदर्भ ओवरलैपिंग मैप किए गए सत्र |
| पहचान संबंधी भ्रम | वे नाम जिन्हें ConnectID मैपिंग की आवश्यकता है |

<a id="why-it-avoids-memory-access"></a>
## यह मेमोरी एक्सेस से क्यों बचता है

RandomDayGuard सर्वर-स्वामित्व वाली फ़ाइलों से काम करता है:

```text
Saved/Logs/*.log
Admin.ini
World saves
PlayerData
Backups
runtime evidence
```

यह इसे क्लाइंट-साइड मेमोरी स्थिति पर कम निर्भर बनाता है और गेम अपडेट में कम नाजुक बनाता है।

ट्रेडऑफ़:

```text
It cannot prove hidden live actions unless the server writes evidence.
```

<a id="crash-correlated-returners"></a>
## क्रैश-सहसंबद्ध रिटर्नर्स

पैटर्न:

```text
Account joins.
Server crashes or restarts.
Same account reconnects quickly.
Pattern repeats.
```

उपयोगी फ़ाइलें:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="rapid-reconnect-probers"></a>
## रैपिड रीकनेक्ट प्रोबर्स

पैटर्न:

```text
join -> leave -> join -> leave -> join
```

उपयोगी फ़ाइलें:

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
```

<a id="multi-account-clusters"></a>
## मल्टी-अकाउंट क्लस्टर

पैटर्न:

```text
Several accounts join in the same window.
Warnings or crashes follow.
Some accounts rotate or reconnect after restart.
```

उपयोगी फ़ाइलें:

```text
runtime/raid_cases/
runtime/forensic_days/YYYY-MM-DD/raid_cases.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

नियम:

```text
A cluster is not a mass-ban list.
Each account still needs its own evidence.
```

<a id="sticky-backup-recommendation"></a>
## स्टिकी बैकअप अनुशंसा

इसके बाद एक स्टिकी बैकअप बनाएं:

```text
first full baseline completes
object_registry.json exists
file_manifest.tsv exists
world_state_latest.json has scan_complete=true
Admin.ini is verified
trusted IDs are configured
```

बैक अप:

```text
RandomDayGuard/config.lua
RandomDayGuard/SavedRoot.txt
RandomDayGuard/runtime/baselines/
RandomDayGuard/runtime/object_registry.json
RandomDayGuard/runtime/world_state/current/world_state_latest.json
Saved/SaveGames/Server/Admin.ini
```

<a id="recovery-model"></a>
## रिकवरी मॉडल

```text
Clean install
-> verify live defense
-> complete first baseline
-> create sticky backup
-> run server normally
-> use daily rollups for review
-> restore sticky backup if needed
```
