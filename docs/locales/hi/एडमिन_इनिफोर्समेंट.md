# Admin.ini प्रवर्तन

> **कैनोनिकल अंग्रेजी स्रोत:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). यह स्थानीयकृत दस्तावेज़ सटीक कमांड, पथ, कुंजियाँ, स्थिति मान, हैश और फ़ाइल नाम सुरक्षित रखता है। यदि तकनीकी शब्दांकन भिन्न है, तो अंग्रेजी स्रोत का उपयोग करें।


RandomDayGuard अपने डिफ़ॉल्ट सेटअप में सर्वर प्रतिबंध सूची को नहीं बदलता है। यह केवल व्यवस्थापक के समीक्षा हेतु रिपोर्ट बनाता है। यह पृष्ठ उन व्यवस्थापकों के लिए वैकल्पिक स्वचालित प्रतिबंध-सूची अद्यतन की व्याख्या करता है जो इसे जानबूझकर सक्षम करते हैं।

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## प्रतिबंध सूची बदलने से पहले गार्ड क्या जाँचता है

गार्ड केवल तभी प्रतिबंध लगाता है जब नीचे दिया गया प्रत्येक उत्तर **हाँ**:

1. क्या वर्तमान साक्ष्य ने पर्याप्त विश्वास के साथ एक विशिष्ट खाते की पहचान की है?
2. क्या खाता न तो मॉडरेटर है और न ही वह खाता जिसे व्यवस्थापक ने विश्वसनीय के रूप में चिह्नित किया है?
3. क्या खाता पहले से ही प्रतिबंध सूची में नहीं है?
4. क्या खाता कॉन्फ़िगर किए गए स्वचालित-क्रिया स्कोर तक पहुंच गया?
5. क्या गार्ड करंट पढ़ सकता है `Admin.ini` और एक समान बैकअप सहेजें?
6. किया `Admin.ini` जब गार्ड अपडेट तैयार कर रहा हो तो क्या यह अपरिवर्तित रहेगा?
7. सहेजने के बाद, क्या पूरी फ़ाइल इच्छित परिणाम से बिल्कुल मेल खाती है?

यदि कोई उत्तर है तो **नहीं**, या जाँच नहीं की जा सकती, गार्ड चला जाता है `Admin.ini` अपरिवर्तित है और अपनी रिपोर्ट में कारण दर्ज करता है। यदि बचत शुरू हो जाती है लेकिन अंतिम जांच विफल हो जाती है, तो गार्ड सत्यापित बैकअप को पुनर्स्थापित करता है।

<a id="file-format"></a>
## फ़ाइल स्वरूप

`Admin.ini` को केवल स्वच्छ प्रतिबंध लाइनें प्राप्त होनी चाहिए:

```ini
BannedPlayer=<ID>
```

- कोई नाम नहीं।
- कोई टिप्पणी नहीं।
- कोई कारण नहीं।
- कोई प्रत्यय नहीं।

<a id="safe-defaults"></a>
## सुरक्षित डिफ़ॉल्ट

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## आईडी स्रोत पर प्रतिबंध लगाएं

सर्वश्रेष्ठ स्रोत:

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

रनटाइम या तो पूरी तरह से संख्यात्मक आईडी या संपूर्ण दस्तावेज़ को स्वीकार करता है `<digits>_+_|<non-space token>` कनेक्शन फॉर्म और इससे संख्यात्मक प्रतिबंध आईडी प्राप्त होता है। अज्ञात प्रत्यय के साथ मनमाना संख्यात्मक उपसर्ग अस्वीकार कर दिए जाते हैं; उन्हें प्रतिबंध आईडी में नहीं काटा गया है।

सही:

```ini
BannedPlayer=2535422284688820
```

गलत:

```ini
BannedPlayer=ExamplePlayer
```

यह भी गलत है:

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## सटीक सेटिंग्स गार्ड जाँचता है

ये सेटिंग्स ऊपर वर्णित जांचों को लागू करती हैं। प्रत्येक सूचीबद्ध शर्त सत्य होनी चाहिए:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

यदि कोई शर्त गलत है या जाँच नहीं की जा सकती है, तो गार्ड प्रतिबंध सूची को अपरिवर्तित छोड़ देता है और रिकॉर्ड करता है कि इसे किसने रोका।

<a id="transaction-safety"></a>
## लेन-देन सुरक्षा

एकमात्र `Admin.ini` उत्परिवर्तन पथ इन चरणों को क्रम में निष्पादित करता है:

1. आधिकारिक बाइट्स पढ़ें और संरचनात्मक रूप से मान्य करें।
2. उसी स्नैपशॉट से मॉडरेटर, विश्वसनीय और मौजूदा-प्रतिबंध स्थिति प्राप्त करें।
3. `runtime/backups/` और इसे बाइट दर बाइट सत्यापित करें।
4. फिर से पढ़ें `Admin.ini` प्रतिस्थापन से ठीक पहले और किसी भी बाहरी परिवर्तन को अस्वीकार करें।
5. कॉन्फ़िगर नियंत्रित प्रतिस्थापन पथ के माध्यम से उम्मीदवार लिखें।
6. संपूर्ण उम्मीदवार बाइट्स के बराबर करने के लिए संपूर्ण रीडबैक बाइट्स की आवश्यकता होती है।
7. रीडबैक विफलता पर, सत्यापित बैकअप को केवल तभी पुनर्स्थापित करें जब वर्तमान फ़ाइल अभी भी गार्ड द्वारा लिखी गई सटीक उम्मीदवार हो। यदि किसी अन्य लेखक ने इसे बदल दिया है, तो गार्ड अज्ञात बाहरी बाइट्स को अधिलेखित करने के बजाय रोलबैक से इनकार कर देता है।

डुप्लिकेट आईडी बेकार हैं: कोई दूसरी पंक्ति और कोई दूसरा बैकअप नहीं लिखा जाता है। बैकअप नामों में टाइमस्टैम्प, सोर्स-बाइट फिंगरप्रिंट और क्लीन आईडी शामिल है, इसलिए अलग-अलग प्रयास पुराने एक-सेकंड फ़ाइल नाम को साझा नहीं कर सकते हैं।

<a id="local-regression-proof"></a>
## स्थानीय प्रतिगमन प्रमाण

`tests/lua/enforcement_runtime_test.lua` भेजे गए लोडर को एक बार बूट करता है और फिर उसके वास्तविक स्थानीय को निष्पादित करता है `append_ban()` रिपॉजिटरी के नीचे पृथक सिंथेटिक फ़ाइलों के विरुद्ध बंद होना `.tmp/` निर्देशिका। इसमें इंसर्शन, डुप्लिकेट इडेम्पोटेंसी, moderator/trusted अस्वीकृति, कमजोर और विकृत पहचान अस्वीकृति, बाइट-सटीक बैकअप सत्यापन, समवर्ती संशोधन अस्वीकृति, असफल रीडबैक के बाद सफल रोलबैक, और पोस्ट-राइट बाहरी परिवर्तन को ओवरराइट करने से इनकार। इसके फ़ाइल सिस्टम रैपर फिक्स्चर रूट के बाहर किसी भी उत्परिवर्तन को अस्वीकार करते हैं; कोई वास्तविक सर्वर पथ या वास्तविक `Admin.ini` का उपयोग किया जाता है।

इसे `python tools/test_public_pipeline.py`. फिक्स्चर पास केवल स्थानीय लेनदेन व्यवहार को साबित करता है। यह प्रवर्तन को सक्षम नहीं करता है, उत्पादन लेखन को अधिकृत नहीं करता है, या होस्ट-विशिष्ट अनुमतियों को साबित नहीं करता है।

<a id="rollback"></a>
## रोलबैक

1. सर्वर बंद करें।
2. नवीनतम पुनर्स्थापित करें Admin.ini `runtime/backups/`.
3. गलत को हटाएं `BannedPlayer=<ID>` लाइन।
4. सर्वर प्रारंभ करें।
5. फिर से खोलें Admin.ini और पुष्टि करें कि लाइन कायम है या हटा दी गई है।
6. संरक्षित करें `enforced_bans.jsonl` ऑडिट के लिए।
