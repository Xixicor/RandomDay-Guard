# योगदान

> **कैनोनिकल अंग्रेजी स्रोत:** [CONTRIBUTING.md](../../../CONTRIBUTING.md). यह स्थानीयकृत दस्तावेज़ सटीक कमांड, पथ, कुंजियाँ, स्थिति मान, हैश और फ़ाइल नाम सुरक्षित रखता है। यदि तकनीकी शब्दांकन भिन्न है, तो अंग्रेजी स्रोत का उपयोग करें।


RandomDayGuard पार्सर्स, दस्तावेज़ीकरण, परीक्षण और सार्वजनिक-सुरक्षित सत्यापन में केंद्रित, प्रतिलिपि प्रस्तुत करने योग्य सुधार स्वीकार करता है। प्रत्येक परिवर्तन को सार्वजनिक परियोजना अनुबंध तक सीमित रखें और समीक्षा-प्रथम व्यवहार बनाए रखें: गार्ड को छोड़ देना चाहिए `Admin.ini` आवश्यक सुरक्षा जांच की पुष्टि नहीं होने पर अपरिवर्तित।

<a id="prepare-a-safe-workspace"></a>
## एक सुरक्षित कार्यस्थल तैयार करें

1. रिपॉजिटरी को फोर्क या क्लोन करें और एक केंद्रित शाखा बनाएं।
2. एक समर्थित Python 3 दुभाषिया स्थापित करें। जब आप Lua को बदलते हैं तो एक Lua कंपाइलर स्थापित करें `luac -p` सिंटैक्स की जांच कर सकता है।
3. पढ़ें [दस्तावेज़ीकरण होम](%E0%A4%A6%E0%A4%B8%E0%A5%8D%E0%A4%A4%E0%A4%BE%E0%A4%B5%E0%A5%87%E0%A4%9C%E0%A4%BC%E0%A5%80%E0%A4%95%E0%A4%B0%E0%A4%A3.md), [आर्किटेक्चर](%E0%A4%86%E0%A4%B0%E0%A5%8D%E0%A4%95%E0%A4%BF%E0%A4%9F%E0%A5%87%E0%A4%95%E0%A5%8D%E0%A4%9A%E0%A4%B0.md), और [साक्ष्य सीमा](%E0%A4%B8%E0%A4%BE%E0%A4%95%E0%A5%8D%E0%A4%B7%E0%A5%8D%E0%A4%AF_%E0%A4%B8%E0%A5%80%E0%A4%AE%E0%A4%BE.md) उस क्षेत्र के लिए जिसे आप बदलेंगे।
4. निरीक्षण करें `git status` असंबद्ध कार्य को संपादित करने और संरक्षित करने से पहले।
5. केवल सिंथेटिक या सैनिटाइज्ड फिक्स्चर का उपयोग करें।

कभी भी निजी सर्वर लॉग, सहेजे गए फ़ोल्डर, प्लेयर पहचानकर्ता सबमिट न करें `Admin.ini`, निजी अधिसूचना समापन बिंदु, क्रेडेंशियल, निजी पथ, रनटाइम आउटपुट, या कॉपी किए गए लाइव साक्ष्य।

<a id="make-a-focused-change"></a>
## एक केंद्रित परिवर्तन करें

- मौजूदा नामकरण, स्वरूपण, सुरक्षा जांच और मॉड्यूल स्वामित्व का पालन करें।
- प्रत्येक प्रक्रिया या सटीक तथ्य के लिए एक विहित दस्तावेज़ स्वामी रखें।
- व्यवहार या सार्वजनिक आउटपुट में परिवर्तन होने पर उपयोगकर्ता दस्तावेज़ और उदाहरण अपडेट करें।
- व्यावहारिक होने पर बग फिक्स के लिए एक रिग्रेशन टेस्ट जोड़ें।
- परीक्षण पास करने के लिए खाता पुष्टिकरण, विश्वसनीय-खाता सुरक्षा, बैकअप सत्यापन, बाहरी-परिवर्तन का पता लगाना, सहेजी गई फ़ाइल तुलना, पुनर्प्राप्ति, या केवल-समीक्षा डिफ़ॉल्ट को कमजोर न करें।

<a id="run-the-relevant-checks"></a>
## संबंधित जांच चलाएँ

केवल दस्तावेज़ीकरण परिवर्तनों के लिए, चलाएँ:

```powershell
python -B tools\generate_documentation_audit.py --check
python -B -m unittest discover tests -p "test_documentation*.py"
git diff --check
```

स्रोत, कॉन्फ़िगरेशन, पैकेजिंग या परीक्षण परिवर्तनों के लिए, [सत्यापन और रिलीज़ समीक्षा](%E0%A4%B8%E0%A4%A4%E0%A5%8D%E0%A4%AF%E0%A4%BE%E0%A4%AA%E0%A4%A8_%E0%A4%94%E0%A4%B0_%E0%A4%B0%E0%A4%BF%E0%A4%B2%E0%A5%80%E0%A4%9C%E0%A4%BC.md), जिसमें लुआ सिंटैक्स जांच, रिपॉजिटरी सत्यापन, सार्वजनिक-पाइपलाइन परीक्षण और पूर्ण यूनिट-टेस्ट सूट शामिल है। प्रत्येक छूटे हुए या अनुपलब्ध चेक की रिपोर्ट करें; इसे पारित के रूप में वर्णित न करें।

<a id="submit-the-change-for-review"></a>
## समीक्षा के लिए परिवर्तन सबमिट करें

पूरे अंतर की समीक्षा करने के बाद ही एक केंद्रित पुल अनुरोध खोलें। शामिल करें:

- समस्या और इच्छित व्यवहार;
- सटीक फ़ाइलें और सार्वजनिक अनुबंध बदल गए;
- आदेश चलते हैं और उनके परिणाम;
- गोपनीयता, अनुकूलता, और प्रवर्तन प्रभाव; और
- शेष सीमाएँ या अनुवर्ती कार्य।

जनरेट किए गए रनटाइम साक्ष्य या रिलीज़ आर्काइव को तब तक शामिल न करें जब तक कि परिवर्तन के लिए स्पष्ट रूप से आवश्यकता न हो और उन्हें मान्य न किया जाए। कोई योगदान किसी तृतीय-पक्ष साइट पर रिलीज़, परिनियोजन, लाइव-सर्वर परीक्षण, प्रवर्तन कार्रवाई या प्रकाशन को अधिकृत नहीं करता है।

[निजी सुरक्षा मार्ग](%E0%A4%B8%E0%A5%81%E0%A4%B0%E0%A4%95%E0%A5%8D%E0%A4%B7%E0%A4%BE.md), कोई सार्वजनिक समस्या या सामान्य पुल अनुरोध नहीं।
