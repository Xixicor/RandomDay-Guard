# सुरक्षा नीति

> **कैनोनिकल अंग्रेजी स्रोत:** [SECURITY.md](../../../SECURITY.md). यह स्थानीयकृत दस्तावेज़ सटीक कमांड, पथ, कुंजियाँ, स्थिति मान, हैश और फ़ाइल नाम सुरक्षित रखता है। यदि तकनीकी शब्दांकन भिन्न है, तो अंग्रेजी स्रोत का उपयोग करें।


<a id="report-a-vulnerability-privately"></a>
## निजी तौर पर भेद्यता की रिपोर्ट करें

उपयोग करें [GitHub निजी भेद्यता रिपोर्टिंग](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) रिपॉजिटरी मालिक को एक गोपनीय रिपोर्ट भेजने के लिए। यदि वह फॉर्म उपलब्ध नहीं है, तो [मालिक की सार्वजनिक GitHub प्रोफ़ाइल](https://github.com/Xixicor) भेद्यता विवरण शामिल किए बिना एक निजी संपर्क चैनल का अनुरोध करने के लिए।

एक्सप्लॉइट स्टेप्स, क्रेडेंशियल्स, प्राइवेट सर्वर पाथ्स, प्लेयर आइडेंटिफ़ायर आदि वाले सार्वजनिक मुद्दे को न खोलें। `Admin.ini`, सहेजा गया डेटा, वेबहुक यूआरएल, या लाइव साक्ष्य फ़ाइलें।

<a id="include-useful-evidence"></a>
## उपयोगी साक्ष्य शामिल करें

प्रदान करें:

- प्रभावित RandomDayGuard संस्करण या कमिट;
- प्रभावित घटक और अपेक्षित सुरक्षित व्यवहार;
- स्वच्छीकृत फिक्स्चर का उपयोग करके न्यूनतम पुनरुत्पादन चरण;
- देखा गया प्रभाव और क्या यह दोहराने योग्य है; और
- कोई भी प्रस्तावित शमन जो निजी डेटा को उजागर नहीं करता है।

वास्तविक रहस्य न भेजें। समस्या को पुन: उत्पन्न करने के लिए आवश्यक संरचना को संरक्षित करते हुए निजी पथ, खाता पहचानकर्ता, होस्टनाम और टोकन को स्पष्ट प्लेसहोल्डर से बदलें।

<a id="expect-review-first-handling"></a>
## समीक्षा-प्रथम प्रबंधन की अपेक्षा करें

एक रिपोर्ट अनुरक्षक समीक्षा के लिए साक्ष्य है, न कि सर्वर तक पहुंचने, लाइव लक्ष्य का परीक्षण करने, शोषण विवरण प्रकाशित करने, या असफल-बंद डिफ़ॉल्ट को कमजोर करने के लिए प्राधिकरण। मालिक निजी रिपोर्ट के माध्यम से दायरे को सत्यापित करेगा और किसी भी प्रकटीकरण का समन्वय करेगा।
