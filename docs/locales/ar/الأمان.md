# سياسة الأمان

> **المصدر الإنجليزي الأساسي:** [SECURITY.md](../../../SECURITY.md). تحتفظ هذه الوثائق المترجمة بالأوامر والمسارات والمفاتيح وقيم الحالة والتجزئة وأسماء الملفات بشكل دقيق. إذا اختلفت الصياغة الفنية، استخدم المصدر باللغة الإنجليزية.


<a id="report-a-vulnerability-privately"></a>
## الإبلاغ عن ثغرة أمنية بشكل خاص

استخدم [GitHub الإبلاغ عن الثغرات الخاصة](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) لإرسال تقرير سري إلى مالك المستودع. إذا لم يكن هذا النموذج متاحًا، فاستخدم [الملف الشخصي GitHub العام للمالك](https://github.com/Xixicor) لطلب قناة اتصال خاصة دون تضمين تفاصيل الثغرة الأمنية.

لا تفتح مشكلة عامة تحتوي على خطوات الاستغلال أو بيانات الاعتماد أو مسارات الخادم الخاصة أو معرفات اللاعبين `Admin.ini` أو البيانات المحفوظة أو عناوين URL للخطاف على الويب أو ملفات الأدلة المباشرة.

<a id="include-useful-evidence"></a>
## تضمين أدلة مفيدة

تقديم:

- المتأثرة RandomDayGuard الإصدار أو الالتزام؛
- المكون المتأثر والسلوك الآمن المتوقع؛
- الحد الأدنى من خطوات إعادة الإنتاج باستخدام التركيبات المعقمة؛
- التأثير الملحوظ وما إذا كان قابل للتكرار؛ و
- أي إجراءات تخفيف مقترحة لا تكشف البيانات الخاصة.

لا ترسل أسرارًا حقيقية. استبدل المسارات الخاصة ومعرفات الحساب وأسماء المضيفين والرموز المميزة بعناصر نائبة واضحة مع الحفاظ على البنية اللازمة لإعادة إنتاج المشكلة.

<a id="expect-review-first-handling"></a>
## توقع التعامل مع المراجعة أولاً

التقرير هو دليل على مراجعة المشرف، وليس ترخيصًا للوصول إلى الخادم، أو اختبار هدف مباشر، أو نشر تفاصيل الاستغلال، أو إضعاف الإعدادات الافتراضية التي تم إغلاقها بعد الفشل. وسيقوم المالك بالتحقق من صحة النطاق وتنسيق أي إفصاح من خلال التقرير الخاص.
