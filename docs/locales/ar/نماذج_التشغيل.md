# أمثلة العمليات العملية

> **المصدر الإنجليزي الأساسي:** [EXAMPLE_RUNS.md](../../EXAMPLE_RUNS.md). تحتفظ هذه الوثائق المترجمة بالأوامر والمسارات والمفاتيح وقيم الحالة والتجزئة وأسماء الملفات بشكل دقيق. إذا اختلفت الصياغة الفنية، استخدم المصدر باللغة الإنجليزية.


تستخدم هذه الأمثلة قيمًا مخترعة لشرح تحولات الحالة المتوقعة؛ فهي ليست توافقًا مباشرًا أو دليلًا على اللاعب.

<a id="successful-current-cycle"></a>
## الدورة الحالية الناجحة

المدخلات: سجل نشط قابل للقراءة، version/boot/epoch, `poll_id=41`، استطلاع حالي مكتمل، جذور accounting/history/report قابلة للكتابة، لا توجد سياسة حظر للمسح البطيء.

المتوقع:

```text
server_status = full
player_activity = full or limited_expected_empty
case_review = full or limited_expected_empty
daily_rollup = full or limited_expected_empty
critical_guard = full or limited_expected_empty
```

يحتوي كل مسار مُمكّن على JSON/TXT ومخرجات ونفس السلالة في `route_proof.json`. تعتمد حالة المسار على موضوعاته الخاصة، وليس على رسالة نجاح عامة.

<a id="expected-empty-player-and-case-routes"></a>
## المشغل الفارغ المتوقع ومسارات الحالة

المدخلات: اكتمل إثبات الدورة الحالية؛ لا توجد صفوف لاعب حالية أو محتفظ بها؛ لا توجد حالة محتفظ بها ولا يوجد حساب REVIEW/BAN-ELIGIBLE حالي.

المتوقع:

```text
player_activity.route_proof_status = limited_expected_empty
player_activity.expected_empty = true
player_activity.players = []

case_review.route_proof_status = limited_expected_empty
case_review.expected_empty = true
case_review.cases = []
```

تشير التقارير المترجمة إلى عدم ملاحظة أي موضوع محدد مؤهل. ويقولون أيضًا إن هذا لا يثبت عدم اتصال أي شخص على الإطلاق أو أنه لا يوجد سياق مفقود. لم يتم إنشاء أي عنصر نائب player/case.

<a id="partial-bounded-scan"></a>
## مسح محدود جزئيًا

المدخلات: تيار جديد log/poll; `scan_checkpoint.json` أو `scan_progress.json` موجود؛ المسح غير مكتمل؛ الافتراضي `slow_world_scan_blocks_current_reports=false`.

المتوقع:

```text
world_save_scan.status = partial
source accounting = partial
server_status may still be full for fresh current state
historical routes name the scan limitation
```

المجموعة `slow_world_scan_blocks_current_reports=true` فقط عندما يريد المشغل أن يقوم المصدر البطيء الاختياري بحظر التقارير الحالية. الاسترداد هو السماح لعامل الفحص بالاستئناف، وليس حذف نقطة التحقق.

<a id="missing-current-cycle-proof"></a>
## إثبات الدورة الحالية مفقود

المدخلات: السجل النشط غير متاح، `poll_id=0`، أو boot/epoch/last-poll النسب مفقود.

المتوقع:

```text
current_cycle_proof_complete = false
all route proof statuses = missing
each configured route envelope status = suppressed_current_cycle
delivery_eligible = false
delivery_attempted = false
```

المغلف المحظور هو سجل تدقيق، وليس تسليم في قائمة الانتظار. تظل السجلات النهائية القديمة تاريخية فقط. أصلح الحقل الأول المفقود lineage/source وأنشئ دورة أحدث.

<a id="malformed-optional-adminini-source"></a>
## اختياري مشوه Admin.ini المصدر

المدخلات: `Admin.ini` موجود ولكنه فشل في التحقق من صحة البنية.

المتوقع:

```text
admin_ini.status = malformed
source reference preserved
write/enforcement path closed
```

احتفظ بالملف واستعيد التنسيق النظيف الذي تمت مراجعته. احتفظ بالنص التوضيحي في أدلة وقت التشغيل؛ كل `Admin.ini` يبقى الحظر على الإدخال `BannedPlayer=<ID>`.

<a id="required-active-log-probe-error"></a>
## يلزم وجود خطأ في فحص السجل النشط

المدخلات: فشل مسبار السجل النشط المطلوب المحدد مع وجود خطأ قراءة معقم.

المتوقع:

```text
source_accounting.sources[active_log].status = error
source_accounting.sources[active_log].detail = "bounded active-log probe failed: <sanitized reason>"
coverage_status = unavailable
all route proof statuses = missing
```

`error` في الصف المصدر بتفاصيله المحددة. يستخدم تقرير المستوى الأعلى `unavailable`، ويظل دليل المسار `missing` حتى تثبت الدورة الحالية الأحدث المصدر المطلوب.

<a id="incompatible-or-stale-baseline"></a>
## خط الأساس غير متوافق أو قديم

المدخلات: تم التغيير package/source الهوية أو stale/incompatible البيان الأساسي.

متوقع: تسجل حالة التحقق من الصحة أو وقت التشغيل عدم التوافق؛ لا تطالب حالة المسح الضوئي بإعادة الاستخدام المكتمل. احتفظ بالأدلة السابقة، وابدأ في إعادة بناء خط الأساس بشكل واضح، وانتظر الدليل النهائي الجديد. إن إعادة البناء القسري بدون سبب مسجل لا يعد الاسترداد الافتراضي.

<a id="paired-report-write-failure"></a>
## فشل في كتابة التقرير المقترن

المدخلات: JSON تنجح الكتابة ولكن TXT تفشل الكتابة، أو العكس.

المتوقع:

```text
route_proof_status = missing
completed = false
coverage_status = unavailable
output_write_detail = "paired JSON/TXT write failed: <sanitized reason>"
next_action = repair both route output writes
```

يبذل الكاتب قصارى جهده لإعادة كتابة كلا الأخوين ليتقاربا عند الفشل. لا يمكن لأحد الأخوة الناجحين أن يظل بمثابة مطالبة بالنجاح. لا تؤدي تفاصيل الكتابة المحددة إلى إنشاء قيمة تغطية خامسة ذات مستوى أعلى.

<a id="route-proof-write-failure"></a>
## فشل الكتابة أثناء مقاومة التوجيه

المدخلات: تمت كتابة أزواج المسار ولكن `route_proof.json` لا يمكن استبداله.

متوقع: تتم إعادة كتابة كافة التقارير `missing`، جميع نتائج الإشعارات هي `route_proof_write_failed`، ولا يتم قبول أي مظروف. قد يحتوي المسار الذي تم تكوينه على `suppressed_current_cycle` مظروف تدقيق به علامات تسليم خاطئة. قم بإصلاح جذر الإخراج وأعد إنشاء نفس الدورة الحالية.

<a id="review-only-enforcement-example"></a>
## مثال على فرض المراجعة فقط

التكوين:

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

متوقع: قد تتم كتابة النتائج والحالات والتوصيات؛ `Admin.ini` يبقى دون تغيير. هذا هو الإعداد الافتراضي العام.

<a id="approved-write-success-example"></a>
## مثال نجاح الكتابة المعتمد

لا يجوز إلا لاختبار معتمد بشكل منفصل تعيين مفاتيح الكتابة الثلاثة جميعها. ويجب أيضًا إثبات هوية رقمية نظيفة، trust/moderator الاستبعاد، والحد الأدنى للأهلية، والصلاحية Admin.ini path/parse، ونجاح النسخ الاحتياطي، ونجاح الكتابة، ومساواة القراءة، والأدلة الخاصة بالحساب.

المتوقع:

```text
runtime/backups/Admin_<timestamp>_<source-fingerprint>_<clean-ID>.ini
Admin.ini contains one clean BannedPlayer=<ID>
runtime/enforced_bans.jsonl and evidence mirror record success
```

المثال الناجح لا يمكّن التنفيذ التلقائي للحسابات الأخرى.

<a id="writereadback-failure-with-rollback"></a>
## Write/readback الفشل مع التراجع

المدخلات: تم تمرير كل بوابة كتابة مسبقة؛ فشل استبدال الكتابة أو القراءة؛ `rollback_on_readback_failure=true` والنسخة الاحتياطية التي تم التحقق منها متاحة.

المتوقع: دليل الفشل يسجل المرحلة و `rollback_success`؛ تتم استعادة Admin.ini البايتات الأصلية ولا يتم الإبلاغ عن فرض الحساب بنجاح. إذا فشلت العودة أيضًا، توقف عن الكتابة، واحتفظ بكليهما files/evidence، واستعد يدويًا من النسخة الاحتياطية.

<a id="local-outbox-example"></a>
## مثال لصندوق الصادر المحلي

المدخلات: تم تمكين الإشعار في وضع `local_file_outbox`، وتمكين المسار، وإكمال إثبات المسار، وإما `full` أو السماح به صراحةً متوقع-فارغ.

المغلف المتوقع:

```text
schema = randomdayguard.notification/v1
completed_output = true
status = ready_for_local_consumer
delivery_eligible = true
delivery_backend = none
delivery_attempted = false
```

بالنسبة إلى missing/ineligible الإخراج، قد يحتوي نفس المسار بدلاً من ذلك على `status=suppressed_current_cycle`, `completed_output=false` الحالي و`delivery_eligible=false`. يثبت أي من الملفين كتابة محلية فقط. لا يتم تجميع أو استنتاج أي إيصال مزود أو نقل أو تسليم أو قراءة.
