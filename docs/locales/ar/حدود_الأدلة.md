<a id="evidence-boundary"></a>
# حدود الأدلة

> **المصدر الإنجليزي الأساسي:** [EVIDENCE_BOUNDARY.md](../../EVIDENCE_BOUNDARY.md). تحتفظ هذه الوثائق المترجمة بالأوامر والمسارات والمفاتيح وقيم الحالة والتجزئة وأسماء الملفات بشكل دقيق. إذا اختلفت الصياغة الفنية، استخدم المصدر باللغة الإنجليزية.


استخدم هذه الصفحة لتحديد ما RandomDayGuard يمكنه الإبلاغ وما لا يزال يتطلب مراجعة بشرية.

<a id="core-rule"></a>
## القاعدة الأساسية

RandomDayGuard يسجل الملاحظات المقيدة من الملفات المملوكة للخادم. يجب أن يحدد المصدر والنطاق وحالة التجميع والحدود لكل نتيجة مادية.

الأدلة المنظمة موثوقة. تقرير مترجم يوضح الأدلة؛ ولا يمكنها إضافة حقائق غائبة عن السجل المنظم.

<a id="evidence-source-classes"></a>
## فئات مصدر الأدلة

| فئة المصدر | الاستخدام النموذجي | لا تثبت من تلقاء نفسها |
|---|---|---|
| `admin_ini` | حالة الإدارة الحالية والمدققة write/readback السياق | من تسبب في ذلك حادث |
| `active_log` | يستبدل server/session أحداث مرئية في السجل النشط | النية أو الملكية أو الضرر المباشر |
| `recent_backup_logs` | سياق السجل التاريخي | وقع حدث حالي |
| `playerdata_filenames` | التأكيد على وجود معرف حساب نظيف | السلوك أو الذنب أو ملكية الهوية بما يتجاوز المعرف المكشوف |
| `existing_cases` | سياق المراجعة السابقة | أن التفسير المسبق يظل صحيحًا |
| `existing_reports` | الملخصات والقرارات السابقة | الحقيقة الحالية دون دعم حالي |
| `existing_evidence` | الأدلة التاريخية المنظمة | النشاط الحالي |
| مسح حفظ العالم المحدود | بطيء world/class السياق | إجراء اللاعب أو الملكية أو السرقة أو النسخ أو الضرر |

يسجل كل مصدر availability/readability وعدد الملفات ومراجع المصدر والنطاق الحالي أو التاريخي وبيان `does_not_prove` صريح.

<a id="source-states"></a>
## حالات المصدر

| الحالة | المشغل بمعنى |
|---|---|
| `available` | كان المصدر قابلاً للقراءة وتم جمع الأدلة. |
| `expected_empty` | كان المصدر قابلاً للقراءة وليس له أي سجل مطابق. |
| `partial` | تم جمع بعض الأدلة؛ التغطية غير مكتملة. |
| `deferred` | تم تأجيل العمل المحدود عمدًا. |
| `unavailable` | المصدر غير موجود في هذه البيئة. |
| `malformed` | المصدر موجود ولكن لا يمكن تحليله بأمان. |
| `permission_denied` | المراقبة تفتقر إلى إذن القراءة. |
| `error` | فشلت عملية التجميع لمسجل آخر. السبب. |

الفارغ المتوقع هو ملاحظة صالحة. يجب ألا يتم تحويلها مطلقًا إلى لاعب أو قضية أو حادثة أو اتهام ملفق.

<a id="current-versus-historical-evidence"></a>
## الأدلة الحالية مقابل الأدلة التاريخية

ينتمي الدليل الحالي إلى نافذة المجموعة النشطة أو عصر الخادم. تأتي الأدلة التاريخية من السجلات أو الحالات أو التقارير أو سجلات الأدلة أو النسخ الاحتياطية أو خطوط الأساس السابقة.

يمكن أن توفر الأدلة التاريخية السياق. ولا يمكنها أن تملأ بصمت فجوة الأدلة الحالية. يجب أن تقوم التقارير بتسمية كلا النطاقين والاستشهاد بمصادرهما بشكل منفصل.

<a id="corroboration-rule"></a>
## قاعدة التأييد

هذه سياقات مفيدة ولكنها ليست دليلاً مباشرًا في حد ذاتها:

- عرض الأسماء أو تشابه الأسماء؛
- مصادفة التوقيت؛
- قطع الاتصال أو إعادة الاتصال churn;
- حادث واحد أو انفجار تحذيري;
- رموز الفئة أو المسار أو الممثل أو الخريطة أو عدد الكائنات؛
- العضوية في حالة مجمعة تلقائيًا؛
- تقارير سابقة بدون تأكيد المصدر الحالي.

لا تدعي الذنب أو النية أو الغش أو الملكية أو السرقة أو النسخ أو الضرر المباشر أو الاستخدام المباشر للحاويات أو إجراء الجرد المباشر أو الإحداثيات المباشرة الدقيقة أو اختبار الاتصال المباشر، أو سلوك على مستوى الذاكرة بدون دليل يكشف الحقيقة بشكل مباشر.

<a id="truthful-report-language"></a>
## لغة تقرير صادقة

استخدم:

```text
Observed: the account was active in the recorded crash window.
Interpretation: repeated overlap warrants operator review.
Unknown: the cause of the crash.
Does not prove: that the account caused the crash.
Next action: compare the cited current session and lifecycle records.
```

تجنب:

```text
The player crashed the server.
The player stole or duplicated items.
The world token proves who used the object.
```

<a id="report-reading-order"></a>
## ترتيب قراءة التقرير

يجب أن يشرح كل تقرير يواجه الجمهور ما يلي:

1. عادي المعنى.
2. سبب أهميته.
3. الدليل الفني ومراجع المصدر.
4. الإجراء التالي.
5. لم يتم إثبات الحدود والمجهولات والمطالبات.
