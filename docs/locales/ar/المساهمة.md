# المساهمة

> **المصدر الإنجليزي الأساسي:** [CONTRIBUTING.md](../../../CONTRIBUTING.md). تحتفظ هذه الوثائق المترجمة بالأوامر والمسارات والمفاتيح وقيم الحالة والتجزئة وأسماء الملفات بشكل دقيق. إذا اختلفت الصياغة الفنية، استخدم المصدر باللغة الإنجليزية.


RandomDayGuard يقبل التحسينات المركزة والقابلة للتكرار للمحللين اللغويين والوثائق والاختبارات والتحقق من الصحة العامة. اجعل كل تغيير مرتبطًا بعقد المشروع العام وحافظ على سلوك المراجعة أولاً: يجب على الحارس ترك `Admin.ini` بدون تغيير عندما لا يمكن تأكيد فحص الأمان المطلوب.

<a id="prepare-a-safe-workspace"></a>
## قم بإعداد مساحة عمل آمنة

1. اقسم المستودع أو استنسخه وأنشئ فرعًا مركزًا.
2. قم بتثبيت مترجم Python 3 مدعوم. قم بتثبيت مترجم Lua عند تغيير Lua حتى يتمكن `luac -p` من التحقق من بناء الجملة.
3. اقرأ [صفحة التوثيق الرئيسية](%D8%A7%D9%84%D9%88%D8%AB%D8%A7%D8%A6%D9%82.md), [الهندسة المعمارية](%D8%A7%D9%84%D9%87%D9%86%D8%AF%D8%B3%D8%A9_%D8%A7%D9%84%D9%85%D8%B9%D9%85%D8%A7%D8%B1%D9%8A%D8%A9.md) الحالي و[حدود الأدلة](%D8%AD%D8%AF%D9%88%D8%AF_%D8%A7%D9%84%D8%A3%D8%AF%D9%84%D8%A9.md) للمنطقة التي ستغيرها.
4. افحص `git status` قبل التحرير والاحتفاظ بالعمل غير ذي الصلة.
5. استخدم التركيبات الاصطناعية أو المعقمة فقط.

لا ترسل مطلقًا سجلات الخادم الخاصة، أو المجلدات المحفوظة، أو معرفات المشغل، `Admin.ini`، أو نقاط نهاية الإشعارات الخاصة، أو بيانات الاعتماد، أو المسارات الخاصة، أو مخرجات وقت التشغيل، أو المنسوخة مباشرة الأدلة.

<a id="make-a-focused-change"></a>
## قم بإجراء تغيير مركز

- اتبع التسمية الحالية والتنسيق وعمليات التحقق من السلامة وملكية الوحدة.
- احتفظ بمالك توثيق أساسي واحد لكل إجراء أو حقيقة محددة.
- قم بتحديث وثائق المستخدم والأمثلة عندما يتغير السلوك أو المخرجات العامة.
- أضف اختبار الانحدار لإصلاح الأخطاء عندما يكون ذلك عمليًا.
- لا تضعف تأكيد الحساب، أو حماية الحساب الموثوق، أو التحقق من النسخ الاحتياطي، أو اكتشاف التغيير الخارجي، أو مقارنة الملفات المحفوظة، أو الاسترداد، أو الإعدادات الافتراضية للمراجعة فقط لإجراء الاختبار.

<a id="run-the-relevant-checks"></a>
## قم بتشغيل عمليات التحقق ذات الصلة

بالنسبة للتغييرات المتعلقة بالوثائق فقط، تشغيل:

```powershell
python -B tools\generate_documentation_audit.py --check
python -B -m unittest discover tests -p "test_documentation*.py"
git diff --check
```

بالنسبة إلى تغييرات المصدر أو التكوين أو التغليف أو الاختبار، قم أيضًا بإجراء عمليات التحقق القابلة للتطبيق من [التحقق من الصحة ومراجعة الإصدار](%D8%A7%D9%84%D8%AA%D8%AD%D9%82%D9%82_%D9%85%D9%86_%D8%A7%D9%84%D8%B5%D8%AD%D8%A9_%D9%88%D8%A7%D9%84%D8%A5%D8%B5%D8%AF%D8%A7%D8%B1.md)، بما في ذلك عمليات التحقق من بناء جملة Lua، والتحقق من صحة المستودع، واختبارات المسار العام، ومجموعة اختبار الوحدة الكاملة. الإبلاغ عن كل شيك تم تخطيه أو غير متوفر؛ لا تصفها بأنها تم تمريرها.

<a id="submit-the-change-for-review"></a>
## أرسل التغيير للمراجعة

افتح طلب سحب مركَّز فقط بعد مراجعة الفرق بالكامل. قم بتضمين:

- المشكلة والسلوك المقصود؛
- تم تغيير الملفات الدقيقة والعقود العامة؛
- تشغيل الأوامر ونتائجها؛
- تأثير الخصوصية والتوافق والتنفيذ؛ و
- القيود المتبقية أو أعمال المتابعة.

لا تقم بتضمين أدلة وقت التشغيل التي تم إنشاؤها أو أرشيفات الإصدار ما لم يتطلب التغيير ذلك بشكل صريح ويتحقق من صحته. لا تسمح المساهمة بالإصدار أو النشر أو اختبار الخادم المباشر أو إجراء التنفيذ أو النشر على موقع جهة خارجية.

الإبلاغ عن الثغرات الأمنية من خلال [مسار الأمان الخاص](%D8%A7%D9%84%D8%A3%D9%85%D8%A7%D9%86.md)، وليس مشكلة عامة أو طلب سحب عادي.
