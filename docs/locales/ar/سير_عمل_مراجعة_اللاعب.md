# سير عمل مراجعة اللاعب

> **المصدر الإنجليزي الأساسي:** [PLAYER_REVIEW_WORKFLOW.md](../../PLAYER_REVIEW_WORKFLOW.md). تحتفظ هذه الوثائق المترجمة بالأوامر والمسارات والمفاتيح وقيم الحالة والتجزئة وأسماء الملفات بشكل دقيق. إذا اختلفت الصياغة الفنية، استخدم المصدر باللغة الإنجليزية.


استخدم هذه الصفحة للاعب واحد أو حساب أو حالة واحدة. الغرض هو قرار مراجعة قابل للتكرار، وليس اتهامًا آليًا.

<a id="quick-path"></a>
## المسار السريع

1. افتح `runtime/final_logs/player_activity_latest.json`.
2. تأكد من حالة المسار في `runtime/final_logs/route_proof.json`.
3. حدد الملاحظات الحالية وأيها تاريخية.
4. تحقق من الهوية المستشهد بها ومراجع مصدر الجلسة.
5. مراجعة `case_review_latest.json` عند وجود حالة مترابطة. موجود.
6. سجل الأشياء المجهولة و`does_not_prove` قبل اختيار الإجراء.
7. اترك التنفيذ معطلاً ما لم يتم إثبات بوابات التنفيذ المنفصلة.

<a id="1-confirm-route-proof"></a>
## 1. تأكيد إثبات المسار

فسر مسار اللاعب على النحو التالي:

| الحالة | الإجراء |
|---|---|
| `full` | استمر، مع الاستمرار في مراجعة حدود المصدر. |
| `limited_expected_empty` | استمر فقط مع الموضوعات الموجودة بالفعل؛ لا تخترع لاعبًا أو حالة مفقودة. |
| `missing` | أوقف قرار اللاعب واستكشف أخطاء المسار وإصلاحها. |

لا تحل المجدول السليم محل إثبات المسار.

<a id="2-establish-identity"></a>
## 2. إنشاء الهوية

يفضل معرف حساب نظيف مدعومًا بأدلة هوية مكشوفة من الخادم، وحيثما كان ذلك متاحًا، PlayerData أسماء الملفات. احتفظ بمرجع المصدر الأولي.

لا تفرض من:

- اسم عرض فقط؛
- اسم يظهر في إشعار أو لوحة استضافة؛
- تشابه في التوقيت؛
- هوية غير محددة أو ضعيفة الثقة؛
- تقرير تاريخي بدون تأكيد حالي.

<a id="3-separate-current-from-historical"></a>
## 3. افصل بين الحالي والتاريخي

يصف الدليل الحالي نافذة التقارير النشطة أو عصر الخادم. قد تفسر الأدلة التاريخية أحد الأنماط، لكنها لا تستطيع ملء الفجوات في النافذة الحالية بصمت.

سجل كلا النطاقين بشكل مستقل:

```text
Current observations:
Current source references:
Historical context:
Historical source references:
```

<a id="4-review-observations-and-interpretation"></a>
## 4. راجع الملاحظات والتفسير

اقرأ أقسام التقرير هذه بوضوح:

```text
observed
interpretation
unknown
does_not_prove
next_action
source_references
```

أعد فتح الأدلة المنظمة المستشهد بها لأي قرار جوهري. الترجمة هي عبارة عن إبحار وشرح، وليست دليلاً جديدًا.

<a id="5-calibrate-the-decision"></a>
## 5. معايرة القرار

| القرار | يستخدم عندما |
|---|---|
| `INFO` | ملاحظة عادية أو منخفضة السياق. |
| `WATCH` | إشارة ضعيفة أو غير مكتملة تستحق المراقبة. |
| `REVIEW` | تحتاج الأدلة المرتبطة إلى حكم المسؤول. |
| `BAN-ELIGIBLE` | تنظيف الهوية والبيانات يتم استيفاء عتبات الأدلة المحددة؛ لا تزال بوابات الكتابة سارية. |
| `AUTO-BANNED` | تم تمكين التنفيذ بشكل صريح ونجح النسخ الاحتياطي والكتابة والقراءة والتدقيق. |

لا يوجد تصنيف قرار يثبت الذنب أو النية.

<a id="6-apply-the-evidence-boundary"></a>
## 6. تطبيق حدود الأدلة

الأعطال، وإعادة الاتصال، والتحذيرات، object/class الرموز المميزة، وتجميع الحالات يمكن أن تدعم المراجعة. فهي وحدها لا تثبت الغش أو السرقة أو النسخ أو الملكية أو الضرر المباشر أو السببية للحوادث.

إذا كانت الهوية أو التحليل أو النسخ الاحتياطي أو الكتابة أو القراءة أو التراجع ضعيفة أو فاشلة، فيجب إغلاق التنفيذ.
