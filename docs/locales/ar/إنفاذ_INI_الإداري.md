# Admin.iniفرض

> **المصدر الإنجليزي الأساسي:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). تحتفظ هذه الوثائق المترجمة بالأوامر والمسارات والمفاتيح وقيم الحالة والتجزئة وأسماء الملفات بشكل دقيق. إذا اختلفت الصياغة الفنية، استخدم المصدر باللغة الإنجليزية.


RandomDayGuard لا يغير قائمة حظر الخادم في الإعداد الافتراضي الخاص به. يقوم فقط بإنشاء تقارير للمشرف لمراجعتها. تشرح هذه الصفحة التحديث الاختياري لقائمة الحظر التلقائي للمسؤولين الذين يقومون بتمكينها عمدًا.

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## ما الذي يتحقق منه Guard قبل تغيير قائمة الحظر

يضيف Guard حظرًا فقط عندما تكون كل إجابة أدناه هي **نعم**:

1. هل حددت الأدلة الحالية حسابًا محددًا يتمتع بثقة كافية؟
2. هل الحساب ليس وسيطًا ولا حسابًا تم وضع علامة "موثوق" على المشرف؟
3. هل الحساب ليس موجودًا بالفعل في قائمة الحظر؟
4. هل وصل الحساب إلى نتيجة الإجراء التلقائي التي تم تكوينها؟
5. هل يستطيع Guard قراءة `Admin.ini` الحالي وحفظ نسخة احتياطية مماثلة؟
6. هل `Admin.ini` البقاء دون تغيير أثناء إعداد Guard للتحديث؟
7. هل يتطابق الملف الكامل تمامًا مع النتيجة المقصودة بعد الحفظ؟

إذا كانت أي إجابة هي **لا**، أو لا يمكن التحقق منها، يترك Guard `Admin.ini` دون تغيير ويسجل السبب في تقاريره. إذا بدأ الحفظ ولكن فشل الفحص النهائي، فسيقوم Guard باستعادة النسخة الاحتياطية التي تم التحقق منها.

<a id="file-format"></a>
## تنسيق الملف

`Admin.ini` يجب أن يتلقى خطوط حظر نظيفة فقط:

```ini
BannedPlayer=<ID>
```

- بدون أسماء.
- لا توجد تعليقات.
- لا توجد أسباب.
- لا اللواحق.

<a id="safe-defaults"></a>
## الإعدادات الافتراضية الآمنة

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## مصدر معرف الحظر

أفضل مصدر:

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

يقبل وقت التشغيل إما معرفًا رقميًا بالكامل أو نموذج الاتصال الموثق الكامل `<digits>_+_|<non-space token>` ويستمد منه معرف الحظر الرقمي. يتم رفض البادئات الرقمية العشوائية ذات اللاحقة غير المعروفة؛ ولم يتم اقتطاعها في معرف الحظر.

صحيح:

```ini
BannedPlayer=2535422284688820
```

خطأ:

```ini
BannedPlayer=ExamplePlayer
```

خطأ أيضًا:

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## الإعدادات الدقيقة عمليات التحقق من الحماية

تنفذ هذه الإعدادات عمليات التحقق الموضحة أعلاه. يجب أن يكون كل شرط مدرج صحيحًا:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

إذا كان أي شرط خاطئًا أو لا يمكن التحقق منه، يترك Guard قائمة الحظر دون تغيير ويسجل ما أوقفها.

<a id="transaction-safety"></a>
## سلامة المعاملات

ينفذ مسار الطفرة `Admin.ini` الوحيد هذه الخطوات بالترتيب:

1. قراءة والتحقق من صحتها هيكليًا البايتات الموثوقة.
2. اشتق حالة المشرف والموثوق وحالة الحظر الحالية من نفس اللقطة.
3. اكتب نسخة احتياطية فريدة ضمن `runtime/backups/` وتحقق منها بايت مقابل بايت.
4. أعد قراءة `Admin.ini` مباشرة قبل الاستبدال وارفض أي بايت خارجي. التغيير.
5. اكتب المرشح من خلال مسار الاستبدال المتحكم فيه الذي تم تكوينه.
6. اطلب أن تكون وحدات بايت القراءة الكاملة مساوية لوحدات بايت المرشح الكاملة.
7. في حالة فشل إعادة القراءة، قم باستعادة النسخة الاحتياطية التي تم التحقق منها فقط بينما يظل الملف الحالي هو المرشح المحدد الذي كتبه Guard. إذا قام كاتب آخر بتغييره، يرفض Guard التراجع بدلاً من الكتابة فوق وحدات البايت الخارجية غير المعروفة.

المعرفات المكررة غير فعالة: لا تتم كتابة سطر ثانٍ ولا نسخة احتياطية ثانية. تتضمن أسماء النسخ الاحتياطية طابعًا زمنيًا وبصمة بايت المصدر ومعرفًا نظيفًا، لذا لا يمكن للمحاولات المنفصلة مشاركة اسم الملف القديم الذي تبلغ مدته ثانية واحدة.

<a id="local-regression-proof"></a>
## إثبات الانحدار المحلي

`tests/lua/enforcement_runtime_test.lua` يقوم بتشغيل أداة التحميل المشحونة مرة واحدة ثم ينفذ الإغلاق المحلي الحقيقي `append_ban()` ضد الملفات الاصطناعية المعزولة أسفل المستودع `.tmp/` الدليل. وهو يغطي الإدراج، والعجز المكرر، moderator/trusted الرفض، ورفض الهوية الضعيفة والمشوهة، والتحقق من النسخ الاحتياطي الدقيق للبايت، ورفض التعديل المتزامن، والاستعادة الناجحة بعد فشل عملية القراءة، ورفض الكتابة فوق التغيير الخارجي بعد الكتابة. ترفض أغلفة نظام الملفات الخاصة به أي طفرة خارج جذر التثبيت؛ لا يوجد مسار خادم حقيقي أو `Admin.ini`.

قم بتشغيله من خلال `python tools/test_public_pipeline.py`. يثبت تمرير التثبيت سلوك المعاملة المحلية فقط. ولا يعمل على تمكين التنفيذ أو التفويض بكتابة الإنتاج أو إثبات الأذونات الخاصة بالمضيف.

<a id="rollback"></a>
## التراجع

1. أوقف الخادم.
2. استعادة الأحدث Admin.ini نسخة احتياطية من `runtime/backups/`.
3. قم بإزالة `BannedPlayer=<ID>` سطر إذا لزم الأمر.
4. قم بتشغيل الخادم.
5. أعد فتحه Admin.ini وتأكد من استمرار الخط أو إزالته.
6. احفظ `enforced_bans.jsonl` للتدقيق.
