# أنماط الممثل السيئ والمرونة

> **المصدر الإنجليزي الأساسي:** [BAD_ACTOR_PATTERNS_AND_RESILIENCE.md](../../BAD_ACTOR_PATTERNS_AND_RESILIENCE.md). تحتفظ هذه الوثائق المترجمة بالأوامر والمسارات والمفاتيح وقيم الحالة والتجزئة وأسماء الملفات بشكل دقيق. إذا اختلفت الصياغة الفنية، استخدم المصدر باللغة الإنجليزية.


استخدم هذه الصفحة لفهم كيف يساعد الحارس في مراجعة إساءة استخدام الأعطال، وسلوك الاستغلال المجاور، وتخطيط الاسترداد.

<a id="what-the-guard-can-help-with"></a>
## ما يمكن أن يساعد فيه الحارس

| النمط | ما يجب التحقق منه |
|---|---|
| العوائد المرتبطة بالتعطل | نفس الحساب نشط قبل الأعطال ويعود بعد إعادة التشغيل |
| اختبار إعادة الاتصال السريع | تكرار join/leave أو timeout/reconnect الحلقات |
| مجموعات الحسابات المتعددة | الانضمام إلى الموجات، ونوافذ التحذير المشتركة، ونوافذ الفشل المشتركة |
| ضغط الاندفاع التحذيري | تكرار ActorChannelFailure أو نوافذ تحذير الحفظ |
| سياق خارج الحدود | PlayerData/map/world السياق عندما يكون قابلاً للقراءة |
| تداخل حفظ اللمس | سياق الحفظ العالمي الجلسات المعينة المتداخلة |
| ارتباك الهوية | الأسماء التي تحتاج إلى تعيين ConnectID |

<a id="why-it-avoids-memory-access"></a>
## لماذا يتجنب الوصول إلى الذاكرة

RandomDayGuard يعمل من الملفات المملوكة للخادم:

```text
Saved/Logs/*.log
Admin.ini
World saves
PlayerData
Backups
runtime evidence
```

وهذا يجعله أقل اعتمادًا على حالة الذاكرة من جانب العميل وأقل هشاشة عبر اللعبة التحديثات.

المقايضة:

```text
It cannot prove hidden live actions unless the server writes evidence.
```

<a id="crash-correlated-returners"></a>
## العائدون المرتبطون بالانهيار

النمط:

```text
Account joins.
Server crashes or restarts.
Same account reconnects quickly.
Pattern repeats.
```

ملفات مفيدة:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="rapid-reconnect-probers"></a>
## مسبارات إعادة الاتصال السريعة

النمط:

```text
join -> leave -> join -> leave -> join
```

ملفات مفيدة:

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
```

<a id="multi-account-clusters"></a>
## مجموعات الحسابات المتعددة

النمط:

```text
Several accounts join in the same window.
Warnings or crashes follow.
Some accounts rotate or reconnect after restart.
```

ملفات مفيدة:

```text
runtime/raid_cases/
runtime/forensic_days/YYYY-MM-DD/raid_cases.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

القاعدة:

```text
A cluster is not a mass-ban list.
Each account still needs its own evidence.
```

<a id="sticky-backup-recommendation"></a>
## توصية النسخ الاحتياطي الثابت

إنشاء نسخة احتياطية ثابتة بعد:

```text
first full baseline completes
object_registry.json exists
file_manifest.tsv exists
world_state_latest.json has scan_complete=true
Admin.ini is verified
trusted IDs are configured
```

رجوع لأعلى:

```text
RandomDayGuard/config.lua
RandomDayGuard/SavedRoot.txt
RandomDayGuard/runtime/baselines/
RandomDayGuard/runtime/object_registry.json
RandomDayGuard/runtime/world_state/current/world_state_latest.json
Saved/SaveGames/Server/Admin.ini
```

<a id="recovery-model"></a>
## نموذج الاسترداد

```text
Clean install
-> verify live defense
-> complete first baseline
-> create sticky backup
-> run server normally
-> use daily rollups for review
-> restore sticky backup if needed
```
