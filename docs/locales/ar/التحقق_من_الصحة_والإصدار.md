# التحقق من الصحة والإصدار

> **المصدر الإنجليزي الأساسي:** [VALIDATION_AND_RELEASE.md](../../VALIDATION_AND_RELEASE.md). تحتفظ هذه الوثائق المترجمة بالأوامر والمسارات والمفاتيح وقيم الحالة والتجزئة وأسماء الملفات بشكل دقيق. إذا اختلفت الصياغة الفنية، استخدم المصدر باللغة الإنجليزية.


هذه الصفحة مخصصة للمساهمين ومشرفي الإصدار. لا يحتاج مشغلو الخادم إلى تشغيل هذه الأوامر للتثبيت RandomDayGuard.

<a id="user-visible-proof"></a>
## دليل مرئي للمستخدم

يكون الإصدار مفهومًا عندما يتمكن مشغل جديد من تثبيته، والعثور على تقرير حالة الخادم الأول، وتمييز مسارات التقرير الخمسة، واتباع إجراء واحد واضح من مثال عملي. يجب ألا تتطلب مهام القارئ معرفة Git أو PowerShell أو Python أو المجموع الاختباري.

<a id="contributor-checks"></a>
## عمليات التحقق من المساهمين

```powershell
python -B tools/validate_repo.py
python -B tools/test_public_pipeline.py
python -B -m unittest discover tests
```

عندما يكون `luac` متاح:

```powershell
luac -p RandomDayGuard/Scripts/main.lua
luac -p RandomDayGuard/Scripts/public_pipeline.lua
```

تغطي اختبارات تركيبات Lua المُحمل والمجدول ومسارات التقرير ومعاملات الكتابة الاختيارية Admin.ini. تستخدم تركيبات التنفيذ الملفات المؤقتة فقط وتتحقق من الهوية، ورفض الحساب الموثوق، والحدود، والنسخ الاحتياطي، ورفض التغيير المتزامن، والقراءة، والتراجع.

<a id="package-proof"></a>
## إثبات الحزمة

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

- تتطابق جميع علامات الإصدار مع `VERSION`.
- الإصدار الحالي فقط موجود ضمن `releases/`.
- تقوم الحزمة ZIP يحتوي على `RandomDayGuard/Scripts/main.lua` الأساسي ولا يوجد متغير لحالة الأحرف الصغيرة المُحمل.
- يتم استبعاد مخرجات وقت التشغيل، والتكوين الخاص، وبيانات الاعتماد، والمسارات المحلية، وذاكرات التخزين المؤقت، وعناصر الاختبار.
- يظل التكوين العام للمراجعة فقط مع تعطيل التنفيذ.
- تظل أمثلة التقارير الخمسة التي تم العمل عليها متسقة مع ملكية المسار وتركيبات اختبار الإصدار.
- ZIP البايتات الأساسية حتمية ومتطابقة `CHECKSUMS.sha256`.
- يتم التحقق من صحة جميع روابط الوثائق المحلية و27 صفحة إدخال محلية.

<a id="avoid-validation-environment-pitfalls"></a>
## تجنب مخاطر بيئة التحقق

- تشغيل عمليات فحص كتابة المستودع بشكل تسلسلي لتجنب تعارض الملفات المؤقتة.
- في نظام التشغيل Windows، قم بفحص أسماء الأعضاء المؤرشفة أو تهجئة المسار المعداد بدلاً من البحث عن ملف غير حساس لحالة الأحرف عند التحقق من وجود أدوات تحميل مكررة.
- أمر `luac` المفقود أو وقت تشغيل Lua هو قدرة غير متوفرة، وليس بناء جملة أو وقت تشغيل عابر. test.
- تثبت التركيبة فقط مدخلاتها النموذجية. لا يثبت أن خادمًا مباشرًا أنتج تقريرًا حاليًا.
- سجل مهلات الأوامر والإخراج الجزئي بدلاً من افتراض الاكتمال.

<a id="repair-failed-repository-validation"></a>
## إصلاح فشل التحقق من صحة المستودع

ابدأ بالمسار أو العقد الأول الذي تم الإبلاغ عنه. قم بتصحيح هذا العنصر، وأعد إجراء الاختبار الضيق، ثم أعد تشغيل المصفوفة الكاملة. لا تخفي القدرة المفقودة عن طريق إزالة الاختبار الذي يتطلبها.

<a id="known-limits-and-release-decision"></a>
## الحدود المعروفة وقرار الإصدار

تثبت الشيكات المحلية عقود المصدر والتركيبات والحزمة والتوثيق. يتطلب تثبيت خادم محدد أو نافذة استقرار طويلة الأمد أو عرض العميل نتيجة تكامل منفصلة. سجل هذه النتيجة مع بنيتها وتكوينها ومدتها والمخرجات التي تمت ملاحظتها قبل تقديم المطالبة المطابقة.
