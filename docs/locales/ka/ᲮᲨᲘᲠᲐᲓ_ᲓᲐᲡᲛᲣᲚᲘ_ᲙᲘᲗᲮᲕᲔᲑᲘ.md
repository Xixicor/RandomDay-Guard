# FAQ

> **კანონიკური ინგლისური წყარო:** [FAQ.md](../../FAQ.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


<a id="is-randomdayguard-the-randomday-mod"></a>
## არის RandomDayGuard RandomDay მოდიფიკაცია?

არა. RandomDay Mod ცვლის სერვერის გამოცდილებას. RandomDayGuard უყურებს სერვერის მტკიცებულების ფენას.

<a id="does-live-defense-work-before-the-scan-completes"></a>
## მუშაობს თუ არა ცოცხალი დაცვა სკანირების დასრულებამდე?

დიახ. ცოცხალი დაცვა იყენებს ჟურნალებს და სესიის მოვლენებს. საბაზისო სკანირება აუმჯობესებს კონტექსტს მოგვიანებით.

<a id="why-can-the-first-scan-take-a-long-time"></a>
## რატომ შეიძლება გაგრძელდეს პირველი სკანირება დიდი დრო?

პირველი სკანირების აწყობა world/object კონტექსტი, ფაილის მანიფესტები და ხელახლა გამოყენებადი საბაზისო მონაცემები.

<a id="what-do-i-check-first-after-startup"></a>
## რა შევამოწმო ჯერ დაწყების შემდეგ?

```text
runtime/current/poll_status.json
```

მოძებნეთ:

```text
scheduler_status=running
poll_id increasing
poll_in_flight=false
```

<a id="where-are-player-summaries"></a>
## სად არის მოთამაშის შეჯამებები?

```text
runtime/account_evidence.json
runtime/account_evidence.tsv
```

<a id="where-is-the-daily-quick-review-package"></a>
## სად არის ყოველდღიური სწრაფი განხილვის პაკეტი?

```text
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

<a id="which-file-should-i-upload-for-fastest-review"></a>
## რომელი ფაილი უნდა ავტვირთო უსწრაფესი განხილვისთვის?

```text
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="can-it-write-bans-automatically"></a>
## შეიძლება თუ არა ავტომატურად დაწეროს აკრძალვები?

მხოლოდ იმ შემთხვევაში, თუ ცალსახად ჩართულია.

ნაგულისხმევი:

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

<a id="what-does-adminini-receive"></a>
## რას აკეთებს Admin.ini მიიღეთ?

მხოლოდ:

```ini
BannedPlayer=<ID>
```

სახელები, კომენტარები, მიზეზები და სუფიქსები არ არის.

<a id="is-a-display-name-enough-to-ban"></a>
## საკმარისია საჩვენებელი სახელი აკრძალვისთვის?

არა. გამოიყენეთ სერვერის ჟურნალი `Login request` `ConnectID` ან ექვივალენტური სერვერის მტკიცებულება.

<a id="can-one-crash-ban-someone"></a>
## შეიძლება ვინმეს ავარია აკრძალოს?

ნაგულისხმევად არა.

<a id="can-object-count-alone-ban-someone"></a>
## შეიძლება თუ არა მარტო ობიექტმა აკრძალოს ვინმე?

ნაგულისხმევად არა.

<a id="should-savedroottxt-point-to-the-world-folder"></a>
## უნდა SavedRoot.txt მიუთითებს მსოფლიო საქაღალდეზე?

არა. მიუთითეთ ის `AbioticFactor/Saved`.

<a id="what-if-the-world-folder-changes"></a>
## რა მოხდება, თუ მსოფლიო საქაღალდე შეიცვლება?

მიხედეთ მას, როგორც საბაზისო იდენტობის ცვლილებას. შეინახეთ ძველი საბაზისო ხაზი და შექმენით ახალი.
