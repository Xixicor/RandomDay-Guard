# კონფიგურაციის კონცეფციები

> **კანონიკური ინგლისური წყარო:** [CONFIG_REFERENCE.md](../../CONFIG_REFERENCE.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


ეს ახსნა აღწერს, თუ რას აკონტროლებს თითოეული ძირითადი კონფიგურაციის არე, როდის მუშაობს და როგორ ურთიერთქმედებს მტკიცებულებებთან და უსაფრთხოების კარიბჭეებთან. ის არ ფლობს ზუსტ საველე კატალოგს ან პროფილის პროცედურებს.

დავალებაზე ორიენტირებული წინასწარ დაყენებისა და უსაფრთხო ცვლილების ნაბიჯებისთვის გამოიყენეთ [`CONFIG_PROFILES.md`](%E1%B2%9E%E1%B2%A0%E1%B2%9D%E1%B2%A4%E1%B2%98%E1%B2%9A%E1%B2%94%E1%B2%91%E1%B2%98%E1%B2%A1_%E1%B2%99%E1%B2%9D%E1%B2%9C%E1%B2%A4%E1%B2%98%E1%B2%92%E1%B2%A3%E1%B2%A0%E1%B2%90%E1%B2%AA%E1%B2%98%E1%B2%90.md). ყველა ზუსტი წყაროს ველისთვის, ნაგულისხმევი, ტიპი, უცვლელი, გამომავალი ეფექტი და აღდგენის წესი გამოიყენეთ გენერირებული [`CONFIG_FIELD_CATALOG.md`](CONFIG_FIELD_CATALOG.md); ვალიდატორს სჭირდება ერთი სტრიქონი იქ ყოველი გაგზავნისთვის `config.lua` ფოთლის ველი.

<a id="top-level-safety"></a>
## უმაღლესი დონის უსაფრთხოება

| ვარიანტი | ნაგულისხმევი | მნიშვნელობა |
|---|---:|---|
| `enabled` | `true` | მცველის ძირითადი გადამრთველი |
| `enforcement.review_only_mode` | `true` | Record/recommend |
| `enforcement.auto_ban` | `false` | ნაგულისხმევად არ მოხდეს ავტომატურად აკრძალვა |
| `enforcement.write_admin_ini` | `false` | არ დაწეროთ Admin.ini ნაგულისხმევად |

დაიცავით ისინი, სანამ სერვერის მფლობელი არ განიხილავს გამოსავალს.

<a id="saved"></a>
## `saved`

აკონტროლებს, როგორ პოულობს მცველი სერვერს `Saved/` საქაღალდე და ფაილების რომელი ოჯახების სკანირება შეუძლია.

გამოიყენეთ, როდესაც:

```text
Saved root auto-detection fails.
World folder changed.
Provider or container path is unusual.
```

შეამოწმეთ:

```text
runtime/saved_path_probe.json
RandomDayGuard/SavedRoot.txt
```

წესი:

```text
SavedRoot.txt -> AbioticFactor/Saved
not -> Worlds/<WorldName>
```

სასარგებლო ვარიანტები:

| ვარიანტი | უსაფრთხო მნიშვნელობა | რატომ |
|---|---|---|
| `enabled` | `true` | საჭიროა პირდაპირი თავდაცვისთვის |
| `start_at_end_on_first_run` | `true` | აცილებს ძველ ჟურნალებს, როგორც პირდაპირი ღონისძიებები |
| `tail_backup_logs` | `false` | სარეზერვო ჟურნალები ისტორიაა და არა ცოცხალი |
| `max_lines_per_poll` | შეზღუდული | ინარჩუნებს გამოკითხვის ციკლის რეაგირებას |


<a id="source_accounting"></a>
## `source_accounting`

აკონტროლებს აშკარა მტკიცებულების წყაროს გაშუქებას და ფარგლებს.

| გასაღები | ნაგულისხმევი | მნიშვნელობა |
|---|---:|---|
| `enabled` | `true` | წერს წყაროს აღრიცხვას საჯარო მარშრუტებისთვის. |
| `require_terminal_status` | `true` | მოითხოვს თითოეულ წყაროს გამოავლინოს აშკარა ტერმინალი ან არასრული მდგომარეობა. |
| `distinguish_current_from_historical` | `true` | განცალკევებულია მიმდინარე და ისტორიული მტკიცებულებები. |
| `slow_world_scan_blocks_current_reports` | `false` |  საშუალებას აძლევს მიმდინარე მოხსენებებს განაცხადონ, რომ შემოსაზღვრული სამყაროს სკანირება გადადებულია ან ნაწილობრივი. |
| `changed_file_manifest` | საბაზისო მანიფესტის გზა | მიმართვა გამოიყენება შეზღუდული historical/world აღრიცხვა. |

წყაროს მდგომარეობაა `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied` ან `error`.

პარამეტრები `source_accounting.enabled = false` ჩუმად არ შლის სტატუსის გამომავალს. მილსადენი კვლავ წერს `runtime/final_logs/source_accounting_latest.json` `enabled=false`, `status="unavailable"` და `disabled_reason="source_accounting_disabled"`. ასევე წერს ისტორიული სტატუსის ჩანაწერს მიუწვდომელი აღრიცხვით. იმის გამო, რომ წყაროს აღრიცხვა ანგარიშის კონტრაქტის ნაწილია, ყველა მარშრუტი ვერ დაიხურება `missing`; არცერთი მარშრუტი არ განიხილება როგორც დასრულებული, სანამ აღრიცხვა გამორთულია.

<a id="reports"></a>
## `reports`

აკონტროლებს ზოგადი ადგილობრივი მოხსენების მილსადენს.

ნაგულისხმევი ჩართავს ხუთივე მარშრუტს და წერს ქვეშ `runtime/final_logs`:

```text
server_status
daily_rollup
player_activity
case_review
critical_guard
```

თითოეულმა მარშრუტმა უნდა ჩაიწეროს სტრუქტურირებული და თარგმნილი გამომავალი, პლუს მტკიცებულება `route_proof.json`. მარშრუტის გამორთვა წარმოშობს `missing` მტკიცებულება, ვიდრე პრეტენზია დასრულებულია.

<a id="notification"></a>
## `notification`

არასავალდებულო ზოგადი ლოკალური ფაილის გამავალი ყუთი. ის ნაგულისხმევად გამორთულია და არაფერს უგზავნის გარე პროვაიდერს.

ნაგულისხმევი:

```lua
notification = {
    enabled = false,
    mode = "local_file_outbox",
    include_expected_empty = false,
},
```

შეტყობინებების ყველა მარშრუტი ნაგულისხმევად გამორთულია. როდესაც განზრახ ჩართულია, გასასვლელმა შეიძლება მოიხმაროს მხოლოდ დასრულებული ნათარგმნი ანგარიში `route_proof.json`. ადგილობრივი მტკიცებულებები და ანგარიშები რჩება ავტორიტეტული. კონკრეტული პროვაიდერის მიწოდება, მიწოდების საბოლოო წერტილები, რწმუნებათა სიგელები და ხიდები არ არის საჯარო დამოუკიდებელი დამკვირვებლის კონტრაქტის ნაწილი.

<a id="scanning"></a>
## `scanning`

აკონტროლებს საბაზისო სკანირებას, გამშვებ პუნქტს და შეცვლილი ფაილის განახლებას.

გამოიყენეთ, როდესაც:

```text

refreshing changed files later
```

შეამოწმეთ:

```text
runtime/scan_progress.json
runtime/scan_checkpoint.json
runtime/scan_complete.json
runtime/baselines/file_manifest.tsv
```

მნიშვნელოვანი პარამეტრები:

```lua
scanning = {
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
    changed_file_detection = true,
},
```

```text
runtime/forensic_days/YYYY-MM-DD/forensic_day_summary.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
```

```text
Daily summaries are rebuildable indexes.
Source evidence remains authoritative.
```

<a id="logging"></a>

```text
keep_enforced_forever
keep_evidence_forever
```

<a id="enforcement"></a>
## `enforcement`

აკონტროლებს რეკომენდაციებს და რეალურ Admin.ini წერს.

სანამ დაცვამ შეძლოს აკრძალვის დამატება, ქვემოთ მოცემული ყველა განცხადება უნდა იყოს ჭეშმარიტი:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
account identity is mapped
not trusted
not moderator
threshold is met
```

თუ ერთი განცხადება მცდარია ან მისი შემოწმება შეუძლებელია, მცველი ტოვებს `Admin.ini` უცვლელია და აფიქსირებს მიზეზს.

<a id="admin_ini"></a>
## `admin_ini`

აკონტროლებს ფაილების უსაფრთხო ჩაწერას.

წესები:

```text
Back up before writing.
Preserve existing bans.
Preserve moderators.
Write clean BannedPlayer=<ID> only.
```

## `restart_request`

აკონტროლებს არასავალდებულო ლოკალური მარკერის ფაილებს, რომლებიც შეიძლება შეამოწმოს სხვა ოპერატორის საკუთრებაში არსებულმა პროცესმა. ის არ გადაიტვირთება და არ კლავს სერვერს.

ნაგულისხმევი:

```lua
restart_request = {
    enabled = false,
    restart_marker_file = "runtime/request_restart.flag",
    restart_reason_file = "runtime/restart_reason.json",
},
```

გამომავალი:

```text
runtime/request_restart.flag
runtime/restart_reason.json
```

არ არის შეფუთული ჰოსტინგის პანელი, პროვაიდერის ხიდი ან გადატვირთვის ავტომატიზაცია. მარკერის შექმნის ჩართვა არ ადასტურებს, რომ გარე პროცესმა მოიხმარა მოთხოვნა ან გადატვირთა სერვერი.
