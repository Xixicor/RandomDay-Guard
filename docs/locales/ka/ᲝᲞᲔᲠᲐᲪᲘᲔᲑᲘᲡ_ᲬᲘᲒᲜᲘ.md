# ოპერაციების სათამაშო წიგნი

> **კანონიკური ინგლისური წყარო:** [OPERATIONS_PLAYBOOK.md](../../OPERATIONS_PLAYBOOK.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


ეს არის ჩვეულებრივი წაკითხვის თანმიმდევრობა RandomDayGuard. თქვენ არ გჭირდებათ იცოდეთ JSON, Git, გამშვები ჯამები ან ბრძანების ხაზის ხელსაწყოები ჯანსაღი სერვერის გადასახედად.

<a id="daily-operator-flow"></a>
## ოპერატორის ყოველდღიური ნაკადი

1. გახსენით `runtime/final_logs/server_status_latest.txt`. ის გეტყვით, აკონტროლებს თუ არა Guard სერვერის მიმდინარე გაშვებას, როდის დასრულდება მისი ბოლო ციკლი, რამდენი მოთამაშეა დაკავშირებული და არასრულია თუ არა წყარო ან სკანირება.
2. გახსენით `runtime/final_logs/daily_rollup_latest.txt` დღეში ერთხელ. ის აჯამებს ერთდღიან სესიებს, გამოსვლას, დასახელებულ საქმეს, პირადობის ინვენტარს და წყაროს გაშუქებას ყოველი ინდივიდუალური ჩანაწერის გამეორების გარეშე.
3. გახსენით `runtime/final_logs/player_activity_latest.txt` მხოლოდ მაშინ, როდესაც სერვერს ჰქონდა შეერთება, დატოვება ან აქტიური სესია დღის განმავლობაში.
4. გახსენით `runtime/final_logs/case_review_latest.txt` მხოლოდ მაშინ, როდესაც ის ასახელებს მიმდინარე სუბიექტს. ანგარიში იძლევა ანგარიშს, განხილვის სტატუსს, ქულას, პირადობის წყაროს და შემდეგ გასახსნელად ჩანაწერებს.
5. გახსენით `runtime/final_logs/critical_guard_latest.txt` მხოლოდ მაშინ, როდესაც Guard იტყობინება წარუმატებლობის შესახებ საკუთარი გაშვების, მონიტორინგის ციკლის ან ანგარიშის ჩაწერის დროს.

თუ მარშრუტს არაფერი აქვს საანგარიშო, მცველი ჩაწერს მოსალოდნელ-ცარიელ შედეგს. ეს არის დასრულებული შემოწმება და არა გამოტოვებული ანგარიში.

<a id="what-to-read-inside-a-report"></a>
## რა უნდა წაიკითხოთ მოხსენებაში

წაიკითხეთ ეს სექციები თანმიმდევრობით:

1. **შეჯამება** - რას მოიცავს ეს ანგარიში.
2. **რა დააკვირდა მცველმა** - ამ მარშრუტისთვის შეგროვებული ფაქტობრივი დროის ანაბეჭდები, რაოდენობა, ანგარიშები, სესიები ან სტატუსის მნიშვნელობები.
3. **რას ნიშნავს** - ამ ჩანაწერების უბრალო ენაზე ინტერპრეტაცია.
4. **რა რჩება უცნობი** - წყაროს ან სკანირების ლიმიტი, რომელიც გავლენას ახდენს შედეგზე.
5. **რეკომენდირებულია შემდეგი ნაბიჯი** - მონიტორინგი, დასახელებული სუბიექტის გადახედვა თუ მცველის შეკეთება.
6. **მტკიცებულებების საზღვარი** - მოხსენების ფარგლების ლიმიტი.

ტექნიკური ჩანაწერი და წყაროს მითითებები გამოჩნდება ბოლოს მკითხველებისთვის, რომლებსაც სჭირდებათ ზუსტი სტრუქტურირებული მტკიცებულებების შემოწმება.

<a id="when-a-report-is-missing"></a>
## როდესაც ანგარიში აკლია

გახსენით `runtime/final_logs/route_proof.json` მხოლოდ მაშინ, როდესაც წაკითხვადი ანგარიში არ არის ან ნათქვამია, რომ მისი მიმდინარე მტკიცებულება აკლია. თითოეულ მარშრუტს აქვს შემდეგი შედეგიდან ერთი:

| შედეგი | მნიშვნელობა |
|---|---|
| `full` | მცველმა დაასრულა მარშრუტი მიმდინარე მარშრუტის საკუთრებაში არსებული მტკიცებულებებით. |
| `limited_expected_empty` | მცველმა დაასრულა მარშრუტი და ვერ იპოვა საკვალიფიკაციო ღონისძიება, ან ჩაწერა დასახელებული სიმწიფის ლიმიტი. |
| `missing` | მოთხოვნილი წყარო, საგვარეულო შემოწმება ან დაწყვილებული ანგარიშის ჩაწერა არ დასრულებულა. |

გამოტოვებული მარშრუტისთვის მიჰყევით დასახელებულ წყაროს ან ჩაწერეთ შეცდომა ანგარიშში. ჯერ არ შეცვალოთ დაუკავშირებელი მარშრუტები ან შეტყობინების პარამეტრები.

<a id="after-a-crash-or-restart"></a>
## ავარიის ან გადატვირთვის შემდეგ

1. სერვერის სტატუსის წაკითხვა ახალი სერვერზე გაშვებული დროის ანაბეჭდისა და უახლესი დასრულებული მონიტორინგის ციკლისთვის.
2. წაიკითხეთ Critical Guard მიმდინარე გაშვების ან გამოკითხვის წარუმატებლობისთვის.
3. მოთამაშის აქტივობის წაკითხვა მხოლოდ იმ შემთხვევაში, თუ იმავე დღის სესია შეუერთდა, დატოვა ან დაბრუნდა სასიცოცხლო ციკლის ცვლილების შემდეგ.
4. კონფიგურაციის შეცვლამდე შეინახეთ ციტირებული წყაროს ჩანაწერი.

<a id="before-enabling-optional-adminini-writes"></a>
## არასავალდებულო ჩართვამდე Admin.ini წერს

ნაგულისხმევი პაკეტი უყურებს და ანგარიშებს `Admin.ini`. მოწინავე ოპერატორებს შეუძლიათ ჩართონ არასავალდებულო აღსრულების გზა ფაილის ასლის შესამოწმებლად. მცველი შემდეგ მოითხოვს სუფთა ციფრული ანგარიშის ID-ს, იცავს სანდო ანგარიშებს, ქმნის და ამოწმებს სარეზერვო ასლს, უარყოფს პარალელურ ცვლილებებს, კითხულობს შენახულ ფაილს და აღადგენს სარეზერვო ასლს, თუ ვერიფიკაცია ვერ მოხერხდა. იხილეთ [`ADMIN_INI_ENFORCEMENT.md`](ADMIN_INI_ENFORCEMENT.md) სრული დაყენებისა და ტესტირების პროცედურისთვის.
