# უსაფრთხოების პოლიტიკა

> **კანონიკური ინგლისური წყარო:** [SECURITY.md](../../../SECURITY.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


<a id="report-a-vulnerability-privately"></a>
## შეატყობინეთ დაუცველობის შესახებ პირადად

გამოიყენეთ [GitHub პირადი დაუცველობის მოხსენება](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) კონფიდენციალური ანგარიშის გასაგზავნად საცავის მფლობელთან. თუ ეს ფორმა მიუწვდომელია, გამოიყენეთ [მფლობელის საჯარო GitHub პროფილი](https://github.com/Xixicor) მოითხოვეთ პირადი საკონტაქტო არხი დაუცველობის დეტალების გარეშე.

არ გახსნათ საჯარო საკითხი, რომელიც შეიცავს ექსპლოიტის ნაბიჯებს, რწმუნებათა სიგელებს, სერვერის კერძო ბილიკებს, მოთამაშის იდენტიფიკატორებს, `Admin.ini`, შენახული მონაცემები, webhook URL-ები ან ცოცხალი მტკიცებულების ფაილები.

<a id="include-useful-evidence"></a>
## შეიტანეთ სასარგებლო მტკიცებულება

მიუთითეთ:

- დაზარალებული RandomDayGuard ვერსია ან commit;
- დაზარალებული კომპონენტი და მოსალოდნელი უსაფრთხო ქცევა;
- მინიმალური რეპროდუქციის ეტაპები გაწმენდილი მოწყობილობების გამოყენებით;
- დაკვირვებული ზემოქმედება და განმეორებადი თუ არა; და
- ნებისმიერი შემოთავაზებული შემარბილებელი საშუალება, რომელიც არ ასახავს პირად მონაცემებს.

არ გაგზავნოთ რეალური საიდუმლოებები. შეცვალეთ პირადი ბილიკები, ანგარიშის იდენტიფიკატორები, ჰოსტების სახელები და ჟეტონები მკაფიო ჩანაცვლებით, პრობლემის რეპროდუცირებისთვის საჭირო სტრუქტურის შენარჩუნებით.

<a id="expect-review-first-handling"></a>
## მოველით განხილვას პირველ რიგში

ანგარიში არის მტკიცებულება შემნახველის მიმოხილვისთვის, არა ავტორიზაციის სერვერზე წვდომის, ცოცხალი სამიზნის შესამოწმებლად, ექსპლოიტის დეტალების გამოქვეყნების ან მარცხით დახურული ნაგულისხმევის შესუსტებისთვის. მფლობელი დაადასტურებს ფარგლებს და კოორდინაციას გაუწევს ნებისმიერ გამჟღავნებას პირადი ანგარიშის მეშვეობით.
