# ვალიდაცია და გამოშვება

> **კანონიკური ინგლისური წყარო:** [VALIDATION_AND_RELEASE.md](../../VALIDATION_AND_RELEASE.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


ეს გვერდი განკუთვნილია კონტრიბუტორებისა და გამოშვების შემსრულებლებისთვის. სერვერის ოპერატორებს არ სჭირდებათ ამ ბრძანებების გაშვება RandomDayGuard.

<a id="user-visible-proof"></a>
## მომხმარებლის თვალსაჩინო მტკიცებულება

გამოშვება გასაგებია, როდესაც ახალ ოპერატორს შეუძლია მისი ინსტალაცია, იპოვოს პირველი სერვერის სტატუსის ანგარიში, განასხვავოს ანგარიშის ხუთი მარშრუტი და მიჰყვეს ერთი მკაფიო მოქმედებას დამუშავებული მაგალითიდან. მკითხველის ამოცანები არ უნდა მოითხოვდეს Git-ის, PowerShell, Python-ის ან გამშვები ჯამის ცოდნას.

<a id="contributor-checks"></a>
## კონტრიბუტორი ამოწმებს

```powershell
python -B tools/validate_repo.py
python -B tools/test_public_pipeline.py
python -B -m unittest discover tests
```

როდესაც `luac` ხელმისაწვდომია:

```powershell
luac -p RandomDayGuard/Scripts/main.lua
luac -p RandomDayGuard/Scripts/public_pipeline.lua
```

ლუას მოწყობილობების ტესტები მოიცავს ჩამტვირთველს, განრიგს, მოხსენების მარშრუტებს და არჩევით Admin.ini ტრანზაქციის ჩაწერა. აღსრულების პროგრამები იყენებს მხოლოდ დროებით ფაილებს და ადასტურებს იდენტურობას, სანდო ანგარიშის უარყოფას, ზღვრებს, სარეზერვო ასლებს, ერთდროულად შეცვლაზე უარის თქმას, წაკითხვას და დაბრუნებას.

<a id="package-proof"></a>
## პაკეტის მტკიცებულება

```powershell
python -B tools/build_release_zip.py --check
git diff --check
```

- ყველა ვერსიის მარკერი ემთხვევა `VERSION`.
- მხოლოდ მიმდინარე ვერსია არსებობს `releases/`.
- ZIP შეიცავს კანონიკურ `RandomDayGuard/Scripts/main.lua` ბილიკი და არ არის პატარა ასოების ვარიანტის ჩამტვირთავი.
- გაშვების დროის გამომავალი, პირადი კონფიგურაცია, რწმუნებათა სიგელები, ლოკალური ბილიკები, ქეშები და სატესტო არტეფაქტები გამორიცხულია.
- საჯარო კონფიგურაცია რჩება მხოლოდ განხილვის შემთხვევაში, როდესაც აღსრულება გამორთულია.
- ხუთი დამუშავებული ანგარიშის მაგალითები შეესაბამება მარშრუტის მფლობელობას და გამოშვების ტესტის ინსტრუქციას.
- ZIP ბაიტებს დეტერმინისტული და ემთხვევა `CHECKSUMS.sha256`.
- ყველა ადგილობრივი დოკუმენტაციის ბმული და ლოკალური შესვლის 27 გვერდი ვალიდირებულია.

<a id="avoid-validation-environment-pitfalls"></a>
## მოერიდეთ ვალიდაციის გარემოს ხარვეზებს

- შეასრულეთ საცავში ჩაწერის შემოწმებები სერიულად, რათა თავიდან აიცილოთ დროებითი ფაილების კამათი.
- Windows-ზე, დუბლიკატი ჩამტვირთველების შემოწმებისას, შეამოწმეთ წევრების დაარქივებული სახელები ან ჩამოთვლილი ბილიკის მართლწერა, ვიდრე რეგისტრირებული ფაილების ძიება.
- გამოტოვებულია `luac` ბრძანება ან Lua Runtime მიუწვდომელი შესაძლებლობაა და არა ჩაბარებული სინტაქსი ან გაშვების ტესტი.
- მოწყობილობა ადასტურებს მხოლოდ მის მოდელირებულ შეყვანას. ეს არ ამტკიცებს, რომ ცოცხალი სერვერი აწარმოებს მიმდინარე მოხსენებას.
- ჩაწერეთ ბრძანების დროის ამოწურვა და ნაწილობრივი გამომავალი, დასრულებამდე ვარაუდის ნაცვლად.

<a id="repair-failed-repository-validation"></a>
## საცავის წარუმატებელი ვალიდაციის შეკეთება

დაიწყეთ პირველი მოხსენებული ბილიკით ან კონტრაქტით. შეასწორეთ ეს ელემენტი, ხელახლა გაიარეთ ვიწრო ტესტი, შემდეგ კვლავ გაუშვით სრული მატრიცა. არ დამალოთ გამოტოვებული შესაძლებლობა ტესტის წაშლით, რომელიც ამას მოითხოვს.

<a id="known-limits-and-release-decision"></a>
## ცნობილი ლიმიტები და გათავისუფლების გადაწყვეტილება

ადგილობრივი შემოწმებები ადასტურებს კონტრაქტებს წყაროს, მოწყობილობების, პაკეტისა და დოკუმენტაციის შესახებ. კონკრეტული სერვერის ინსტალაცია, გრძელვადიანი სტაბილურობის ფანჯარა ან კლიენტის ჩვენება მოითხოვს ცალკე ინტეგრაციის შედეგს. ჩაწერეთ ეს შედეგი მისი აგებულებით, კონფიგურაციით, ხანგრძლივობითა და დაკვირვებით, სანამ შესატყვისი პრეტენზია გამოთქვამთ.
