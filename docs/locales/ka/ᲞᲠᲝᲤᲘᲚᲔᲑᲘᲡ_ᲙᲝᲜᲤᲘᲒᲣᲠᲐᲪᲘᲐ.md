# კონფიგურაციის პროფილები

> **კანონიკური ინგლისური წყარო:** [CONFIG_PROFILES.md](../../CONFIG_PROFILES.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


გამოიყენეთ ეს სახელმძღვანელო, რომ აირჩიოთ და გამოიყენოთ პრაქტიკული კონფიგურაციის პროფილი. ახსნისთვის, თუ როგორ ურთიერთქმედებენ პარამეტრების ჯგუფები, წაიკითხეთ [`CONFIG_REFERENCE.md`](%E1%B2%99%E1%B2%9D%E1%B2%9C%E1%B2%A4%E1%B2%98%E1%B2%92%E1%B2%A3%E1%B2%A0%E1%B2%90%E1%B2%AA%E1%B2%98%E1%B2%98%E1%B2%A1_%E1%B2%9B%E1%B2%98%E1%B2%97%E1%B2%98%E1%B2%97%E1%B2%94%E1%B2%91%E1%B2%90.md). ზუსტი ველებისთვის, ნაგულისხმევი, ტიპებისა და ინვარიანტებისთვის გამოიყენეთ გენერირებული [`CONFIG_FIELD_CATALOG.md`](CONFIG_FIELD_CATALOG.md).

ქვემოთ ლუას თითოეული ბლოკი არის უმაღლესი დონის შენატანების ნაკრები, რომელსაც შეუძლია შეცვალოს შესაბამისი ჩანაწერები გაგზავნილში `return { ... }` ცხრილი.

<a id="profile-chooser"></a>
## პროფილის ამომრჩეველი

| სიტუაცია | გამოიყენეთ ეს პროფილი |
|---|---|
| პირველი ინსტალაცია | უსაფრთხო პირველი ინსტალაცია |
| სერვერი არასტაბილურია და ხშირად იშლება | მიმდინარე მტკიცებულება ნელი სკანირების გარეშე |
| გსურთ object/world კონტექსტი | სრული საბაზისო |
| გსურთ ძველი ჟურნალების გადახედვა | კრიმინალისტიკური შემავსებელი |
| გსურთ რეკომენდაციები, მაგრამ არა ჩაწერა | აღსრულების ტესტირება |
| თქვენ მზად ხართ მცველს მისცეთ უფლება დაწეროს აკრძალვები | აღსრულება ჩართულია |
| დისკი შეზღუდულია | დისკის დაბალი ზრდა |
| თქვენ დაასრულეთ სუფთა საბაზისო ხაზი | საკმარისი სარეზერვო დაყენება |

<a id="safe-first-install"></a>
## უსაფრთხო პირველი ინსტალაცია

პირველ რიგში გამოიყენეთ ეს პირდაპირ სერვერზე.

```lua
enforcement = {
    review_only_mode = true,
    auto_ban = false,
    write_admin_ini = false,
},

log_tail = {
    enabled = true,
    start_at_end_on_first_run = true,
    tail_backup_logs = false,
},

scanning = {
    full_scan_on_start = true,
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
},

reports = {
    enabled = true,
},

notification = {
    enabled = false,
},
```

რას აკეთებს ეს:

```text
Tracks live sessions.
Starts the baseline scan.
Does not edit Admin.ini.
Avoids treating old backup logs as fresh live events.
```

<a id="current-evidence-without-slow-scan"></a>
## მიმდინარე მტკიცებულება ნელი სკანირების გარეშე

გამოიყენეთ ეს, თუ სერვერი არასტაბილურია და გჭირდებათ crash/reconnect მტკიცებულება მძიმე სკანირებამდე.

```lua
log_tail = {
    enabled = true,
},

scanning = {
    full_scan_on_start = false,
},

enforcement = {
    review_only_mode = true,
    auto_ban = false,
    write_admin_ini = false,
},

reports = {
    enabled = true,
},

notification = {
    enabled = false,
},
```

რას აკეთებს ეს:

```text
Tracks logins, joins, leaves, reconnects, crashes, and unclean sessions.
Delays heavy world scanning.
```

<a id="full-baseline"></a>
## სრული საბაზისო

გამოიყენეთ ეს მას შემდეგ, რაც სერვერი დიდხანს დარჩება სკანირებისთვის.

```lua
scanning = {
    full_scan_on_start = true,
    resume_incomplete_scan = true,
    reuse_completed_baseline = true,
    incremental_refresh_after_baseline = true,
},
```

რას აკეთებს ეს:

```text
Builds object registry.
Writes world-state context.
Creates file manifest.
Enables changed-file refresh later.
```

<a id="forensic-backfill"></a>
## კრიმინალისტიკური შემავსებელი

გამოიყენეთ ეს მხოლოდ ისტორიული ჟურნალების განზრახ განხილვისას.

```lua
log_tail = {
    start_at_end_on_first_run = false,
    tail_backup_logs = true,
    backfill_backup_logs_on_start = true,
},
```

გამოყენებამდე:

```text
Back up runtime/log_offsets.tsv.
Expect old events to be reprocessed.
Return to live settings when finished.
```

<a id="enforcement-testing"></a>
## აღსრულების ტესტირება

გამოიყენეთ ეს ადრე Admin.ini წერა.

```lua
enforcement = {
    review_only_mode = true,
    auto_ban = false,
    write_admin_ini = false,
},
```

რა უნდა შეამოწმოთ:

```text
runtime/account_evidence.json
runtime/warnings/
runtime/forensic_days/YYYY-MM-DD/ban_recommendations.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="enforcement-enabled"></a>
## აღსრულება ჩართულია

გამოიყენეთ ეს მხოლოდ მას შემდეგ, რაც მიმოხილვა სწორი იქნება.

```lua
enforcement = {
    review_only_mode = false,
    auto_ban = true,
    write_admin_ini = true,
    require_clean_ban_id = true,
    preserve_existing_bans = true,
    preserve_moderators = true,
},
```

ჩართვამდე:

```text
Trusted IDs are configured.
Moderator IDs are preserved.
Admin.ini backups work.
Ban recommendations are understandable.
Thresholds are accepted by the server owner.
```

<a id="low-disk-growth"></a>
## დისკის დაბალი ზრდა

გამოიყენეთ ეს, როდესაც გაშვების ფაილები ძალიან სწრაფად იზრდება.

```lua
logging = {
    low_importance_mode = "aggregate",
    write_low_importance_raw_events = false,
},

retention = {
    detailed_retention_days = 7,
    rotate_jsonl_when_bytes_exceed = 5242880,
    max_raw_events_lines = 20000,
    compact_json_outputs = true,
},
```

<a id="sticky-backup-setup"></a>
## საკმარისი სარეზერვო დაყენება

გამოიყენეთ პირველი დასრულებული საბაზისო ხაზის შემდეგ.

შეამოწმეთ, რომ არსებობს:

```text
runtime/scan_complete.json
runtime/object_registry.json
runtime/object_registry_counts.tsv
runtime/baselines/last_completed_baseline.json
runtime/baselines/file_manifest.tsv
runtime/world_state/current/world_state_latest.json
```

შემდეგ შექმენით მათი სარეზერვო ასლები `config.lua`, `SavedRoot.txt` და `Admin.ini`.
