# არქიტექტურა და სიცოცხლის ციკლი

> **კანონიკური ინგლისური წყარო:** [ARCHITECTURE.md](../../ARCHITECTURE.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


RandomDayGuard არის ერთი UE4SS დამკვირვებელი პლუს ერთი იზოლირებული საანგარიშო მოდული. ის კითხულობს სერვერის საკუთრებაში არსებულ ფაილებს, ინარჩუნებს შეზღუდულ ადგილობრივ მდგომარეობას და წერს ადგილობრივ მტკიცებულებებს და მიმოხილვის შედეგებს. მას არ აქვს პროვაიდერი, მართვის პანელი, შეტყობინებების სერვისი, RandomDay ან ქსელის დამოკიდებულება.

<a id="end-to-end-data-flow"></a>
## მონაცემთა ნაკადი ბოლოდან ბოლომდე

1. UE4SS იტვირთება ერთი კანონიკური შესასვლელი წერტილი `RandomDayGuard/Scripts/main.lua`. ამჟამინდელი პაკეტები არ იგზავნება მცირე რეგისტრის ვარიანტების დუბლიკატზე.
2. ჩამტვირთავი კითხულობს `config.lua`, სამი მონაცემთა ლექსიკონი და სურვილისამებრ `SavedRoot.txt`. ვერსიის იდენტიფიკაცია უნდა ეთანხმებოდეს `VERSION`, `MANIFEST.json` და `BUILD_MARKER.txt`.
3. შენახული ფესვის აღმოჩენა ამოწმებს შეზღუდულ ცნობილ კანდიდატებს და პირდაპირ ცნობილ ფაილებს. ის იწერს იმას, რაც იკითხებოდა `runtime/saved_path_probe.json`; მხოლოდ დირექტორიის პოვნა არ არის მტკიცებულების გაშუქება.
4. პირდაპირი ფენა ადევს აქტიურ სერვერის ჟურნალს უსაფრთხო ოფსეტურიდან. ის ახდენს ცხოვრების ციკლის, სესიის, ანგარიშის, გაფრთხილების, ხელახლა დაკავშირების და სხვა დაკვირვებულ მოვლენებს ნორმალიზებას მხოლოდ მტკიცებულებებად და მიმდინარე კადრებში.
5. ნელი ფენის ინვენტარიზაცია ინახება შენახულ ფაილებს შემოსაზღვრულ ნაწილებად. ის წერს პროგრესს და ამოწმებს, განაახლებს არასრულ სამუშაოს, ადარებს შეცვლილი ფაილის მანიფესტს და აწარმოებს ნაწილობრივ შემდეგ საბოლოო object/world კონტექსტი.
6. მიმოხილვის ლოგიკა აკავშირებს მხოლოდ მის ხელთ არსებულ მტკიცებულებებს. სუსტი ფაილის სახელები, დრო, კლასების რაოდენობა, ფარდობითი კოორდინატები, შეფერხება, ერთი ავარია ან პინგი რჩება კონტექსტში და არ შეუძლია მხოლოდ აღსრულების ავტორიზაცია.
7. ცალკე მოხსენების თანამშრომელი ურეკავს `Scripts/public_pipeline.lua`. ის აგროვებს წყაროს კლასებს, აღრიცხავს მიმდინარე ისტორიულ მასშტაბებს, აკავშირებს ციკლს version/boot/epoch/poll/source სიახლე, წერს ხუთ მარშრუტს JSON/TXT წყვილდება და შემდეგ წერს `route_proof.json`.
8. როდესაც ცალსახად ჩართულია, ადგილობრივი გასასვლელი აკოპირებს მითითებებს დასრულებული ანგარიშიდან მარშრუტის მტკიცებულების არსებობის შემდეგ. ის ჩაწერს `delivery_backend="none"` და `delivery_attempted=false`; ტრანსპორტი ამ პროდუქტის გარეთ არის.

## მიმდინარე და ისტორიული მტკიცებულებები

მიმდინარე მტკიცებულება ეკუთვნის აქტიურ boot/poll და არასოდეს არის რეკონსტრუირებული მხოლოდ შენახული ფაილის სახელებიდან. ისტორიული მტკიცებულებები მოიცავს შემობრუნებულ მორებს, გამძლე account/session ისტორია, შენახული cases/reports/evidence და შემოსაზღვრული მსოფლიოს შენახვა სკანირება. ანგარიშები ავლენს ცალკეულ მიმდინარე და ისტორიულ მასივებს და რაოდენობას. ჩუმად გადატვირთვამ არ უნდა წაშალოს გამძლე კონტექსტი და ისტორიული ჩანაწერი არ უნდა იყოს წარმოდგენილი როგორც ამჟამინდელი ყოფნა.

<a id="completion-and-recovery-boundary"></a>
## დასრულებისა და აღდგენის საზღვარი

ერთი მარშრუტის დასრულება მოითხოვს მიმდინარე ციკლის ვერსიის შესატყვისს, ჩატვირთვის ID, ეპოქის ID, პოზიტიური გამოკითხვის ID, ახალი აქტიური ჟურნალის სტატუსი, ორივე მარშრუტის გამოსავალი და მისი შეყვანა `route_proof.json`. შეტყობინების პრეტენზიები დამატებით მოითხოვს იმავე ციკლის ლოკალურ კონვერტს; გარე მიწოდება არასოდეს არის საჯარო მტკიცებულების ნაწილი.
