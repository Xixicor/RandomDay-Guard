# სამუშაო ოპერაციის მაგალითები

> **კანონიკური ინგლისური წყარო:** [EXAMPLE_RUNS.md](../../EXAMPLE_RUNS.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


ეს მაგალითები იყენებენ გამოგონილ მნიშვნელობებს მოსალოდნელი მდგომარეობის გადასვლების ასახსნელად; ისინი არ არის ცოცხალი თავსებადობა ან მოთამაშის მტკიცებულება.

<a id="successful-current-cycle"></a>
## წარმატებული მიმდინარე ციკლი

შეყვანები: იკითხებადი აქტიური ჟურნალი, version/boot/epoch, `poll_id=41`, დასრულდა მიმდინარე გამოკითხვა, ჩასაწერი accounting/history/report ფესვები, ნელი სკანირების წესების გარეშე.

მოსალოდნელია:

```text
server_status = full
player_activity = full or limited_expected_empty
case_review = full or limited_expected_empty
daily_rollup = full or limited_expected_empty
critical_guard = full or limited_expected_empty
```

ყველა ჩართული მარშრუტი აქვს JSON/TXT გამომავალი და იგივე ხაზი `route_proof.json`. მარშრუტის სტატუსი დამოკიდებულია საკუთარ სუბიექტებზე და არა ზოგად წარმატებაზე.

<a id="expected-empty-player-and-case-routes"></a>
## მოსალოდნელი-ცარიელი დამკვრელისა და ქეისის მარშრუტები

შეყვანები: მიმდინარე ციკლის მტკიცებულება დასრულებულია; არ არის მიმდინარე ან შენარჩუნებული მოთამაშის რიგები; არ არის შენახული ქეისი და არ არის მიმდინარე REVIEW/BAN-ELIGIBLE ანგარიში.

მოსალოდნელია:

```text
player_activity.route_proof_status = limited_expected_empty
player_activity.expected_empty = true
player_activity.players = []

case_review.route_proof_status = limited_expected_empty
case_review.expected_empty = true
case_review.cases = []
```

თარგმნილი ანგარიშები ამბობს, რომ არცერთი დასაშვები შეზღუდული სუბიექტი არ დაფიქსირებულა. ისინი ასევე ამბობენ, რომ ეს არ ამტკიცებს, რომ არავის არასოდეს უკავშირდებოდა ან რომ კონტექსტი არ აკლია. ადგილის დამჭერი არ არის player/case შექმნილია.

<a id="partial-bounded-scan"></a>
## ნაწილობრივ შემოსაზღვრული სკანირება

შეყვანები: ახალი დენი log/poll; `scan_checkpoint.json` ან `scan_progress.json` არსებობს; სკანირება არასრულია; ნაგულისხმევი `slow_world_scan_blocks_current_reports=false`.

მოსალოდნელია:

```text
world_save_scan.status = partial
source accounting = partial
server_status may still be full for fresh current state
historical routes name the scan limitation
```

დაყენება `slow_world_scan_blocks_current_reports=true` მხოლოდ მაშინ, როდესაც ოპერატორს სურს, რომ სურვილისამებრ ნელი წყარო დაბლოკოს მიმდინარე ანგარიშები. აღდგენა არის იმის საშუალება, რომ სკანირების მუშაკმა განაახლოს და არა საგუშაგოს წაშლა.

<a id="missing-current-cycle-proof"></a>
## გამოტოვებულია მიმდინარე ციკლის მტკიცებულება

შეყვანები: აქტიური ჟურნალი მიუწვდომელია, `poll_id=0` ან boot/epoch/last-poll გვარი აკლია.

მოსალოდნელია:

```text
current_cycle_proof_complete = false
all route proof statuses = missing
each configured route envelope status = suppressed_current_cycle
delivery_eligible = false
delivery_attempted = false
```

ჩახშობილი კონვერტი არის აუდიტის ჩანაწერი და არა რიგში მიწოდება. ძველი ბოლო ჟურნალები მხოლოდ ისტორიულად რჩება. შეაკეთეთ პირველი დაკარგული lineage/source ველი და გენერირება უფრო ახალი ციკლი.

<a id="malformed-optional-adminini-source"></a>
## არასწორი არჩევითი Admin.ini წყარო

შეყვანები: `Admin.ini` არსებობს, მაგრამ სტრუქტურული ვალიდაცია ვერ მოხერხდა.

მოსალოდნელია:

```text
admin_ini.status = malformed
source reference preserved
write/enforcement path closed
```

შეინახეთ ფაილი და აღადგინეთ განხილული სუფთა ფორმატი. შეინახეთ განმარტებითი ტექსტი გაშვების მტკიცებულებებში; თითოეული `Admin.ini` შესვლის აკრძალვა რჩება მხოლოდ `BannedPlayer=<ID>`.

<a id="required-active-log-probe-error"></a>
## აუცილებელი აქტიური ჟურნალის გამოძიების შეცდომა

შეყვანები: შემოსაზღვრული, საჭირო აქტიური ჟურნალის ზონდი ვერ ხერხდება გაწმენდილი წაკითხვის შეცდომით.

მოსალოდნელია:

```text
source_accounting.sources[active_log].status = error
source_accounting.sources[active_log].detail = "bounded active-log probe failed: <sanitized reason>"
coverage_status = unavailable
all route proof statuses = missing
```

`error` რჩება საწყის მწკრივზე მისი შემოსაზღვრული დეტალებით. უმაღლესი დონის ანგარიში იყენებს `unavailable` და მარშრუტის მტკიცებულება რჩება `missing` სანამ ახალი მიმდინარე ციკლი არ დაადასტურებს საჭირო წყაროს.

<a id="incompatible-or-stale-baseline"></a>
## შეუთავსებელი ან მოძველებული საბაზისო ხაზი

შეყვანები: შეიცვალა package/source ვინაობა ან stale/incompatible საბაზისო მანიფესტი.

მოსალოდნელია: ვალიდაციის ან გაშვების სტატუსი აღრიცხავს შეუთავსებლობას; სკანირების მდგომარეობა არ აცხადებს დასრულებულ ხელახლა გამოყენებას. შეინახეთ წინასწარი მტკიცებულებები, დაიწყეთ საბაზისო ხაზის აშკარა აღდგენა და დაელოდეთ ახალ ტერმინალის მტკიცებულებას. იძულებითი აღდგენა ჩაწერილი მიზეზის გარეშე არ არის ნაგულისხმევი აღდგენა.

<a id="paired-report-write-failure"></a>
## დაწყვილებული მოხსენების ჩაწერის წარუმატებლობა

შეყვანები: JSON ჩაწერა წარმატებით დასრულდა, მაგრამ TXT ჩაწერა ვერ მოხერხდა, ან პირიქით.

მოსალოდნელია:

```text
route_proof_status = missing
completed = false
coverage_status = unavailable
output_write_detail = "paired JSON/TXT write failed: <sanitized reason>"
next_action = repair both route output writes
```

მწერალი საუკეთესო ძალისხმევით ხელახლა წერს ორივე და-ძმას მარცხის შესახვედრად. ერთი წარმატებული ძმა არ შეიძლება დარჩეს წარმატების პრეტენზიად. შემოსაზღვრული ჩაწერის დეტალი არ ქმნის მეხუთე ზედა დონის დაფარვის მნიშვნელობას.

<a id="route-proof-write-failure"></a>
## მარშრუტის საწინააღმდეგო ჩაწერის წარუმატებლობა

შეყვანები: მარშრუტების წყვილები დაიწერა, მაგრამ `route_proof.json` ჩანაცვლება შეუძლებელია.

მოსალოდნელია: ყველა ანგარიში ხელახლა დაიწერა `missing`, შეტყობინების ყველა შედეგი არის `route_proof_write_failed` და კონვერტი არ მიიღება. კონფიგურირებულ მარშრუტს შეიძლება ჰქონდეს `suppressed_current_cycle` აუდიტის კონვერტი მიწოდების დროშებით false. შეაკეთეთ გამომავალი ფესვი და განაახლეთ იგივე მიმდინარე ციკლი.

<a id="review-only-enforcement-example"></a>
## მხოლოდ მიმოხილვის აღსრულების მაგალითი

კონფიგურაცია:

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

მოსალოდნელია: შეიძლება დაიწეროს ქულები, შემთხვევები და რეკომენდაციები; `Admin.ini` უცვლელი რჩება. ეს არის საჯარო ნაგულისხმევი.

<a id="approved-write-success-example"></a>
## დამტკიცებული ჩაწერის წარმატების მაგალითი

მხოლოდ ცალკე დამტკიცებულ ტესტს შეუძლია სამივე ჩაწერის ჩამრთველის დაყენება. მან ასევე უნდა დაამტკიცოს სუფთა რიცხვითი იდენტურობა, trust/moderator გამორიცხვა, ზღვრული დასაშვებობა, მოქმედებს Admin.ini path/parse, სარეზერვო ასლის წარმატება, ჩაწერის წარმატება, წაკითხვის თანასწორობა და ანგარიშის სპეციფიკური მტკიცებულება.

მოსალოდნელია:

```text
runtime/backups/Admin_<timestamp>_<source-fingerprint>_<clean-ID>.ini
Admin.ini contains one clean BannedPlayer=<ID>
runtime/enforced_bans.jsonl and evidence mirror record success
```

წარმატებული მაგალითი არ იძლევა ავტომატურ აღსრულებას სხვა ანგარიშებისთვის.

<a id="writereadback-failure-with-rollback"></a>
## Write/readback წარუმატებლობა უკან დაბრუნებასთან ერთად

შეყვანები: ყველა წინასწარ ჩაწერის კარი გავიდა; ჩანაცვლების ჩაწერა ან წაკითხვა ვერ ხერხდება; `rollback_on_readback_failure=true` და დადასტურებული სარეზერვო ასლი ხელმისაწვდომია.

მოსალოდნელია: წარუმატებლობის მტკიცებულება აღრიცხავს სტადიას და `rollback_success`; ორიგინალი Admin.ini ბაიტები აღდგენილია და ანგარიში არ არის მოხსენებული, როგორც წარმატებით განხორციელებული. თუ უკან დაბრუნება ასევე ვერ მოხერხდა, შეწყვიტე ჩაწერა, შეინახეთ ორივე files/evidence და ხელით აღადგინეთ სარეზერვო ასლი.

<a id="local-outbox-example"></a>
## ლოკალური გასასვლელის მაგალითი

შეყვანები: შეტყობინება ჩართულია `local_file_outbox` რეჟიმი, მარშრუტი ჩართულია, დასრულებული მარშრუტის დადასტურება და ან `full` ან აშკარად დაშვებულია მოსალოდნელი- ცარიელი.

მოსალოდნელი კონვერტი:

```text
schema = randomdayguard.notification/v1
completed_output = true
status = ready_for_local_consumer
delivery_eligible = true
delivery_backend = none
delivery_attempted = false
```

missing/ineligible გამომავალი, იგივე გზა შეიძლება შეიცავდეს `status=suppressed_current_cycle`, `completed_output=false` და `delivery_eligible=false`. ნებისმიერი ფაილი ადასტურებს მხოლოდ ლოკალურ ჩაწერას. არცერთი პროვაიდერის, ტრანსპორტირების, მიწოდების ან წაკითხვის ქვითარი არ არის შეფუთული ან დასკვნითი.
