# ინსტალაცია RandomDayGuard

> **კანონიკური ინგლისური წყარო:** [INSTALL.md](../../../INSTALL.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


ეს სახელმძღვანელო დაინსტალირებს `v0.4.12-alpha` Abiotic Factor ერთგულ სერვერზე, რომელიც უკვე იყენებს UE4SS. მოდი არ არის მიბმული ერთ ჰოსტინგ კომპანიასთან ან მართვის პანელთან.

<a id="before-you-begin"></a>
## სანამ დაიწყებთ

თქვენ გჭირდებათ:

- წვდომა გამოყოფილი სერვერის შესაჩერებლად და გასაშვებად;
- სერვერის UE4SS `Mods` საქაღალდე;
- მიმდინარე RandomDayGuard საქაღალდე, თუ განაახლებთ;
- სერვერის მონაცემების სარეზერვო ასლი, რომელსაც ჩვეულებრივ იცავთ რეჟიმის შეცვლამდე.

**Mods საქაღალდე** არის `ue4ss/Mods/` დირექტორია გამოყოფილი სერვერის ინსტალაციის შიგნით. RandomDayGuard ეკუთვნის პირდაპირ ამ საქაღალდეში.

<a id="new-installation"></a>
## ახალი ინსტალაცია

1. გააჩერეთ გამოყოფილი სერვერი.
2. ამოიღეთ RandomDayGuard ZIP ახალ ცარიელ საქაღალდეში.
3. დააკოპირეთ ამოღებული `RandomDayGuard` საქაღალდე სერვერის UE4SS `Mods` საქაღალდე. შედეგი უნდა იყოს ერთი `Mods/RandomDayGuard/` საქაღალდე და არა მეორე RandomDayGuard საქაღალდე ჩასმულია მასში.
4. გახსენით UE4SS `mods.txt` და ჩართეთ:

   ```text
   RandomDayGuard : 1
   ```

5. ჩართეთ სერვერი ნორმალურად.
6. დაელოდეთ UE4SS და თამაშის სერვერი დაიწყება, შემდეგ მიჰყევით [წაიკითხეთ პირველი ანგარიში](%E1%B2%93%E1%B2%90%E1%B2%98%E1%B2%AC%E1%B2%A7%E1%B2%94%E1%B2%97_%E1%B2%90%E1%B2%A5.md).

არ დააკოპიროთ ახალი გამოშვება გაშვებული ინსტალაციის დროს. შეინახეთ სარეზერვო ასლი მანამ, სანამ განახლებული ინსტალაცია არ შექმნის სერვერის სტატუსის მიმდინარე ანგარიშს.

<a id="update-an-existing-installation"></a>
## განაახლეთ არსებული ინსტალაცია

1. გააჩერეთ სერვერი.
2.  დააკოპირეთ სრულად დაინსტალირებული RandomDayGuard საქაღალდე უსაფრთხო სარეზერვო ადგილას.
3. გადაიტანეთ ძველი პროგრამის საქაღალდე UE4SS `Mods` ახალი გამოშვების მასზე გადატანის ნაცვლად.
4. დააკოპირეთ ახალი RandomDayGuard საქაღალდეში `Mods`.
5. აღადგინეთ მხოლოდ თქვენი განხილული ადგილობრივი კონფიგურაცია და შენახული მტკიცებულება. თუ კონფიგურაციის სახელმძღვანელო ჩამოთვლის ახალ ველებს, შეაერთეთ ისინი განხილულ ასლში ყველა პარამეტრის ბრმად შეცვლის ნაცვლად.
6. დაადასტურეთ `RandomDayGuard : 1` ჩართული რჩება.
7. ჩართეთ სერვერი და წაიკითხეთ სერვერის სტატუსის მიმდინარე ანგარიში.

ეს სუფთა საქაღალდის განახლება ასევე შლის მოძველებულ ფაილებს ძველი გამოცემებიდან ოპერატორს პროგრამის ფაილების სახელების შემოწმების თხოვნის გარეშე.

<a id="help-guard-find-the-server-records"></a>
## დაეხმარეთ დაცვას სერვერის ჩანაწერების პოვნაში

მცველი ჩვეულებრივ პოულობს აბიოტურ ფაქტორს `Saved` დირექტორია ავტომატურად. თუ ეს შეუძლებელია, დააყენეთ სრული გზა `Saved` დირექტორიაში `SavedRoot.txt` RandomDayGuard საქაღალდე. მიუთითეთ `Saved`, არა ერთი ცალკეული სამყაროს ქვემოთ.

პირველი სერვერის სტატუსის მოხსენებაში ნათქვამია, ნაპოვნია თუ არა ჩანაწერის მდებარეობა და რომელი წყარო ჯგუფები იყო ხელმისაწვდომი. გამოიყენეთ [პრობლემების აღმოფხვრა](%E1%B2%9E%E1%B2%A0%E1%B2%9D%E1%B2%91%E1%B2%9A%E1%B2%94%E1%B2%9B%E1%B2%94%E1%B2%91%E1%B2%98%E1%B2%A1_%E1%B2%90%E1%B2%A6%E1%B2%9B%E1%B2%9D%E1%B2%A4%E1%B2%AE%E1%B2%95%E1%B2%A0%E1%B2%90.md) როდესაც მას არ შეუძლია მდებარეობის წაკითხვა.

<a id="first-run-behavior"></a>
## პირველი გაშვების ქცევა

ნაგულისხმევი ინსტალაცია უყურებს ხელმისაწვდომ ჩანაწერებს და წერს ანგარიშებს. ის არ იცვლება `Admin.ini` ან დაამატეთ აკრძალვა. ეს საშუალებას გაძლევთ დაადასტუროთ შეგროვების, თარგმანისა და ანგარიშის ხარისხი, სანამ გადაწყვეტთ, ჩართოთ თუ არა რაიმე არასავალდებულო მოქმედება.

[წაიკითხეთ პირველი ანგარიში](%E1%B2%93%E1%B2%90%E1%B2%98%E1%B2%AC%E1%B2%A7%E1%B2%94%E1%B2%97_%E1%B2%90%E1%B2%A5.md)

<a id="disable-or-remove-randomdayguard"></a>
## გამორთეთ ან წაშალეთ RandomDayGuard

1. გააჩერეთ სერვერი.
2. დააკოპირეთ სრული RandomDayGuard საქაღალდე უსაფრთხო არქივში.
3. მოდის გამოსართავად დააყენეთ `RandomDayGuard : 0` UE4SS `mods.txt`.
4. მისი წასაშლელად, გადაიტანეთ სრული RandomDayGuard საქაღალდე ამოღებულია `Mods` დადასტურების შემდეგ, არქივი შეიძლება გაიხსნას.
5. ჩართეთ სერვერი და დაადასტურეთ, რომ Guard აღარ იწყება.

Guard-ის გამორთვა ან წაშლა აჩერებს მომავალ შეგროვებას. ის არ წაშლის თამაშის მონაცემებს, არ შლის დაარქივებულ მოხსენებებს და არ აბრუნებს ცალკეულ ოპერატორის მოქმედებას.

<a id="roll-back-an-update"></a>
## გადააბრუნეთ განახლება

თუ ახალი ინსტალაცია არ იტვირთება ან ვერ აწარმოებს მიმდინარე ანგარიშს:

1. გააჩერეთ სერვერი.
2. გადაიტანეთ წარუმატებელი ინსტალაცია განზე მისი ჩანაწერების წაშლის გარეშე.
3. აღადგინეთ სრული წინასწარი განახლება RandomDayGuard საქაღალდე.
4. აღადგინეთ განხილული კონფიგურაცია და შენახული მტკიცებულება იმავე სარეზერვო ასლიდან.
5. დაადასტურეთ, რომ რეჟიმი ჩართულია და გაუშვით სერვერი.
6. წაიკითხეთ აღდგენილი სერვერის სტატუსის ანგარიში სხვა ცვლილების განხორციელებამდე.
