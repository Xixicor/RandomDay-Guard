# ცუდი მოქმედი ნიმუშები და გამძლეობა

> **კანონიკური ინგლისური წყარო:** [BAD_ACTOR_PATTERNS_AND_RESILIENCE.md](../../BAD_ACTOR_PATTERNS_AND_RESILIENCE.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


გამოიყენეთ ეს გვერდი იმის გასაგებად, თუ როგორ გეხმარება მცველი ავარიის ბოროტად გამოყენების, ექსპლოიტის მიმდებარე ქცევისა და აღდგენის დაგეგმვაში.

<a id="what-the-guard-can-help-with"></a>
## რაში დაეხმარება მცველს

| ნიმუში | რა უნდა შეამოწმოთ |
|---|---|
| ავარიასთან დაკავშირებული ანაზღაურება | იგივე ანგარიში აქტიურია ავარიამდე და ბრუნდება გადატვირთვის შემდეგ |
| სწრაფი ხელახალი დაკავშირება | გამეორებული join/leave ან timeout/reconnect მარყუჟები |
| მრავალ ანგარიშის კლასტერები | ტალღების შეერთება, გაზიარებული გამაფრთხილებელი ფანჯრები, გაზიარებული წარუმატებლობის ფანჯრები |
| გაფრთხილება ადიდებული სტრესის შესახებ | გამეორებული ActorChannelFailure ან შენახვის გამაფრთხილებელი ფანჯრები |
| საზღვრებს გარეთ კონტექსტი | PlayerData/map/world კონტექსტი, როცა იკითხება |
| შენახვა-შეხებით გადახურვა | მსოფლიო შენახვა კონტექსტის გადაფარვის რუკების სესიები |
| იდენტობის დაბნეულობა | სახელები, რომლებიც საჭიროებენ ConnectID-ის რუკს |

<a id="why-it-avoids-memory-access"></a>
## რატომ ერიდება მეხსიერებაზე წვდომას

RandomDayGuard მუშაობს სერვერის საკუთრებაში არსებული ფაილებიდან:

```text
Saved/Logs/*.log
Admin.ini
World saves
PlayerData
Backups
runtime evidence
```

ეს ხდის მას ნაკლებად დამოკიდებულს კლიენტის მხრიდან მეხსიერების მდგომარეობაზე და ნაკლებად მყიფეა თამაშის განახლებების დროს.

ვაჭრობა:

```text
It cannot prove hidden live actions unless the server writes evidence.
```

<a id="crash-correlated-returners"></a>
## ავარიასთან დაკავშირებული დამაბრუნებლები

ნიმუში:

```text
Account joins.
Server crashes or restarts.
Same account reconnects quickly.
Pattern repeats.
```

სასარგებლო ფაილები:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="rapid-reconnect-probers"></a>
## სწრაფი ხელახალი დაკავშირების მაძიებლები

ნიმუში:

```text
join -> leave -> join -> leave -> join
```

სასარგებლო ფაილები:

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
```

<a id="multi-account-clusters"></a>
## მრავალ ანგარიშის კლასტერები

ნიმუში:

```text
Several accounts join in the same window.
Warnings or crashes follow.
Some accounts rotate or reconnect after restart.
```

სასარგებლო ფაილები:

```text
runtime/raid_cases/
runtime/forensic_days/YYYY-MM-DD/raid_cases.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

წესი:

```text
A cluster is not a mass-ban list.
Each account still needs its own evidence.
```

<a id="sticky-backup-recommendation"></a>
## რეზერვო ასლის რეკომენდაცია

შექმენით წებოვანი სარეზერვო საშუალება შემდეგ:

```text
first full baseline completes
object_registry.json exists
file_manifest.tsv exists
world_state_latest.json has scan_complete=true
Admin.ini is verified
trusted IDs are configured
```

სარეზერვო ასლი:

```text
RandomDayGuard/config.lua
RandomDayGuard/SavedRoot.txt
RandomDayGuard/runtime/baselines/
RandomDayGuard/runtime/object_registry.json
RandomDayGuard/runtime/world_state/current/world_state_latest.json
Saved/SaveGames/Server/Admin.ini
```

<a id="recovery-model"></a>
## აღდგენის მოდელი

```text
Clean install
-> verify live defense
-> complete first baseline
-> create sticky backup
-> run server normally
-> use daily rollups for review
-> restore sticky backup if needed
```
