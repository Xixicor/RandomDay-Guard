# გამომავალი და მდგომარეობის სქემის მითითება

> **კანონიკური ინგლისური წყარო:** [OUTPUT_SCHEMA_REFERENCE.md](../../OUTPUT_SCHEMA_REFERENCE.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


ეს არის კანონიკური კონტრაქტი გენერირებული ოპერატორის წინაშე არსებული ფაილებისთვის. ის მხოლოდ ფლობს ზუსტ გამომავალ ბილიკებს, ველების სახელებს, დაშვებულ მნიშვნელობებს, საგვარეულო მოთხოვნებს და მარშრუტების სქემებს. ამ ფაქტების ხელახალი განსაზღვრის ნაცვლად, პროცედურული სახელმძღვანელოები ბმულს აძლევენ აქ.

გაშვების მტკიცებულება ავტორიტეტულია; ფაილის სახელი, დამგეგმავი გულისცემა, ნათარგმნი მოხსენება ან ლოკალური გასასვლელი ობიექტი არ ამტკიცებს უფრო მეტს, ვიდრე საკუთარი ველები და გვარი.

## საჯარო მოხსენების მარშრუტები

ანგარიშის თანამშრომელი ფლობს ხუთ მარშრუტს `runtime/final_logs/`:

| მარშრუტი | კონტრაქტი | `full` მოთხოვნა | მოსალოდნელი-ცარიელი მნიშვნელობა |
|---|---|---|---|
| `server_status` | მიმდინარე განრიგის, აქტიური ჟურნალის, სკანირების მოლოდინში და წყაროს დაფარვის მდგომარეობა. | მიმდინარე boot/epoch/poll შტო, ახალი აქტიური ჟურნალი, accounting/history წერს და JSON/TXT წყვილი. | არ გამოიყენება სხვაგვარად ჯანსაღი მიმდინარე ციკლისთვის; დაკარგული ხაზი არის `missing`. |
| `daily_rollup` | მიმდინარე day/window უწყვეტობა სერვერზე, ფლეერებზე, ქეისებზე, სკანირებაზე და დაფარვაზე. | ისტორიული აღრიცხვის ტერმინალი საკმარისია მარშრუტისთვის და მიმდინარე ციკლის დადასტურებისთვის. | შეკავებული მოთამაშეები და განხილვის შემთხვევები არ არის. |
| `player_activity` | გამოყავით მიმდინარე და ისტორიული player/account დაკვირვებები. | მიმდინარე ციკლის მტკიცებულება პლუს ერთი ან მეტი current/historical რიგები. | შეზღუდულ შეყვანებში მოთამაშის შესაბამისი რიგები არ არის; არ არის სინთეზური საგანი. |
| `case_review` | დასახელებული შენახული შემთხვევები და მიმდინარე review/BAN-ELIGIBLE კანდიდატები. | მიმდინარე ციკლის მტკიცებულება პლუს ერთი ან მეტი დასახელებული შემთხვევა წყაროს მითითებით. | არც ერთი დასახელებული შემთხვევა არ აკმაყოფილებს განხილვის კრიტერიუმებს; სინთეტიკური ქეისის გარეშე. |
| `critical_guard` | მიმდინარე ჩატვირთვის განრიგის, გაშვების, გამოკითხვის ან მტკიცებულების მთლიანობის წარუმატებლობა. | მიმდინარე ციკლის მტკიცებულება პლუს მიმდინარე კრიტიკული უკმარისობა. | ამჟამინდელი კრიტიკული მარცხი არ არის; ძველი ტექსტური შეცდომები არ ფლობს ამ მარშრუტს. |

ყველა ჩართული მარშრუტი წერს `<route>_latest.json` და `<route>_latest.txt`. წყვილი არ დასრულებულა `runtime/final_logs/route_proof.json` იწერს იმავე ვერსიას, ჩატვირთვას, ეპოქას, გამოკითხვას და წყაროს სიახლეს.

<a id="report-json-schema"></a>
## ანგარიში JSON სქემა

ყველა მარშრუტი JSON იყენებს `schema="randomdayguard.report/v1"`.

| ველი | ტიპი | მნიშვნელობა და უცვლელი |
|---|---|---|
| `schema` | სტრიქონი | ზუსტად `randomdayguard.report/v1`. |
| `generated_ts`, `report_date` | სტრიქონი | გენერაციის დროის ანაბეჭდი და ანგარიშის თარიღი. |
| `version` | სტრიქონი | Runtime/package იდენტურობა ამ ციკლისთვის. |
| `boot_id`, `epoch_id` | სტრიქონი | მიმდინარე პროცესის ჩატვირთვისა და სერვერის უწყვეტობის ეპოქა. ორივე საჭიროა დასრულებისთვის. |
| `poll_id` | მთელი რიცხვი | მიმდინარე გამოკითხვის დადებითი იდენტიფიკატორი. Zero/missing არ შეუძლია მარშრუტის დასრულება. |
| `source_freshness` | ობიექტი | `status`, `checked_ts`, აქტიური ჟურნალის სტატუსი, ბოლო გამოკითხვის დროის შტამპი და ბოლო დასრულებული გამოკითხვის დრო. |
| `current_cycle_proof_complete` | ლოგიკური | true მხოლოდ მაშინ, როდესაც საგვარეულო და ახალი active-log/current-poll მტკიცებულება თანხმდება. |
| `route` | ხმა | ზემოხსენებული ხუთი მარშრუტიდან ერთ-ერთი. |
| `route_proof_status` | ხმა | `full`, `limited_expected_empty` ან `missing`. |
| `coverage_status` | ხმა | ზუსტად `complete`, `complete_with_gaps`, `partial` ან `unavailable`. |
| `completed`, `expected_empty` | ლოგიკური | `completed` მცდარია მხოლოდ `missing`; `expected_empty` მართალია მხოლოდ `limited_expected_empty`. |
| `observed` | სტრიქონების მასივი | ბეტონი შენარჩუნებულია facts/counts/statuses. |
| `interpretation` | სტრიქონების მასივი | ფრთხილი მნიშვნელობა დაკალიბრებულია მტკიცებულებებზე. |
| `unknown` | სტრიქონების მასივი | გამოტოვებული ვინაობა, ისტორია, წყარო ან კონტექსტი. |
| `does_not_prove` | სტრიქონების მასივი | დასკვნა, რომელსაც მტკიცებულება არ შეუძლია. |
| `next_action` | სტრიქონი | ყველაზე უსაფრთხო შეზღუდული ოპერატორის მოქმედება. |
| `source_references` | სტრიქონების მასივი | დახარისხებული უნიკალური runtime/Saved მითითებები. |
| `enforcement_authority` | ლოგიკური | ყოველთვის ცრუ. ანგარიში არასოდეს იძლევა წერის უფლებას. |
| `output_paths` | ორი სტრიქონი | JSON და TXT ბილიკები დამატებულია დაწყვილებულ ჩაწერამდე. |

`coverage_status` მხოლოდ უმაღლესი დონის აღრიცხვაა. წყაროს ჩანაწერები ცალკე ფლობენ `available`, `expected_empty`, `partial`, `deferred`, `unavailable`, `malformed`, `permission_denied` და `error`. მარშრუტის მტკიცებულება ცალკე ფლობს `full`, `limited_expected_empty` და `missing`; მნიშვნელობები არასოდეს კვეთს ამ საზღვრებს.

მარშრუტის გაფართოებები:

- `server_status`: `scheduler_status`, `active_log_status` და `server_metrics`. მეტრიკა აღრიცხავს მიმდინარე ეპოქის დაწყებას, ბოლო დასრულებული გამოკითხვის დროის ნიშანს და ID, აქტიური მოთამაშეების რაოდენობას, active/backup-log ითვლის, სკანირება pending/progress მნიშვნელობები და configured/usable/unavailable წყარო-ჯგუფის აღრიცხვა. ისინი არ იგონებენ მუშაობის დროს, გადატვირთვას, სარეზერვო დროის ნიშანს ან გათიშვის ხანგრძლივობას, როდესაც არცერთი წყარო არ ამხელს ამ ფაქტებს.
- `player_activity`: `player_activity_present`, `movement`, `same_day_sessions`, `current_player_count`, `current_evidence_player_count`, `historical_player_count`, `historical_session_count`, `current_players`, `historical_players` და თავსებადობის მასივი `players`. ყოველი ერთდღიანი სესია ინახავს სესიის ID-ს, ანგარიშის ID-ს, საჩვენებელ სახელს, როცა ცნობილია, join/leave დროის ანაბეჭდები, გასვლის და სასიცოცხლო ციკლის დროშები და წყაროს მითითებები. შეინარჩუნა პირადობა და PlayerData ყოფნა რჩება კონტექსტში და არა დღეს აქტივობის დამადასტურებელი.
- `case_review`: `cases`, `review_subjects`, `current_case_count` და `retained_case_count`. მიმდინარე განხილვის საგანი იწერს თავის case/account ID, საჩვენებელი სახელი, როდესაც ცნობილია, სტატუსი, ქულა, პირადობის დამაჯერებლობა, first/last დაკვირვება, გაფრთხილების რაოდენობა, მიზეზები, მიმდინარე დროშა და წყაროს მითითებები. შენახული შემთხვევები თავისთავად არ ქმნის მიმდინარე თემას.
- `critical_guard`: `critical_failure_present` და `current_boot_error_only=true`.
- `daily_rollup`: `daily_maturity`, `once_per_day_continuity`, `dedupe_window` და `daily_metrics`. მეტრიკა აღრიცხავს მოხსენების თარიღს, აქტიურ მოთამაშეებს, ანგარიშებს ერთდღიანი აქტივობით, შეერთებები, ტოვებები, სუფთა და უწმინდური გასვლები, სასიცოცხლო ციკლის დაბრუნება, მიმდინარე დასახელებული განხილვის საგნები, შენახული შემთხვევები, current/retained იდენტურობის რაოდენობა და წყაროს ჯგუფის დაფარვა.

<a id="translated-txt-schema"></a>
## თარგმნილია TXT სქემა

დაწყვილებული ტექსტური ფაილი მიდის ოპერატორის მიერ წასაკითხი შედეგით და გადააქვს ხაზის დეტალები ბოლომდე. ის ინახავს სექციის ამ ზუსტ წესრიგს:

```text
RandomDayGuard <route title>
Generated: <timestamp>

Summary
<one plain-language route summary>

What Guard observed
- ...

What it means
- ...

What remains unknown
- ...

Recommended next step
...

Evidence boundary
- ...

Rating explanation
- ...

Technical record
- Route: <route>
- Version: <version>
- Cycle: boot=<boot> epoch=<epoch> poll=<poll>
- Source freshness: <status>
- Route result: <full|limited_expected_empty|missing>
- Coverage: <status>

Translation notes
- ...

Source references
- ...
```

თარგმანი იყენებს მხოლოდ სტრუქტურირებულ მოხსენების ველებს და დამტკიცებულ ლექსიკონის რუკებს. მას არ შეუძლია დაამატოს მოთამაშეები, შემთხვევები, მიწოდება, მიზეზობრივი კავშირი, საკუთრება, განზრახვა ან აღსრულების უფლებამოსილება, რომელიც არ არის სტრუქტურირებულ ანგარიშში. ტექნიკური დეტალები ხელმისაწვდომი რჩება წაკითხვადი შედეგის ჩანაცვლების გარეშე.

<a id="source-accounting-schema"></a>
## წყაროების აღრიცხვის სქემა

`runtime/final_logs/source_accounting_latest.json` იყენებს `randomdayguard.source-accounting/v1` გენერირებით reason/status, enablement/disabled მიზეზი, current/historical განსხვავება, შეცვლილი ფაილის მანიფესტი, წყაროს ჩანაწერები, usable/unavailable კლასების სიები და პრეტენზიის ლიმიტი.

თითოეული წყაროს ჩანაწერი შეიცავს:

| ველი | ტიპი | მნიშვნელობა |
|---|---|---|
| `source_class` | სტრიქონი | ქვემოთ რვა კლასიდან ერთ-ერთი. |
| `scope` | `current` ან `historical` | დროის ფლობა; ფარგლები არასოდეს არ ერწყმის ჩუმად. |
| `required` | ლოგიკური | მხოლოდ `active_log` საჭიროა მიმდინარე ციკლის მარშრუტის განახლებისთვის. |
| `status` | ხმა | ქვემოთ ჩამოთვლილი წყაროს შედეგი. |
