# წყაროს მოდულის მითითება

> **კანონიკური ინგლისური წყარო:** [SOURCE_MODULE_REFERENCE.md](../../SOURCE_MODULE_REFERENCE.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


ეს გვერდი ასახავს ყველა წყაროს, კონფიგურაციას, მონაცემს, თავსებადობის-ჩამტვირთველს და გაშვების დროის ჩანაცვლების კლასს, რომლებიც დაშვებულია გამოშვების ნებადართული სიით. მანქანის ინდექსი არის [`TRACEABILITY_INDEX.json`](../../TRACEABILITY_INDEX.json); ეს გვერდი წასაკითხი კანონიკური ახსნაა. თითოეული გენერირებული აპარატის მწკრივი ასახელებს განსხვავებულ path/class, დანიშნულება, მფლობელის წყაროს ბლოკი, საჯარო პარამეტრები, გვერდითი ეფექტები, ოპერატორის თვალსაჩინო მდგომარეობა, წარუმატებლობები, აღდგენა და კანონიკური დოკუმენტი.

## UE4SS დამტვირთავი და მცველი

`Scripts/main.lua` ფლობს დამოუკიდებელი მეთვალყურეების სტარტაპს, Saved-root აღმოჩენას, მიმდინარე ჟურნალის კუდს, სერვერის ეპოქებს და სესიებს, შეზღუდულ გამოკითხვას და სკანირებას, object/world კონტექსტი, მიმოხილვის ქულა, `Admin.ini` უსაფრთხოების კარიბჭეები, ძველი ოპერაციული შედეგები და ცალკე მოხსენება-მუშაკთა გადაცემა. მან უნდა შეინარჩუნოს პირდაპირი კენჭისყრა შეზღუდული, სანამ ნელი ისტორიული მუშაობა დამოუკიდებლად განახლდება. გულისცემა, გაშვების მარკერი ან გაზრდილი `poll_id` ადასტურებს მხოლოდ ამ კომპონენტს; მარშრუტის დასრულება მოითხოვს იგივე მიმდინარე ჩატვირთვას, ეპოქას, გამოკითხვას, წყაროს განახლებას, მოხსენების წყვილს და მარშრუტის დადასტურებას.

წყაროს და პაკეტს აქვს ერთი ავტორიტეტი: `RandomDayGuard/Scripts/main.lua`. პატარა `scripts/` ასლი არ არის წყაროს ხის ან გამოშვების ნაწილი. ერთი კანონიკური მართლწერის შენახვა ხელს უშლის საქმის შეჯახების წარუმატებლობებს, როდესაც პაკეტი ამოღებულია Windows-ზე ან Linux-ზე.

## საჯარო მოხსენების მოდული

`Scripts/public_pipeline.lua` იღებს გამოძახებას ჰოსტის სერთიფიკატების ან პროვაიდერის გადამყვანების ნაცვლად. ის აწარმოებს რვა წყაროს კლასს, აღრიცხავს ტერმინალურ და არასრულ მდგომარეობებს, ინახავს მიმდინარე მოთამაშეებს შენახული ისტორიისგან განცალკევებით, თარგმნის თითოეულ მარშრუტს თანმიმდევრობით `Observed`, `Interpretation`, `Unknown`, `Does not prove`, `Next action` და `Source references`, შემდეგ წერს მარშრუტის მტკიცებულებას. არასავალდებულო შეტყობინების რეჟიმი წერს ლოკალურ JSON მხოლოდ კონვერტი; ის არასოდეს აცხადებს მიწოდებას ან არ აერთიანებს მიწოდებას endpoint/bridge.

შესასრულებელი მოწყობილობა `tests/lua/public_pipeline_runtime_test.lua` ატვირთავს ამ გაგზავნილ მოდულს Lua-ით, ადასტურებს სრულ და მოსალოდნელ-ცარიელ მარშრუტებს, ადასტურებს დაკარგული-მიმდინარე წყაროს ციკლის დახურვას და ადასტურებს, რომ არასრული მარშრუტები არ შედის გასასვლელში.

## კონფიგურაცია და მონაცემები

[`CONFIG_FIELD_CATALOG.md`](CONFIG_FIELD_CATALOG.md) და [`TRACEABILITY_INDEX.json`](../../TRACEABILITY_INDEX.json) გენერირებულია `tools/generate_documentation_audit.py` `config.lua`, პაკეტის დაშვების სია და წყაროს მიერ აღმოჩენილი გამომავალი კლასები. ზუსტი გენერირებული კონტენტი და ერთი-ერთზე გაშუქება დამოწმებულია. სამი JSON ლექსიკონები არის ეტიკეტები და რუქები და არა მტკიცებულებების წყაროები. ოპერატორს შეუძლია შეცვალოს კონფიგურაცია, შენახული ფესვის შერჩევა და ჩართვა; წყარო, ლექსიკონები, მანიფესტები და შეფუთული წაკითხვები ეკუთვნის გამოშვებას.

<a id="package-layout"></a>
## პაკეტის განლაგება

შემშენებელი აღიარებს მხოლოდ სამ root იურიდიულ ფაილს, `RandomDayGuard/` ბილიკები და ცარიელი გაშვების ჩანაცვლების ადგილები. ის უბრძანებს წევრებს ბაიტით, ასწორებს ZIP მეტამონაცემები, შეფუთავს კანონიკურ ჩამტვირთველს ერთხელ, სკანირებს ყველა წევრს პირადი მასალისთვის, ჩაწერს SHA-256 თითოეული წევრისთვის, აკავშირებს სახელებს და ბაიტებს ერთი შინაარსის დაიჯესტში და აშენებს ორჯერ. ტესტები უარყოფენ ყოველი შემთხვევის შეჯახებას და ადასტურებენ, რომ ნორმალური ამოღება აწარმოებს ზუსტად ერთ ფიზიკურ ფაილს არქივში.

საჯარო საცავი ინახავს მხოლოდ მიმდინარე გამოშვების საქაღალდეს. მშენებელი ამოწმებს, რომ მისი ZIP, შემოწმების ჯამი, შენიშვნები, ვერსიის მარკერები და წყაროს ხე თანხმდება.

## კოდის კომენტარის კონტრაქტი

გაშვების დროის კომენტარები არის მომხმარებელთა მოკლე კონტრაქტები და არა მეორე სახელმძღვანელო. თითოეული გაგზავნილი გაშვების მოდული უნდა განათავსოს ერთი კანონიკური ბმული მის გახსნის კომენტარების ბლოკში:

```lua
-- Documentation: docs/SOURCE_MODULE_REFERENCE.md#ue4ss-loader-and-watchdog
```

არააშკარა მდგომარეობა, დაგეგმვა, write/readback/rollback, წყაროს აღმოჩენა, თარგმანი, მტკიცებულება, გამომავალი სქემა, მარშრუტი-კადენცია და რედაქციის ბლოკები იყენებენ ფოკუსირებულ კომენტარებს ამ ლეიბლებთან, სადაც ეს შესაძლებელია:

```lua
-- Public contract: <invariant or consequence>
-- Evidence boundary: <what the input cannot prove>
-- Failure behavior: <how the block fails closed or recovers>
-- Documentation: docs/<canonical-file>.md#<existing-anchor>
```

მთავარ ჩამტვირთველს ასევე აქვს ერთი ფოკუსირებული მფლობელის კომენტარი კონფიგურაციის ჩატვირთვის, შენახული აღმოჩენისთვის, ატომური ჩანაცვლებისთვის, აღსრულებისა და დაგეგმვისთვის. ეს კომენტარები მიუთითებს კონტროლის ნაკადის და წარუმატებლობის საზღვრებს; ისინი არ ცვლიან მუშაობის დროის ქცევას.

ვალიდატორი მოითხოვს მოდულის დონის `Documentation:` ბმული თითოეული გაშვების მოდულისთვის, წყვეტს ყველა კომენტარის გზას და წამყვანს, მოითხოვს ორიენტირებული კონტრაქტისა და წარუმატებლობის კომენტარებს ორივე გაშვების მოდულში და ადარებს იგივე კანონიკურ ბმულებს `TRACEABILITY_INDEX.json`. კომენტარი არის მიკვლევადობა და არა გაშვების მტკიცებულება.

## კონტრიბუტორის ცვლილების საკონტროლო სია

1. განაახლეთ ერთი მფლობელი მოდული და მისი ფოკუსირებული მოწყობილობა.
2. განაახლეთ კანონიკური კონფიგურაცია, სქემა, გამომავალი, მტკიცებულება ან სიცოცხლის ციკლის სექცია.
3. გაშვება `python -B tools/generate_documentation_audit.py --write` კონფიგურაციის, შეფუთული ბილიკის, გენერირებული გამომავალი კლასის, მფლობელის ან აღდგენის ხელშეკრულების ცვლილებების შემდეგ.
4. გაშვება `python -B tools/generate_documentation_audit.py --check`, ფოკუსირებული ერთეულის ტესტები, რეალური ლუას მოწყობილობა, სადაც Lua არის ხელმისაწვდომი, სრული ვალიდატორი, ორი დამოუკიდებელი დეტერმინისტული ნაგებობა და `git diff --check`.
5. გადახედეთ გენერირებულ ZIP წევრების სია, გამშვები ჯამი და პირადი მასალის სკანირება გამოშვების შექმნამდე.
