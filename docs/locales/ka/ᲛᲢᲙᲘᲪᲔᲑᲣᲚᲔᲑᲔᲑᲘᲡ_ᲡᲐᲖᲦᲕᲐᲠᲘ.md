# მტკიცებულებების საზღვარი

> **კანონიკური ინგლისური წყარო:** [EVIDENCE_BOUNDARY.md](../../EVIDENCE_BOUNDARY.md). ეს ლოკალიზებული დოკუმენტაცია ინახავს ზუსტ ბრძანებებს, ბილიკებს, გასაღებებს, სტატუსის მნიშვნელობებს, ჰეშებსა და ფაილების სახელებს. თუ ტექნიკური ფორმულირება განსხვავდება, გამოიყენეთ ინგლისური წყარო.


გამოიყენეთ ეს გვერდი, რათა გადაწყვიტოთ რა RandomDayGuard შეუძლია მოხსენება და ის, რაც ჯერ კიდევ მოითხოვს ადამიანის განხილვას.

<a id="core-rule"></a>
## ძირითადი წესი

RandomDayGuard აღრიცხავს შეზღუდულ დაკვირვებებს სერვერის საკუთრებაში არსებული ფაილებიდან. მან უნდა განსაზღვროს წყარო, არეალი, შეგროვების მდგომარეობა და საზღვრები ყველა მატერიალური დასკვნისთვის.

სტრუქტურირებული მტკიცებულება ავტორიტეტულია. ნათარგმნი ანგარიში განმარტავს მტკიცებულებებს; მას არ შეუძლია დაამატოს ფაქტები, რომლებიც არ არის სტრუქტურირებული ჩანაწერში.

<a id="evidence-source-classes"></a>
## მტკიცებულებების წყაროს კლასები

| წყაროს კლასი | ტიპიური გამოყენება | არ ამტკიცებს თავისთავად |
|---|---|---|
| `admin_ini` |  არსებული ადმინისტრაციის მდგომარეობა და აუდიტი write/readback კონტექსტი | ვინ გამოიწვია ინციდენტი |
| `active_log` | მიმდინარე server/session მოვლენები ჩანს აქტიურ ჟურნალში | განზრახვა, საკუთრება ან პირდაპირი ზიანი |
| `recent_backup_logs` | ისტორიული ჟურნალის კონტექსტი | მოხდა მიმდინარე მოვლენა |
| `playerdata_filenames` | დადასტურება იმისა, რომ სუფთა ანგარიშის იდენტიფიკატორი არსებობს | ქცევა, დანაშაული ან ვინაობის მფლობელობა გამოვლენილი იდენტიფიკატორის მიღმა |
| `existing_cases` | წინასწარი განხილვის კონტექსტი | რომ წინა ინტერპრეტაცია სწორი რჩება |
| `existing_reports` | ადრე შეჯამებები და გადაწყვეტილებები | მიმდინარე სიმართლე მიმდინარე დადასტურების გარეშე |
| `existing_evidence` | ისტორიული სტრუქტურირებული მტკიცებულება | მიმდინარე აქტივობა |
| შეზღუდული მსოფლიოს შენახვის სკანირება | ნელი world/class კონტექსტი | მოთამაშის მოქმედება, საკუთრება, ქურდობა, დუბლირება ან დაზიანება |

თითოეული წყარო ჩაწერილია availability/readability, ფაილების რაოდენობა, წყაროს მითითებები, მიმდინარე ან ისტორიული ფარგლები და აშკარა `does_not_prove` განცხადება.

<a id="source-states"></a>
## წყაროს მდგომარეობები

| მდგომარეობა | ოპერატორის მნიშვნელობა |
|---|---|
| `available` | წყარო იკითხებადი და მტკიცებულებები შეგროვდა. |
| `expected_empty` | წყარო იკითხებადი და კანონიერად არ ჰქონდა შესატყვისი ჩანაწერი. |
| `partial` | შეგროვდა გარკვეული მტკიცებულებები; დაფარვა არასრულია. |
| `deferred` | შეზღუდული სამუშაო განზრახ გადაიდო. |
| `unavailable` | წყარო არ არის ამ გარემოში. |
| `malformed` | წყარო არსებობს, მაგრამ მისი უსაფრთხოდ ანალიზი შეუძლებელია. |
| `permission_denied` | დამკვირვებელს არ აქვს წაკითხვის ნებართვა. |
| `error` | შეგროვება ვერ მოხერხდა სხვა ჩაწერილი მიზეზის გამო. |

მოსალოდნელი ცარიელი დაკვირვება სწორია. ის არასოდეს უნდა გადაიზარდოს შეთითხნილ მოთამაშედ, საქმედ, ინციდენტად ან ბრალდებად.

<a id="current-versus-historical-evidence"></a>
## მიმდინარე და ისტორიული მტკიცებულებები

მიმდინარე მტკიცებულება ეკუთვნის აქტიურ კოლექციურ ფანჯარას ან სერვერის ეპოქას. ისტორიული მტკიცებულებები მომდინარეობს წინა ჟურნალებიდან, საქმეებიდან, მოხსენებებიდან, მტკიცებულებების ჩანაწერებიდან, სარეზერვო ასლებიდან ან საბაზისო ხაზებიდან.

ისტორიულ მტკიცებულებებს შეუძლია მოგვაწოდოს კონტექსტი. მას არ შეუძლია ჩუმად შეავსოს მიმდინარე მტკიცებულების ხარვეზი. მოხსენებებმა უნდა დაასახელოს ორივე სფერო და ცალკე მოიყვანოს მათი წყაროები.

<a id="corroboration-rule"></a>
## დადასტურების წესი

ეს არის სასარგებლო კონტექსტი, მაგრამ თავისთავად არ არის პირდაპირი მტკიცებულება:

- აჩვენეთ სახელები ან სახელების მსგავსება;
- დროის დამთხვევა;
- გათიშვა ან ხელახლა დაკავშირების შეფერხება;
- ერთი ავარია ან გაფრთხილება;
- კლასი, ბილიკი, მსახიობი, რუკა ან ობიექტების დათვლის ნიშნები;
- წევრობა ავტომატურად დაჯგუფებულ საქმეში;
- წინა ანგარიშები მიმდინარე წყაროს დადასტურების გარეშე.

არ განაცხადოთ დანაშაული, განზრახვა, თაღლითობა, საკუთრება, ქურდობა, დუბლირება, პირდაპირი დაზიანება, პირდაპირი კონტეინერის გამოყენება, პირდაპირი ინვენტარიზაციის ქმედება, ზუსტი ცოცხალი კოორდინატები, ცოცხალი პინგ ან მეხსიერების დონეზე ქცევა მტკიცებულების გარეშე, რომელიც პირდაპირ ასახავს ფაქტს.

<a id="truthful-report-language"></a>
## სიმართლის მოხსენების ენა

გამოიყენეთ:

```text
Observed: the account was active in the recorded crash window.
Interpretation: repeated overlap warrants operator review.
Unknown: the cause of the crash.
Does not prove: that the account caused the crash.
Next action: compare the cited current session and lifecycle records.
```

მოერიდეთ:

```text
The player crashed the server.
The player stole or duplicated items.
The world token proves who used the object.
```

<a id="report-reading-order"></a>
## მოხსენება წაკითხვის ბრძანების შესახებ

ყველა საჯარო მოხსენებაში უნდა იყოს განმარტებული:

1. მარტივი მნიშვნელობა.
2. რატომ აქვს მნიშვნელობა.
3. ტექნიკური მტკიცებულება და წყაროს მითითებები.
4. შემდეგი მოქმედება.
5. შეზღუდვები, უცნობები და პრეტენზიები არ არის დადასტურებული.
