# மோசமான-நடிகர் வடிவங்கள் மற்றும் நெகிழ்ச்சி

> **நியாய ஆங்கில மூல:** [BAD_ACTOR_PATTERNS_AND_RESILIENCE.md](../../BAD_ACTOR_PATTERNS_AND_RESILIENCE.md). இந்த உள்ளூர்மயமாக்கப்பட்ட ஆவணம் சரியான கட்டளைகள், பாதைகள், விசைகள், நிலை மதிப்புகள், ஹாஷ்கள் மற்றும் கோப்பு பெயர்களைப் பாதுகாக்கிறது. தொழில்நுட்ப வார்த்தைகள் வேறுபட்டால், ஆங்கில மூலத்தைப் பயன்படுத்தவும்.


விபத்து முறைகேடு, சுரண்டல்-அருகிலுள்ள நடத்தை மற்றும் மீட்புத் திட்டமிடல் ஆகியவற்றை மதிப்பாய்வு செய்ய காவலர் எவ்வாறு உதவுகிறார் என்பதைப் புரிந்துகொள்ள இந்தப் பக்கத்தைப் பயன்படுத்தவும்.

<a id="what-the-guard-can-help-with"></a>
## பாதுகாவலர் என்ன உதவ முடியும்

| முறை | என்ன சரிபார்க்க வேண்டும் |
|---|---|
| Crash-correlated returns | அதே கணக்கு செயலிழக்கும் முன் செயலில் உள்ளது மற்றும் மறுதொடக்கம் செய்த பிறகு திரும்பும் |
| விரைவான மறுஇணைப்பு ஆய்வு | மீண்டும் join/leave அல்லது timeout/reconnect சுழல்கள் |
| பல கணக்கு கிளஸ்டர்கள் | அலைகள், பகிரப்பட்ட எச்சரிக்கை சாளரங்கள், பகிரப்பட்ட தோல்வி சாளரங்கள் |
| எச்சரிக்கை வெடிப்பு அழுத்தம் | மீண்டும் ActorChannelFailure அல்லது சேமிப்பு எச்சரிக்கை சாளரங்கள் |
| வரம்புக்கு அப்பாற்பட்ட சூழல் | PlayerData/map/world படிக்கக்கூடிய போது சூழல் |
| Save-touch overlap | உலக சேமிப்பு சூழல் ஒன்றுடன் ஒன்று மேப் செய்யப்பட்ட அமர்வுகள் |
| அடையாளக் குழப்பம் | ConnectID மேப்பிங் தேவைப்படும் பெயர்கள் |

<a id="why-it-avoids-memory-access"></a>
## அது ஏன் நினைவக அணுகலைத் தவிர்க்கிறது

RandomDayGuard சேவையகத்திற்குச் சொந்தமான கோப்புகளிலிருந்து செயல்படுகிறது:

```text
Saved/Logs/*.log
Admin.ini
World saves
PlayerData
Backups
runtime evidence
```

இது கிளையன்ட் பக்க நினைவக நிலையைச் சார்ந்து இருப்பதைக் குறைக்கிறது மற்றும் கேம் புதுப்பிப்புகள் முழுவதும் பலவீனமாக உள்ளது.

வர்த்தகம்:

```text
It cannot prove hidden live actions unless the server writes evidence.
```

<a id="crash-correlated-returners"></a>
## Crash-correlated returners

முறை:

```text
Account joins.
Server crashes or restarts.
Same account reconnects quickly.
Pattern repeats.
```

பயனுள்ள கோப்புகள்:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="rapid-reconnect-probers"></a>
## விரைவான மறுஇணைப்பு ப்ரோபர்கள்

முறை:

```text
join -> leave -> join -> leave -> join
```

பயனுள்ள கோப்புகள்:

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
```

<a id="multi-account-clusters"></a>
## பல கணக்கு கிளஸ்டர்கள்

முறை:

```text
Several accounts join in the same window.
Warnings or crashes follow.
Some accounts rotate or reconnect after restart.
```

பயனுள்ள கோப்புகள்:

```text
runtime/raid_cases/
runtime/forensic_days/YYYY-MM-DD/raid_cases.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

விதி:

```text
A cluster is not a mass-ban list.
Each account still needs its own evidence.
```

<a id="sticky-backup-recommendation"></a>
## ஒட்டும் காப்புப் பிரதி பரிந்துரை

பின்னர் ஒட்டும் காப்புப்பிரதியை உருவாக்கவும்:

```text
first full baseline completes
object_registry.json exists
file_manifest.tsv exists
world_state_latest.json has scan_complete=true
Admin.ini is verified
trusted IDs are configured
```

காப்புப்பிரதி:

```text
RandomDayGuard/config.lua
RandomDayGuard/SavedRoot.txt
RandomDayGuard/runtime/baselines/
RandomDayGuard/runtime/object_registry.json
RandomDayGuard/runtime/world_state/current/world_state_latest.json
Saved/SaveGames/Server/Admin.ini
```

<a id="recovery-model"></a>
## மீட்பு மாதிரி

```text
Clean install
-> verify live defense
-> complete first baseline
-> create sticky backup
-> run server normally
-> use daily rollups for review
-> restore sticky backup if needed
```
