# சரிசெய்தல்

> **நியாய ஆங்கில மூல:** [TROUBLESHOOTING.md](../../TROUBLESHOOTING.md). இந்த உள்ளூர்மயமாக்கப்பட்ட ஆவணம் சரியான கட்டளைகள், பாதைகள், விசைகள், நிலை மதிப்புகள், ஹாஷ்கள் மற்றும் கோப்பு பெயர்களைப் பாதுகாக்கிறது. தொழில்நுட்ப வார்த்தைகள் வேறுபட்டால், ஆங்கில மூலத்தைப் பயன்படுத்தவும்.


பாதுகாவலர் ஏற்றாதபோது, ​​ஆதாரத்தைச் சேகரிக்க முடியாதபோது, ​​அறிக்கை தோன்றாதபோது அல்லது வழித்தோன்றல் நீங்கள் எதிர்பார்த்ததற்கு முரணாக இருக்கும்போது இந்தப் பக்கத்தைப் பயன்படுத்தவும். முடிவு மரத்தில் தொடங்கி ஒரு கிளையைப் பின்பற்றவும். அர்ப்பணிக்கப்பட்ட [நிலை மற்றும் பிழை குறிப்பு](%E0%AE%A8%E0%AE%BF%E0%AE%B2%E0%AF%88_%E0%AE%AE%E0%AE%B1%E0%AF%8D%E0%AE%B1%E0%AF%81%E0%AE%AE%E0%AF%8D_%E0%AE%AA%E0%AE%BF%E0%AE%B4%E0%AF%88_%E0%AE%95%E0%AF%81%E0%AE%B1%E0%AE%BF%E0%AE%AA%E0%AF%8D%E0%AE%AA%E0%AF%81.md) தோல்வியடைந்த லேயர் தெரிந்த பிறகுதான்.

கட்டமைப்பை மாற்றும் முன் அல்லது மீண்டும் நிறுவும் முன் தற்போதைய இயக்க நேரக் கோப்புகளைப் பாதுகாக்கவும். ஒரு பழமையான அல்லது காணாமல் போன கலைப்பொருள் தோல்வியுற்ற கட்டத்தை அடையாளம் காட்டுகிறது; மீண்டும் மீண்டும் தொடங்குவது அந்த ஆதாரத்தை அழிக்கலாம்.

<a id="choose-the-failure-path"></a>
## தோல்வி பாதையைத் தேர்ந்தெடுக்கவும்

<a id="1-decide-whether-guard-loaded"></a>
### 1. காவலர் ஏற்றப்பட்டதா என்பதைத் தீர்மானிக்கவும்

- **இல்லை `runtime/` கோப்புகள் உள்ளன:** பின்பற்றவும் [விடுபட்ட இயக்க நேர கோப்புகளை மீட்டமைக்கவும்](#restore-missing-runtime-files). நிறுவல் பாதை, நியமன ஏற்றி, `enabled.txt`, மற்றும் `mods.txt` அறிக்கைகளை விசாரிக்கும் முன்.
- **தற்போதைய நிலை கோப்புகள் உள்ளன:** காவலர் நிலையை எழுதும் அளவுக்கு ஏற்றப்பட்டது. படி 2 க்கு தொடரவும்; மீண்டும் நிறுவுவது முதல் பதில் அல்ல.

<a id="2-decide-whether-the-scheduler-is-advancing"></a>
### 2. திட்டமிடுபவர் முன்னேறுகிறாரா என்பதைத் தீர்மானிக்கவும்

திற:

```text
runtime/current/startup_status.json
runtime/current/poll_status.json
```

- **கவுண்டர்கள் மற்றும் நேர முத்திரைகள் முன்கூட்டியே:** படி 3ஐத் தொடரவும்.
- **`poll_id` நிலையானது, `poll_in_flight` உண்மையாகவே இருக்கும் அல்லது திட்டமிடல் நிலை இயங்கவில்லை:** பின்பற்றவும் [சிக்கப்பட்டுள்ள வாக்கெடுப்பு வளையத்தை மீட்டெடுக்கவும்](#recover-a-stuck-poll-loop).
- **திட்டமிடல் முன்னேற்றம் தொடரும் போது அடிப்படை ஸ்கேன் நிலுவையில் உள்ளது:** இது ஒரு எச்சரிக்கை, தானாகவே தோல்வியடைந்த தொடக்கம் அல்ல. பேக்லாக் அல்லது ஸ்கேன் முன்னேற்றம் நின்றால் மட்டுமே விசாரிக்கவும்.

<a id="3-classify-route-proof"></a>
### 3. பாதை ஆதாரத்தை வகைப்படுத்தவும்

திற `runtime/final_logs/route_proof.json` மற்றும் ஒவ்வொரு வழியையும் தனித்தனியாக ஆய்வு செய்யவும்.

- **`full`:** எதிர்பாராத வார்த்தைகளை தற்போதைய `source_references` மற்றும் பரம்பரை. சொற்கள் மட்டும் தவறாகத் தோன்றுவதால், விநியோகத்தை மாற்ற வேண்டாம்.
- **`limited_expected_empty`:** மூலக் கணக்கியல் முறையான வெற்று முடிவை ஆதரிக்கிறது என்பதை உறுதிப்படுத்தவும். செயற்கை பிளேயர் அல்லது கேஸை உருவாக்க வேண்டாம்.
- **`missing`:** பின்பற்றவும் [விடுபட்ட வழியைக் கண்டறியவும்](#diagnose-a-missing-route).

<a id="4-classify-source-coverage"></a>
### 4. மூல கவரேஜை வகைப்படுத்தவும்

- **`partial`, `deferred`, `unavailable`, `malformed`, `permission_denied`, அல்லது `error`:** பின்பற்றவும் [முழுமையற்ற மூல கவரேஜை விளக்கவும்](#interpret-incomplete-source-coverage), பின்னர் [நிலை மற்றும் பிழை குறிப்பு](%E0%AE%A8%E0%AE%BF%E0%AE%B2%E0%AF%88_%E0%AE%AE%E0%AE%B1%E0%AF%8D%E0%AE%B1%E0%AF%81%E0%AE%AE%E0%AF%8D_%E0%AE%AA%E0%AE%BF%E0%AE%B4%E0%AF%88_%E0%AE%95%E0%AF%81%E0%AE%B1%E0%AE%BF%E0%AE%AA%E0%AF%8D%E0%AE%AA%E0%AF%81.md).
- **கட்டமைக்கப்பட்ட மூலமானது தற்போதையது ஆனால் மொழிபெயர்க்கப்பட்டுள்ளது அல்லது நிலுவையில் உள்ள வெளியீடு பழையது:** டெலிவரி எண்ட்பாயிண்ட் அல்ல, முடித்தல் கைபேசியைக் கண்டறியவும். டெலிவரி உள்ளமைவை மாற்றுவதற்கு முன், நேர முத்திரைகள் இரண்டையும் பாதுகாத்து அறிக்கை மற்றும் அனுப்புதல் நிலையை ஆய்வு செய்யவும்.

<a id="5-follow-the-matching-branch"></a>
### 5. பொருந்தும் கிளையைப் பின்பற்றவும்

- முழுமையற்ற அடையாளம்: [மேப் செய்யப்படாத பிளேயரை வரைபடமாக்குங்கள்](#map-an-unmapped-player).
- தினசரி தொடர்ச்சி இல்லை: [விடுபட்ட தினசரி ரோல்அப்பை மீட்டெடுக்கவும்](#restore-a-missing-daily-rollup).
- வெளிப்படையாக அங்கீகரிக்கப்பட்ட அமலாக்க சோதனை எழுதவில்லை: [தடுக்கப்பட்டதைக் கண்டறியவும் Admin.ini எழுது](#diagnose-a-blocked-adminini-write).
- ZIP பிரித்தெடுத்தல் தோல்வி: [விண்டோஸ் பிரித்தெடுத்தல் கேஸ் மோதலை தீர்க்கவும்](#resolve-a-windows-extraction-folder-collision).
- பிக்ஸ்சர், தொகுப்பு அல்லது களஞ்சிய சரிபார்ப்பு தோல்வியடைந்தது: [சரிபார்ப்பு மற்றும் வெளியீட்டு மதிப்பாய்வு](%E0%AE%9A%E0%AE%B0%E0%AE%BF%E0%AE%AA%E0%AE%BE%E0%AE%B0%E0%AF%8D%E0%AE%AA%E0%AF%8D%E0%AE%AA%E0%AF%81_%E0%AE%AE%E0%AE%B1%E0%AF%8D%E0%AE%B1%E0%AF%81%E0%AE%AE%E0%AF%8D_%E0%AE%B5%E0%AF%86%E0%AE%B3%E0%AE%BF%E0%AE%AF%E0%AF%80%E0%AE%9F%E0%AF%81.md#avoid-validation-environment-pitfalls).

<a id="6-stop-with-one-proved-outcome"></a>
### 6. ஒரு நிரூபிக்கப்பட்ட முடிவோடு நிறுத்துங்கள்

ஒரு பிழையறிந்து திருத்தும் பாஸ் முடியும் போது:

- வழி நடப்பு மற்றும் `full`;
- வழி நடப்பு மற்றும் `limited_expected_empty` பெயரிடப்பட்ட காரணத்திற்காக;
- ஒரு துல்லியமான தடுப்பான், ஆதாரப் பாதை மற்றும் அடுத்த செயல் ஆகியவை பதிவு செய்யப்பட்டுள்ளன; அல்லது
- ரோல்பேக் முந்தைய அறியப்பட்ட நிலையை மீட்டமைத்தது மற்றும் தோல்வியுற்ற சான்றுகள் பாதுகாக்கப்பட்டது.

“சேவையகம் இயங்குகிறது,” அதிகரித்த இதயத் துடிப்பு அல்லது HTTP வெற்றி மட்டுமே அறிக்கை வழி முடிந்ததாக நிரூபிக்கப்படவில்லை.

<a id="diagnose-a-missing-route"></a>
## விடுபட்ட வழியைக் கண்டறியவும்

திற `runtime/final_logs/route_proof.json` மற்றும் ஒப்பிடுக `server_status`, `daily_rollup`, `player_activity`, `case_review`, மற்றும் `critical_guard`.

1. வழியின் காரணம், பரம்பரை, தலைமுறை நேரம் மற்றும் மூலக் குறிப்புகளைப் படிக்கவும்.
2. பெயரிடப்பட்ட கட்டமைக்கப்பட்ட மூலமானது உள்ளது மற்றும் அதே சுழற்சியைச் சேர்ந்தது என்பதை உறுதிப்படுத்தவும்.
3. மொழிபெயர்க்கப்பட்ட வெளியீடு மற்றும் நிலுவையில் உள்ள உறையுடன் அதன் mtime ஐ ஒப்பிடுக.
4. இறுதிப் பதிவுகள் மொழிபெயர்க்கப்பட்ட அல்லது நிலுவையில் உள்ள வெளியீட்டை விட புதியதாக இருந்தால், பழைய நிறைவு அனுப்புதலைப் பதிவுசெய்து, அந்த ஒப்படைப்பை முதலில் சரிசெய்யவும்.
5. அனைத்து உள்ளூர் வெளியீடும் தற்போதையதாக இருந்தாலும், டெலிவரி இல்லை என்றால், பாதை உள்ளமைவு மற்றும் அனுப்புநரின் நிலையைச் சரிபார்க்கவும்.

திட்டமிடுபவர் ஆரோக்கியத்தையோ அல்லது ஐந்து வழிச் சான்றுக்கு ஒரு வெற்றிகரமான அறிவிப்பையோ விளம்பரப்படுத்த வேண்டாம்.

<a id="interpret-incomplete-source-coverage"></a>
## முழுமையற்ற மூல கவரேஜை விளக்கவும்

| நிலை | என்ன செய்வது |
|---|---|
| `partial` | சேகரித்த ஆதாரங்களை மட்டும் பயன்படுத்தவும் மற்றும் முழுமையான கவரேஜ் உரிமைகோரல்களைத் தவிர்க்கவும். |
| `deferred` | கட்டமைப்பை மாற்றும் முன், பின்னர் வரம்புக்குட்பட்ட பணி முன்னேற்றங்களை உறுதிப்படுத்தவும். |
| `unavailable` | சுற்றுச்சூழல் வரம்பை பதிவு செய்யவும்; நிரூபிக்கப்பட்ட பாதை அல்லது அனுமதி சிக்கலை மட்டும் சரிசெய்யவும். |
| `malformed` | மூலத்தைப் பாதுகாத்தல் மற்றும் பாகுபடுத்தும் பிழை; விடுபட்ட மதிப்புகளை யூகிக்க வேண்டாம். |
| `permission_denied` | தேவையான குறுகிய வாசிப்பு அனுமதியை மட்டும் வழங்கவும். |
| `error` | வழியை நம்புவதற்கு முன் விவரங்களைப் பாதுகாத்து, பெயரிடப்பட்ட கட்டத்தைக் கண்டறியவும். |

<a id="restore-missing-runtime-files"></a>
## விடுபட்ட இயக்க நேர கோப்புகளை மீட்டமைக்கவும்

உறுதிப்படுத்தவும்:

```text
mods.txt contains RandomDayGuard : 1
RandomDayGuard/enabled.txt exists
RandomDayGuard/Scripts/main.lua exists
```

சரியான நிறுவல் ரூட்:

```text
AbioticFactor/Binaries/Win64/ue4ss/Mods/RandomDayGuard/
```

இந்த உள்ளமைக்கப்பட்ட தளவமைப்பை நிராகரி:

```text
Mods/RandomDayGuard/RandomDayGuard/Scripts/main.lua
```

## விண்டோஸ் பிரித்தெடுத்தல் கோப்புறை மோதலைத் தீர்க்கவும்

ஒரு பழைய வெளியீடு நிரல் கோப்பகங்களைப் பயன்படுத்தியது, அதன் பெயர்கள் மூலதனத்தால் மட்டுமே வேறுபடுகின்றன. சில விண்டோஸ் எக்ஸ்ட்ராக்டர்கள் ஒரு ZIP ஏற்கனவே உள்ள கோப்புறையில் வைக்கப்பட்டுள்ளது.

1. நிறுவப்பட்ட மோட் அல்லது அதன் ஆதாரத்தை அல்ல, தோல்வியுற்ற தற்காலிக பிரித்தலை மட்டும் நீக்கவும்.
2. புதிய வெற்று தற்காலிக கோப்பகத்தை உருவாக்கவும்.
3. தற்போதைய வெளியீட்டை அங்கு பிரித்தெடுக்கவும்.
4. அது ஒன்றை உருவாக்குவதை உறுதிப்படுத்தவும் RandomDayGuard கோப்புறை மற்றும் ஒரு நிரல் கோப்பகம்.
5. விண்டோஸ் இன்னும் மோதலைப் புகாரளித்தால், வெளியீட்டை மீண்டும் பதிவிறக்கி, வெளியீட்டு பதிப்பு மற்றும் பயன்படுத்தப்பட்ட பிரித்தெடுத்தல் ஆகியவற்றைப் புகாரளிக்கவும்.

நிறுவப்பட்ட கோப்புறையில் புதிய வெளியீட்டைப் பிரித்தெடுக்க வேண்டாம். [`../INSTALL.md`](%E0%AE%A8%E0%AE%BF%E0%AE%B1%E0%AF%81%E0%AE%B5%E0%AE%B2%E0%AF%8D.md).

## எதிர்பார்க்கப்பட்ட பதிப்பை ஏற்றவும்

மூல மார்க்கரைச் சரிபார்த்து, மார்க்கரை உருவாக்கவும்:

```sh
grep -n "local VERSION" RandomDayGuard/Scripts/main.lua
cat RandomDayGuard/BUILD_MARKER.txt
```

அவர்கள் உடன்படவில்லை என்றால்:

1. சேவையகத்தை நிறுத்து.
2. நிறுவப்பட்ட கோப்புறை, மதிப்பாய்வு செய்யப்பட்ட உள்ளமைவு மற்றும் இயக்க நேரச் சான்று ஆகியவற்றைக் காப்புப் பிரதி எடுக்கவும்.
3. நிலை மற்றும் திட்டமிடப்பட்ட தொகுப்பை ஆய்வு செய்யவும்.
4. தொகுப்பு-நிர்வகிக்கப்பட்ட நிரல் மற்றும் தரவு கோப்புகளை மட்டும் மாற்றவும்.
5. கேனானிகல் லோடர் இருப்பதை உறுதிப்படுத்தவும், மேலும் சிற்றெழுத்து நகல் எதுவும் சேர்க்கப்படவில்லை.
6. இயக்க நேர வெளியீட்டை தீர்மானிக்கும் முன் ஒருமுறை தொடங்கி தற்போதைய குறிப்பான்களை மீண்டும் படிக்கவும்.

## நிறுத்தப்பட்ட வரலாற்று ஸ்கேனை மீட்டெடுக்கவும்

தற்போதைய கண்காணிப்பு மற்றும் வரலாற்று கண்டுபிடிப்பு தனித்தனியாக உள்ளன. ஒரு பெரிய காப்பகத்திற்கு பல வரம்பிற்குட்பட்ட சுழற்சிகள் தேவைப்படலாம், எனவே அதை ஸ்தம்பித்ததாக அழைக்க ஒரே ஒரு மாறாத கவனிப்பு போதாது.

1. திற `runtime/current/report_worker_status.json`.
2. பதிவு `scan_cursor`, கண்டுபிடிக்கப்பட்ட கோப்புகள், முடிக்கப்பட்ட கோப்புகள் மற்றும் `last_progress_ts`.
3. குறைந்தது இரண்டு சாதாரண அறிக்கை-பணியாளர் வாய்ப்புகளுக்காகக் காத்திருந்து, அதே புலங்களை மீண்டும் ஒப்பிடவும்.
4. கர்சர், பூர்த்தி செய்யப்பட்ட எண்ணிக்கை அல்லது முன்னேற்ற நேரம் முன்னேறினால், ஸ்கேன் இன்னும் வேலை செய்கிறது. அதை வரம்பிடவும்.
5. வாக்கெடுப்பு ஐடிகள் மற்றும் தற்போதைய அறிக்கைகள் தொடர்ந்து முன்னேறும் போது அனைத்து முன்னேற்றப் புலங்களும் மாறாமல் இருந்தால், நிலைக் கோப்பைப் பாதுகாத்து, பணியாளரின் கட்டத்தால் பெயரிடப்பட்ட மூல வகுப்பைச் சரிபார்க்கவும். மீண்டும் முயற்சிக்கும் முன் அந்த மூலப் பாதையை சரிசெய்யவும் அல்லது தோல்வியைப் படிக்கவும்.

நிறுத்தப்பட்ட வரலாற்று ஸ்கேன், பழைய பதிவுகள் தேவைப்படும் முடிவுகளை வரம்பிடுகிறது. செயலில் உள்ள பதிவு மற்றும் தற்போதைய சுழற்சி ஆதாரம் புதியதாக இருக்கும் தற்போதைய அறிக்கையை இது செல்லுபடியாகாது.

## தடுக்கப்பட்டதைக் கண்டறியவும் Admin.ini எழுது

வெளிப்படையான ஒப்புதல் மற்றும் செலவழிப்பு சோதனைக் கோப்புடன் மட்டுமே அமலாக்கச் சோதனையை இயக்கவும், நேரடி சேவையகக் கோப்புடன் இல்லை. சோதனை உள்ளமைவு காவலரை எழுதச் சொல்கிறது என்பதை முதலில் உறுதிப்படுத்தவும்:

```lua
review_only_mode = false
auto_ban = true
write_admin_ini = true
```

பின்னர் பதிவுசெய்யப்பட்ட தோல்விக்கான காரணத்தைப் படிக்கவும். காவலர் ஒரு கணக்கை அடையாளம் காண வேண்டும், மதிப்பீட்டாளர்கள் மற்றும் நம்பகமான கணக்குகளைப் பாதுகாக்க வேண்டும், போதுமான கணக்கு-குறிப்பிட்ட சான்றுகளைக் கண்டறிய வேண்டும், புதிய காப்புப்பிரதியை உருவாக்கி சரிபார்க்க வேண்டும், வேறு எந்த நிரலும் கோப்பை மாற்றவில்லை என்பதை உறுதிப்படுத்த வேண்டும், உத்தேசித்துள்ள புதுப்பிப்பைச் சேமிக்க வேண்டும், மேலும் முழுமையான சேமித்த கோப்பை அந்த நோக்கத்துடன் ஒப்பிட வேண்டும். எந்தப் படியும் தோல்வியுற்றாலோ அல்லது சரிபார்க்க முடியாமலோ, தடைப்பட்டியலை மாற்றாமல் விடவும். பார்க்கவும் [Admin.ini அமலாக்கம்](%E0%AE%A8%E0%AE%BF%E0%AE%B0%E0%AF%8D%E0%AE%B5%E0%AE%BE%E0%AE%95%E0%AE%AE%E0%AF%8D_%E0%AE%87%E0%AE%A9%E0%AE%BF_%E0%AE%85%E0%AE%AE%E0%AE%B2%E0%AE%BE%E0%AE%95%E0%AF%8D%E0%AE%95%E0%AE%AE%E0%AF%8D.md).

## விடுபட்ட தினசரி ரோல்அப்பை மீட்டெடுக்கவும்

உறுதிப்படுத்து `forensic_rollup.enabled = true`, பிறகு ஆய்வு:

```text
runtime/current/forensic_today.json
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

இவை விடுபட்டால், அந்த வரிசையில் ஸ்டார்ட்அப், வாக்கெடுப்பு, அறிக்கை-பணியாளர் மற்றும் மூல-கணக்கியல் நிலை ஆகியவற்றைச் சரிபார்க்கவும். தினசரி ரோல்அப் என்பது ஒரு நாளுக்கு ஒரு தொடர்ச்சிப் பதிவாகும், மீண்டும் மீண்டும் வரும் சர்வர்-நிலை அறிவிப்பு அல்ல.

## சரியான நிலை அல்லது பிழையைப் பார்க்கவும்

பயன்படுத்து [நிலை மற்றும் பிழை குறிப்பு](%E0%AE%A8%E0%AE%BF%E0%AE%B2%E0%AF%88_%E0%AE%AE%E0%AE%B1%E0%AF%8D%E0%AE%B1%E0%AF%81%E0%AE%AE%E0%AF%8D_%E0%AE%AA%E0%AE%BF%E0%AE%B4%E0%AF%88_%E0%AE%95%E0%AF%81%E0%AE%B1%E0%AE%BF%E0%AE%AA%E0%AF%8D%E0%AE%AA%E0%AF%81.md) முழுமையான பாதை, ஆதாரம், PlayerData, அமலாக்கம், தொடக்கம், திட்டமிடல், அறிக்கை மற்றும் அறிவிப்பு குறியீடு அட்டவணைகள். தேடுதல் அட்டவணைகளைத் தனித்தனியாக வைத்திருப்பது, இந்தப் பழுதுபார்ப்புப் பக்கம் இரண்டாவது ஸ்கீமா கையேடாக மாறுவதைத் தடுக்கிறது.
