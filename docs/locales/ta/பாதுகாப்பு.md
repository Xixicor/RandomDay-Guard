# பாதுகாப்புக் கொள்கை

> **நியாய ஆங்கில மூல:** [SECURITY.md](../../../SECURITY.md). இந்த உள்ளூர்மயமாக்கப்பட்ட ஆவணம் சரியான கட்டளைகள், பாதைகள், விசைகள், நிலை மதிப்புகள், ஹாஷ்கள் மற்றும் கோப்பு பெயர்களைப் பாதுகாக்கிறது. தொழில்நுட்ப வார்த்தைகள் வேறுபட்டால், ஆங்கில மூலத்தைப் பயன்படுத்தவும்.


<a id="report-a-vulnerability-privately"></a>
## பாதிப்பை தனிப்பட்ட முறையில் புகாரளிக்கவும்

பயன்படுத்து [GitHub தனிப்பட்ட பாதிப்பு அறிக்கை](https://github.com/Xixicor/RandomDay-Guard/security/advisories/new) ஒரு ரகசிய அறிக்கையை களஞ்சிய உரிமையாளருக்கு அனுப்ப. அந்த படிவம் கிடைக்கவில்லை என்றால், [உரிமையாளரின் பொது GitHub சுயவிவரம்](https://github.com/Xixicor) பாதிப்பு விவரங்களைச் சேர்க்காமல் தனிப்பட்ட தொடர்பு சேனலைக் கோர.

சுரண்டல் படிகள், நற்சான்றிதழ்கள், தனிப்பட்ட சர்வர் பாதைகள், பிளேயர் அடையாளங்காட்டிகள், `Admin.ini`, சேமிக்கப்பட்ட தரவு, வெப்ஹூக் URLகள் அல்லது நேரடி ஆதாரக் கோப்புகள்.

<a id="include-useful-evidence"></a>
## பயனுள்ள சான்றுகளைச் சேர்க்கவும்

வழங்கவும்:

- பாதிக்கப்பட்ட RandomDayGuard பதிப்பு அல்லது உறுதி;
- பாதிக்கப்பட்ட கூறு மற்றும் எதிர்பார்க்கப்படும் பாதுகாப்பான நடத்தை;
- சுத்திகரிப்பு செய்யப்பட்ட சாதனங்களைப் பயன்படுத்தி குறைந்தபட்ச மறுஉற்பத்தி படிகள்;
- கவனிக்கப்பட்ட தாக்கம் மற்றும் அது மீண்டும் மீண்டும் செய்யக்கூடியதா; மற்றும்
- தனிப்பட்ட தரவை வெளிப்படுத்தாத ஏதேனும் முன்மொழியப்பட்ட தணிப்பு.

உண்மையான ரகசியங்களை அனுப்ப வேண்டாம். தனிப்பட்ட பாதைகள், கணக்கு அடையாளங்காட்டிகள், ஹோஸ்ட் பெயர்கள் மற்றும் டோக்கன்களை தெளிவான ஒதுக்கிடங்களுடன் மாற்றவும், அதே நேரத்தில் சிக்கலை மீண்டும் உருவாக்க தேவையான கட்டமைப்பைப் பாதுகாக்கவும்.

<a id="expect-review-first-handling"></a>
## முதல் மதிப்பாய்வை எதிர்பாருங்கள்

ஒரு அறிக்கை என்பது பராமரிப்பாளர் மதிப்பாய்வுக்கான ஆதாரம், சேவையகத்தை அணுகுவதற்கான அங்கீகாரம் அல்ல, நேரடி இலக்கைச் சோதிப்பது, சுரண்டல் விவரங்களை வெளியிடுவது அல்லது தோல்வி-மூடப்பட்ட இயல்புநிலைகளை பலவீனப்படுத்துவது. உரிமையாளர் நோக்கத்தைச் சரிபார்த்து, தனிப்பட்ட அறிக்கையின் மூலம் எந்தவொரு வெளிப்பாட்டையும் ஒருங்கிணைப்பார்.
