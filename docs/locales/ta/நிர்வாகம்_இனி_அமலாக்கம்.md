# Admin.ini அமலாக்கம்

> **நியாய ஆங்கில மூல:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). இந்த உள்ளூர்மயமாக்கப்பட்ட ஆவணம் சரியான கட்டளைகள், பாதைகள், விசைகள், நிலை மதிப்புகள், ஹாஷ்கள் மற்றும் கோப்பு பெயர்களைப் பாதுகாக்கிறது. தொழில்நுட்ப வார்த்தைகள் வேறுபட்டால், ஆங்கில மூலத்தைப் பயன்படுத்தவும்.


RandomDayGuard அதன் இயல்புநிலை அமைப்பில் சர்வர் தடை பட்டியலை மாற்றாது. நிர்வாகி மதிப்பாய்வு செய்ய மட்டுமே இது அறிக்கைகளை உருவாக்குகிறது. வேண்டுமென்றே இயக்கும் நிர்வாகிகளுக்கான விருப்பத் தானியங்கி தடைப்பட்டியல் புதுப்பிப்பை இந்தப் பக்கம் விளக்குகிறது.

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## தடை பட்டியலை மாற்றும் முன் காவலர் என்ன சரிபார்க்கிறார்

கீழே உள்ள ஒவ்வொரு பதிலும் இருக்கும் போது மட்டுமே காவலர் தடையைச் சேர்க்கிறார் **ஆம்**:

1. தற்போதைய சான்றுகள் ஒரு குறிப்பிட்ட கணக்கை போதுமான நம்பிக்கையுடன் அடையாளம் கண்டுள்ளதா?
2. கணக்கு மதிப்பீட்டாளர் அல்லது நிர்வாகி கணக்கு நம்பகமானதாகக் குறிக்கப்படவில்லையா?
3. கணக்கு ஏற்கனவே தடை பட்டியலில் இல்லையா?
4. கணக்கு உள்ளமைக்கப்பட்ட தானியங்கு-செயல் ஸ்கோரை அடைந்ததா?
5. தற்போதையதைப் படிக்க முடியும் `Admin.ini` மற்றும் ஒரே மாதிரியான காப்புப்பிரதியைச் சேமிக்கவா?
6. செய்தேன் `Admin.ini` மாறாமல் இருக்க வேண்டுமா?
7. சேமித்த பிறகு, முழு கோப்பும் உத்தேசித்த முடிவுடன் சரியாகப் பொருந்துகிறதா?

ஏதேனும் பதில் என்றால் **இல்லை**, அல்லது சரிபார்க்க முடியவில்லை, காவலர் வெளியேறுகிறார் `Admin.ini` மாறாமல் அதன் அறிக்கைகளில் காரணத்தை பதிவு செய்கிறது. சேமிக்கத் தொடங்கினாலும் இறுதிச் சரிபார்ப்பு தோல்வியடைந்தால், சரிபார்க்கப்பட்ட காப்புப்பிரதியை Guard மீட்டமைக்கிறது.

<a id="file-format"></a>
## கோப்பு வடிவம்

`Admin.ini` சுத்தமான தடை வரிகளை மட்டுமே பெற வேண்டும்:

```ini
BannedPlayer=<ID>
```

- பெயர்கள் இல்லை.
- கருத்துகள் இல்லை.
- காரணங்கள் இல்லை.
- பின்னொட்டுகள் இல்லை.

<a id="safe-defaults"></a>
## பாதுகாப்பான இயல்புநிலைகள்

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## ஐடி மூலத்தைத் தடை செய்

சிறந்த ஆதாரம்:

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

இயக்க நேரம் முழு எண் ஐடி அல்லது முழு ஆவணப்படுத்தப்பட்ட `<digits>_+_|<non-space token>` இணைப்புப் படிவம் மற்றும் அதிலிருந்து எண் தடை ஐடியைப் பெறுகிறது. அறியப்படாத பின்னொட்டுடன் தன்னிச்சையான எண் முன்னொட்டுகள் நிராகரிக்கப்படுகின்றன; அவை தடை ஐடியாக துண்டிக்கப்படவில்லை.

சரியானது:

```ini
BannedPlayer=2535422284688820
```

தவறு:

```ini
BannedPlayer=ExamplePlayer
```

மேலும் தவறு:

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## சரியான அமைப்புகள் காவலர் சோதனைகள்

இந்த அமைப்புகள் மேலே விவரிக்கப்பட்ட சரிபார்ப்புகளைச் செயல்படுத்துகின்றன. பட்டியலிடப்பட்ட ஒவ்வொரு நிபந்தனையும் உண்மையாக இருக்க வேண்டும்:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

எந்த நிபந்தனையும் தவறானது அல்லது சரிபார்க்க முடியாவிட்டால், காவலர் தடைப்பட்டியலை மாற்றாமல் விட்டுவிட்டு, அதை நிறுத்தியதைப் பதிவுசெய்கிறார்.

<a id="transaction-safety"></a>
## பரிவர்த்தனை பாதுகாப்பு

ஒரே `Admin.ini` பிறழ்வு பாதை இந்த வழிமுறைகளை வரிசையாகச் செய்கிறது:

1. அதிகாரப்பூர்வ பைட்டுகளைப் படித்து கட்டமைப்பு ரீதியாக சரிபார்க்கவும்.
2. அதே ஸ்னாப்ஷாட்டிலிருந்து மதிப்பீட்டாளர், நம்பகமான மற்றும் ஏற்கனவே உள்ள தடை நிலையைப் பெறவும்.
3. `runtime/backups/` மற்றும் பைட்டிற்கான பைட்டைச் சரிபார்க்கவும்.
4. மீண்டும் படிக்கவும் `Admin.ini` உடனடியாக மாற்றுவதற்கு முன் மற்றும் வெளிப்புற மாற்றங்களை நிராகரிக்கவும்.
5. கட்டமைக்கப்பட்ட கட்டுப்படுத்தப்பட்ட மாற்று பாதையின் மூலம் வேட்பாளரை எழுதவும்.
6. முழுமையான கேண்டிடேட் பைட்டுகளுக்கு சமமாக, முழுமையான ரீட்பேக் பைட்டுகள் தேவை.
7. ரீட்பேக் தோல்வியில், தற்போதைய கோப்பு காவலரால் எழுதப்பட்ட சரியான விண்ணப்பமாக இருக்கும்போது மட்டுமே சரிபார்க்கப்பட்ட காப்புப்பிரதியை மீட்டெடுக்கவும். வேறொரு எழுத்தாளர் அதை மாற்றினால், அறியப்படாத வெளிப்புற பைட்டுகளை மேலெழுதுவதற்குப் பதிலாக, கார்டு திரும்பப்பெற மறுக்கிறது.

நகல் ஐடிகள் வலிமையற்றவை: இரண்டாவது வரியும் இரண்டாவது காப்புப்பிரதியும் எழுதப்படவில்லை. காப்புப் பெயர்களில் நேர முத்திரை, மூல-பைட் கைரேகை மற்றும் சுத்தமான ஐடி ஆகியவை அடங்கும், எனவே தனி முயற்சிகள் பழைய ஒரு நொடி கோப்புப் பெயரைப் பகிர முடியாது.

<a id="local-regression-proof"></a>
## உள்ளூர் பின்னடைவு சான்று

`tests/lua/enforcement_runtime_test.lua` அனுப்பப்பட்ட ஏற்றியை ஒருமுறை துவக்கி அதன் உண்மையான உள்ளூர் இயக்கத்தை இயக்குகிறது `append_ban()` களஞ்சியத்திற்கு கீழே உள்ள தனிமைப்படுத்தப்பட்ட செயற்கை கோப்புகளுக்கு எதிராக மூடுதல் `.tmp/` அடைவு. இது உட்செலுத்துதல், நகல் ஐடிம்போடென்சி, moderator/trusted நிராகரிப்பு, பலவீனமான மற்றும் தவறான அடையாள நிராகரிப்பு, பைட்-சரியான காப்புப்பிரதி சரிபார்ப்பு, ஒரே நேரத்தில் மாற்றியமைத்தல் நிராகரிப்பு, தோல்வியடைந்த மறுபரிசீலனைக்குப் பிறகு வெற்றிகரமான பின்வாங்கல் மற்றும் எழுதப்பட்ட வெளிப்புற மாற்றத்தை மேலெழுத மறுத்தல். அதன் கோப்பு முறைமை ரேப்பர்கள் ஃபிக்சர் ரூட்டிற்கு வெளியே எந்த மாற்றத்தையும் நிராகரிக்கின்றன; உண்மையான சர்வர் பாதை அல்லது உண்மையான `Admin.ini` பயன்படுத்தப்படுகிறது.

இதன் மூலம் இயக்கவும் `python tools/test_public_pipeline.py`. ஃபிக்சர் பாஸ் உள்ளூர் பரிவர்த்தனை நடத்தையை மட்டுமே நிரூபிக்கிறது. இது அமலாக்கத்தை இயக்காது, தயாரிப்பு எழுதுதலை அங்கீகரிக்காது அல்லது ஹோஸ்ட்-குறிப்பிட்ட அனுமதிகளை நிரூபிக்காது.

<a id="rollback"></a>
## மீண்டும் திரும்புதல்

1. சேவையகத்தை நிறுத்து.
2. சமீபத்தியதை மீட்டமை Admin.ini இலிருந்து காப்புப்பிரதி `runtime/backups/`.
3. தவறானதை அகற்று `BannedPlayer=<ID>` வரி.
4. சேவையகத்தைத் தொடங்கு.
5. மீண்டும் திற Admin.ini மற்றும் வரி நீடித்தது அல்லது அகற்றப்பட்டது என்பதை உறுதிப்படுத்தவும்.
6. பாதுகாக்கவும் `enforced_bans.jsonl` தணிக்கைக்கு.
