# প্রমাণের সীমানা

> **ক্যাননিকাল ইংরেজি উৎস:** [EVIDENCE_BOUNDARY.md](../../EVIDENCE_BOUNDARY.md). এই স্থানীয় ডকুমেন্টেশন সঠিক কমান্ড, পাথ, কী, স্থিতি মান, হ্যাশ এবং ফাইলের নাম সংরক্ষণ করে। প্রযুক্তিগত শব্দের ভিন্নতা থাকলে, ইংরেজি উৎস ব্যবহার করুন।


কি সিদ্ধান্ত নিতে এই পৃষ্ঠাটি ব্যবহার করুন RandomDayGuard রিপোর্ট করতে পারে এবং কিসের জন্য এখনও মানুষের পর্যালোচনা প্রয়োজন৷

<a id="core-rule"></a>
## মূল নিয়ম

RandomDayGuard সার্ভার-মালিকানাধীন ফাইল থেকে আবদ্ধ পর্যবেক্ষণ রেকর্ড করে। এটিকে অবশ্যই উৎস, সুযোগ, সংগ্রহের অবস্থা এবং প্রতিটি উপাদানের উপসংহারের সীমা চিহ্নিত করতে হবে।

গঠিত প্রমাণ প্রামাণিক৷ একটি অনুবাদিত রিপোর্ট প্রমাণ ব্যাখ্যা করে; এটি কাঠামোগত রেকর্ড থেকে অনুপস্থিত তথ্য যোগ করতে পারে না।

<a id="evidence-source-classes"></a>
## প্রমাণ উৎস ক্লাস

| উৎস শ্রেণী | সাধারণ ব্যবহার | নিজে থেকে প্রমাণিত হয় না |
|---|---|---|
| `admin_ini` | বিদ্যমান প্রশাসনিক অবস্থা এবং নিরীক্ষিত write/readback প্রসঙ্গ | কে একটি ঘটনা ঘটিয়েছে |
| `active_log` | বর্তমান server/session সক্রিয় লগে দৃশ্যমান ঘটনা | উদ্দেশ্য, মালিকানা, বা সরাসরি ক্ষতি |
| `recent_backup_logs` | ঐতিহাসিক লগ প্রসঙ্গ | একটি বর্তমান ঘটনা ঘটেছে |
| `playerdata_filenames` | একটি ক্লিন অ্যাকাউন্ট শনাক্তকারী বিদ্যমান রয়েছে তা নিশ্চিত করুন | উন্মুক্ত শনাক্তকারীর বাইরে আচরণ, অপরাধবোধ বা পরিচয়ের মালিকানা |
| `existing_cases` | পূর্ব পর্যালোচনা প্রসঙ্গে | যে একটি পূর্বের ব্যাখ্যা সঠিক থাকে |
| `existing_reports` | আগের সারাংশ এবং সিদ্ধান্ত | বর্তমান সত্যতা ছাড়াই বর্তমান সত্য |
| `existing_evidence` | ঐতিহাসিক কাঠামোগত প্রমাণ | বর্তমান কার্যকলাপ |
| বাউন্ডেড ওয়ার্ল্ড-সেভ স্ক্যান | ধীরে world/class প্রসঙ্গ | প্লেয়ার অ্যাকশন, মালিকানা, চুরি, নকল, বা ক্ষতি |

প্রতিটি উৎস রেকর্ড করে availability/readability, ফাইলের সংখ্যা, উৎস উল্লেখ, বর্তমান বা ঐতিহাসিক সুযোগ, এবং একটি স্পষ্ট `does_not_prove` বিবৃতি।

<a id="source-states"></a>
## সোর্স স্টেটস

| রাজ্য | অপারেটর মানে |
|---|---|
| `available` | উৎসটি পাঠযোগ্য ছিল এবং প্রমাণ সংগ্রহ করা হয়েছিল৷ |
| `expected_empty` | উৎসটি পঠনযোগ্য ছিল এবং বৈধভাবে কোনো মিলিত রেকর্ড ছিল না। |
| `partial` | কিছু ​​প্রমাণ সংগ্রহ করা হয়েছিল; কভারেজ অসম্পূর্ণ। |
| `deferred` | বাউন্ডেড কাজ ইচ্ছাকৃতভাবে স্থগিত করা হয়েছিল। |
| `unavailable` | উৎসটি এই পরিবেশে উপস্থিত নয়৷ |
| `malformed` | উৎসটি বিদ্যমান কিন্তু নিরাপদে পার্স করা যাবে না। |
| `permission_denied` | ওয়াচডগের পড়ার অনুমতি নেই৷ |
| `error` | অন্য একটি রেকর্ড করা কারণে সংগ্রহ ব্যর্থ হয়েছে৷ |

প্রত্যাশিত খালি একটি বৈধ পর্যবেক্ষণ। এটিকে কখনই একটি বানোয়াট প্লেয়ার, মামলা, ঘটনা বা অভিযোগে রূপান্তর করা উচিত নয়৷

<a id="current-versus-historical-evidence"></a>
## বর্তমান বনাম ঐতিহাসিক প্রমাণ

বর্তমান প্রমাণ সক্রিয় সংগ্রহ উইন্ডো বা সার্ভার যুগের অন্তর্গত। ঐতিহাসিক প্রমাণ পূর্বের লগ, মামলা, রিপোর্ট, প্রমাণ রেকর্ড, ব্যাকআপ বা বেসলাইন থেকে আসে।

ঐতিহাসিক প্রমাণ প্রসঙ্গ প্রদান করতে পারে৷ এটি নীরবে একটি বর্তমান-প্রমাণ শূন্যতা পূরণ করতে পারে না। প্রতিবেদনগুলিকে অবশ্যই উভয় স্কোপের লেবেল দিতে হবে এবং তাদের উত্স আলাদাভাবে উল্লেখ করতে হবে৷

<a id="corroboration-rule"></a>
## সংশোধনের নিয়ম

এগুলি দরকারী প্রসঙ্গ কিন্তু নিজের দ্বারা সরাসরি প্রমাণ নয়:

- প্রদর্শন নাম বা নামের মিল;
- টাইমিং কাকতালীয়;
- সংযোগ বিচ্ছিন্ন বা পুনরায় সংযোগ মন্থন;
- একটি ক্র্যাশ বা সতর্কতা বিস্ফোরণ;
- শ্রেণী, পথ, অভিনেতা, মানচিত্র, বা অবজেক্ট-কাউন্ট টোকেন;
- স্বয়ংক্রিয়ভাবে গোষ্ঠীবদ্ধ ক্ষেত্রে সদস্যপদ;
- বর্তমান উৎস নিশ্চিতকরণ ছাড়াই পূর্বের প্রতিবেদন।

অপরাধ, অভিপ্রায়, প্রতারণা, মালিকানা, চুরি, নকল, সরাসরি ক্ষতি, সরাসরি কন্টেইনার ব্যবহার, সরাসরি ইনভেন্টরি অ্যাকশন, সঠিক লাইভ কোঅর্ডিনেট, লাইভ পিং, বা মেমরি-লেভেল আচরণ দাবি করবেন না যা সরাসরি সত্যটি প্রকাশ করে।

<a id="truthful-report-language"></a>
## সত্যপূর্ণ প্রতিবেদনের ভাষা

ব্যবহার করুন:

```text
Observed: the account was active in the recorded crash window.
Interpretation: repeated overlap warrants operator review.
Unknown: the cause of the crash.
Does not prove: that the account caused the crash.
Next action: compare the cited current session and lifecycle records.
```

এড়িয়ে চলুন:

```text
The player crashed the server.
The player stole or duplicated items.
The world token proves who used the object.
```

<a id="report-reading-order"></a>
## রিপোর্ট পড়ার অর্ডার

প্রত্যেক জন-মুখী প্রতিবেদনের ব্যাখ্যা করা উচিত:

1. সরল অর্থ।
2. এটা কেন গুরুত্বপূর্ণ।
3. প্রযুক্তিগত প্রমাণ এবং উৎস উল্লেখ।
4. পরবর্তী পদক্ষেপ।
5. সীমা, অজানা, এবং দাবি প্রমাণিত হয়নি৷
