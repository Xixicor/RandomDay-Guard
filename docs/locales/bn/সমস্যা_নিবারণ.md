# সমস্যা নিবারণ

> **ক্যাননিকাল ইংরেজি উৎস:** [TROUBLESHOOTING.md](../../TROUBLESHOOTING.md). এই স্থানীয় ডকুমেন্টেশন সঠিক কমান্ড, পাথ, কী, স্থিতি মান, হ্যাশ এবং ফাইলের নাম সংরক্ষণ করে। প্রযুক্তিগত শব্দের ভিন্নতা থাকলে, ইংরেজি উৎস ব্যবহার করুন।


এই পৃষ্ঠাটি ব্যবহার করুন যখন গার্ড লোড হয় না, একটি উত্স সংগ্রহ করা যায় না, একটি প্রতিবেদন প্রদর্শিত হয় না, বা রুট প্রুফ আপনার প্রত্যাশার বিরোধী হয়৷ সিদ্ধান্ত গাছ দিয়ে শুরু করুন এবং একটি শাখা অনুসরণ করুন। ডেডিকেটেড ব্যবহার করুন [স্থিতি এবং ত্রুটির রেফারেন্স](%E0%A6%B8%E0%A7%8D%E0%A6%A5%E0%A6%BF%E0%A6%A4%E0%A6%BF_%E0%A6%8F%E0%A6%AC%E0%A6%82_%E0%A6%A4%E0%A7%8D%E0%A6%B0%E0%A7%81%E0%A6%9F%E0%A6%BF%E0%A6%B0_%E0%A6%B0%E0%A7%87%E0%A6%AB%E0%A6%BE%E0%A6%B0%E0%A7%87%E0%A6%A8%E0%A7%8D%E0%A6%B8.md) ব্যর্থ স্তরটি জানার পরেই৷

কনফিগারেশন পরিবর্তন বা পুনরায় ইনস্টল করার আগে বর্তমান রানটাইম ফাইলগুলি সংরক্ষণ করুন৷ একটি বাসি বা অনুপস্থিত আর্টিফ্যাক্ট একটি ব্যর্থ পর্যায় চিহ্নিত করে; বারবার রিস্টার্ট সেই প্রমাণ মুছে দিতে পারে।

<a id="choose-the-failure-path"></a>
## ব্যর্থতার পথ বেছে নিন

<a id="1-decide-whether-guard-loaded"></a>
### 1. গার্ড লোড করা হয়েছে কিনা তা নির্ধারণ করুন

- **না `runtime/` ফাইল বিদ্যমান:** অনুসরণ করুন [অনুপস্থিত রানটাইম ফাইল পুনরুদ্ধার করুন](#restore-missing-runtime-files)। ইনস্টল পাথ, ক্যানোনিকাল লোডার, `enabled.txt` এবং `mods.txt` রিপোর্ট তদন্ত করার আগে।
- **বর্তমান স্থিতি ফাইল বিদ্যমান:** রাজ্য লেখার জন্য গার্ড যথেষ্ট লোড হয়েছে৷ ধাপ 2 চালিয়ে যান; পুনরায় ইনস্টল করা প্রথম প্রতিক্রিয়া নয়৷

<a id="2-decide-whether-the-scheduler-is-advancing"></a>
### 2. সিডিউলার অগ্রসর হচ্ছে কিনা তা নির্ধারণ করুন

খুলুন:

```text
runtime/current/startup_status.json
runtime/current/poll_status.json
```

- **কাউন্টার এবং টাইমস্ট্যাম্প অগ্রিম:** ধাপ 3 চালিয়ে যান।
- **`poll_id` স্ট্যাটিক, `poll_in_flight` সত্য থাকে, অথবা সময়সূচী স্থিতি চলছে না:** অনুসরণ করুন [একটি আটকে থাকা পোল লুপ পুনরুদ্ধার করুন](#recover-a-stuck-poll-loop).
- **শিডিউলারের অগ্রগতি অব্যাহত থাকার সময় বেসলাইন স্ক্যান মুলতুবি থাকে:** এটি একটি সতর্কতা, স্বয়ংক্রিয়ভাবে একটি ব্যর্থ স্টার্টআপ নয়৷ ব্যাকলগ বা স্ক্যানের অগ্রগতি বন্ধ হলেই তদন্ত করুন।

<a id="3-classify-route-proof"></a>
### 3. রুট প্রমাণ শ্রেণীবদ্ধ করুন

খুলুন `runtime/final_logs/route_proof.json` এবং প্রতিটি রুট আলাদাভাবে পরিদর্শন করুন।

- **`full`:** বর্তমানের সাথে অপ্রত্যাশিত শব্দের তুলনা করুন `source_references` এবং বংশ। ডেলিভারি পরিবর্তন করবেন না কারণ একা শব্দই ভুল বলে মনে হচ্ছে।
- **`limited_expected_empty`:** নিশ্চিত করুন উৎস অ্যাকাউন্টিং একটি বৈধ খালি ফলাফল সমর্থন করে৷ সিন্থেটিক প্লেয়ার বা কেস তৈরি করবেন না।
- **`missing`:** অনুসরণ করুন [একটি অনুপস্থিত রুট নির্ণয় করুন](#diagnose-a-missing-route).

<a id="4-classify-source-coverage"></a>
### 4. উৎস কভারেজ শ্রেণীবদ্ধ করুন

- **`partial`, `deferred`, `unavailable`, `malformed`, `permission_denied` বা `error`:** অনুসরণ করুন [অসম্পূর্ণ উৎস কভারেজ ব্যাখ্যা করুন](#interpret-incomplete-source-coverage), তারপর [স্থিতি এবং ত্রুটির রেফারেন্স](%E0%A6%B8%E0%A7%8D%E0%A6%A5%E0%A6%BF%E0%A6%A4%E0%A6%BF_%E0%A6%8F%E0%A6%AC%E0%A6%82_%E0%A6%A4%E0%A7%8D%E0%A6%B0%E0%A7%81%E0%A6%9F%E0%A6%BF%E0%A6%B0_%E0%A6%B0%E0%A7%87%E0%A6%AB%E0%A6%BE%E0%A6%B0%E0%A7%87%E0%A6%A8%E0%A7%8D%E0%A6%B8.md).
- **স্ট্রাকচার্ড সোর্স বর্তমান কিন্তু অনূদিত বা মুলতুবি আউটপুট পুরনো:** কমপ্লিশন হ্যান্ডঅফ নির্ণয় করুন, ডেলিভারি এন্ডপয়েন্ট নয়। ডেলিভারি কনফিগারেশন পরিবর্তন করার আগে উভয় টাইমস্ট্যাম্প সংরক্ষণ করুন এবং রিপোর্ট এবং প্রেরণের অবস্থা পরিদর্শন করুন৷

<a id="5-follow-the-matching-branch"></a>
### 5. মিলিত শাখা অনুসরণ করুন

- অসম্পূর্ণ পরিচয়: [একটি আনম্যাপ করা প্লেয়ারকে ম্যাপ করুন](#map-an-unmapped-player).
- দৈনিক ধারাবাহিকতা অনুপস্থিত: [একটি অনুপস্থিত দৈনিক রোলআপ পুনরুদ্ধার করুন](#restore-a-missing-daily-rollup).
- স্পষ্টভাবে অনুমোদিত এনফোর্সমেন্ট টেস্ট লিখেনি: [অবরুদ্ধ নির্ণয় করুন Admin.ini লিখুন](#diagnose-a-blocked-adminini-write).
- ZIP নিষ্কাশন ব্যর্থ হয়েছে: [একটি Windows নিষ্কাশন কেস সংঘর্ষের সমাধান করুন](#resolve-a-windows-extraction-folder-collision).
- ফিক্সচার, প্যাকেজ, বা সংগ্রহস্থল পরীক্ষা ব্যর্থ হয়েছে: [বৈধকরণ এবং রিলিজ পর্যালোচনা](%E0%A6%AC%E0%A7%88%E0%A6%A7%E0%A6%95%E0%A6%B0%E0%A6%A3_%E0%A6%8F%E0%A6%AC%E0%A6%82_%E0%A6%AA%E0%A7%8D%E0%A6%B0%E0%A6%95%E0%A6%BE%E0%A6%B6.md#avoid-validation-environment-pitfalls).

<a id="6-stop-with-one-proved-outcome"></a>
### 6. একটি প্রমাণিত ফলাফল দিয়ে থামুন

একটি সমস্যা সমাধানের পাস শেষ হয় যখন:

- রুটটি বর্তমান এবং `full`;
- রুটটি বর্তমান এবং `limited_expected_empty` নামের কারণে;
- একটি সঠিক ব্লকার, প্রমাণ পথ এবং পরবর্তী ক্রিয়া রেকর্ড করা হয়; অথবা
- রোলব্যাক পূর্বের পরিচিত অবস্থা পুনরুদ্ধার করেছে এবং ব্যর্থ প্রমাণ সংরক্ষণ করেছে৷

“সার্ভার চলছে,” ক্রমবর্ধমান হার্টবিট বা HTTP একা সাফল্য প্রমাণ করে না যে রিপোর্ট রুট সম্পূর্ণ হয়েছে৷

<a id="diagnose-a-missing-route"></a>
## একটি অনুপস্থিত রুট নির্ণয় করুন

খুলুন `runtime/final_logs/route_proof.json` এবং তুলনা করুন `server_status`, `daily_rollup`, `player_activity`, `case_review` এবং `critical_guard`.

1. রুটের কারণ, বংশ, প্রজন্মের সময় এবং উৎসের রেফারেন্স পড়ুন।
2. নিশ্চিত করুন যে নামযুক্ত কাঠামোগত উৎস বিদ্যমান এবং একই চক্রের অন্তর্গত।
3. অনুবাদিত আউটপুট এবং মুলতুবি থাকা খামের সাথে এর এমটাইম তুলনা করুন।
4. যদি চূড়ান্ত লগগুলি অনূদিত বা মুলতুবি আউটপুটের চেয়ে নতুন হয়, তাহলে পুরানো সমাপ্তির প্রেরণ রেকর্ড করুন এবং প্রথমে সেই হ্যান্ডঅফটি মেরামত করুন৷
5. যদি সমস্ত স্থানীয় আউটপুট বর্তমান থাকে কিন্তু ডেলিভারি অনুপস্থিত থাকে, তাহলে রুট কনফিগারেশন এবং প্রেরকের স্থিতি পরীক্ষা করুন৷

শিডিউলারের স্বাস্থ্য বা পাঁচ-রুট প্রমাণের জন্য একটি সফল বিজ্ঞপ্তি প্রচার করবেন না।

<a id="interpret-incomplete-source-coverage"></a>
## অসম্পূর্ণ উৎস কভারেজ ব্যাখ্যা করুন

| রাজ্য | কি করতে হবে |
|---|---|
| `partial` | শুধুমাত্র সংগ্রহ করা প্রমাণ ব্যবহার করুন এবং সম্পূর্ণ-কভারেজ দাবি এড়ান। |
| `deferred` | কনফিগারেশন পরিবর্তন করার আগে পরে আবদ্ধ কাজের অগ্রগতি নিশ্চিত করুন৷ |
| `unavailable` | পরিবেশের সীমা রেকর্ড করুন; শুধুমাত্র একটি প্রমাণিত পথ বা অনুমতি সমস্যা সংশোধন করুন। |
| `malformed` | উৎস সংরক্ষণ এবং পার্স ত্রুটি; অনুপস্থিত মান অনুমান করবেন না। |
| `permission_denied` | শুধুমাত্র সংকীর্ণ পড়ার অনুমতি দিন৷ |
| `error` | রুটে নির্ভর করার আগে বিশদ বিবরণ সংরক্ষণ করুন এবং নামযুক্ত পর্যায়ে নির্ণয় করুন৷ |

<a id="restore-missing-runtime-files"></a>
## অনুপস্থিত রানটাইম ফাইল পুনরুদ্ধার করুন

নিশ্চিত করুন:

```text
mods.txt contains RandomDayGuard : 1
RandomDayGuard/enabled.txt exists
RandomDayGuard/Scripts/main.lua exists
```

সঠিক ইনস্টল রুট হল:

```text
AbioticFactor/Binaries/Win64/ue4ss/Mods/RandomDayGuard/
```

এই নেস্টেড লেআউট প্রত্যাখ্যান করুন:

```text
Mods/RandomDayGuard/RandomDayGuard/Scripts/main.lua
```

ফাইলগুলো সঠিক হলে কিন্তু UE4SS গার্ড শুরু করেনি, সংরক্ষণ করুন `UE4SS.log` এবং প্রকৃত গেম-প্রসেস শুরুর সাথে এর স্টার্টআপ টাইমস্ট্যাম্প তুলনা করুন।

<a id="resolve-a-windows-extraction-folder-collision"></a>
## একটি Windows নিষ্কাশন ফোল্ডার সংঘর্ষের সমাধান করুন

একটি পুরানো রিলিজ প্রোগ্রাম ডিরেক্টরি ব্যবহার করে যার নাম শুধুমাত্র ক্যাপিটালাইজেশন দ্বারা ভিন্ন। কিছু উইন্ডোজ এক্সট্রাক্টর এই নামগুলিকে একত্রিত করে যখন একটি ZIP একটি বিদ্যমান ফোল্ডারে রাখা হয়৷

1. শুধুমাত্র অসফল অস্থায়ী নিষ্কাশন মুছুন, ইনস্টল করা মোড বা তার প্রমাণ নয়৷
2. একটি নতুন খালি অস্থায়ী ডিরেক্টরি তৈরি করুন৷
3. সেখানে বর্তমান রিলিজ এক্সট্র্যাক্ট করুন।
4. নিশ্চিত করুন এটি একটি তৈরি করে RandomDayGuard ফোল্ডার এবং একটি প্রোগ্রাম ডিরেক্টরি।
5. যদি Windows এখনও একটি সংঘর্ষের রিপোর্ট করে, তাহলে রিলিজটি আবার ডাউনলোড করুন এবং রিলিজ সংস্করণ এবং এক্সট্রাক্টর ব্যবহার করা হয়েছে তা রিপোর্ট করুন।

ইনস্টল ফোল্ডারে কখনোই নতুন রিলিজ বের করবেন না। [`../INSTALL.md`](%E0%A6%87%E0%A6%A8%E0%A6%B8%E0%A7%8D%E0%A6%9F%E0%A6%B2%E0%A7%87%E0%A6%B6%E0%A6%A8.md).

<a id="load-the-expected-version"></a>
## প্রত্যাশিত সংস্করণ লোড করুন

সোর্স মার্কার এবং বিল্ড মার্কার চেক করুন:

```sh
grep -n "local VERSION" RandomDayGuard/Scripts/main.lua
cat RandomDayGuard/BUILD_MARKER.txt
```

যদি তারা একমত না হয়:

1. সার্ভার বন্ধ করুন।
2. ইনস্টল করা ফোল্ডার, পর্যালোচনা করা কনফিগারেশন এবং রানটাইম প্রমাণের ব্যাক আপ নিন।
3. উদ্দেশিত প্যাকেজ পর্যায় ও পরিদর্শন করুন।
4. শুধুমাত্র প্যাকেজ-পরিচালিত প্রোগ্রাম এবং ডেটা ফাইলগুলি প্রতিস্থাপন করুন৷
5. কনোনিকাল লোডার বিদ্যমান আছে এবং কোন ছোট হাতের ডুপ্লিকেট যোগ করা হয়নি তা নিশ্চিত করুন।
6. একবার শুরু করুন এবং রানটাইম আউটপুট বিচার করার আগে বর্তমান মার্কারগুলি পড়ুন।

<a id="correct-a-missing-saved-root"></a>
## একটি অনুপস্থিত সংরক্ষিত রুট সংশোধন করুন

খুলুন `runtime/saved_path_probe.json`। সম্পূর্ণ অ্যাবায়োটিক ফ্যাক্টরের জন্য যাচাইকৃত পরম পথটি রাখুন `Saved/` ডিরেক্টরিতে `SavedRoot.txt`; শুধুমাত্র একটি বিশ্ব ডিরেক্টরি নির্দেশ করবেন না. সীমাবদ্ধ মূলের বাইরের একটি পথ অবশ্যই প্রত্যাখ্যান করা উচিত।

<a id="recover-a-stalled-historical-scan"></a>
## একটি স্থবির ঐতিহাসিক স্ক্যান পুনরুদ্ধার করুন

বর্তমান পর্যবেক্ষণ এবং ঐতিহাসিক আবিষ্কার আলাদা। একটি বড় আর্কাইভের জন্য অনেকগুলি আবদ্ধ চক্রের প্রয়োজন হতে পারে, তাই একটি অপরিবর্তিত পর্যবেক্ষণ এটিকে স্থবির বলার জন্য যথেষ্ট নয়৷

1. খুলুন `runtime/current/report_worker_status.json`.
2. রেকর্ড করুন `scan_cursor`, ফাইলগুলি আবিষ্কৃত হয়েছে, ফাইলগুলি সম্পূর্ণ হয়েছে, এবং `last_progress_ts`.
3. অন্তত দুটি স্বাভাবিক রিপোর্ট-কর্মী সুযোগের জন্য অপেক্ষা করুন এবং একই ক্ষেত্র আবার তুলনা করুন।
4. যদি কার্সার, সম্পূর্ণ গণনা, বা অগ্রগতির সময় অগ্রসর হয়, স্ক্যান এখনও কাজ করছে৷ এটাকে আবদ্ধ রেখে দিন।
5. যদি পোল আইডি এবং বর্তমান প্রতিবেদনগুলি অগ্রসর হওয়ার সময় সমস্ত অগ্রগতি ক্ষেত্র অপরিবর্তিত থাকে, তাহলে স্ট্যাটাস ফাইলটি সংরক্ষণ করুন এবং কর্মী পর্যায়ের নাম দেওয়া উত্স শ্রেণিটি পরীক্ষা করুন৷ সেই উৎস পথটি মেরামত করুন বা পুনরায় চেষ্টা করার আগে ব্যর্থতা পড়ুন।

একটি স্থবির ঐতিহাসিক স্ক্যান সিদ্ধান্তগুলিকে সীমাবদ্ধ করে যার জন্য পুরানো রেকর্ডের প্রয়োজন হয়৷ এটি এমন একটি বর্তমান প্রতিবেদনকে বাতিল করে না যার সক্রিয়-লগ এবং বর্তমান-চক্র প্রমাণ তাজা৷

<a id="recover-a-stuck-poll-loop"></a>
## একটি আটকে থাকা পোল লুপ পুনরুদ্ধার করুন

খুলুন:

```text
runtime/current/poll_status.json
runtime/poll_error.txt
```

রেকর্ড করুন `poll_id`, `poll_completed_count`, `poll_in_flight`, `poll_stage`, `scheduler_status` এবং সীমাবদ্ধ ব্যবধানে দুবার টাইমস্ট্যাম্প।

- যদি কাউন্টার অগ্রসর হয়, লুপ আটকে থাকে না; পরবর্তী কর্মী পর্যায়ে নির্ণয় করুন।
- যদি `poll_in_flight=true` অপরিবর্তিত থাকবে, রিস্টার্ট করার আগে শেষ অগ্রগতি পর্যায় এবং ত্রুটি সংরক্ষণ করুন।
- যদি সময়সূচী বন্ধ হয়ে যায়, তাহলে পূর্ববর্তী ত্রুটি এবং স্টার্টআপ হ্যান্ডঅফ পরিদর্শন করুন।

একটি স্থবির জীবনচক্রের জন্য ক্ষতিপূরণ দিতে দ্বিতীয় লুপের মালিক যোগ করবেন না৷

<a id="start-the-scan-after-log-backlog"></a>
## লগ ব্যাকলগের পরে স্ক্যান শুরু করুন

এ `runtime/current/poll_status.json`, তুলনা করুন:

```text
active_log_caught_up
active_log_unread_bytes
log_backlog_pending
```

সক্রিয় লগে অপঠিত বাইট থাকা পর্যন্ত ঐতিহাসিক স্ক্যান অপেক্ষা করা উচিত৷ নিশ্চিত করুন পরবর্তী পোল ব্যাকলগ কমিয়ে দেয়। আগাম পোল সহ একটি নির্দিষ্ট অপঠিত গণনা একটি উত্স-টেইল সমস্যা; একটি ফিক্সড পোল একটি শিডিউলার সমস্যা৷

<a id="preserve-scan-progress-after-a-crash"></a>
## ক্র্যাশের পরে স্ক্যানের অগ্রগতি সংরক্ষণ করুন

সংরক্ষণ করুন এবং তুলনা করুন:

```text
runtime/scan_checkpoint.json
runtime/scan_progress.json
runtime/baselines/file_manifest.tsv
```

চেকপয়েন্ট বা ম্যানিফেস্ট অনুপস্থিত কিনা, সংরক্ষিত রুট বা বিশ্ব পরিবর্তিত হয়েছে, বা চেকপয়েন্টটি পুরানো চিহ্নিত হয়েছে কিনা তা পরীক্ষা করুন৷ অগ্রগতি আরও নতুনভাবে দেখানোর জন্য একটি বৈধ বেসলাইন মুছবেন না।

<a id="map-an-unmapped-player"></a>
## একটি আনম্যাপ করা প্লেয়ারকে ম্যাপ করুন

অনুমোদিত লগের সাথে সেশন প্রমাণের তুলনা করুন:

```text
runtime/evidence/session_events.jsonl
Saved/Logs/AbioticFactor.log
```

একটি সম্পূর্ণ সন্ধান করুন `Login request` প্রদর্শন নামের মধ্যে সম্পর্ক, `ConnectID` এবং `UniqueId`। যদি কোনো স্বীকৃত সংযোগ পরিচয় বিদ্যমান না থাকে, তাহলে সারিটি শুধুমাত্র-পর্যালোচনার জন্য রাখুন। একটি প্রদর্শন নাম বা PlayerData একা ফাইলের নাম একটি প্রয়োগযোগ্য পরিচয় নয়৷

<a id="diagnose-a-blocked-adminini-write"></a>
## অবরুদ্ধ নির্ণয় করুন Admin.ini লিখুন

একটি এনফোর্সমেন্ট পরীক্ষা চালান শুধুমাত্র স্পষ্ট অনুমোদন এবং একটি নিষ্পত্তিযোগ্য পরীক্ষা ফাইলের সাথে, কোন লাইভ সার্ভার ফাইলের সাথে নয়৷ প্রথমে নিশ্চিত করুন যে পরীক্ষার কনফিগারেশন গার্ডকে লিখতে বলে:

```lua
review_only_mode = false
auto_ban = true
write_admin_ini = true
```

তারপর রেকর্ড করা ব্যর্থতার কারণ পড়ুন। গার্ডকে অবশ্যই একটি অ্যাকাউন্ট সনাক্ত করতে হবে, মডারেটর এবং বিশ্বস্ত অ্যাকাউন্টগুলিকে সুরক্ষিত করতে হবে, যথেষ্ট অ্যাকাউন্ট-নির্দিষ্ট প্রমাণ খুঁজে বের করতে হবে, একটি নতুন ব্যাকআপ তৈরি এবং যাচাই করতে হবে, নিশ্চিত করতে হবে যে অন্য কোনও প্রোগ্রাম ফাইলটি পরিবর্তন করেনি, উদ্দিষ্ট আপডেট সংরক্ষণ করতে হবে এবং সেই অভিপ্রেত ফলাফলের সাথে সম্পূর্ণ সংরক্ষিত ফাইলের তুলনা করতে হবে। কোনো পদক্ষেপ ব্যর্থ হলে বা চেক করা না গেলে, নিষেধাজ্ঞার তালিকা অপরিবর্তিত রাখুন। দেখুন [Admin.ini প্রয়োগ](%E0%A6%85%E0%A7%8D%E0%A6%AF%E0%A6%BE%E0%A6%A1%E0%A6%AE%E0%A6%BF%E0%A6%A8_%E0%A6%87%E0%A6%A8%E0%A6%BF_%E0%A6%8F%E0%A6%A8%E0%A6%AB%E0%A7%8B%E0%A6%B0%E0%A7%8D%E0%A6%B8%E0%A6%AE%E0%A7%87%E0%A6%A8%E0%A7%8D%E0%A6%9F.md).

<a id="restore-a-missing-daily-rollup"></a>
## একটি অনুপস্থিত দৈনিক রোলআপ পুনরুদ্ধার করুন

নিশ্চিত করুন `forensic_rollup.enabled = true`, তারপর পরিদর্শন করুন:

```text
runtime/current/forensic_today.json
runtime/forensic_days/YYYY-MM-DD/
runtime/final_logs/YYYY-MM-DD/
```

এগুলি অনুপস্থিত থাকলে, সেই ক্রমে স্টার্টআপ, পোল, রিপোর্ট-কর্মী এবং সোর্স-অ্যাকাউন্টিং স্ট্যাটাস দেখুন। দৈনিক রোলআপ হল প্রতিদিন একটি ধারাবাহিকতা রেকর্ড, পুনরাবৃত্তি করা সার্ভার-স্থিতি বিজ্ঞপ্তি নয়।

<a id="look-up-an-exact-status-or-error"></a>
## একটি সঠিক স্থিতি বা ত্রুটি দেখুন

ব্যবহার করুন [স্থিতি এবং ত্রুটির রেফারেন্স](%E0%A6%B8%E0%A7%8D%E0%A6%A5%E0%A6%BF%E0%A6%A4%E0%A6%BF_%E0%A6%8F%E0%A6%AC%E0%A6%82_%E0%A6%A4%E0%A7%8D%E0%A6%B0%E0%A7%81%E0%A6%9F%E0%A6%BF%E0%A6%B0_%E0%A6%B0%E0%A7%87%E0%A6%AB%E0%A6%BE%E0%A6%B0%E0%A7%87%E0%A6%A8%E0%A7%8D%E0%A6%B8.md) PlayerData, এনফোর্সমেন্ট, স্টার্টআপ, সময়সূচী, রিপোর্ট, এবং বিজ্ঞপ্তি কোড টেবিল। লুকআপ টেবিলগুলিকে আলাদা রাখা এই মেরামত পৃষ্ঠাটিকে দ্বিতীয় স্কিমা ম্যানুয়াল হতে বাধা দেয়৷
