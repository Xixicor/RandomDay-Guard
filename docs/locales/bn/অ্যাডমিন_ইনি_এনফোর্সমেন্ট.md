# Admin.ini প্রয়োগ

> **ক্যাননিকাল ইংরেজি উৎস:** [ADMIN_INI_ENFORCEMENT.md](../../ADMIN_INI_ENFORCEMENT.md). এই স্থানীয় ডকুমেন্টেশন সঠিক কমান্ড, পাথ, কী, স্থিতি মান, হ্যাশ এবং ফাইলের নাম সংরক্ষণ করে। প্রযুক্তিগত শব্দের ভিন্নতা থাকলে, ইংরেজি উৎস ব্যবহার করুন।


RandomDayGuard তার ডিফল্ট সেটআপে সার্ভারের নিষেধাজ্ঞার তালিকা পরিবর্তন করে না। এটি শুধুমাত্র একজন প্রশাসকের পর্যালোচনা করার জন্য প্রতিবেদন তৈরি করে। এই পৃষ্ঠাটি এমন প্রশাসকদের জন্য ঐচ্ছিক স্বয়ংক্রিয় নিষেধাজ্ঞা-তালিকা আপডেট ব্যাখ্যা করে যারা ইচ্ছাকৃতভাবে এটি সক্ষম করে।

<a id="what-guard-checks-before-changing-the-ban-list"></a>
## নিষেধাজ্ঞার তালিকা পরিবর্তন করার আগে গার্ড কী পরীক্ষা করে

নিচের প্রতিটি উত্তর **হ্যাঁ**:

1. বর্তমান প্রমাণ কি পর্যাপ্ত আত্মবিশ্বাসের সাথে একটি নির্দিষ্ট অ্যাকাউন্ট শনাক্ত করেছে?
2. অ্যাকাউন্টটি কি কোনো মডারেটর বা অ্যাকাউন্টটি প্রশাসককে বিশ্বস্ত হিসাবে চিহ্নিত করা হয়নি?
3. অ্যাকাউন্টটি কি ইতিমধ্যেই নিষিদ্ধ তালিকায় নেই?
4. অ্যাকাউন্ট কি কনফিগার করা স্বয়ংক্রিয়-অ্যাকশন স্কোরে পৌঁছেছে?
5. প্রহরী বর্তমান পড়তে পারে `Admin.ini` এবং একটি অভিন্ন ব্যাকআপ সংরক্ষণ করবেন?
6. করেছে `Admin.ini` গার্ড আপডেট প্রস্তুত করার সময় অপরিবর্তিত থাকবেন?
7. সংরক্ষণের পরে, সম্পূর্ণ ফাইলটি কি অভিপ্রেত ফলাফলের সাথে মেলে?

যদি কোনো উত্তর হয় **না**, বা চেক করা যাবে না, গার্ড ছেড়ে যায় `Admin.ini` অপরিবর্তিত এবং তার রিপোর্টে কারণ রেকর্ড করে৷ যদি সংরক্ষণ শুরু হয় কিন্তু চূড়ান্ত চেক ব্যর্থ হয়, গার্ড যাচাইকৃত ব্যাকআপ পুনরুদ্ধার করে।

<a id="file-format"></a>
## ফাইল বিন্যাস

`Admin.ini` শুধুমাত্র পরিষ্কার নিষেধাজ্ঞার লাইন পেতে হবে:

```ini
BannedPlayer=<ID>
```

- কোন নাম নেই।
- কোন মন্তব্য নেই৷
- কোন কারণ নেই।
- কোন প্রত্যয় নেই।

<a id="safe-defaults"></a>
## নিরাপদ ডিফল্ট

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
require_clean_ban_id = true
preserve_existing_bans = true
preserve_moderators = true
```

<a id="ban-id-source"></a>
## আইডি উৎস নিষিদ্ধ করুন

সেরা উৎস:

```text
Login request
Name=<player>
ConnectID=<raw_id>
UniqueId=<platform_id>
```

রানটাইম হয় একটি সম্পূর্ণ সংখ্যাসূচক আইডি বা সম্পূর্ণ নথিভুক্ত `<digits>_+_|<non-space token>` সংযোগ ফর্ম এবং এটি থেকে সাংখ্যিক নিষেধাজ্ঞা আইডি প্রাপ্ত। একটি অজানা প্রত্যয় সহ নির্বিচারে সাংখ্যিক উপসর্গ প্রত্যাখ্যান করা হয়; তারা একটি নিষেধাজ্ঞা আইডি মধ্যে কাটা হয় না.

সঠিক:

```ini
BannedPlayer=2535422284688820
```

ভুল:

```ini
BannedPlayer=ExamplePlayer
```

এছাড়াও ভুল:

```text
BannedPlayer=<ID>
```

<a id="exact-settings-guard-checks"></a>
## সঠিক সেটিংস গার্ড চেক

এই সেটিংস উপরে বর্ণিত চেকগুলি বাস্তবায়ন করে৷ প্রতিটি তালিকাভুক্ত শর্ত সত্য হতে হবে:

```text
review_only_mode == false
auto_ban == true
write_admin_ini == true
ban_id is clean numeric
identity is mapped
not trusted
not moderator
threshold is met
account-specific evidence exists
```

কোন শর্ত মিথ্যা হলে বা চেক করা না গেলে, গার্ড নিষেধাজ্ঞার তালিকাটি অপরিবর্তিত রেখে দেয় এবং এটি কী থামিয়েছে তা রেকর্ড করে৷

<a id="transaction-safety"></a>
## লেনদেনের নিরাপত্তা

একমাত্র `Admin.ini` মিউটেশন পাথ ক্রমানুসারে এই ধাপগুলি সম্পাদন করে:

1. অনুমোদিত বাইটগুলি পড়ুন এবং কাঠামোগতভাবে যাচাই করুন৷
2. একই স্ন্যাপশট থেকে মডারেটর, বিশ্বস্ত, এবং বিদ্যমান-নিষিদ্ধ অবস্থা প্রাপ্ত করুন৷
3. এর অধীনে একটি অনন্য ব্যাকআপ লিখুন `runtime/backups/` এবং বাইটের জন্য বাইট যাচাই করুন৷
4. পুনরায় পড়ুন `Admin.ini` অবিলম্বে প্রতিস্থাপনের আগে এবং কোনো বাহ্যিক পরিবর্তন প্রত্যাখ্যান করুন।
5. কনফিগার করা নিয়ন্ত্রিত প্রতিস্থাপন পথের মাধ্যমে প্রার্থী লিখুন।
6. সম্পূর্ণ প্রার্থীর বাইটের সমান করতে সম্পূর্ণ রিডব্যাক বাইটের প্রয়োজন৷
7. রিডব্যাক ব্যর্থ হলে, শুধুমাত্র যাচাইকৃত ব্যাকআপ পুনরুদ্ধার করুন যখন বর্তমান ফাইলটি এখনও গার্ড দ্বারা লিখিত সঠিক প্রার্থী। অন্য লেখক এটি পরিবর্তন করলে, গার্ড অজানা বহিরাগত বাইটগুলিকে ওভাররাইট করার পরিবর্তে রোলব্যাক প্রত্যাখ্যান করে।

ডুপ্লিকেট আইডিগুলি অদম্য: কোন দ্বিতীয় লাইন এবং কোন দ্বিতীয় ব্যাকআপ লেখা নেই৷ ব্যাকআপ নামের মধ্যে একটি টাইমস্ট্যাম্প, সোর্স-বাইট ফিঙ্গারপ্রিন্ট এবং ক্লিন আইডি অন্তর্ভুক্ত থাকে তাই আলাদা প্রচেষ্টা পুরানো এক-সেকেন্ড ফাইলের নাম শেয়ার করতে পারে না৷

<a id="local-regression-proof"></a>
## স্থানীয় রিগ্রেশন প্রমাণ

`tests/lua/enforcement_runtime_test.lua` শিপড লোডারটিকে একবার বুট করে এবং তারপরে এটির আসল স্থানীয় চালায় `append_ban()` ভান্ডারের নীচে বিচ্ছিন্ন সিন্থেটিক ফাইলগুলির বিরুদ্ধে বন্ধ `.tmp/` ডিরেক্টরি। এটি সন্নিবেশ, সদৃশ অদম্যতা, moderator/trusted প্রত্যাখ্যান, দুর্বল এবং বিকৃত পরিচয় প্রত্যাখ্যান, বাইট-সঠিক ব্যাকআপ যাচাইকরণ, সমসাময়িক পরিবর্তন প্রত্যাখ্যান, ব্যর্থ রিডব্যাকের পরে সফল রোলব্যাক, এবং পোস্ট-রাইট বাহ্যিক পরিবর্তন ওভাররাইট করতে অস্বীকার। এর ফাইলসিস্টেম র্যাপারগুলি ফিক্সচার রুটের বাইরে যেকোন মিউটেশন প্রত্যাখ্যান করে; কোন বাস্তব সার্ভার পাথ বা বাস্তব নেই `Admin.ini` ব্যবহার করা হয়৷

এটি চালান `python tools/test_public_pipeline.py`। একটি ফিক্সচার পাস শুধুমাত্র স্থানীয় লেনদেনের আচরণ প্রমাণ করে। এটি এনফোর্সমেন্ট সক্ষম করে না, প্রোডাকশন লেখার অনুমোদন দেয় না বা হোস্ট-নির্দিষ্ট অনুমতি প্রমাণ করে না।

<a id="rollback"></a>
## রোলব্যাক

1. সার্ভার বন্ধ করুন।
2.  সাম্প্রতিক পুনরুদ্ধার করুন Admin.ini `runtime/backups/`.
3. ভুলটি সরান `BannedPlayer=<ID>` লাইন।
4. সার্ভার শুরু করুন৷
5. পুনরায় খুলুন Admin.ini এবং নিশ্চিত করুন যে লাইনটি টিকে আছে বা সরানো হয়েছে।
6. সংরক্ষণ করুন `enforced_bans.jsonl` অডিটের জন্য।
