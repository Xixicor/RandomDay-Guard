# খারাপ-অভিনেতার নিদর্শন এবং স্থিতিস্থাপকতা

> **ক্যাননিকাল ইংরেজি উৎস:** [BAD_ACTOR_PATTERNS_AND_RESILIENCE.md](../../BAD_ACTOR_PATTERNS_AND_RESILIENCE.md). এই স্থানীয় ডকুমেন্টেশন সঠিক কমান্ড, পাথ, কী, স্থিতি মান, হ্যাশ এবং ফাইলের নাম সংরক্ষণ করে। প্রযুক্তিগত শব্দের ভিন্নতা থাকলে, ইংরেজি উৎস ব্যবহার করুন।


গার্ড কীভাবে ক্র্যাশ অপব্যবহার, শোষণ-সংলগ্ন আচরণ এবং পুনরুদ্ধারের পরিকল্পনা পর্যালোচনা করতে সহায়তা করে তা বোঝার জন্য এই পৃষ্ঠাটি ব্যবহার করুন৷

<a id="what-the-guard-can-help-with"></a>
## গার্ড কি সাহায্য করতে পারে

| প্যাটার্ন | কি চেক করবেন |
|---|---|
| ক্র্যাশ-সম্পর্কিত রিটার্ন | ক্র্যাশ হওয়ার আগে একই অ্যাকাউন্ট সক্রিয় এবং পুনরায় চালু করার পরে ফিরে আসে |
| দ্রুত পুনঃসংযোগ অনুসন্ধান | পুনরাবৃত্ত join/leave বা timeout/reconnect লুপ |
| মাল্টি-অ্যাকাউন্ট ক্লাস্টার | তরঙ্গে যোগ দিন, শেয়ার্ড ওয়ার্নিং উইন্ডো, শেয়ার করা ব্যর্থ উইন্ডো |
| সতর্কতা বার্স্ট স্ট্রেস | পুনরাবৃত্ত ActorChannelFailure বা সংরক্ষণ-সতর্কতা উইন্ডো |
| সীমার বাইরের প্রসঙ্গ | PlayerData/map/world পঠনযোগ্য হলে প্রসঙ্গ |
| সেভ-টাচ ওভারল্যাপ | ওয়ার্ল্ড-সেভ কনটেক্সট ওভারল্যাপিং ম্যাপ করা সেশন |
| পরিচয় বিভ্রান্তি | যে নামগুলির ConnectID ম্যাপিং প্রয়োজন |

<a id="why-it-avoids-memory-access"></a>
## এটি কেন মেমরি অ্যাক্সেস এড়ায়

RandomDayGuard সার্ভার-মালিকানাধীন ফাইলগুলি থেকে কাজ করে:

```text
Saved/Logs/*.log
Admin.ini
World saves
PlayerData
Backups
runtime evidence
```

এটি এটিকে ক্লায়েন্ট-সাইড মেমরির অবস্থার উপর কম নির্ভর করে এবং গেম আপডেট জুড়ে কম ভঙ্গুর করে তোলে৷

ট্রেডঅফ:

```text
It cannot prove hidden live actions unless the server writes evidence.
```

<a id="crash-correlated-returners"></a>
## ক্র্যাশ-সম্পর্কিত রিটার্নার্স

প্যাটার্ন:

```text
Account joins.
Server crashes or restarts.
Same account reconnects quickly.
Pattern repeats.
```

উপযোগী ফাইল:

```text
runtime/server_lifecycle_events.jsonl
runtime/server_epochs.jsonl
runtime/evidence/crash_reconnect_events.jsonl
runtime/account_evidence.json
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

<a id="rapid-reconnect-probers"></a>
## দ্রুত রিকানেক্ট প্রোবার

প্যাটার্ন:

```text
join -> leave -> join -> leave -> join
```

উপযোগী ফাইল:

```text
runtime/evidence/session_events.jsonl
runtime/session_events.tsv
runtime/account_evidence.json
runtime/forensic_days/YYYY-MM-DD/players.tsv
```

<a id="multi-account-clusters"></a>
## মাল্টি-অ্যাকাউন্ট ক্লাস্টার

প্যাটার্ন:

```text
Several accounts join in the same window.
Warnings or crashes follow.
Some accounts rotate or reconnect after restart.
```

উপযোগী ফাইল:

```text
runtime/raid_cases/
runtime/forensic_days/YYYY-MM-DD/raid_cases.tsv
runtime/final_logs/YYYY-MM-DD/final_forensic_log.txt
```

নিয়ম:

```text
A cluster is not a mass-ban list.
Each account still needs its own evidence.
```

<a id="sticky-backup-recommendation"></a>
## স্টিকি ব্যাকআপ সুপারিশ

এর পরে একটি স্টিকি ব্যাকআপ তৈরি করুন:

```text
first full baseline completes
object_registry.json exists
file_manifest.tsv exists
world_state_latest.json has scan_complete=true
Admin.ini is verified
trusted IDs are configured
```

ব্যাক আপ:

```text
RandomDayGuard/config.lua
RandomDayGuard/SavedRoot.txt
RandomDayGuard/runtime/baselines/
RandomDayGuard/runtime/object_registry.json
RandomDayGuard/runtime/world_state/current/world_state_latest.json
Saved/SaveGames/Server/Admin.ini
```

<a id="recovery-model"></a>
## পুনরুদ্ধার মডেল

```text
Clean install
-> verify live defense
-> complete first baseline
-> create sticky backup
-> run server normally
-> use daily rollups for review
-> restore sticky backup if needed
```
