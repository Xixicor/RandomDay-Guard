<a id="worked-operation-examples"></a>
# কাজ করা অপারেশন উদাহরণ

> **ক্যাননিকাল ইংরেজি উৎস:** [EXAMPLE_RUNS.md](../../EXAMPLE_RUNS.md). এই স্থানীয় ডকুমেন্টেশন সঠিক কমান্ড, পাথ, কী, স্থিতি মান, হ্যাশ এবং ফাইলের নাম সংরক্ষণ করে। প্রযুক্তিগত শব্দের ভিন্নতা থাকলে, ইংরেজি উৎস ব্যবহার করুন।


এই উদাহরণগুলি প্রত্যাশিত অবস্থার রূপান্তর ব্যাখ্যা করতে উদ্ভাবিত মান ব্যবহার করে; তারা লাইভ সামঞ্জস্য বা প্লেয়ার প্রমাণ নয়।

<a id="successful-current-cycle"></a>
## সফল বর্তমান চক্র

ইনপুট: পঠনযোগ্য সক্রিয় লগ, version/boot/epoch, `poll_id=41`, সম্পূর্ণ বর্তমান পোল, লেখার যোগ্য accounting/history/report রুট, কোন ব্লকিং স্লো-স্ক্যান নীতি।

প্রত্যাশিত:

```text
server_status = full
player_activity = full or limited_expected_empty
case_review = full or limited_expected_empty
daily_rollup = full or limited_expected_empty
critical_guard = full or limited_expected_empty
```

প্রতিটি সক্রিয় রুটে আছে JSON/TXT আউটপুট এবং `route_proof.json`। রুটের স্থিতি তার নিজস্ব বিষয়ের উপর নির্ভর করে, সাধারণ সাফল্যের বার্তার উপর নয়।

<a id="expected-empty-player-and-case-routes"></a>
## প্রত্যাশিত-খালি প্লেয়ার এবং কেস রুট

ইনপুট: বর্তমান-চক্র প্রমাণ সম্পূর্ণ; কোন বর্তমান বা ধরে রাখা প্লেয়ার সারি; কোন রিটেনড কেস এবং কোন কারেন্ট নেই REVIEW/BAN-ELIGIBLE অ্যাকাউন্ট।

প্রত্যাশিত:

```text
player_activity.route_proof_status = limited_expected_empty
player_activity.expected_empty = true
player_activity.players = []

case_review.route_proof_status = limited_expected_empty
case_review.expected_empty = true
case_review.cases = []
```

অনুবাদিত প্রতিবেদনগুলি বলে যে কোনও যোগ্য আবদ্ধ বিষয় পরিলক্ষিত হয়নি৷ তারা আরও বলে যে এটি প্রমাণ করে না যে কেউ কখনও সংযুক্ত নয় বা কোনও প্রসঙ্গ অনুপস্থিত। কোনো স্থানধারক নেই player/case তৈরি হয়৷

<a id="partial-bounded-scan"></a>
## আংশিক আবদ্ধ স্ক্যান

ইনপুট: তাজা বর্তমান log/poll; `scan_checkpoint.json` বা `scan_progress.json` বিদ্যমান; স্ক্যান অসম্পূর্ণ; ডিফল্ট `slow_world_scan_blocks_current_reports=false`.

প্রত্যাশিত:

```text
world_save_scan.status = partial
source accounting = partial
server_status may still be full for fresh current state
historical routes name the scan limitation
```

সেট করুন `slow_world_scan_blocks_current_reports=true` শুধুমাত্র তখনই যখন অপারেটর সেই ঐচ্ছিক ধীরগতির উৎসটি বর্তমান প্রতিবেদনগুলিকে ব্লক করতে চায়৷ পুনরুদ্ধার হল স্ক্যান কর্মীকে পুনরায় শুরু করার অনুমতি দেওয়া, চেকপয়েন্ট মুছে ফেলার জন্য নয়৷

<a id="missing-current-cycle-proof"></a>
## কারেন্ট-সাইকেল প্রমাণ নেই

ইনপুট: সক্রিয় লগ অনুপলব্ধ, `poll_id=0` বা boot/epoch/last-poll বংশ অনুপস্থিত৷

প্রত্যাশিত:

```text
current_cycle_proof_complete = false
all route proof statuses = missing
each configured route envelope status = suppressed_current_cycle
delivery_eligible = false
delivery_attempted = false
```

 চাপা খামটি একটি অডিট রেকর্ড, একটি সারিবদ্ধ বিতরণ নয়৷ পুরানো চূড়ান্ত লগ শুধুমাত্র ঐতিহাসিক থেকে যায়. প্রথম অনুপস্থিত মেরামত করুন lineage/source ফিল্ড এবং একটি নতুন চক্র তৈরি করুন৷

<a id="malformed-optional-adminini-source"></a>
## বিকৃত ঐচ্ছিক Admin.ini উৎস

ইনপুট: `Admin.ini` বিদ্যমান কিন্তু পরিষ্কার কাঠামোগত বৈধতা ব্যর্থ হয়৷

প্রত্যাশিত:

```text
admin_ini.status = malformed
source reference preserved
write/enforcement path closed
```

ফাইলটি সংরক্ষণ করুন এবং একটি পর্যালোচনা করা পরিষ্কার বিন্যাস পুনরুদ্ধার করুন৷ রানটাইম প্রমাণে ব্যাখ্যামূলক পাঠ্য রাখুন; প্রতিটি `Admin.ini` নিষেধাজ্ঞা এন্ট্রি রয়ে গেছে শুধুমাত্র `BannedPlayer=<ID>`.

<a id="required-active-log-probe-error"></a>
## প্রয়োজনীয় সক্রিয়-লগ অনুসন্ধান ত্রুটি

ইনপুট: আবদ্ধ প্রয়োজনীয় সক্রিয়-লগ প্রোব একটি স্যানিটাইজড রিড ত্রুটির সাথে ব্যর্থ হয়৷

প্রত্যাশিত:

```text
source_accounting.sources[active_log].status = error
source_accounting.sources[active_log].detail = "bounded active-log probe failed: <sanitized reason>"
coverage_status = unavailable
all route proof statuses = missing
```

`error` এর আবদ্ধ বিশদ সহ উৎস সারিতে থাকে। শীর্ষ-স্তরের রিপোর্ট `unavailable`, এবং রুট প্রুফ রয়ে গেছে `missing` যতক্ষণ না একটি নতুন বর্তমান চক্র প্রয়োজনীয় উৎস প্রমাণ করে।

<a id="incompatible-or-stale-baseline"></a>
## বেমানান বা পুরানো বেসলাইন

ইনপুট: পরিবর্তিত package/source পরিচয় বা stale/incompatible বেসলাইন ম্যানিফেস্ট৷

প্রত্যাশিত: বৈধতা বা রানটাইম স্থিতি অসঙ্গতি রেকর্ড করে; স্ক্যান স্টেট সম্পূর্ণ পুনঃব্যবহারের দাবি করে না। পূর্বের প্রমাণ সংরক্ষণ করুন, একটি সুস্পষ্ট বেসলাইন পুনর্নির্মাণ শুরু করুন এবং নতুন টার্মিনাল প্রমাণের জন্য অপেক্ষা করুন। একটি রেকর্ড করা কারণ ছাড়া একটি জোরপূর্বক পুনর্নির্মাণ ডিফল্ট পুনরুদ্ধার নয়৷

<a id="paired-report-write-failure"></a>
## জোড়া রিপোর্ট লেখার ব্যর্থতা

ইনপুট: JSON লিখতে সফল হয় কিন্তু TXT লিখতে ব্যর্থ, অথবা বিপরীত।

প্রত্যাশিত:

```text
route_proof_status = missing
completed = false
coverage_status = unavailable
output_write_detail = "paired JSON/TXT write failed: <sanitized reason>"
next_action = repair both route output writes
```

লেখক সর্বোত্তম প্রচেষ্টা ব্যর্থতার সাথে একত্রিত হওয়ার জন্য উভয় ভাইবোনকে পুনর্লিখন করেছেন৷ একজন সফল ভাইবোন সাফল্যের দাবি হিসাবে থাকতে পারে না। আবদ্ধ লেখার বিবরণ পঞ্চম শীর্ষ-স্তরের কভারেজ মান তৈরি করে না।

<a id="route-proof-write-failure"></a>
## রুট-প্রুফ লেখার ব্যর্থতা

ইনপুট: রুট জোড়া লেখা হয়েছে কিন্তু `route_proof.json` প্রতিস্থাপন করা যাবে না।

প্রত্যাশিত: সমস্ত প্রতিবেদন পুনরায় লেখা হয়েছে `missing`, সমস্ত বিজ্ঞপ্তির ফলাফল হল `route_proof_write_failed`, এবং কোন খাম গ্রহণ করা হয় না। একটি কনফিগার করা রুটে একটি `suppressed_current_cycle` ডেলিভারি পতাকা সহ অডিট খাম মিথ্যা৷ আউটপুট রুট মেরামত করুন এবং একই বর্তমান চক্র পুনরায় তৈরি করুন।

<a id="review-only-enforcement-example"></a>
## শুধু-পর্যালোচনা প্রয়োগের উদাহরণ

কনফিগ:

```lua
review_only_mode = true
auto_ban = false
write_admin_ini = false
```

প্রত্যাশিত: স্কোর, কেস এবং সুপারিশ লেখা হতে পারে; `Admin.ini` অপরিবর্তিত রয়েছে। এটি সর্বজনীন ডিফল্ট৷

<a id="approved-write-success-example"></a>
## অনুমোদিত লেখার সাফল্যের উদাহরণ

শুধুমাত্র একটি পৃথকভাবে অনুমোদিত পরীক্ষা তিনটি লেখার সুইচ সেট করতে পারে৷ এটি অবশ্যই পরিষ্কার সাংখ্যিক পরিচয় প্রমাণ করতে হবে, trust/moderator বর্জন, থ্রেশহোল্ড যোগ্যতা, বৈধ Admin.ini path/parse, ব্যাকআপ সাফল্য, লেখার সাফল্য, রিডব্যাক সমতা, এবং অ্যাকাউন্ট-নির্দিষ্ট প্রমাণ।

প্রত্যাশিত:

```text
runtime/backups/Admin_<timestamp>_<source-fingerprint>_<clean-ID>.ini
Admin.ini contains one clean BannedPlayer=<ID>
runtime/enforced_bans.jsonl and evidence mirror record success
```

সফল উদাহরণটি অন্য অ্যাকাউন্টের জন্য স্বয়ংক্রিয় প্রয়োগ সক্ষম করে না৷

<a id="writereadback-failure-with-rollback"></a>
## Write/readback রোলব্যাকের সাথে ব্যর্থতা

ইনপুট: প্রতিটি প্রাক-লিখন গেট পাস; প্রতিস্থাপন লিখতে বা রিডব্যাক ব্যর্থ হয়; `rollback_on_readback_failure=true` এবং যাচাইকৃত ব্যাকআপ উপলব্ধ।

প্রত্যাশিত: ব্যর্থতার প্রমাণ স্টেজ রেকর্ড করে এবং `rollback_success`; মূল Admin.ini বাইটগুলি পুনরুদ্ধার করা হয়েছে এবং অ্যাকাউন্টটি সফলভাবে প্রয়োগ করা হয়েছে বলে প্রতিবেদন করা হয়নি৷ যদি রোলব্যাকও ব্যর্থ হয়, লেখা বন্ধ করুন, উভয়ই সংরক্ষণ করুন files/evidence, এবং ব্যাকআপ থেকে ম্যানুয়ালি পুনরুদ্ধার করুন।

<a id="local-outbox-example"></a>
## স্থানীয় আউটবক্সের উদাহরণ

ইনপুট: বিজ্ঞপ্তি সক্রিয় করা হয়েছে `local_file_outbox` মোড, রুট সক্ষম, সম্পূর্ণ রুট প্রমাণ, এবং হয় `full` বা স্পষ্টভাবে অনুমোদিত প্রত্যাশিত-খালি৷

প্রত্যাশিত খাম:

```text
schema = randomdayguard.notification/v1
completed_output = true
status = ready_for_local_consumer
delivery_eligible = true
delivery_backend = none
delivery_attempted = false
```

এর জন্য missing/ineligible আউটপুট, একই পথের পরিবর্তে `status=suppressed_current_cycle`, `completed_output=false` এবং `delivery_eligible=false`। হয় ফাইল শুধুমাত্র একটি স্থানীয় লেখা প্রমাণ করে। কোন প্রদানকারী, পরিবহন, বিতরণ, বা পড়ার রসিদ বান্ডিল বা অনুমান করা হয় না।
