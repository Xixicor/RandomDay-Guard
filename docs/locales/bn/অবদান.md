# অবদান

> **ক্যাননিকাল ইংরেজি উৎস:** [CONTRIBUTING.md](../../../CONTRIBUTING.md). এই স্থানীয় ডকুমেন্টেশন সঠিক কমান্ড, পাথ, কী, স্থিতি মান, হ্যাশ এবং ফাইলের নাম সংরক্ষণ করে। প্রযুক্তিগত শব্দের ভিন্নতা থাকলে, ইংরেজি উৎস ব্যবহার করুন।


RandomDayGuard পার্সার্স, ডকুমেন্টেশন, পরীক্ষা, এবং সর্বজনীন-নিরাপদ বৈধতা ফোকাসড, পুনরুত্পাদনযোগ্য উন্নতি গ্রহণ করে। প্রতিটি পরিবর্তনকে পাবলিক প্রজেক্ট চুক্তির সাথে আবদ্ধ রাখুন এবং পর্যালোচনা-প্রথম আচরণ সংরক্ষণ করুন: গার্ডকে অবশ্যই চলে যেতে হবে `Admin.ini` অপরিবর্তিত যখন একটি প্রয়োজনীয় নিরাপত্তা পরীক্ষা নিশ্চিত করা যাবে না।

<a id="prepare-a-safe-workspace"></a>
## একটি নিরাপদ ওয়ার্কস্পেস প্রস্তুত করুন

1. ভান্ডারটিকে কাঁটা বা ক্লোন করুন এবং একটি ফোকাসড শাখা তৈরি করুন৷
2. একটি সমর্থিত Python 3 ইন্টারপ্রেটার ইনস্টল করুন৷ আপনি লুয়া পরিবর্তন করার সময় একটি লুয়া কম্পাইলার ইনস্টল করুন`luac -p` সিনট্যাক্স পরীক্ষা করতে পারে।
3. পড়ুন [ডকুমেন্টেশন হোম](%E0%A6%A1%E0%A6%95%E0%A7%81%E0%A6%AE%E0%A7%87%E0%A6%A8%E0%A7%8D%E0%A6%9F%E0%A7%87%E0%A6%B6%E0%A6%A8.md), [আর্কিটেকচার](%E0%A6%86%E0%A6%B0%E0%A7%8D%E0%A6%95%E0%A6%BF%E0%A6%9F%E0%A7%87%E0%A6%95%E0%A6%9A%E0%A6%BE%E0%A6%B0.md) এবং [প্রমাণের সীমানা](%E0%A6%AA%E0%A7%8D%E0%A6%B0%E0%A6%AE%E0%A6%BE%E0%A6%A3%E0%A7%87%E0%A6%B0_%E0%A6%B8%E0%A7%80%E0%A6%AE%E0%A6%BE%E0%A6%A8%E0%A6%BE.md) আপনি যে এলাকার পরিবর্তন করবেন তার জন্য।
4. পরিদর্শন করুন `git status` সম্পর্কহীন কাজ সম্পাদনা ও সংরক্ষণ করার আগে।
5. শুধুমাত্র সিন্থেটিক বা স্যানিটাইজড ফিক্সচার ব্যবহার করুন।

কখনও ব্যক্তিগত সার্ভার লগ, সংরক্ষিত ফোল্ডার, প্লেয়ার শনাক্তকারী, `Admin.ini`, ব্যক্তিগত বিজ্ঞপ্তির এন্ডপয়েন্ট, শংসাপত্র, ব্যক্তিগত পাথ, রানটাইম আউটপুট বা কপি করা লাইভ প্রমাণ।

<a id="make-a-focused-change"></a>
## একটি ফোকাসড পরিবর্তন করুন

- বিদ্যমান নামকরণ, ফর্ম্যাটিং, নিরাপত্তা পরীক্ষা এবং মডিউল মালিকানা অনুসরণ করুন৷
- প্রতিটি পদ্ধতি বা সঠিক তথ্যের জন্য একটি ক্যানোনিকাল ডকুমেন্টেশনের মালিক রাখুন।
- ব্যবহার বা সর্বজনীন আউটপুট পরিবর্তন হলে ব্যবহারকারীর ডকুমেন্টেশন এবং উদাহরণ আপডেট করুন।
- ব্যবহারিক হলে একটি বাগ ফিক্সের জন্য একটি রিগ্রেশন পরীক্ষা যোগ করুন।
- একটি পরীক্ষা পাস করার জন্য অ্যাকাউন্ট নিশ্চিতকরণ, বিশ্বস্ত-অ্যাকাউন্ট সুরক্ষা, ব্যাকআপ যাচাইকরণ, বাইরের-পরিবর্তন সনাক্তকরণ, সংরক্ষিত-ফাইল তুলনা, পুনরুদ্ধার, বা শুধুমাত্র পর্যালোচনার ডিফল্টগুলিকে দুর্বল করবেন না।

<a id="run-the-relevant-checks"></a>
## প্রাসঙ্গিক পরীক্ষা চালান

কেবল-ডকুমেন্টেশন পরিবর্তনের জন্য, চালান:

```powershell
python -B tools\generate_documentation_audit.py --check
python -B -m unittest discover tests -p "test_documentation*.py"
git diff --check
```

উৎস, কনফিগারেশন, প্যাকেজিং বা পরীক্ষার পরিবর্তনের জন্য, এছাড়াও প্রযোজ্য চেকগুলি চালান [বৈধকরণ এবং রিলিজ পর্যালোচনা](%E0%A6%AC%E0%A7%88%E0%A6%A7%E0%A6%95%E0%A6%B0%E0%A6%A3_%E0%A6%8F%E0%A6%AC%E0%A6%82_%E0%A6%AA%E0%A7%8D%E0%A6%B0%E0%A6%95%E0%A6%BE%E0%A6%B6.md) লুয়া সিনট্যাক্স চেক, রিপোজিটরি যাচাইকরণ, পাবলিক-পাইপলাইন পরীক্ষা এবং সম্পূর্ণ ইউনিট-টেস্ট স্যুট সহ। প্রতিটি এড়িয়ে যাওয়া বা অনুপলব্ধ চেক রিপোর্ট করুন; এটিকে পাস হিসাবে বর্ণনা করবেন না।

<a id="submit-the-change-for-review"></a>
## পর্যালোচনার জন্য পরিবর্তন জমা দিন

শুধুমাত্র সম্পূর্ণ পার্থক্য পর্যালোচনা করার পরে একটি ফোকাসড টান অনুরোধ খুলুন৷ অন্তর্ভুক্ত:

- সমস্যা এবং উদ্দেশ্যমূলক আচরণ;
- সঠিক ফাইল এবং সর্বজনীন চুক্তি পরিবর্তিত হয়েছে;
- কমান্ড চালানো এবং তাদের ফলাফল;
- গোপনীয়তা, সামঞ্জস্যতা, এবং প্রয়োগের প্রভাব; এবং
- বাকি সীমাবদ্ধতা বা ফলো-আপ কাজ।

উত্পন্ন রানটাইম প্রমাণ বা রিলিজ সংরক্ষণাগারগুলি অন্তর্ভুক্ত করবেন না যদি না পরিবর্তনটি স্পষ্টভাবে প্রয়োজন এবং তাদের যাচাই করে। একটি অবদান তৃতীয় পক্ষের সাইটে প্রকাশ, স্থাপনা, লাইভ-সার্ভার পরীক্ষা, এনফোর্সমেন্ট অ্যাকশন বা প্রকাশনার অনুমোদন দেয় না।

এর মাধ্যমে দুর্বলতা রিপোর্ট করুন [ব্যক্তিগত নিরাপত্তা রুট](%E0%A6%A8%E0%A6%BF%E0%A6%B0%E0%A6%BE%E0%A6%AA%E0%A6%A4%E0%A7%8D%E0%A6%A4%E0%A6%BE.md), কোনো পাবলিক সমস্যা বা সাধারণ টানার অনুরোধ নয়।
